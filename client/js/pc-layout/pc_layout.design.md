## ① 켜고 끄기 — 판정식 · 10번 누름 · 켜기/끄기

**용어** `armed` = 이번 실행에서 10번 누름으로 켜 둔 상태(메모리 변수). `body.pc-mode` = **지금 PC 배치가 실제로 적용 중**. 언제나 `pc-mode === (armed && _canShow())`.

**판정식**(`pc_layout.js` 한 곳에만 둔다. CSS 는 `@media` 로 감싸지 않는다)
```js
var PC_MIN_W = 1200;
function _isPcDevice() {
    var cap = window.Capacitor;
    if (cap && typeof cap.isNativePlatform === 'function' && cap.isNativePlatform()) return false;   // 앱
    if (navigator.maxTouchPoints > 0) return false;                                                   // 터치가 되는 기기
    if (!window.matchMedia) return false;
    if (window.matchMedia('(any-pointer: coarse)').matches) return false;                             // 손가락 입력이 하나라도 있음
    return window.matchMedia('(hover: hover) and (pointer: fine)').matches;                           // 주 입력이 마우스
}
function _canShow() {
    return _isPcDevice() && window.innerWidth >= PC_MIN_W && document.body.classList.contains('om-mode');
}
```
높이 조건은 없다. 터치 화면이 달린 노트북은 켜지지 않는다(⑫ 알릴 것 3).

**10번 누름**
- 페이지가 뜰 때(`DOMContentLoaded`) 붙이는 것은 `#bottom-tab-bar` 의 `click`(bubble) 리스너 **하나뿐**. `preventDefault`·`stopPropagation` 을 부르지 않는다.
- 상수 `PC_TAPS = 10`, `PC_GAP_MS = 3000`. 변수 `_pcTaps`, `_pcLastTap`(이름에 `_tapCount`·`TAP_THRESHOLD`·`_bindTrigger` 를 쓰지 않는다).
```
누른 것 = e.target.closest('.tab-btn'); 없으면 끝
data-target 이 'ocean-map-section' 이 아니면: _pcTaps = 0; 끝
now = Date.now(); if (now - _pcLastTap > PC_GAP_MS) _pcTaps = 0; _pcLastTap = now; _pcTaps++
_pcTaps < PC_TAPS 면 끝.  _pcTaps = 0
armed 이면: disarm(true)                // 끈다 + 안내
아니고 _canShow() 가 false 면: 끝        // 조용히 아무 일도 없다(휴대폰·태블릿·터치 노트북·좁은 창)
아니면: arm(true)                       // 켠다 + 안내
```
- 「해양종합정보」 탭이 점검으로 막혀 있으면 사람의 누름이 창 단계에서 끊겨(`index2.html:6425-6430`) 세어지지 않는다 → 점검 중에는 못 들어간다(의도. README 에 적는다).

**켜기·끄기·창 크기**
```
arm(toast):    armed = true;  _apply(); toast 면 안내 A
disarm(toast): armed = false; _apply(); toast 면 안내 B
_apply():
  want = armed && _canShow();  if (want === _on) return;  _on = want
  켜질 때: ① window.OceanMenu.close()   ② 처음이면 _build() + window 'resize' 리스너(_apply) 붙임
           ③ document.body.classList.add('pc-mode')   ④ #om-sidebar.setAttribute('aria-hidden','false')
           ⑤ _afterTab()(지금 「특보 및 전망」 화면이 보이는 중이면 전용 지도 준비)
  꺼질 때: ① classList.remove('pc-mode')   ② #om-sidebar.setAttribute('aria-hidden','true')
  둘 다:   _kick() — window.dispatchEvent(new Event('resize')) 를 **0ms 뒤와 400ms 뒤 두 번**
```
- `_kick` 이 두 번인 까닭 **[실측 `q1.js` E1 · `l2/w2.js`]**: 한 번만 보내면 끄거나 좁힌 뒤 `<html>` 의 `--main-tab-height` 가 48px 로 굳는다(실제 탭 줄 67px — `.tab-btn{transition:all .2s}` 도중에 잰다). 둘째 resize 뒤 67px.
- `_kick` 이 보낸 resize 로 `_apply` 가 다시 불려도 `want === _on` 이라 바로 끝난다(되풀이 없음).
- **`<html>` 의 `--main-tab-height` 는 건드리지 않는다.** (그 값을 읽는 JS 세 곳이 `parseFloat(…) || 68` 이라 0 을 줘도 68 로 읽는다 — `shrt_forecast_layer.js:863`·`vsby_forecast_layer.js:531`·`index2_patch.js:817-818`. 영향은 토스트 높이뿐이라 그대로 둔다.)
- 안내는 `window._showOceanToast(글, 'bottom', ms)`(있을 때만):
  - A: 「PC 화면으로 바뀌었습니다 · 새로고침(F5)하면 원래 화면으로 돌아갑니다」 3500
  - B: 「원래 화면으로 돌아왔습니다」 1800
  - 창 크기로 쉬거나 돌아올 때는 안내 없음.
- **나가는 법**: 위 막대 [원래 화면으로] · 같은 탭 다시 10번 · 새로고침. 창을 1200 미만으로 줄이면 `pc-mode` 가 떨어져 평소 화면, 넓히면 다시 붙는다(다시 누를 필요 없음).
- **저장 안 함**: `localStorage`·`sessionStorage`·URL·`history` 에 쓰지 않는다.
- 창구: `window.PcLayout = { isArmed, isOn, arm, disarm }`(시험·점검용).

### 특보 전용 지도 (`pc_alert_map.js`)
- 해양종합정보 지도와 **공유하는 상태가 없다**(그 지도를 만들지 않고, 그 층·저장값·켜짐을 건드리지 않는다) [실측].
- 층은 앱과 같은 4층 구조(부모 색칠 40 · 자식 색칠 41 · 부모 선+이름 80 · 자식 선+이름 81) + 고른 구역 테두리 90. 자식 층에 `minZoom` 없음.
  스타일은 `OceanWarnActive._styleAlways`(켜짐 여부 무관) → `OceanWarnZone.onlyFill` / `onlyStrokeAndText`.
- 특보정보에 처음 들어올 때 만든다(섹션 class 를 보는 관찰자 — [해상일기도]↔[특보 및 전망] 은 `data-active-tab` 이 안 바뀐다). 처음 한 번 구역 전체에 맞춘다(`_fitOnce`).
- 특보 카드(단추·연안·부이 칸 제외)를 누르면 그 해역의 부모 구역으로 이동 — 목록 → 지도 한 방향.
- `weather-alert`·`ov-warn-zone`·`ov-warn-active`·`main-ocean` 중 하나가 점검으로 막히면 구역을 그리지 않고 「특보구역 표시는 점검 중입니다」.

## ⑦ 점검 차단 · 사용량 통계 · 저장값이 새지 않게 하는 규칙
1. **PC 코드는 기존 버튼을 프로그램으로 누르지 않는다**(`.click()` 금지). 버튼이 스스로 저장한다(`ocean_warn_zone.js:537` 등) — 정적 시험 19.
2. **새 단추로 기존 기능을 부르지 않는다.** 설정·제보·로고(새로 받기)·AI 챗봇은 기존 요소 그대로라 점검 차단(`index2.html:6407` — 사람의 누름만 본다)과 집계(`utils.js:328-345`)가 그대로 걸린다. `NariyaChat`(내부 이름)·`openChat`·`openSettingsModal`·`openReportModal` 을 PC 코드에서 부르지 않는다.
3. 새로 만든 단추가 부르는 것은 넷뿐: `switchMainTab('weather-group')`(알약 — 그 함수가 차단을 스스로 본다, `index2_patch.js:272-276`) · `NoticeHub._ptr.refresh()` · 지도 확대·축소 · `disarm`.
4. AI 챗봇·AI 연안 안전 브리핑의 노출 조건을 바꾸지 않는다.
5. 특보 전용 지도는 `weather-alert`·`ov-warn-zone`·`ov-warn-active`·`main-ocean` 중 하나가 막히면 구역을 그리지 않는다. 「해역별 특보현황」 몸통의 `display` 를 덮지 않는다.
6. 새 집계 키를 만들지 않는다.
7. 꺼져 있을 때 0 영향: 페이지가 뜰 때 리스너 하나, 그 밖의 요소·리스너·관찰자는 처음 켤 때.

## ⑫ 사용자에게 알릴 것 / 확인받을 것

**알릴 것**
1. 새로고침(F5)을 누르면 PC 화면이 꺼진다(「껐다 켜면 원래대로」의 결과). 자료는 로고를 누르면 새로 받고(특보정보 화면으로 옮겨 간다), 특보 자료는 5분마다 저절로 새로 받는다(`client/auto_refresh.js:8-13`).
2. AI 챗봇·AI 연안 안전 브리핑은 지금 노출 설정 그대로다 — 꺼져 있으면 PC 화면에도 없다.
3. **터치 화면이 달린 노트북에서는 켜지지 않는다**(「터치 기기는 PC 로 보지 않는다」를 글자 그대로 따랐다). 켜지게 하려면 판정식 한 줄을 풀면 된다.
4. 「지점 창이 열려 있으면 다른 지점 누름을 무시」(종전 합의)는 휴대폰 그대로이고 PC 화면에서만 바로 바뀐다.
5. 「큰 아코디언은 하나만 펼침」(2026-11-19)도 휴대폰 그대로. PC 화면에서는 왼쪽 「해역별 특보현황」이 늘 펼쳐져 있고 오른쪽 세 카드끼리만 하나씩 펼쳐진다.
6. 「해양종합정보」가 점검으로 막혀 있는 동안에는 PC 화면에 들어갈 수 없다.
7. 시안과 달라진 13가지(⑪).
8. PC 와 무관한 기존 결함: 웹에서 뒤로가기를 빠르게 두 번 누르면 같은 페이지 안 이동이 되풀이되고 사이트를 못 떠난다(R_convenience 실측 1,542번 — 총괄은 다시 돌리지 않았다, `core/backbutton.js:779-806`). 「서버 연결 불가」 창이 떠 있을 때 뒤로가기는 새로고침이다.

**확인받을 것**(아래 기본값으로 만들고, 답에 따라 고친다)
- 가. [보기] 화면에서도 오른쪽 칸을 늘 둔다(상세가 가운데 팝업으로 뜨는 화면에서는 빈 안내만 보인다). 그 화면들에서는 칸을 없애 지도를 넓힐지.
- 나. 터치 화면 달린 노트북을 PC 로 볼지(알릴 것 3).
- 다. PC 화면을 켠 횟수를 세는 집계를 넣을지(지금: 넣지 않음).
