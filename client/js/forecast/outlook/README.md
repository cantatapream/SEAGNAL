## 관심 기상청 — 「기상청 해상 기상 전망」 종합 예보 (2026-10-17 사용자 확정)

> 사용자 원문: *"현재 기상청 해상 기상 전망은 최초 앱 설치 시 모든 지방청 단기전망이 모두 나오도록 되어있고 설정 버튼을 통해서 원하는 지방기상청 정보를 수신할 수 있도록 되어있는데 이렇게 하지말고 처음 설치했을 때 기상청 해상 기상 전망 아코디언을 누르면 관심 기상청이 설정되지 않았다는 문구와 함께 아코디언 펼쳐진 화면에 설정하기 버튼이 있는데 그것을 누르면 이렇게 나오도록하고, 여기서 복수로 선택되도록 하는것이 아닌 한개 기상청만 선택할 수 있도록 하자. 그리고 초기화 버튼을 없애고 완료와 취소 버튼을 두도록 하는거야."*
>
> 같은 날 추가 원문(⚙ 자리): *"아코디언에 설정버튼 반영방법은 이미지 5처럼 반영해줘(기상청 해상 기상 전망도 마찬가지로)"* — 이미지 5 = 「🧭 활동지점 안전 브리핑」 머리 오른쪽 끝의 회색 ⚙.

### 옛 기기만 관심해역 기준을 남긴다 (`decideOfficeLegacyZoneFallback`, 2026-10-17 사용자 확정)

> 사용자 원문: *"지금처럼 두자. 그렇지만 새롭게 설정하는 사람, 최초 설치한 사람 등에 대해서는 뜨도록 해야해."*

- 뜻: 이 판 전부터 관심해역을 쓰던 사람은 종합 예보가 갑자기 안내 칸으로 바뀌지 않게 **지금처럼**(관심해역이 가장 많은 지방청) 둔다.
  처음 설치한 사람·새로 설정하는 사람은 관심해역을 골랐더라도(설치 직후 온보딩 포함) **관심 기상청을 고를 때까지 안내 칸 + [설정하기]** 를 본다.
- 표시: `localStorage 'officeLegacyZoneFallback'` — `'1'` 옛 기기 · `'0'` 아님 · 없음 = 아직 안 정함.
- **처음 한 번만 정한다**: 새 판을 처음 연 순간 ①관심 기상청이 없고 ②관심해역이 저장돼 있으면 `'1'`, 아니면 `'0'` 을 저장한다.
  이미 `'1'`·`'0'` 이 있으면 다시 정하지 않는다 — 그래서 새 설치 기기가 나중에 관심해역을 골라도 다음 실행에 옛 기기로 바뀌지 않는다.
- 정한 뒤의 경우:

| 경우 | 결과 |
|---|---|
| 옛 기기가 나중에 관심해역을 모두 지움 | 기댈 관심해역이 없으니 안내 칸. 다시 고르면 관심해역 기준이 돌아온다(표시는 `'1'` 그대로) |
| 옛 기기가 관심 기상청을 고름 | 고른 곳(1순위)이 앞선다 |
| 처음 연 순간 관심 기상청을 이미 골라 둔 기기 | `'0'` — 고른 곳이 늘 앞서므로 기댈 일이 없다 |
| 앱 데이터를 지움 | 표시도 지워지므로 처음 설치와 같다(그 순간 관심해역도 없으니 `'0'`) |
| 저장소를 못 읽음/못 씀 | 못 읽으면 처음 보는 기기로 판정, 못 쓰면 그 판정을 이번 실행에만 쓴다 |

- **순서(2026-10-17 코드로 확인)**: 판정은 `marine_forecast.js` 를 읽는 순간(맨 위, 동기) 한 번 돈다.
  `index2.html` 에서 `settings/settings.js` 가 이 파일보다 앞이라 `UserSettings.init()` 이 이미 저장값을 읽어 둔 상태다.
  관심해역을 저장하는 곳 — `onboarding/zone_setup.js _save`(이 파일보다 뒤에 실림, 「해역별 특보현황」 ⚙ 를 **눌러야** 열림) ·
  `settings.js saveSettingsAndClose`(설정 창 [저장]) — 은 모두 사용자가 눌러야 돈다. 그래서 처음 설치한 기기에서는 온보딩이 관심해역을 저장하기 **전에** `'0'` 으로 정해진다.
  관심해역을 저장하는 `settings/settings.js`·`onboarding/zone_setup.js` 를 싣는 HTML 은 `index2.html` 하나뿐이다(`client` 의 `*.html` grep — 그 페이지에는 이 파일도 실린다). 회귀 시험이 `window.openZoneSetup` 이 달리는 순간의 표시 값을 적어 이 순서를 고정한다.

### 설정 팝업 (`openOfficeSettingsPanel`)

- 여는 곳: 아코디언 **머리 오른쪽 끝 ⚙**(`#regional-office-settings-btn`, 늘 보임 — 종전의 「종합 예보」 칸 ⚙ 를 옮김) · 안내 칸 [설정하기]. 아코디언이 닫혀 있으면 펼친 뒤 맨 위에 띄운다.
- 모양은 종전 팝업(📋 지방청 표시 설정) 그대로, **라디오 7줄(한 곳만)** · [초기화] 없음 · **[취소] / [완료]**. [완료]는 한 곳을 골라야 눌린다.
- [완료] = 저장 → 닫기 → 종합 예보 다시 그림. [취소]·×·Esc·하드웨어 뒤로가기(`PopupStack` `'office-settings-panel'`) = 저장 없이 닫기. ⚙ 를 한 번 더 눌러도 [취소]와 같다.
- 처음 선택 = 지금 화면에 보이는 곳(관심해역에서 고른 곳 포함).

### 저장 (`localStorage 'officeManualSettings'`)

- 꼴은 종전과 같다 `{ "109": false, …, "184": true }` — 이제 [완료]는 **한 곳만 true** 로 저장한다(옛 판 앱이 읽어도 그 한 곳이 보인다).
- 읽는 곳: 이 파일뿐(`getOfficeManualSettings` → `getChosenOfficeCode`). 서버·푸시 구독은 이 값을 쓰지 않는다(2026-10-17 `client`·`local_server` 전체 grep 으로 확인 — station-briefing 문서의 「같은 관례」 언급 2곳만 있음).
- **옛 설정 옮기기**: 여러 곳을 켜 둔 저장값은 **팝업 차례(수도권→부산→광주→강원→대전→대구→제주)에서 가장 앞선 곳 하나**만 쓴다. 읽을 때마다 같은 규칙으로 줄이고 저장값은 [완료] 전까지 그대로 둔다. 전부 꺼 둔 저장값·깨진 값은 「안 고름」으로 본다(빈 화면 대신 안내 칸 또는 관심해역 기준).

## 색칠 AI 고르기 (2026-11-16)
- 해상 기상 전망(초단기·단기 — `local_server/marine_forecast_processor.js`)과 지방청 전망(`local_server/regional_bulletin_collector.js`)의
  `{{loc:}}`·`{{num:}}`·`{{warn:}}` 표시를 붙이는 AI 는 종전 Gemini(`gemini-2.5-flash-lite`) 고정이었다.
- 이제 관리자 → AI → 「AI 모델 설정」의 **③ 해상 기상 전망 색칠** 순서대로 부른다(`services/bulletin_ai.js` 기능 `forecast`).
  기본 순서는 Gemini 만 = 종전 동작. 이미 색칠해 캐시에 둔 전망은 다시 부르지 않으므로 바꾼 순서는 **새로 들어온 전망부터** 적용된다.
- 사용자 확정 원문: *"그렇게 진행하자."* (질문: 해상 기상 전망 색칠 AI 를 어디서 설정하나 → Gemini 고정이라 답하고 관리자 화면에서 고르게 하자고 제안한 것에 대한 답)
- **Gemma (2026-11-19)** — 사용자: *"단기, 초단기, 지방청별 기상전망에 대해 색을 입히고 … Gemma ai를 사용해도 될 것 같은데? 무료니까"* · *"기존 통합관리자센터에서 ai 모델 선택하는데 Gemma 를 추가해야"* ·
  (실제 시험 뒤) *"젬마가 색칠하는 기능을 넣자 격상읽기는 하지말고. 단, 젬마가 색칠할 수 없는 문제, 한도 초과, 서버 붐빔 등 문제가 있다면 그때 내가 선택한 api가 호출하여 색칠하도록 하자."* ·
  *"이미 플라이아이오 시크릿으로 반영된 gemini키인 GEMINI_API_KEY_26_8 로 젬마를 호출하도록 하자."*
  - ③ 색칠 칸 맨 위 **「먼저 Gemma」** 줄 — 쓰지 않음(기본 = 종전 그대로) | `gemma-4-26b-a4b-it` | `gemma-4-31b-it`(Gemini API 가 제공하는 Gemma 두 모델, 같은 키).
  - 고르면 Gemma 가 먼저 색칠하고, **못 하면 아래에 정해 둔 순서대로** 이어서 부른다. 못 함 = 오류·한도 초과(429)·수요 과다(503)·60초 시간 초과·빈 답·JSON 을 못 꺼냄·`categories`/`summary` 없음·
    색 표시 꼴이 깨짐(`{{num:…}for}`)·원문 줄을 빼먹음(날씨해설: 칸마다 글 길이 85% 미만 — `marine_forecast_processor.gemmaKeptText` / 지방청 전망: 글 전체 글자 수가 원문의 97% 미만 — `regional_bulletin_collector.gemmaKeptSummary`).
  - Gemma 는 JSON 모드 없이·「생각 최소」로 부른다(실제 키로 확인 — JSON 모드는 답을 배열로 싸고, 생각 기본은 글 한 편에 2~3분). 공용 Gemini 키의 쿨다운을 건드리지 않는다(`gemini_client.callPlain`).
  - 관리자 화면: 「시험 호출」 버튼 · 마지막 Gemma 결과(날짜·시각, 서버를 올린 뒤 성공·실패 횟수 — 못 해서 다음 AI 가 대신 색칠했으면 붉게).
  - 실측(2026-11-19 날씨해설 4편): 답 꼴은 맞았으나 유의사항 줄을 빼거나 표시 꼴이 깨진 답이 있었고(위 검사로 거른다), Gemini 2~7초에 견줘 16~26초, 연달아 부르면 「수요 과다·한도 초과」가 났다.

## 해상 기상 전망 안쪽 칸 — 「종합 예보」 칸 없앰 · 하나만 펼침 · 기본값 · 요약↔전문 (2026-11-19 사용자 확정)

> *"굳이 종합예보라고 되어있을 필요가 없잖아 ? 어차피 지방기상청은 1개만 선택가능한 것이니. 따라서 종합예보 는 없애고 제주지방기상청 단기전망을 종합 예보 수준으로 올려야해."*
> *"기상청 해상기상전망 아코디언 안에서도 마찬가지로 아코디언이 한개 이상 켜지지 않도록 해주고 또한 기본적으로 지방기상청 단기전망부터 켜지도록 하되, 지방기상청을 선택하지 않은 사람은 초단기전망과 단기전망 중 발표가 최신인것을 먼저 켜지도록 해줘."*
> *"지방기상청 전망에서 전문 보기로 켰을 떄에는 AI 해상기상요약은 접히도록 해줘. … "AI 해상 기상 요약" 부분 헤더는 아코디언으로 만들어야 할 것이야."*
> 질문 답: 기본값은 *"앱을 껏다켰을 때도 기본값부터. 단, 앱을 끄지 않았을 떄에는 마지막으로 펼쳐둔칸 기준"* · 요약↔전문은 「서로 하나만」 · 미설정자 칸 제목 「지방기상청 단기 전망」.

- **한 단계로**: 종전 「종합 예보 (1개 지방청)」 칸 안에 지방청 카드(머리줄 + 본문)가 또 있었다. 이제 `#regional-forecast-section` 칸 머리가 곧 「○○지방기상청 단기 전망 / (발표 시각)」 + 📋 다(`setRegionalHeader` — 종전 카드 머리줄 모양 그대로, 글자 색만 옆 칸과 같게). 본문(기온 · AI 해상 기상 요약 · 전문)은 칸 몸통에 바로 그린다(`renderRegionalForecast`). 관심 기상청이 없거나 자료가 없으면 제목은 「지방기상청 단기 전망」. 지방청 카드용 `window.toggleRegionalOffice` 와 카드 CSS 는 쓸 곳이 없어 지웠다.

- **기본값**(`applyMarineForecastDefaultExpansion`): 앱을 켜고 처음 한 번 — 관심 기상청이 있으면(직접 고름·옛 기기 관심해역 자동 대응 포함, `getRelevantOfficeCodes`) 지방청 칸, 없으면 초단기·단기 중 `reportId` 발표 시각이 최신인 칸(둘 다 모르면 지방청 칸 — 그 안에 [설정하기]). 사용자가 안쪽 칸을 직접 누른 뒤에는 다시 정하지 않는다(그래서 다른 큰 아코디언을 펼쳤다가 돌아와도 마지막 칸 그대로). 값은 메모리에만 있어 앱을 다시 켜면 기본값부터. 관심 기상청 [완료] 뒤에는 지방청 칸을 펼친다. `index2.html` 의 세 칸은 모두 접힌 채 시작한다.
