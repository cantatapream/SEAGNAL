# 해양안전생활 (safety)

하단 메뉴의 **「해양안전생활」** 화면입니다. 예전 「해양생활」 자리를 대체합니다
(2026-09-10 사용자 확정으로 정식 전환 — 그 전까지는 해양생활 탭을 10번 연달아 눌러야

그 자리에서 바꿔치기하던 값 세 가지를 **각 파일의 기본값으로 옮겼습니다.**

## 이 기능은 무엇인가

- 하단 메인탭 이름이 **해양안전생활**으로 바뀝니다.
- 하위탭이 **[해양안전 | 해양생활]** 두 개로 바뀌고, **해양안전이 먼저** 열립니다.
  - **해양안전** — **물빠짐(갯벌 노출 예측)** + **노출암·갯바위 / 간출암 등**(두 버튼,
    동시에 켤 수 있음) 지도. 해양종합정보 지도를 그대로 빌려 쓰되 물빠짐 ·
    노출암 · 간출암 등 · 안내 · 배경지도 · 진북 정렬 · 내 위치만 남기고
    나머지 버튼은 감춥니다. 간출암 등이 켜진 동안엔 서버가 미리 계산해 둔
    **잠김경고**(3시간 이내 잠기는 암초)를 폴링해, 낱개로 보이는 마커에 빨간
    펄스 테두리 + "OO:OO 후 완전히 잠김" 카운트다운을 얹습니다. 여러 마커가 뭉쳐
    보이는 동안에도 그 안에 경고 대상이 있으면 **뭉친 원 둘레가 빨갛게** 됩니다
    (그 안 누구의 시각인지 가릴 수 없어 시각은 안 적습니다).
    마커를 누르면 뜨는 조석 곡선 팝업 아래 "조석" 카드는 고조·저조 옆에 "직전 물때보다
    몇 cm 변했나"를 적는데, 그날 첫 물때의 값은 **어제 마지막 물때**가 있어야 나옵니다 —
    서버가 `prevPeaks` 로 함께 보내 줍니다(2026-09-09 신설).
    여기에 **출입통제**·**낚시금지**·**관제구역**·**항로·해역** 폴리곤 토글도 함께 켤 수 있습니다 —
    **낚시금지**는 낚시 관리 및 육성법 제6조·지자체 조례로 지정된 낚시통제구역
    236곳을 주황색 폴리곤으로 그리고, 탭하면 근거법령·통제시간·대상·벌칙을 팝업으로 보여줍니다.
    **관제구역**은 해양경찰청이 공고한 선박교통관제(VTS)구역 33곳을 인디고색 폴리곤으로
    그리고, 탭하면 관제해역·관제센터 주소·전화·팩스를 팝업으로 보여주면서 **탭한 구역
    하나를 노란 테두리로 하이라이트**합니다(선택 표시 — 다른 구역을 탭하면 옮겨갑니다).
    **항로·해역**은 선박의 입항 및 출항 등에 관한 법률 제10조·해상교통안전법 제30조 등으로
    지정ㆍ고시된 항로 141곳에 한중·한일 어업협정에 따른 국제 해양경계 수역 3곳
    (한중잠정조치수역·한일중간수역·한중과도수역)을 더한 144곳을 그리는데, 항로 141곳은
    마젠타색, 국제 해양경계 수역 3곳은 항로와 헷갈리지 않도록 선홍색으로 구분합니다.
    탭하면 정의·근거·종류·참고문서·참고사이트·담당부서·연락처 중 있는 항목을
    팝업으로 보여줍니다(항로 141곳엔 종류·참고문서·참고사이트만 있습니다).
    면으로 고시된 127곳은 폴리곤(채움+외곽선), 통항분리대처럼
    선으로 고시된 17곳은 선으로 그립니다.
    **항행경보**는 선택한 날짜에 발효 중인 항행경보(선박사고·표류장애물·수중장애물·해상사격훈련
    등)의 구역을 진한 빨간 점선 원형/다각형으로 그립니다. 같은 구역이 시간대만 다르게 여러 번
    나오면(예: 08~18시 사격, 18~24시 사격) 서버가 하나로 합쳐 지도엔 라벨 하나만 그리고,
    탭하면 각 시간대(occurrence)를 구분해서 팝업에 보여줍니다(구역명이 팝업 제목, 이미 끝난
    시간대는 흐리게 + "종료" 표시, 팝업이 길면 세로 스크롤) — 2026-08 사용자 스크린샷으로
    라벨이 겹쳐 뭉개지는 문제를 확인해 도입. 만료된 구역은 라벨을 아예 그리지 않고, 화면에
    활성 구역 라벨이 여럿 겹치면 큰 구역을 우선해(renderOrder) OpenLayers declutter가
    작은 쪽을 자동으로 숨깁니다. 구역이 화면에서 작게 보일 때 탭하면 팝업 대신 그 구역으로
    먼저 확대하고, 충분히 커진 뒤 다시 탭해야 팝업이 뜹니다(fishing_ban.js/seaway.js와
    동일 패턴). 켜면 상단에 **날짜 내비게이션(◀▶)**, 하단에 **기준 시각 슬라이더**가 함께
    뜹니다 — 슬라이더로 시각을 옮기면 그 시각이 지난 구역이 회색으로 바뀌고, 날짜를 넘겨도
    슬라이더 위치는 유지되어 다른 날짜의 임의 시각 상태도 바로 확인할 수 있습니다. 조회 중
    (특히 KHOA 세션 재발급이 섞이면 몇 초 걸림)엔 화면 가운데 로딩 스피너가 뜹니다. 켜면
    실제 지형과 비교하기 쉽도록 배경지도가 **위성지도**로 자동 전환됩니다(끄면 원래대로).
    텍스트(제목/본문/발표기관)는 data.go.kr 공식 API로, 좌표·구역명은 KHOA "항행경보 상황판"
    웹사이트의 내부(미문서화) API로 보강합니다 — 이 내부 API가 막히면 좌표만 빠지고 텍스트
    목록 매칭은 계속 됩니다(부분 실패 허용).
    관제구역·항로·해역 토글은 켤 때 배경지도가 **전자해도**로 자동
    전환됩니다(출입통제·낚시금지는 위성지도로 전환 — 관제구역·항로·해역은 항해 정보라 해도가 맞음).
  - **해양생활** — 기존 6개 활동(바다낚시·서핑·해수욕·스킨스쿠버·갯벌체험·바다갈라짐)을
    화면 **오른쪽 세로 버튼**으로 갈아끼웁니다.
    단, **바다갈라짐**은 표가 넓어 오른쪽 버튼에 가리므로, 이때만 버튼이
    기본맵·안내 아래 **가로 한 줄**로 펼쳐지고 제목 줄도 숨깁니다.
- 배경지도를 해양종합정보와 똑같이 **기본맵 / 전자해도 / 해안도 / 세계지도 / 위성지도** 중에서 고를 수 있습니다.
- **껐다 켜도 이 화면 그대로입니다** — 정식 탭이라 진입 상태를 따로 저장할 필요가 없습니다
  (2026-09-10 전에는 연타로 들어간 상태를 저장하지 않아 새로고침하면 원래 해양생활로 돌아갔습니다).

## 화면에서 찾아가는 법

1. 하단 **해양안전생활** 탭을 누른다 → **해양안전** 화면이 먼저 열린다
2. 하위탭 **해양생활** → 오른쪽 세로 버튼에서 활동 선택
3. **바다낚시**를 다시 한 번 누르면 왼쪽으로 **갯바위 / 선상**이 펼쳐진다
   (해양종합정보의 "천기" 버튼과 같은 방식)
4. 왼쪽 위 **기본맵** 버튼 = 배경지도 선택, **안내** 버튼 = 활동별 유의사항 탭 팝업
5. 오른쪽 버튼 묶음 맨 아래 = **내 위치(GPS)**

집계. **핵심 발견— 감사 자체를 의심(카파시 4번)**: 관할서별 불일치 비율을 보면 대부분 서가 0.4~3.3%대(폴리곤 자체 오차로 설명 가능한 수준)인데 울진(40.6%, 379건 중 154건)·속초(17.9%, 576건 중 103건) 딱 두 서만 압도적으로 높다 — 개별 사고가 그렇게 많이 잘못 기록됐다고 보기보다 **그 두 서의 재구성 폴리곤 자체가 부정확하다는 신호**로 판단(실제로 울진 폴리곤은 신뢰 면이 딱 1개, 학습점 42개뿐으로 다른 서 대비 극히 부실함을 확인). 그래서 울진·속초 관련 불일치는 이번엔 삭제 후보로 안 다루고, 나머지(제주⇄서귀포 등 비율이 낮고 양방향으로 비슷하게 나오는 것들)만 개별 검토 대상으로 좁혀야 한다는 결론. **지도(폴리곤) 수정 + 재분류(2026-08-25)**: 위 의심대로 울진(신뢰 면 1개·순도 0.619·n=42)·속초(서남쪽 경계가 실제보다 북쪽으로 짧게 그려짐) 폴리곤 모두 결함 확인, 법령 원문 도분초 좌표로 재구성해 `coastguard_jurisdiction_faces.json` 교체(울진 순도 0.916·n=403, 속초 순도 0.992·n=384 — 속초는 강릉존 북쪽 조각을 별면으로 추가해 2025-03-31 강릉 개서 이전 주문진 실측 관할까지 반영). 재감사 결과 울진 40.6%→1.6%, 속초 17.9%→0.0%(잔여 59건은 확실한 오분류로 판단해 삭제, 대부분 원양 사고). 이 폴리곤으로 관할서를 "추정"해 채웠던 심판원 통합행(2016 복원 전체+2025 단독 전체, 5,108건)도 `reclassify_after_polygon_fix.js`로 재분류(114건 orgCd 변경). **관할서 불일치 검수 레이어 신설(사고정보 20회 연타)**: 남은 419건(제주⇄서귀포·부산⇄울산 등)은 자동 삭제 대신 사람이 직접 지도에서 보고 고르도록, 심판원 검수 레이어(15회) 다음 단계로 추가 — 검수 서브모드가 5회 연타마다 꺼짐→심판원→관할서불일치 3단 순환(모드 전환마다 토스트 안내), `build_jurisdiction_boundaries.js`가 내보낸 21개 서 경계 폴리곤을 색상별 외곽선으로 그리고(`coastguard_jurisdiction_boundaries.json`), `build_jurisdiction_mismatch_review.js`가 내보낸 "확실한" 불일치 후보(`accident_jurisdiction_mismatch.json`)를 낱개 마커로 찍는다. 마커 클릭 시 팝업에 21개 관할서 버튼(기록됨=주황·폴리곤판정=초록 테두리)이 뜨고 고른 서가 빨간 배경으로 표시되며 검수 패널 선택 목록에 쌓인다 — "선택만 모아뒀다가 일괄 반영"(사용자 확정) 방식이라 내보내기 JSON(`{"jurisdiction":[{"idx","chosen"}]}`)을 `apply_jurisdiction_review.js`가 나중에 한 번에 `accident_ships_hk.json`의 orgCd 에 반영한다(아직 실행 전 — 실제 검수가 끝나야 돌림). **심판원 데이터 검수모드 제거(2026-09-01)**: 위 심판원 검수 레이어(`build_tribunal_review.js`·`accident_tribunal_review.json`·`TRIBUNAL_REVIEW_ON` 등)는 선박사고 전면 재구축(원본 CSV+라이브 데이터 서브미터 정밀도 대조로 좌표파싱 검증 완료, 병합여부 비교는 사건번호 필드 자체가 없어져 못 씀)으로 필요 없어져 사용자 확정으로 삭제했다. 검수 서브모드는 4단(꺼짐→심판원→관할서불일치→카카오지오코딩→꺼짐)에서 3단(꺼짐→관할서불일치→카카오지오코딩→꺼짐)으로 줄었다. |

## 설계 요점 — 기존 코드를 고치지 않고 재사용

활동별 지도·마커·바텀시트 로직은 **기존 파일(fishing.js / surfing*.js / scuba.js /
mudflat.js / sea_parting.js / swimming.js)을 그대로 씁니다.** 이 모듈은 겉껍데기(크롬)만 새로 얹습니다.

- **활동 전환** — 기존 `window.switchSubTab(섹션id)` 를 그대로 호출합니다.
  그래서 지도 초기화·사용량 집계 등 기존 동작이 전부 유지됩니다.
  숨겨진 하위탭 버튼(`.ls-hidden-sub`)을 남겨 둔 이유도 `switchSubTab` 이
  "같은 그룹의 다른 섹션 끄기" 를 할 수 있게 하기 위함입니다.
- **내 위치 / 갯바위·선상** — 새 버튼이 **기존 버튼을 대신 눌러 줍니다**(`.click()`).
  GPS 로직·마커 재렌더링 로직을 복사하지 않습니다.
- **배경지도** — 활동 지도에 해아름 WMS 레이어 3장을 끼워 넣고
  원래 있던 OSM 타일을 "세계지도" 선택지로 씁니다.
  레이어 생성은 `ocean_map.js` 의 `window.oceanCreateKhoaLayer` 를 재사용합니다.
- **"지도 하나처럼"** — 활동마다 지도 인스턴스는 따로지만, 활동을 바꿀 때
  직전 지도의 중심·줌을 그대로 넘겨받아 한 장의 지도를 계속 보는 것처럼 동작합니다.
- **버튼 크기 고정** — 우측 활동 버튼은 `px` 로만 크기를 정한다(54×42, 글자 13px).
  설정의 글자크기를 바꿔도 버튼이 커지지 않아야 하기 때문. 13px 은 해양종합정보
  우측 버튼이 "크게" 설정일 때의 글자 크기(0.7rem)와 같은 값이다.
  긴 이름은 `<span>` 두 개로 나눠 두 줄로 넣는다(스킨/스쿠버, 바다/갈라짐).
  **주의**: `style.css` 가 인라인 `<style>` 보다 뒤에 로드되므로, `.ocean-overlay-btn`
  의 `width:38px` 을 이기려면 선택자에 `#ls-rail` 을 붙여 우선순위를 올려야 한다.
- **발표 시각** — 활동 화면의 제목 줄은 숨기고, 우측 버튼을 누를 때
  `window._showOceanToast` 로 발표 시각을 알린다(해양종합정보와 같은 위치·모양).
- **해양안전(물빠짐)** — `tide_field.js` 는 지도 한 개·DOM id 한 벌에 묶여 있는
  단일 인스턴스 모듈이라, 지도를 새로 만들면 슬라이더·범례·팝업·"확대하세요" 안내가
  전부 따라오지 못합니다. 그래서 **해양종합정보 지도 섹션(`#ocean-map-section`)을
  그대로 켜서** 쓰고, `body.ls-safety` CSS 로 필요 없는 버튼만 감춥니다.
  `#ocean-safety-section` 은 하위탭 전환용 자리표시일 뿐 실제로 보이지 않습니다.
  진짜 해양종합정보 탭과의 구분은 `body[data-active-tab]` 값으로 합니다.
  안내(ⓘ)는 해양종합정보의 17탭 팝업이 뜨지 않도록 `document` 캡처 단계에서 가로채,
  이 화면에 있는 기능(물빠짐·노출암/간출암·CCTV) 3개만 해양종합정보와 같은 탭형 팝업으로
  보여줍니다(`_buildSafetyInfoHtml()` — `window.oceanInfoTabHtml(id)`로 탭 본문을
  가져와 `.ocean-info-tabs`/`.ocean-info-panel` 구조로 재구성, 한 번에 한 탭만 표시).

## 해양종합정보와 상태 분리

해양안전은 해양종합정보 지도를 **빌려 쓰기** 때문에, 아무것도 안 하면 그쪽에서 켜 둔
오버레이(특보구역 선·해구도 격자 등)가 그대로 따라옵니다. 그래서:

- **들어올 때** 켜져 있던 오버레이 버튼을 모두 끄고 그 목록을 기억합니다(`_suspendOceanOverlays`).
- **진짜 해양종합정보 탭으로 갈 때** 그 목록을 되살립니다(`_restoreOceanOverlays`).
  활동 화면으로 넘어갈 때가 아니라 그 탭에 들어갈 때 복원하는 이유는, 활동 화면에
  "특보구역은 참고용…" 같은 엉뚱한 안내 토스트가 뜨는 것을 막기 위해서입니다.
- 버튼을 프로그램으로 누르는 동안에는 `_silently()` 로 토스트를 잠시 막습니다
  (사용자가 직접 누른 게 아니므로).

## 지점 팝업(바텀시트)과 우측 레일

지점 팝업은 활동 섹션(`position:fixed; z-index:50`) **안**에 있어서, 자기 `z-index:999`
가 그 섹션 안에서만 유효합니다. 바깥에 떠 있는 레일(`z-index:60`)을 넘어설 수 없어
닫기 버튼이 레일 버튼에 가렸습니다. → 팝업이 열려 있는 동안에는 레일을 감춥니다
(`body.ls-sheet-open`, `_watchBottomSheets()`). 섹션의 z-index 를 흔드는 것보다 안전합니다.

## 물빠짐 화면의 하단 스택

시간 슬라이더·범례·출처표기(국립해양조사원/OpenStreetMap)가 서로 겹치지 않도록
아래에서 위로 **[하단탭(+서브탭) / 슬라이더 / 출처표기 / 범례]** 순으로 쌓습니다.
세 요소를 `position: fixed` 로 바꾸고 `--ls-bottom-chrome` 하나로 계산하는데,
원래 기준 박스(`#ocean-map-wrapper`)가 서브탭 열림 여부에 따라 화면 끝까지 늘어났다
줄었다 해서 기준이 일정하지 않기 때문입니다.

## 배포 시 주의 — 서비스워커 캐시

`sw.js` 는 `/index2.html` 만 캐시 제외이고 **JS 파일은 stale-while-revalidate 로 캐시**합니다.
그래서 기존 JS 파일을 고쳐 배포하면 사용자는 **새 HTML + 옛 JS** 조합을 한 번 받게 되어
기능이 반쯤 동작하는 상태가 됩니다(실제로 배경지도 전환이 먹통이 된 원인).
**기존 JS 를 수정했으면 `index2.html` 의 `<script src>` 에 `?v=…` 를 새로 붙이거나 값을 바꿔서**
캐시 키를 갈아 끼우세요. (`sw.js` 의 `CACHE_VERSION` 은 `__CACHE_VERSION__` 자리표시자
그대로라 배포해도 옛 캐시가 지워지지 않습니다.)

## 수정 시 주의사항

- **로드 순서 고정** — `index2_patch.js` 보다 먼저 로드되면 탭 전환 후처리가 동작하지 않습니다.
- **글자크기 설정과 무관** — 활동 버튼 크기(`--ls-rail-w` = 54px, 글자 13px)는 px 고정입니다.
  `rem` 으로 바꾸면 "크게" 설정에서 버튼이 같이 커집니다(사용자가 원치 않음).
- **지도 없는 활동**(바다갈라짐)은 기존 UI 를 그대로 두고 CSS 로만 조정합니다.
  버튼을 위로 올린 가로 배치(`body.ls-row`)라 `padding-top` 만 줍니다.
  해수욕은 이제 스킨스쿠버와 동일한 지도형이라(`swimming.js`) 다른 지도 활동들과
  같은 방식(우측 레일이 fixed 오버레이로 뜸)으로 동작하며 별도 padding 보정이 없습니다.
- 이안류(`ripcurrent-section`)는 현재 하위탭에서도 숨김 상태라 레일에도 넣지 않았습니다.
