# 해양안전생활 (safety)

해양생활 탭을 **10번 연달아 누르면** 열리는 시험용 화면입니다.
지금은 트리거로만 들어가지만, 나중에 기존 해양생활 화면을 대체할 자리입니다.

## 이 기능은 무엇인가

- 하단 메인탭 이름이 **해양안전생활**으로 바뀝니다.
- 하위탭이 **[해양안전 | 해양생활]** 두 개로 바뀌고, **해양안전이 먼저** 열립니다.
  - **해양안전** — **물빠짐(갯벌 노출 예측)** + **노출암 / 간출암 등**(두 버튼,
    동시에 켤 수 있음) 지도. 해양종합정보 지도를 그대로 빌려 쓰되 물빠짐 ·
    노출암 · 간출암 등 · 안내 · 배경지도 · 진북 정렬 · 내 위치만 남기고
    나머지 버튼은 감춥니다. 간출암 등이 켜진 동안엔 서버가 미리 계산해 둔
    **잠김경고**(3시간 이내 잠기는 암초)를 폴링해, 낱개로 보이는 마커에 빨간
    펄스 테두리 + "OO:OO 후 완전히 잠김" 카운트다운을 얹습니다.
    여기에 **출입통제**·**낚시금지**·**관제구역**·**항로·해역** 폴리곤 토글도 함께 켤 수 있습니다 —
    **낚시금지**는 낚시 관리 및 육성법 제6조·지자체 조례로 지정된 낚시통제구역
    236곳을 주황색 폴리곤으로 그리고, 탭하면 근거법령·통제시간·대상·벌칙을 팝업으로 보여줍니다.
    **관제구역**은 해양경찰청이 공고한 선박교통관제(VTS)구역 34곳을 인디고색 폴리곤으로
    그리고, 탭하면 관제해역·관제센터 주소·전화·팩스를 팝업으로 보여주면서 **탭한 구역
    하나를 노란 테두리로 하이라이트**합니다(선택 표시 — 다른 구역을 탭하면 옮겨갑니다).
    **항로·해역**은 선박의 입항 및 출항 등에 관한 법률 제10조·해상교통안전법 제30조 등으로
    지정ㆍ고시된 항로 141곳에 한중·한일 어업협정에 따른 국제 해양경계 수역 3곳
    (한중잠정조치수역·한일중간수역·한중과도수역)을 더한 144곳을 그리는데, 항로 141곳은
    마젠타색, 국제 해양경계 수역 3곳은 항로와 헷갈리지 않도록 선홍색으로 구분합니다.
    탭하면 정의·근거·종류·참고문서·참고사이트·담당부서·연락처 중 있는 항목을
    팝업으로 보여줍니다(항로 141곳엔 종류·참고문서·참고사이트만 있습니다).
    면으로 고시된 127곳은 폴리곤(채움+외곽선), 통항분리대처럼
    선으로 고시된 17곳은 선으로 그립니다.
    **항행경보**는 선택한 날짜에 발효 중인 항행경보(선박사고·표류장애물·수중장애물·해상사격훈련
    등)의 구역을 진한 빨간 점선 원형/다각형으로 그립니다. 같은 구역이 시간대만 다르게 여러 번
    나오면(예: 08~18시 사격, 18~24시 사격) 서버가 하나로 합쳐 지도엔 라벨 하나만 그리고,
    탭하면 각 시간대(occurrence)를 구분해서 팝업에 보여줍니다(구역명이 팝업 제목, 이미 끝난
    시간대는 흐리게 + "종료" 표시, 팝업이 길면 세로 스크롤) — 2026-08 사용자 스크린샷으로
    라벨이 겹쳐 뭉개지는 문제를 확인해 도입. 만료된 구역은 라벨을 아예 그리지 않고, 화면에
    활성 구역 라벨이 여럿 겹치면 큰 구역을 우선해(renderOrder) OpenLayers declutter가
    작은 쪽을 자동으로 숨깁니다. 구역이 화면에서 작게 보일 때 탭하면 팝업 대신 그 구역으로
    먼저 확대하고, 충분히 커진 뒤 다시 탭해야 팝업이 뜹니다(fishing_ban.js/seaway.js와
    동일 패턴). 켜면 상단에 **날짜 내비게이션(◀▶)**, 하단에 **기준 시각 슬라이더**가 함께
    뜹니다 — 슬라이더로 시각을 옮기면 그 시각이 지난 구역이 회색으로 바뀌고, 날짜를 넘겨도
    슬라이더 위치는 유지되어 다른 날짜의 임의 시각 상태도 바로 확인할 수 있습니다. 조회 중
    (특히 KHOA 세션 재발급이 섞이면 몇 초 걸림)엔 화면 가운데 로딩 스피너가 뜹니다. 켜면
    실제 지형과 비교하기 쉽도록 배경지도가 **위성지도**로 자동 전환됩니다(끄면 원래대로).
    텍스트(제목/본문/발표기관)는 data.go.kr 공식 API로, 좌표·구역명은 KHOA "항행경보 상황판"
    웹사이트의 내부(미문서화) API로 보강합니다 — 이 내부 API가 막히면 좌표만 빠지고 텍스트
    목록 매칭은 계속 됩니다(부분 실패 허용).
    관제구역·항로·해역 토글은 켤 때 배경지도가 **전자해도**로 자동
    전환됩니다(출입통제·낚시금지는 위성지도로 전환 — 관제구역·항로·해역은 항해 정보라 해도가 맞음).
  - **해양생활** — 기존 6개 활동(바다낚시·서핑·해수욕·스킨스쿠버·갯벌체험·바다갈라짐)을
    화면 **오른쪽 세로 버튼**으로 갈아끼웁니다.
    단, **바다갈라짐**은 표가 넓어 오른쪽 버튼에 가리므로, 이때만 버튼이
    기본맵·안내 아래 **가로 한 줄**로 펼쳐지고 제목 줄도 숨깁니다.
- 배경지도를 해양종합정보와 똑같이 **기본맵 / 전자해도 / 해안도 / 세계지도 / 위성지도** 중에서 고를 수 있습니다.
- **껐다 켜면(새로고침) 원래 해양생활 화면으로 돌아옵니다.** 저장(localStorage)을 하지 않기 때문입니다.

## 화면에서 찾아가는 법

1. 하단 **해양생활** 탭을 3초 안에 10번 누른다 → 해양안전생활 화면 진입(해양안전 먼저)
2. 하위탭 **해양생활** → 오른쪽 세로 버튼에서 활동 선택
3. **바다낚시**를 다시 한 번 누르면 왼쪽으로 **갯바위 / 선상**이 펼쳐진다
   (해양종합정보의 "천기" 버튼과 같은 방식)
4. 왼쪽 위 **기본맵** 버튼 = 배경지도 선택, **안내** 버튼 = 활동별 유의사항 탭 팝업
5. 오른쪽 버튼 묶음 맨 아래 = **내 위치(GPS)**

## 파일 구성

| 파일 | 역할 |
|------|------|
| `life_safety.js` | 진입 트리거, 하위탭 교체, 우측 활동 레일, 배경지도 피커, 안내 팝업, GPS·갯바위/선상 연결 |
| `hazard_rocks.js` | 노출암/간출암 등 토글 레이어(독립 2개, 클러스터 표시) + 클릭 시 종류·수치 말풍선 (해양안전 전용) |
| `access_control.js` | 출입통제구역(연안사고 예방에 관한 법률 제10조) 폴리곤 토글 레이어(해양안전 전용) — 각 해양경찰서 고시·공고 원문에서 경위도가 온전히 확인된 구역만 반영, `/access_control_zones.json`(정적, 지연 로드), 클릭 시 관할서·구역명·상태 토스트 |
| `fishing_ban.js` | 낚시금지(낚시통제)구역 폴리곤 토글 레이어(해양안전 전용) — 낚시 관리 및 육성법 제6조·지자체 조례 지정 236개 구역, `/fishing_ban_zones.json`(정적, 지연 로드), 클릭 시 근거법령·통제시간·벌칙 등 상세 팝업(구역이 화면에서 90px 미만으로 작으면 팝업 대신 그 구역 범위로 먼저 자동 확대 — 라벨만 보이는 줌아웃 상태 대응) |
| `vts_zone.js` | 선박교통관제(VTS)구역 폴리곤 토글 레이어(해양안전 전용) — 해양경찰청 공고 33개 구역, `/vts_zones.json`(정적, 지연 로드), 켤 때 배경지도를 전자해도로 자동 전환. 폴리곤을 처음 탭하면 연보라 선택 하이라이트만(한 번에 하나), 같은 구역을 한 번 더 탭하면 관제해역·관제센터 주소·전화·팩스 상세 팝업(구역이 화면에서 90px 미만으로 작으면 선택·팝업 대신 그 구역 범위로 먼저 자동 확대 — 라벨만 보이는 줌아웃 상태 대응) |
| `seaway.js` | 항로·해역 토글 레이어(해양안전 전용) — 선박의 입항 및 출항 등에 관한 법률 제10조 등 지정ㆍ고시 항로 141곳 + 한중·한일 어업협정에 따른 국제 해양경계 수역 3곳 = 144곳(면 127 + 선 17), `/seaway_zones.json`(정적, 지연 로드), 켤 때 배경지도를 전자해도로 자동 전환, 클릭 시 정의·근거·종류·참고문서·참고사이트·담당부서·연락처 중 있는 항목만 상세 팝업(항로가 화면에서 90px 미만으로 작으면 팝업 대신 그 항로 범위로 먼저 자동 확대 — 라벨만 보이는 줌아웃 상태 대응). 선(통항분리대) 17곳은 원본 이름이 폴리곤 항로와 겹쳐 화면엔 전부 "통항분리대"로 통일(항로 이름보다 작은 글씨), 같은 이름의 조각이 여럿이어도 라벨은 하나만 표시(`_markDuplicateLabels`). 직사각형·완만하게 굽은 다각형 항로는 옆면만 점선 + 입출구 변은 선 없음, 국제 해양경계 수역도 점선(한중과도수역만 더 옅은 선홍)으로 그린다. |
| `navigational_warning.js` | 항행경보 구역 토글 레이어(해양안전 전용) — 선택 날짜의 선박사고·표류장애물·수중장애물·해상사격훈련 등 구역을 원형/다각형으로 표시(`GET /api/navigational-warning/list?date=`, 서버가 같은 구역명끼리 병합해 응답, 날짜별 30분 캐시), 날짜 내비게이션 + 기준 시각 슬라이더(만료 구역 회색 처리 + 라벨 숨김), 활성 구역만 라벨 표시(큰 구역 우선 + declutter로 겹침 자동 회피), 작은 구역은 탭하면 먼저 확대 후 재탭 시 팝업, 조회 중 로딩 스피너, 켜면 배경지도가 위성지도로 자동 전환, 클릭 시 구역의 각 시간대(occurrence)를 구분해 팝업 표시(만료된 시간대는 흐리게 + "종료", 스크롤 가능) |
| `accident_info.js` | 사고정보 토글 레이어(해양안전 전용) — 클릭하면 왼쪽으로 선박(해경)·선박(심판원)·인명 3개 소스 버튼(천기 팝아웃과 같은 개별 아이콘 버튼)이 뜨고, 고르면 팝아웃이 접히며 데이터가 켜지고 배경지도가 위성지도로 자동 전환된다(access_control.js 등과 같은 패턴). 켜진 상태에서 사고정보 버튼을 다시 누르면 전부 끄고 배경지도를 원래대로 되돌린다. **현황**(개별 사고 마커, `hazard_rocks.js`와 같은 줌 기반 클러스터, 클러스터 뭉치는 거리는 건수가 많아 100px로 hazard_rocks.js보다 넓게 잡음)/**분석**(현재 화면을 6×5 격자로 나눠 격자별 건수를 노랑→빨강 색상+숫자로 표시, 격자 클릭 시 연도별·주야간별·사고발생상세 통계 바텀시트) 토글은 사고정보가 켜진 동안만 좌측 상단(`#ocean-topleft-controls`, 해양안전 화면이 빌려 쓰는 해양종합정보 기본맵·안내 버튼 바로 아래)에 나온다(사용자 확정 2026-08-19, 이전엔 소스 선택 팝아웃 안에 있었음). 낱개 마커는 사고유형별 이미지 아이콘(`shared/utils/accident_codes.js`의 `ACCIDENT_TYPE_ICONS`, `client/images/accident_markers/*.png`, hazard_rocks.js와 같은 120px 캔버스 방식), 여러 건이 뭉친 클러스터는 그 안에서 **가장 많은 사고유형의 이미지**를 대표로, 숫자는 999+로 뭉개지 않고 실제 건수를 그대로 보여준다(hazard_rocks.js는 "켜진 버튼" 기준·999+ 표시라 둘 다 다름). 대응 이미지가 없는 사고유형 중 선체결함·속구손상·시설물손상·조난은 지도에서 아예 제외(`ACCIDENT_TYPE_EXCLUDED`), 인명사상은 응급환자 그림, 표류(선박)는 익수자 그림으로 대체 표시한다(사용자 확정 2026-08-18). 데이터는 `/accident_ships_hk.json`·`/accident_ships_hs.json`·`/accident_persons.json`(정적, 소스 버튼 첫 클릭 때 지연 로드) — `local_server/scripts/build_accidents.js`가 국립해양조사원 개방海 원본 CSV(레포엔 없음)로 생성. 코드값→한글 라벨은 `shared/utils/accident_codes.js`. 선박(심판원) CSV엔 발생원인·선박종류 컬럼이 없어 "사고발생상세" 두 번째 탭을 해역별로 대체했고, 인명 CSV엔 발생시각 컬럼이 없어 주/야간 통계를 생략한다(둘 다 실제 원본 컬럼 유무에 따른 제약). **좌표 이상치 필터**: 원본 좌표(ORGNL_XCDNT/YCDNT) 자체에 개별 오류가 소수 섞여 있다(좌표 변환 로직 문제가 아니라 원본 데이터 오류로 확인). `ensureRawFeatures`가 같은 "사고발생위치" 텍스트를 가진 행들의 좌표 중앙값과 비교해 0.3도(≈33km) 이상 벗어난 행을 지도에서 제외한다(사용자 확정 2026-08-20, 실측 hk 42,583건 중 55건·person 21,894건 중 70건 제외). 선박(심판원)은 이 위치텍스트 컬럼이 원본에 없어 필터를 적용하지 못한다(그대로 노출). **위치 미상 뭉침 필터**: 위치텍스트가 완전히 빈 값인 사고들이 관할 해양경찰서의 대표 좌표(청사 근처, 대개 육지)로 채워져 완전히 동일한 좌표를 갖고 있어(hk 최대 30건 겹침), 최대 줌으로 확대해도 클러스터가 안 갈라지고 육지에 무더기로 표출되는 원인이었다. 위치텍스트가 없는 행 중 완전 동일 좌표가 3건 이상이면 실제 사고 위치가 아니라고 보고 제외한다(`findMissingLocationClusters`, 사용자 확정 2026-08-20, 실측 hk 606건 제외). **클러스터 대표점**: `ol.source.Cluster` 기본값(멤버 평균 좌표)이 굴곡진 해안선(특히 서해)에서 육지(반도) 한가운데로 계산되는 게 "육지 표출"의 주된 원인이었다(실측: 태안 인근 사고 5,545건의 평균좌표가 육지 판정). `createCluster` 콜백(`createClusterAtRealPoint`)으로 평균 대신 멤버 중 하나의 실제 좌표를 대표점으로 쓴다. **위도 ±1도 오타 보정**: 원본 데이터베이스 자체의 입력 오타(예: "거제도" 관련 사고가 위도만 1도 높게 찍혀 내륙에 표출)를 시군구 지명 참조표+육지마스크 이중검증으로 34건(hk 24·person 10) 찾아 `LAT_OFFSET_FIXES`로 보정한다 — khoa.go.kr 개방海 실제 API(`selectListCluster.json`) 좌표와 100% 일치 확인해 원본 DB의 오타임을 검증했다(API를 다시 받아도 그대로라 재수집은 의미 없음). **범위 밖 좌표 제외**: 원본 CSV에 대만·뉴질랜드·경도 0(대서양)처럼 명백히 한국과 무관한 좌표가 소수 섞여 있어(`build_accidents.js`의 `isPlausibleLatLon`이 "물리적으로 가능한 위경도"만 검사해 전 세계를 다 통과시킴) 대한민국 근해 범위(위도 24~44·경도 118~144) 밖은 제외한다(`isOutOfKoreaBounds`, hk 13건·hs 130건). 참고: `ocean_overlay.js`의 기존 육지 마스크(`/api/ocean/land-mask`)는 국소적 오차가 있어(해안선 근처 일부 지점 부정확, 서울시청·태평양 등 명백한 지점은 정확) 단독 필터링 근거로는 안 쓰고 위도±1 오타 후보를 좁히는 이중검증에만 썼다. **정수도 좌표 + 육지판정 필터(2026-08-20 3차 재조사)**: 원본 위치가 "OO-00N, OO-00E"처럼 도(度) 단위로만 기록된 저정밀 좌표(예: 양양군 사고 4건이 정확히 `[38,128]`로 겹침 — 강원 산악 내륙 클러스터의 원인)가 소수 있었다. 서해안은 해안이 완만해 1도 반올림이어도 우연히 바다 근처에 남지만, 강원 동해안은 해안선 바로 뒤가 태백산맥이라 산속에 놓인다. `isIntegerDegreeCoord`(위경도 둘 다 정수) + `isLandPoint`(land-mask 재사용)로 "정수도 좌표"에만 좁혀 적용(전체 좌표에 적용하면 해안가 실제 사고까지 16% 오탐 제외됨, 실측). `ensureLandMask()`가 `/api/ocean/land-mask`를 최초 1회 fetch해 캐시. **개별 좌표 오류 4건**: 위 필터들로도 못 잡는 개별 기록(hk 2건 "OO 동방 N해리" 텍스트인데 좌표는 반대로 산속 · person 2건 통영시 사고인데 좌표가 강원권 3도 이상 어긋남)은 `KNOWN_BAD_COORDS`로 하드코딩 제외했다(정확한 값을 추정할 근거가 없어 이상치와 같은 원칙으로 제외). **완도군→필리핀 근처 표출 재확인**: 재조사 결과 해당 레코드(위도 4.08333, 원래 34가 와야 할 자리에 첫 자리 숫자가 빠진 것으로 추정)는 기존 `isOutOfKoreaBounds`(latMin 24)로 이미 걸러지고 있었다 — 코드·서버가 실제로 서빙하는 바이트까지 대조 확인. `accident_info.js`가 지금까지 `index2.html`에 `?v=` 캐시버스터 없이 걸려 있었던 것(위 "배포 시 주의" 참고)이 "머지했는데도 반영이 안 됐다"는 반복 보고의 실제 원인이었을 가능성이 있어, 이번에 처음으로 `?v=LandFilterFix_20260820`을 붙였다. **검수 모드(`?debug=review`, 2026-08-20 추가)**: 사용자가 별도 검수 웹페이지(Artifact)를 만들어봤으나 실제 위성지도 타일은 그 환경 자체가 외부망 접속을 막고 있어 못 띄운다는 한계가 있어, 실제 앱 화면(실제 위성지도·실제 마커 이미지) 그대로 검수하고 싶다는 요청으로 추가한 개발자 전용 기능. URL 에 이 쿼리가 있을 때만 하단 중앙에 작은 패널(선택 수·전체 해제·내보내기)이 뜬다(일반 사용자에겐 노출 안 됨, 우측 세로 버튼 레일·하단 탭바와 안 겹치게 위치). 낱개 마커를 클릭하면 기존 상세 팝업이 그대로 뜨면서(무슨 사고인지 보고 판단하도록) 빨간 테두리 선택이 토글되어 패널 목록에 쌓인다. 뭉친 클러스터를 클릭하면 기존과 동일하게 그 범위로 확대만 될 뿐 선택되지 않는다 — 여러 건이 한 픽셀에 뭉쳐 있을 때 실수로 정상 데이터까지 통째로 선택되는 걸 막기 위함(사용자 확정 2026-08-20). "내보내기"는 `{hk:[origIndex,...], hs:[...], person:[...]}` 형식 JSON(원본 rows 배열 안의 위치)을 텍스트 상자에 채운다. 참고로 `hazard_rocks_isolation.js`가 쓰는 정밀 해안선 격자(`local_server/data/tide_field/coastline_cells.json`, KHOA 전자해도 실측)로 "해안선에서 먼데 육지 판정"을 자동 선별해봤으나, 울릉도·독도가 이 데이터에 없고 한강 등 하천은 애초에 대상 밖이라 오탐이 압도적으로 많아(500m~50km 범위를 전수 확인해도 새로 걸리는 진짜 이상 마커가 없었음) 자동 1차 선별로는 채택하지 않았다 — 검수 모드로 사람이 직접 보는 방식이 낫다고 결론. |

## 설계 요점 — 기존 코드를 고치지 않고 재사용

활동별 지도·마커·바텀시트 로직은 **기존 파일(fishing.js / surfing*.js / scuba.js /
mudflat.js / sea_parting.js / swimming.js)을 그대로 씁니다.** 이 모듈은 겉껍데기(크롬)만 새로 얹습니다.

- **활동 전환** — 기존 `window.switchSubTab(섹션id)` 를 그대로 호출합니다.
  그래서 지도 초기화·사용량 집계 등 기존 동작이 전부 유지됩니다.
  숨겨진 하위탭 버튼(`.ls-hidden-sub`)을 남겨 둔 이유도 `switchSubTab` 이
  "같은 그룹의 다른 섹션 끄기" 를 할 수 있게 하기 위함입니다.
- **내 위치 / 갯바위·선상** — 새 버튼이 **기존 버튼을 대신 눌러 줍니다**(`.click()`).
  GPS 로직·마커 재렌더링 로직을 복사하지 않습니다.
- **배경지도** — 활동 지도에 해아름 WMS 레이어 3장을 끼워 넣고
  원래 있던 OSM 타일을 "세계지도" 선택지로 씁니다.
  레이어 생성은 `ocean_map.js` 의 `window.oceanCreateKhoaLayer` 를 재사용합니다.
- **"지도 하나처럼"** — 활동마다 지도 인스턴스는 따로지만, 활동을 바꿀 때
  직전 지도의 중심·줌을 그대로 넘겨받아 한 장의 지도를 계속 보는 것처럼 동작합니다.
- **버튼 크기 고정** — 우측 활동 버튼은 `px` 로만 크기를 정한다(54×42, 글자 13px).
  설정의 글자크기를 바꿔도 버튼이 커지지 않아야 하기 때문. 13px 은 해양종합정보
  우측 버튼이 "크게" 설정일 때의 글자 크기(0.7rem)와 같은 값이다.
  긴 이름은 `<span>` 두 개로 나눠 두 줄로 넣는다(스킨/스쿠버, 바다/갈라짐).
  **주의**: `style.css` 가 인라인 `<style>` 보다 뒤에 로드되므로, `.ocean-overlay-btn`
  의 `width:38px` 을 이기려면 선택자에 `#ls-rail` 을 붙여 우선순위를 올려야 한다.
- **발표 시각** — 활동 화면의 제목 줄은 숨기고, 우측 버튼을 누를 때
  `window._showOceanToast` 로 발표 시각을 알린다(해양종합정보와 같은 위치·모양).
- **해양안전(물빠짐)** — `tide_field.js` 는 지도 한 개·DOM id 한 벌에 묶여 있는
  단일 인스턴스 모듈이라, 지도를 새로 만들면 슬라이더·범례·팝업·"확대하세요" 안내가
  전부 따라오지 못합니다. 그래서 **해양종합정보 지도 섹션(`#ocean-map-section`)을
  그대로 켜서** 쓰고, `body.ls-safety` CSS 로 필요 없는 버튼만 감춥니다.
  `#ocean-safety-section` 은 하위탭 전환용 자리표시일 뿐 실제로 보이지 않습니다.
  진짜 해양종합정보 탭과의 구분은 `body[data-active-tab]` 값으로 합니다.
  안내(ⓘ)는 해양종합정보의 17탭 팝업이 뜨지 않도록 `document` 캡처 단계에서 가로채,
  이 화면에 있는 기능(물빠짐·노출암/간출암·CCTV) 3개만 해양종합정보와 같은 탭형 팝업으로
  보여줍니다(`_buildSafetyInfoHtml()` — `window.oceanInfoTabHtml(id)`로 탭 본문을
  가져와 `.ocean-info-tabs`/`.ocean-info-panel` 구조로 재구성, 한 번에 한 탭만 표시).

## 해양종합정보와 상태 분리

해양안전은 해양종합정보 지도를 **빌려 쓰기** 때문에, 아무것도 안 하면 그쪽에서 켜 둔
오버레이(특보구역 선·해구도 격자·주요지명 등)가 그대로 따라옵니다. 그래서:

- **들어올 때** 켜져 있던 오버레이 버튼을 모두 끄고 그 목록을 기억합니다(`_suspendOceanOverlays`).
- **진짜 해양종합정보 탭으로 갈 때** 그 목록을 되살립니다(`_restoreOceanOverlays`).
  활동 화면으로 넘어갈 때가 아니라 그 탭에 들어갈 때 복원하는 이유는, 활동 화면에
  "특보구역은 참고용…" 같은 엉뚱한 안내 토스트가 뜨는 것을 막기 위해서입니다.
- 버튼을 프로그램으로 누르는 동안에는 `_silently()` 로 토스트를 잠시 막습니다
  (사용자가 직접 누른 게 아니므로).

## 지점 팝업(바텀시트)과 우측 레일

지점 팝업은 활동 섹션(`position:fixed; z-index:50`) **안**에 있어서, 자기 `z-index:999`
가 그 섹션 안에서만 유효합니다. 바깥에 떠 있는 레일(`z-index:60`)을 넘어설 수 없어
닫기 버튼이 레일 버튼에 가렸습니다. → 팝업이 열려 있는 동안에는 레일을 감춥니다
(`body.ls-sheet-open`, `_watchBottomSheets()`). 섹션의 z-index 를 흔드는 것보다 안전합니다.

## 물빠짐 화면의 하단 스택

시간 슬라이더·범례·출처표기(국립해양조사원/OpenStreetMap)가 서로 겹치지 않도록
아래에서 위로 **[하단탭(+서브탭) / 슬라이더 / 출처표기 / 범례]** 순으로 쌓습니다.
세 요소를 `position: fixed` 로 바꾸고 `--ls-bottom-chrome` 하나로 계산하는데,
원래 기준 박스(`#ocean-map-wrapper`)가 서브탭 열림 여부에 따라 화면 끝까지 늘어났다
줄었다 해서 기준이 일정하지 않기 때문입니다.

## 배포 시 주의 — 서비스워커 캐시

`sw.js` 는 `/index2.html` 만 캐시 제외이고 **JS 파일은 stale-while-revalidate 로 캐시**합니다.
그래서 기존 JS 파일을 고쳐 배포하면 사용자는 **새 HTML + 옛 JS** 조합을 한 번 받게 되어
기능이 반쯤 동작하는 상태가 됩니다(실제로 배경지도 전환이 먹통이 된 원인).
**기존 JS 를 수정했으면 `index2.html` 의 `<script src>` 에 `?v=…` 를 새로 붙이거나 값을 바꿔서**
캐시 키를 갈아 끼우세요. (`sw.js` 의 `CACHE_VERSION` 은 `__CACHE_VERSION__` 자리표시자
그대로라 배포해도 옛 캐시가 지워지지 않습니다.)

## 수정 시 주의사항

- **로드 순서 고정** — `index2_patch.js` 보다 먼저 로드되면 탭 전환 후처리가 동작하지 않습니다.
- **글자크기 설정과 무관** — 활동 버튼 크기(`--ls-rail-w` = 54px, 글자 13px)는 px 고정입니다.
  `rem` 으로 바꾸면 "크게" 설정에서 버튼이 같이 커집니다(사용자가 원치 않음).
- **지도 없는 활동**(바다갈라짐)은 기존 UI 를 그대로 두고 CSS 로만 조정합니다.
  버튼을 위로 올린 가로 배치(`body.ls-row`)라 `padding-top` 만 줍니다.
  해수욕은 이제 스킨스쿠버와 동일한 지도형이라(`swimming.js`) 다른 지도 활동들과
  같은 방식(우측 레일이 fixed 오버레이로 뜸)으로 동작하며 별도 padding 보정이 없습니다.
- 이안류(`ripcurrent-section`)는 현재 하위탭에서도 숨김 상태라 레일에도 넣지 않았습니다.
