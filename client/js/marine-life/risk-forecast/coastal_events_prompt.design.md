# 과제11 — 다음 달 해안 행사 수집 일정과 실제 Gemini 프롬프트

이 작업은 해상 교통·사고예보 통합 이후, 사용자 요청에 따라 기능상 겹치지 않는 행사 수집 부분을 먼저 점검한 결과다. 해상 지도·범례·시트 시간 조율 코드는 수정하지 않았다.

## 수집 일정

기존 `coastal_events_collector`는 한국시간 기준 **매월 마지막 날짜−3일 03:20**에 다음 달의 누락/실패 자료를 수집한다. 예를 들어 2026년10월은 **10월28일03:20 KST에 11월분**을 수집한다. 고정된 '매달28일' 규칙이 아니므로 2월·30일 월·윤년을 달력으로 계산한다.

운영 서버 시작 시 누락된 당월과 예정일이 지난 다음 달을 보충한다. 정상 캐시가 있는 월은 다시 검색하지 않으며, 실패한 월은 이후03:20에 재시도한다. 같은 예약의 중복 실행을 막고 다음 달 오류가 당월의 월별 정상 상태를 덮지 않는다. 개발 `start()`는 자동 수집하지 않는다.

이번 점검에서 기존 일정 로직은 정상으로 확인하여 변경하지 않았다. 새 프롬프트가 머지됐다고 정상인 당월 자료를 강제로 재검색하지 않는다. 다음 수집 또는 누락/실패 재시도에서 적용된다.

## 기존 프롬프트의 누락과 변경

기존 보충 검색은 '스포츠 대회·물때·해맞이 등'으로 축약돼 있었다. 포괄 문구만으로 사용자 요구 유형의 검색을 보장하기 어려워 실제 요청에 다음 항목을 명시했다.

| 검색 분류 | 명시한 대상 |
|---|---|
| 수상·해안 레저 | 철인3종, 오픈워터/수영, 서핑, SUP, 카누, 용선/드래곤보트, 요트 |
| 해안 육상 | 해안도로 마라톤, 달리기, 자전거, 비치발리볼/배구, 걷기 |
| 낚시 | 갯바위, 방파제, 선상 대회 |
| 야간·물때 | 불꽃/해변 음악축제, 해넘이/해맞이, 바닷길 축제, 갯벌 체험 |
| 지역·계절 | 수산물/해산물, 머드, 해안 벚꽃, 군항제, 해수욕장 개장/폐장 |
| 기타 해안 행사 | 에어쇼, 함정 공개 |

유형 목록은 검색 범위이며 실제 개최의 근거가 아니다. 찾지 못한 행사, 취소, 일반 피서 인파, 상시 관광활동, 내륙/하천 행사는 제외하도록 했다. 목표 월의 실제 첫날/마지막 날과 개최기간 겹침을 명시한다. 전월부터 이어지는 후보는 현재 공식 원문에서 주소·일정·개최 여부를 재확인한 경우에만 반영한다.

공식 지자체/주최기관의 행사 안내 **원문 HTTPS URL**, 실제 전체 도로명/지번 주소, 실제 개최기간을 요구한다. 검색결과 페이지/재인용 뉴스/단축 링크와 좌표 추정은 금지한다. 날짜·주소를 확인하지 못하면 제외한다. 기존 서버의 유효 날짜/근거 URI/카카오 주소·좌표 일치/해안 범위/중복 병합/정상본 보존 검증은 유지한다.

## 실제 요청 템플릿

> ⚠**정정 (2026-10-15)** — 아래 템플릿은 **2026-10-13 판**이다. 지금 코드의 질문은 문서 끝 「2026-10-15 보완」의 템플릿으로 바뀌었다(지우지 않고 이력으로 둔다).


아래 텍스트는 코드의 `contents`에서 추출했다. `${target}`는 목표 월, `${province}`는 해당 해안 시도, `monthBounds`는 실제 달력 경계, `known`은 기존 공식 목록, `candidates`는 전월부터 이어지는 재확인 후보다. 실제 프롬프트는 이 값을 채운다.

```text
${target} ${province} 해안에서 열리는 행사 중 관광공사 공식 목록에 빠진 행사를 공식 지자체/주최기관 웹 원문으로 보충 조사하세요. 대상 기간은 ${monthBounds(target).first}부터 ${monthBounds(target).last}까지이며 이 기간과 개최 기간이 겹치는 행사만 조사하세요. 유형별로 빠짐없이 검색하세요: 해안 레저·수상 대회(철인3종·오픈워터 수영·수영·서핑·SUP·카누·용선/드래곤보트·요트), 해안 육상 대회(해안도로 마라톤·달리기·자전거·비치발리볼·배구·걷기), 낚시대회(갯바위·방파제·선상), 야간 대규모 행사(불꽃축제·해변 음악축제·해넘이·해맞이), 물때 행사(바닷길 축제·갯벌 체험), 지역 수산물/해산물 축제·머드축제·해안 벚꽃축제·군항제·해수욕장 개장/폐장 행사, 해안 에어쇼·함정 공개. 유형 목록은 검색 대상이지 실제 개최 근거가 아니므로 찾지 못한 행사를 만들어 넣지 마세요. 이미 취소된 행사, 일반 피서 인파, 상시 관광활동, 내륙/하천 행사는 제외. src는 검색결과 페이지·재인용 뉴스·단축 링크가 아닌 공식 지자체/주최기관의 해당 행사 안내 원문 https URL로 제공하세요. 기존 공식 목록: ${JSON.stringify(known)}. 전월부터 진행되는 미확인 후보: ${JSON.stringify(candidates)}. 후보는 이전 자료일 뿐입니다. 현재 공식 원문에서 개최 여부·실제 주소·기간을 다시 확인한 후보만 events에 넣고, 취소되었거나 재확인하지 못한 후보는 제외하세요. 장소 좌표는 추정하지 마세요. JSON 객체만 답하세요: {"events":[{"name":"행사명","address":"실제 도로명 또는 지번 전체 주소(시도·시군구·번지 포함)","start":"YYYY-MM-DD","end":"YYYY-MM-DD","src":"공식 출처 https URL"}]}. 날짜와 주소를 원문으로 확인할 수 없는 행사는 제외하세요.
```

모델은 기존 `gemini-2.5-flash`, 호출 구분은 `CoastalEvents`, 도구는 `googleSearch`, 키/429 쿨다운은 공용 `gemini_client`다. 이번 변경은 호출 주기·모델·키·요금 정책을 새로 추가하지 않는다. 해상 전국 관할 Gemini 브리핑은 별도 후속 단계다.

## 검증과 남은 한계

실제 `collect()`가 전달한 Gemini 요청 인수를 모의 클라이언트로 받아 유형·월 경계·공식 원문·주소·후보 재확인·모델/검색 도구를 대조했다. 수정 전 31 PASS / 1 FAIL(철인3종 누락), 수정 후 UTC와 America/Los_Angeles에서 각각32 PASS / 0 FAIL이다.

예약 검사는 평년2026년2월25일, 윤년2028년2월26일, 30일 월2026년4월27일, 31일 월2026년10월28일, 연말2026년12월28일→2027년1월을 검사한다. 전날/당일03:19은 다음 달 검색0회, 당일03:20은1회, 같은 시각/정상 다음날은 추가0회임을 확인했다.

실제 유료 Gemini/Google Search, 공식 행사 API, 카카오 API를 호출하지 않았다. 모의 검사는 실제 검색 결과의 완전성이나 Fly의 예약 성공을 증명하지 않는다. 서버의 근거 URL 검사는 HTTPS와 검색 grounding URI 일치 여부를 확인하며 기관 소유 도메인을 별도로 판정하지 않는다. 공식 원문 요구는 프롬프트에 명시한 것으로, 모든 반환 URL이 기관 원문이라고 기계적으로 보증한 것이 아니다. 장기 진행 행사가 모두 수집된다는 보장은 없고 `coverage.completeOngoing=false`를 유지한다.

최종 검증(2026-10-13 07:59 KST): `verify_all.sh` 종료 코드0,83개 스위트3,378 PASS / 0 FAIL. 경로·133개 로드 순서·실제 앱 스모크·HTTP·기존 자료 기준선 검사 통과. 신규 콘솔 오류/404/깨진 시나리오/전역 누락0. 기존 자료/환경 경고는 그대로 구분하며 실제 행사 검색·Fly 예약을 검증했다고 주장하지 않는다.

## 2026-10-15 보완 — 근거 주소·번지 없는 행사장·시도별 실패·질문 보완

사용자 원문(2026-10-15): *"그 외 네가 GEMINI에 대해서 조사한 것은 그대로 반영해줘. 다만, 1년 내내 진행 중인 것은 제외하자. 그리고 GEMINI는 제한을 두지 말도록 하자."*
근거: 독립 검토 3건(근거 주소가 구글 경유 주소라 정확 일치로는 통과 못 함 · 비공식 안내에 번지가 없음 · 한 시도 답이 JSON 이 아니면 달 전체 실패 · 질문 빈칸). 전체 목록과 이유는 설계서 `client/js/ocean-map/coastal-risk/coastal_safety_forecast.design.md` §7 「보완 (2026-10-15)」 1~8.

위 「검증과 남은 한계」의 *"근거 URL 검사는 HTTPS와 검색 grounding URI 일치 여부를 확인"* 은 **정정**: 이제 경유 주소(`vertexaisearch.cloud.google.com/grounding-api-redirect/…`)는 서버가 `redirect:'manual'` 로 한 번 따라가 `Location` 의 실제 주소를 얻고, Gemini 가 적은 `src` 와 「호스트+경로」(끝 `/` 제거, 쿼리·조각 무시)로 비교한다. 저장 `src` 는 풀어낸 실제 주소다. 도메인만 같은 것은 받지 않는다.

위 *"실제 전체 도로명/지번 주소 … 를 요구한다"* 도 **정정**: `address` 는 원문에 번지가 있을 때만 받고(없으면 빈칸, 추정 금지), 대신 `venue`(원문 행사장 이름)·`sgg`(시도+시군구)를 받아 같은 시군구 관광지 이름 또는 카카오 장소검색으로 연결한다.
