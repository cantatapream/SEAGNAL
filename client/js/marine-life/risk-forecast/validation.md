## 구현 범위

최신 사용자 결정 U77·U78에 맞춰 실제 앱의 해양안전에 위험예측 버튼을 연결했다. 초기에는 연안만 켜지고, 지도 선택으로 상세 창이 열린다. 시간 슬라이더, 연안·해상 전환, 경고 경계, 위험구역 이동, 산출 근거 보기와 두 PDF 내려받기를 포함한다. 메인 활동 브리핑과 AI 설정 연결은 이번 범위에서 미룬 결정대로 별도 작업이다.

계산은 서버의 순수 함수로 모으고, 기존 수집 자료와 세 신규 수집기를 읽는 API를 추가했다. 신규 수집기는 Fly 운영 환경에서만 자동 기동한다. 개발 환경의 화면 조회는 외부 API를 자동 호출하지 않는다. 혼잡도는 하루 실제 요청 90회, 관광지 집중률은 900회로 제한하고 재시작 후에도 요청 장부를 유지한다. 행사 수집은 관광공사 공식 축제 목록과 Gemini 보충 검색을 병합하고 Kakao 장소 검색으로 실제 주소를 확인한다.

## 실제 외부 자료와 남은 작업

### 같은 시각의 공공 API 성공과 클라우드 실패

사용자가 2026-10-11 13:00·격자4의 공공 API 실제 응답과 F12 요청 기록을 제공했다. 직접 GET `https://apis.data.go.kr/B554035/sea-tfc-congst-fcst/get_sea_tfc_congst_fcst`이며, `pageNo=1`, `numOfRows=10`, `type=json`, `fcstDate=20261011`, `fcstTime=1300`, `gridLevel=4`였다. 인증키는 한 번 percent-encoding한 형태다. HTTP200·`200 / NORMAL_SERVICE`, 전체5,666개 중 첫10개, 예보 생성시각 `2026-10-11 03:58:12`를 확인했다. 현재 앱의 응답 파서와 정규화 함수가 이10개를 모두 받아들이며, 같은 시각 MTIS 표의 좌표·혼잡 단계·풍속·파고와 불일치0건이다. 사용자가 보낸 키를 디코딩한 값과 기존 서버 설정의 일치 여부만 확인했고 값은 기록하지 않았다.

반면 클라우드에서는 동일 GET 경로·매개변수·항목 순서로 요청해도 HTTP400·`INVALID_REQUEST_PARAMETER_ERROR`(코드10)가 유지됐다. Node와 curl 양쪽에서 재현했고, 키를 한 번 인코딩한 요청과 디코딩된 요청, 공식 JSON 헤더와 사용자 브라우저의 일반 Accept·User-Agent 조건도 대조했다. 공식 포털의 공개 Swagger2.0 명세에서 필수 query7개와 GET 경로가 현재 수집기와 일치한다. 사용자의 실제 성공 요청이 공공 API 호스트로 직접 전송됐으므로 포털 중계 요청으로 설명하지 않는다. 실패 응답에는 예보 본문이 없고, 관찰만으로 인증키·인코딩·프록시·제공기관 중 어느 쪽이 원인인지 단정하지 않는다.

관광공사 v4.1 매뉴얼의 필수 항목과 응답 필드, 첨부 시군구 코드표도 대조했다. 앱의 시군구 코드60개 중 코드표에 없는 것은0개다. 관광지 집중률의 실제 클라우드 요청도 HTTP400·코드10이며, 모의 응답 검증을 실제 수집 성공으로 취급하지 않는다.

과거 성공은 커밋 `42a4514a22`의 설계서 §4.2·§9와 사용자가 제공한 Claude Code 호출 기록에서 확인했다. 2026-10-10 12:00·격자4·첫3개 조회는 `200 / NORMAL_SERVICE`, 전체6,165개였다. 같은 날 격자3 전체2,642개를 받은 후 발생한 Python `max()` 오류는 풍속·파고 null을 숫자와 비교한 후처리 오류였다. API 실패가 아니다. 현재 수집기는 혼잡 자료만 정규화하므로 이 기상 null을 위험 점수나0으로 바꾸지 않는다. 과거 임시 원본과 `get.sh`는 현재 체크아웃·도달 가능한 Git 파일 경로에서 찾지 못했지만, 이후 확보한 당일 성공 요청과 응답으로 현재 계약을 직접 대조했다.

### MTIS 웹 조회 병행 조사

사용자의 네트워크 허용 변경 후, 클라우드에서 [MTIS 혼잡예보](https://mtis.komsa.or.kr/traffic/focst/density)의 공개 페이지와 JS를 HTTP200으로 읽었다. 공개 페이지가 제공하는 새 익명 세션의 정상 CSRF 흐름으로 다음 POST도 HTTP200으로 재현했다. 사용자 쿠키·CSRF를 재사용하거나 저장하지 않았다.

- 지도: `/traffic/focst/focstDnsty`
- 표: `/traffic/focst/dnsty/grid/info`

두 요청의 실제 JSON 조건은 `dateTime=2026-10-11 13:00:00`, `gLevel=lv4`, `startDay=2026-10-11`, `nextDay=2026-10-12`, `lastDay=2026-10-14`였다. 지도·표 모두5,666개의 고유 격자가 있고, 격자 집합·중심점·GeoJSON/WKB 도형이 일치했다. 클라우드에서 새로 받은 행도 사용자 첨부와 변경0건이다. 단계별 건수는 낮음4,783·보통743·높음72·매우높음68이다. 풍속·파고 결측은 각각90건이며 지도 문자열 `"null"`과 표 JSON null을 동일한 결측으로 해석한다.

좌표 필드는 `ctrptYCrd=경도`, `ctrptXCrd=위도`다. 표의 `wetherFrcstTime=1791691200000`은 KST13시이고 지도는 같은 시각 문자열을 제공한다. 기존 해역 변환기로 실제5,666개 중심점을 외부 작업 폴더에서 검증해 해구·참조좌표5,666개 대응, 좌표 불일치0건을 확인했다. 기상 경보구역은5,375개 대응하며 원본 구역 밖291개에 임의 구역을 부여하지 않는다. 이 검증 자료는 정상 운영 캐시에 넣지 않았다.

공개 JS의 정상 격자 클릭 `/traffic/focst/focstDnstyMatch`도 조사했다. 한 격자의 시계열71행은10월11일01시~13일23시이며14일 행이 없다. `lastDay` 값만으로 마지막 날짜 자료 제공을 단정하지 않는다. 엑셀다운은 전체 페이지의 혼잡 단계·격자번호·위도·경도·풍속·파고6개 열을 대상으로 한다.

웹 지도·표·시계열 응답과 엑셀 설정에는 수치 `congestionIndex`와 생성시각 `fcstCreateDateTime`이 없다. 따라서 단계에서 수치 지수를 추정하여 앱의0.1 필터나 상세 수치에 넣지 않는다. 이 웹 조회는 원본 정합성 확인에 유용하지만, 현재 요구사항의 공식 혼잡 수집기를 대체하지 않는다. 같은 시각에 사용자가 성공한 공공 API에는 두 필드가 실제로 존재한다.

### 환경과 실제 수집의 남은 제한

네트워크 변경 후14:25 KST에 실제 앱을 다시 주행했다. 위험예측 버튼으로 유효 연안 면1,320개가 표시되고, 지점 선택의 상세·시간 슬라이더와 OFF 후 선택 해제를 확인했다. 두 PDF는 HTTP200·application/pdf이며 PDF 헤더를 확인했다. 브라우저 미처리 오류는0건이다. 관광지 집중률·행사 자료 없음은 배너와 상세에 유지했다. 이 앱 주행은 공공 API 수집 성공을 뜻하지 않는다.

Chromium의 외부 MTIS 탐색은 `ERR_CERT_AUTHORITY_INVALID`로 실패했다. 제공된 프록시 CA의 지문과 기존 NSS 신뢰 등록을 확인했고 같은 프록시 경로의 OpenSSL 검증은 return0이었다. 따라서 단순한 CA 누락을 원인으로 결론내리지 않는다. 공식 Debian 저장소의 서명된 패키지 목록·SHA256을 검증해 Xvfb·xdotool·libxdo를 작업 폴더에만 준비했고, 별도 프로필의 정상 Certificate Manager 및 네이티브 파일 선택으로 제공된 CA의 PEM·DER 가져오기를 시도했다. 신뢰 목록은 바뀌지 않았고 인증서 오류도 유지됐다. 시스템 설치나 TLS 검증 해제는 하지 않았다. Node의 정상 검증 HTTPS 조회 성공과 Chromium 외부 화면 검증 미완료를 구분한다.
