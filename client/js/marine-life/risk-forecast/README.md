# 위험예측

`index2.html`의 **해양생활 → 해양안전 → 위험예측** 버튼에 연결된 지도 오버레이다. 처음에는 연안만 켜며, 관광지나 해상 칸을 선택하면 시간축과 상세 시트가 열린다. 해상·연안 스위치는 기존 범례 칸에 쌓인다. 선택한 층을 끄거나 Escape를 누르면 시트와 선택 위험구역을 지운다.

지도 범례에는 예비특보·주의보·경보·특보급 날씨 가능성(3일째) 네 줄을 두지 않는다(과제13). 남기는 범례는 해상의 「종합 관심단계/공식 사고예보」 등 색상 범례 한 개뿐이다(2026-10-15 정정: 종합 관심단계 폐지 — 해상 기본 범례는 현재도 「공식 사고예보」). 특보 구역도 지도에 그리지 않는다(2026-10-15, 아래 「특보 영역 미표시」 절). 특보 내용은 상세 시트에 표시한다.

점수·시간축·특보 판정은 `/api/risk-forecast/*` 서버 응답을 사용한다. 연안 관광객 분석은 기존 계산을 유지한다. 해상은 GR4 크기의 공통 표출 격자 하나에서 현재 종합 관심단계·미래 공식 사고예보를 연속 면색으로 표시하고(2026-10-15 합의 변경: 현재도 공식 사고예보 그대로, 혼잡·현재 척수는 상세의 「충돌·접촉 주의」 안내로만 — [marine_fusion.design.md](marine_fusion.design.md) 「충돌·접촉 주의」), 원본 사고·혼잡·현재 교통을 상세에서 비교한다. 클릭 위치에 포함되는 두 격자를 공간으로 연결하며 사고지수에 혼잡 가중치를 추가하지 않는다. 파고·풍속·파주기·파향은 같은 3시간대의 기상청 해구 예보를 별도 출처로 표시한다. 자료가 없거나 수집이 실패하면 정상값을 만들지 않는다.

## 해상 화면 후속 수정 — 2026-10-13

위험예측 버튼은 페이지마다 비활성 모습으로 시작한다. 첫9회는 기능과 다른 오버레이에 영향을 주지 않고,10회째에 해제하면서 연다. 이후 같은 페이지에서는 보통 토글로 동작한다. HTML disabled는 클릭을 받지 못하므로 aria-disabled와 캡처 처리로 구현한다. 서버 인증이나 자동수집 중지 기능은 아니다.

연안·해상 스위치는 위험지형과 동일한 banzone/bzl 스타일을 사용한다. 해상ON은 기본 통합색, 하위 아코디언의 사고위험 예보·실시간 교통·혼잡도 예측은 한 항목만 선택된다. 선택 후 접고 뱃지로 알리며, 선택한 항목을 다시 끄면 기본 통합으로 돌아간다. 실시간 교통 선택은 현재로 복귀하고, 미래 버튼을 누르면 기본 미래 공식 사고예보로 전환한다. **(2026-10-15 대체: 하위 아코디언·뱃지는 없앴다 — 아래 「해상 시트·지도 조작부 화면」 절.)**

메인 해상 슬라이더 대신46px 전폭 하단 바의 고정 날짜·시각 output과 현재/+3H/+6H/+12H 버튼을 제공한다.11시+3H는12시, 다음+3H는15시다. 바는 메인 탭 바로 위이며 출처·축척·색상범례는 그 위로 올린다. 상세 시트의 시간축은 유지하고 메인 시각과 독립적이다. 예보 범위 밖 버튼은 비활성화한다. **(2026-10-16 대체: 왼쪽 날짜 output 은 없애고 -6H~+6H 5버튼·버튼 안 작은 글씨·시각 토스트 — 아래 「하단 시간 버튼 5개·시각 토스트·연안 색 범례·출처/축척 올림」 절.)**

**과제2 — 연안·해상 공통 메인 시각**: 이 하단 바는 해상 전용이 아니라 연안·해상 공통 하나다(연안만 켠 기본 화면에서도 보인다). **(2026-10-16 T24 대체: 하단 바는 해상이 켜져 있을 때만. 연안만이면 바 대신 화면 가운데 위쪽 날짜 넘기기, 연안은 날짜마다 하나 — 아래 「연안 하루 하나·날짜 넘기기」 절.)** 연안 ON이면 서버 `meta.timeline.coast`의 3시간 칸(지금~내일 21시 — 아래 「가」)을 그대로, 해상만 ON이면 지금~내일 21시를 고른다. 두 층의 끝이 같으므로 내일 21시에서 앞으로 버튼이 모두 비활성이 된다(종전의 「해상 예보 범위 밖 (내일까지)」 안내는 연안만 남는 모레 구간이 없어져 삭제). 둘 다 끄면 바가 숨는다. 시트 시각은 계속 독립이다.

결측은 면색·클릭 대상에서 제외한다. 확대 시 화면 주변 격자만 만들고 전국 보기에서는 같은 색상의 폴리곤을 최대256개 도형으로 묶는다. 숫자는 확대된 실시간 교통에만 표시하며, 공간 클릭은 원래 격자와 수치로 연결한다. 완성된 면색에 흐림을 한 번 적용한다. 부가 경계/연안 실패가 정상 해상 프레임 표시를 막지 않는다.

## 특보 영역 미표시 — 과제14 폐지 (2026-10-15)

> 사용자 원문(2026-10-15): *「이미지를 보면 지도에 특보 영역을 표시하지 말자고 했는데 나오고 있는데 없애주고. 범례를 없앴으니 다시 없애야지.」*

위험예측 지도(연안·해상)에는 **특보 구역을 칠하지도, 테두리로 그리지도 않는다.** 과제13에서 특보 범례를 없앤 데 맞춰, 과제14로 넣었던 「특보 있는 해상 구역 배경 면」을 통째로 걷어냈다.

- 화면: `risk_forecast.js`의 `refreshWarnings`(특보 구역 요청·그리기)를 지웠다. `risk_map_layer.js`에서 특보 층 `borders`(`rf-borders-canvas`), `drawWarnings`·`zonesLoaded`, 구역 이름 맞춤(`zoneKey`·`zoneGeometry`)을 지웠고 `boundaries()`는 더 이상 `/api/warn-zones`·`/api/warn-zones-sub`를 내려받지 않는다(육지·섬 외곽선만).
- 서버: 이 화면 전용이던 `GET /api/risk-forecast/warning-zones`와 `risk_store.warningZones`, 연안·해상 frame 응답의 `borders` 필드와 그 계산 함수 `borders()`를 지웠다. 화면이 그리지 않는 자료를 매 시각 계산·캐시하지 않는다.
- 그대로 둔 것(다른 화면과 공용): `/api/warn-zones`·`/api/warn-zones-sub` 경로와 정적 도형 파일(해양지도 탭 `ocean_warn_*`, 위치 알림, 온보딩이 사용), 특보 수집·푸시, 해구 예보. 상세 시트의 특보 행·특보 안내 문구와 해상 점수의 특보 반영은 지도 표시가 아니므로 유지한다.
- 지난 결정 「다」(예비특보 구역은 칠하지 않음, 2026-10-15)는 이 결정으로 흡수됐다 — 이제 어떤 특보 구역도 칠하지 않는다.

## 원천 오류 표시 정책 — 과제16

특보·해구 기상·행사 등의 실패/낡음/결측 공통 배너와 상세 시트의 공통 경고 목록은 공개 지도에서 숨긴다. 수집 상태를 정상으로 바꾸지는 않는다. 개별 값의 자료 없음, 선택한 상세를 읽지 못했을 때의 재시도는 유지한다. 오류 내역은 통합 관리자 센터 **점검 → 데이터 수집현황**(현재 원천 상태·오류·복구 이력 — 2026-10-15 종전 AI → AI 사고예측 → 오류현황에서 옮김)에서만 확인한다. 운영 감시는 `risk_history_sources`의 작은 메타데이터와 기존 `risk_store.sources`의 신선도 규칙을 사용하며 화면용 예보 캐시를 강제 로드하지 않는다. 상세는 [오류 이력 운영 문서](../../../../00_docs/operations/risk-forecast-error-history.md)를 참고한다.

## 자료 없음 문구 판정 — 과제4

행사·특보·강풍이 **없는 날(원천은 정상 수신, 목록만 빔)** 은 서버 `missing`·프레임 `degraded` 에 들지 않아 화면에 자료 없음 문구가 나오지 않는다. **받지 못한 경우(파일 없음·손상·오류·낡음)** 만 `missing` 에 들고, 연안 시트에서는 행사 행의 「자료 없음」과 「확인된 요소 기준」 안내로 정상 없음과 구분된다. 전역 경고 목록은 과제16대로 숨기고 관리자 오류현황에 기록한다. 이안류 **비수기(`offseason`)** 는 정상 상태라 `rip` 결측으로 세지 않는다. 검사: `test_risk_missing_notice`.

## 상세 시트 고정 머리·하단 탭 위 배치 — 과제5·7

시트(`#risk-forecast-sheet`)는 지도 박스가 아니라 화면(viewport) 기준 `position:fixed`로 `bottom:var(--ls-bottom-chrome)`(메인탭+열린 서브탭 높이) 위에 놓는다. `--main-tab-height`가 탭 offsetHeight 실측값이라 아이폰 아래 여백(safe-area)이 이미 들어 있어 `env()`를 더하지 않는다. 서브탭이 열리면 변수가 서브탭만큼 커져 이중 여백이 생기지 않는다.

시트 안은 `.rf-sheet-head`(손잡이·닫기·제목·부제·시각 조작, 고정)와 `.rf-body`(내용, 이 안에서만 스크롤)로 나뉜다. 연안·해상·공식 사고 상세, 해상 종합·관할 브리핑 렌더, 같은 위치 관광지 선택 목록이 같은 머리를 쓴다. 닫기 버튼, PopupStack 등록, 휴대폰 뒤로가기는 그대로다. 미리보기(`risk_forecast_preview.html`)는 프레임 안 absolute 배치를 유지한다.

## 시트 고정 일시 표시 — 과제8

슬라이더 말풍선(`.ocean-sheet-tooltip`)을 없애고 슬라이더 위 빈칸에 `<output class="rf-time-label">`로 「'26.10.14(수) 15:00」(KST)를 고정 표시한다. 값은 시트의 `selected.at`(손잡이를 움직이면 그 값)이며 `RiskFormat.stamp`로 만든다. 메인 지도 시각(`t`)은 읽지 않는다 — 메인 15시, 시트 18시로 옮기고 닫으면 메인은 15시, 다른 지점의 새 시트도 15시로 시작한다. 해상 메인 하단 바의 현재/+3H/+6H/+12H와 고정 일시는 그대로다.

## 즉시 열기와 로딩 스켈레톤 — 과제6

지점을 누르면 응답을 기다리지 않고 시트를 열어 회색 틀(`.rf-skeleton`)을 보인다. 제목은 이 지점의 이름을 아는 연안만 쓰고(해상은 「불러오는 중…」) 이전 지점의 제목·내용은 남기지 않는다. 시트 시각 조작을 바꿔도 같은 지점의 제목은 두고 본문만 회색 틀로 바꾼다. 60초 자동 갱신은 열린 상세를 회색 틀로 바꾸지 않는다. 열린 시트는 응답 전부터 휴대폰 뒤로가기(PopupStack) 대상이다.

늦게 온 응답은 기존 검사(요청 세대·선택 객체·요청 시각 일치)로 버린다: 먼저 누른 다른 지점, 이전 시트 시각, 이미 닫은 시트의 응답은 화면에 나오지 않는다. 요청이 실패하면 회색 틀 대신 오류와 「다시 시도」를 보이며 결측을 정상처럼 꾸미지 않는다.

## 위험구역 현황 아코디언과 지도 중앙 이동 — 과제10

연안 「위험구역(3km 안)」 줄의 「위험구역 N곳 현황」은 버튼 모양(높이 40px 이상, ▾ 표시)의 접힘 아코디언이다. 구역을 누르면 지도가 그 구역을 **시트에 가려지지 않은 남은 지도 영역의 가운데**로 이동·확대하고, 목록에서 그 구역이 눌린 상태(`aria-pressed`)로 표시된다. 다른 구역을 누르면 이전 표시는 해제되고, 다른 지점을 고르면 구역 표시가 지도에서 사라진다. 해상 관할 해역 이동(`marinePoint`)도 같은 여백 계산(`visiblePadding`)을 쓴다. 설계 결정 U72·U74⑦·U78⑥은 `coastal_safety_forecast.design.md`.

**시간 버튼 5개** (`risk_forecast.js` 시간 줄 · `risk_forecast.css` `.rf-marine-timebar`): `-6H · -3H · 현재 · +3H · +6H`. 처음엔 -12H·+12H 까지 7개였으나 버튼이 높아져(40px) 같은 날 뺐다. 연안·해상이 같은 바 하나를 쓰므로(위 과제2) 연안만·해상만·둘 다 켠 경우 모두 같은 규칙이다(「해상도 동일하게」).
- 왼쪽 날짜 `output` 은 없앴다. 선택 시각은 화면에 안 보이는 글자(`[data-map-time]`, 「조회 시각 10.12.(월) 11:00」)로만 남긴다.
- 버튼마다 라벨 아래 **한 줄** 작은 글씨로 누르면 갈 시각 「16.(금) 13:00」(일은 앞 0 없음, KST). [현재]는 지금 시각(`meta.now`)이며 이동해도 바뀌지 않는다. ± 버튼 글씨는 선택 시각이 바뀔 때마다 다시 계산한다.
- 크기: 바 46px·버튼 34px — 종전 4버튼 때와 같다(7버튼 시안은 버튼 40px). 5개가 바 폭을 고르게 나눈다(간격 6px). 작은 글씨 10px, 폭 360px 이하에서는 9px(320px 에서 한 줄에 들어가게 — 9px 를 하한으로 잡았다).
- **± 목표 규칙**(`nextTime`, 앞뒤 대칭): 시각마다 그 시각이 든 3시간 칸(00·03·06…시 시작)을 쓴다. 목표 칸 = 선택 시각의 칸 ± 시간. `+` 는 목표 칸 이상인 첫 시각, 시간축 끝(내일 21시)을 넘으면 비활성. `-` 는 칸이 목표 칸 이하인 마지막 시각, 목표가 지금의 칸이면 지금으로 돌아가고 그보다 앞이면 비활성. 예: 지금 11시 → +3H 12시 → +3H 15시 → -3H 12시 → -3H 11시(지금). 처음(지금)엔 「-」 둘이 회색, 12시에서는 -3H 만 켜진다(-6H 는 06시 칸이라 지금의 09시 칸보다 앞), 15시에서 -6H 는 지금.
- 비활성 버튼은 회색(배경·테두리·글자) · `disabled` · `aria-disabled="true"` · 작은 글씨 비움. [현재] 강조(`aria-pressed`)는 지금 시각일 때만이다.

**시각 토스트** (`timeToast`·`liftToast`, `.rf-time-toast`): 시간 버튼을 누를 때마다 약 2초 「16.(금) 13:00 예보」, 지금으로 돌아오면 「현재 16.(금) 10:00」. 연타하면 글자를 바꿔 치우고 타이머를 새로 잡아 마지막 것만 남는다. `role="status"`·`aria-live="polite"` 로 읽어 준다(종전 왼쪽 output 의 aria-live 를 대신 — 숨김 글자에서는 aria-live 를 뺐다, 두 번 읽히지 않게). 누름은 지도로 통과(`pointer-events:none`). 기본 자리는 시간 줄 바로 위 가운데이고, 그 자리가 출처(브이월드)·축척·색 범례 상자와 겹치면 겹치는 것 위로 올린다(`liftToast` — 범례가 보이면 범례 상자 위). 지도 가운데 스피너·「잠시 후 다시 시도해 주세요」(`.rf-map-wait`)보다는 아래다. 바가 숨으면 함께 숨는다.

**연안 색 범례** (`[data-coast-key]`, `.rf-coast-key`, `colorLegendSync`): 연안 색 범례는 원래 없었다(해상만 있었다). 해상 색 범례와 **같은 왼쪽 아래 상자**(`.rf-color-legend`)의 위쪽에 「위험지수(연안)」 제목 + 4칸 색 막대(`RiskFormat.BAND_COLORS`) + 「평소 수준 · 다소 높음 · 높음 · 매우 높음」. 연안만: 연안 범례만, 해상만: 해상 범례만, 둘 다: 같은 상자에 위(연안)·아래(해상)로 제목과 구분선으로 나눔, 둘 다 끔·위험예측 끔: 상자 숨김. 단계 이름이 길어 상자 폭은 내용에 맞춰 넓어진다(최소 150px). 처음 구현은 왼쪽 위 토글 아래였으나 같은 날 사용자 지시로 옮겼다. 옛 경로(RiskMarine 없음)에는 이 상자가 없어 연안 범례도 없다.

## 다른 메인탭 왕복 시 상태 유지 — 공개 API 두 가지 추가 (2026-10-16)

> 사용자 원문(2026-10-16): *「해양안전생활 탭에서 어떤 버튼을 클릭하여 화면을 표출해놓고 예를 들어 위험예측. 그 상태에서 해양종합정보나 다른 탭을 갔다오면 해양안전생활 화면이 초기화되는데 가장 마지막에 했던 화면 상태로 유지해줘. 단 앱을 껐다가 켜면 초기화상태로 시작.」*

조율은 `../safety/life_safety.js` 1-3 절이 한다. 다른 탭으로 갈 때 위험예측 버튼을 대신 눌러 끄고(`setEnabled(false)` — 60초 주기는 `enabled` 를 보고 요청하지 않는다, 층·하단 시간 바·시트·뒤로가기 항목 정리), 돌아오면 다시 눌러 켠다(`sync()` 로 새 자료). 연안/해상 스위치·[혼잡도/위험 예측]·메인 시각은 이 모듈이 끄고 켜는 동안 지우지 않으므로 그대로 이어진다(「현재」였으면 새 현재로). 이 파일에서 바꾼 것은 `mount()` 가 돌려주는 객체 한 줄뿐이다:

- `getState().selected` 에 `location`(해상 지점의 `{lon,lat}`, 연안은 `null`)을 더했다 — 해상 시트를 같은 좌표로 다시 열기 위해.
- `synced()` — 진행 중인 자료 동기화(`sync()`)가 끝나면 풀리는 약속(없으면 바로 풀림). 다시 켠 직후의 옛 `meta.now` 로 시트를 열면 지난 시각을 요청하게 되므로, 동기화 뒤에 `select()` 한다.

시트 **안의** 시각은 되살리지 않는다 — 위 「시트 고정 일시 표시」 규칙대로 메인 시각에서 다시 시작한다. 검사: `test_life_safety_tab_keep`.

**하위탭 왕복도 같은 길 (2026-10-16 둘째 결정 「4-1, 2, 3 추천대로」)** — 해양안전 ↔ 해양생활 하위탭을 옮겨 다닐 때도 `life_safety.js` 의 switchSubTab 래퍼가 위와 똑같이 끄고(해양생활에 있는 동안 60초 주기 요청 없음) 다시 켜며 시트를 다시 연다. 해양안전을 보던 중 해양안전 하위탭을 다시 누르면 아무것도 끄지 않는다. 이 파일은 바꾸지 않았다. 검사: `test_life_safety_tab_keep` 「하위 탭」 사례.

## 활동지점 안전 브리핑 바로가기 — `RiskForecast.openAt`·`goTo` (2026-10-16)

> 설계서 `../../ocean-map/coastal-risk/coastal_safety_forecast.design.md` §11.4(U55): 브리핑 카드마다 바로가기 → 해양안전생활 > 해양안전 > 「위험예측」에서 그 지점으로.

- `bindApp()` 이 `RiskForecast.openAt(target)` 을 연다 — 미리보기 잠금(10번 누름)을 풀고, 꺼져 있으면 위험예측 버튼을 실제로 눌러 켠 뒤(해양안전 단독 표출 규칙 그대로) `goTo`. 부르는 곳: `client/js/forecast/station-briefing/station_briefing.js openInRisk`(탭 이동은 거기서 `switchMainTab`·`switchSubTab`).
- ⚠잠금 해제: 브리핑 바로가기를 누르면 그 기기에서는 위험예측 미리보기 잠금이 풀린다(브리핑이 지금은 관리자 기기에만 보이므로). 브리핑을 일반 사용자에게 열 때 다시 볼 것.
- 검사: `local_server/scripts/test_station_briefing_ui.js` 「[위험예측에서 보기 ›]」 두 사례.
- **바로가기로 고른 칸은 시트 위 지도 띠 가운데로 — 2026-10-17**. 사용자 원문(휴대폰): *「위험 예측에서 보기를 눌렀을 때 이렇게 이동되는데 바텀시트 위쪽으로 해당 격자가 가운데 와서 바텀시트에 가려지지 않도록 조치해줘.」*
  - 원인: `goTo` 가 `select()` 바로 뒤에 `visiblePadding()` 을 불렀는데, 그때 시트는 0.2초 대기(`RiskSheet.hold`) 중이라 `.open` 이 아직 없어 아래 여백이 기본 30px 였다 — 화면 전체의 가운데로 옮겨진 칸이 곧 올라온 시트(화면의 66%) 뒤에 숨었다. 범위도 칸이 아니라 좌표 둘레 3km 였다.
  - 고침(`risk_forecast.js` `frameTo`·`fitFrame`·`sheetTop`·`framed`, `risk_map_layer.js` `selectionExtent`): 선택 테두리 범위(해상 칸·연안 관광지 영역, 없으면 종전처럼 좌표 둘레 3km)를 시트 위로 보이는 지도 띠의 가운데에 두고 그 범위가 다 들어오게 맞춘다(최대 확대 13). 시트 높이는 숫자로 박지 않고 잰다 — 처음에는 시트가 가장 높이 올라올 때(CSS `max-height`)를 기준으로 곧바로 옮겨 칸이 절대 가리지 않게 하고, 상세가 그려져 시트 높이가 정해지면 실제 높이(`offsetHeight`, 올라오는 움직임은 뺀 제자리)로 **한 번** 고친다(8px 넘게 다를 때만 다시 움직임 — `ResizeObserver` 와 `detail` 뒤). 그 뒤의 시트 높이 변화·사용자가 지도를 끈 뒤에는 지도를 다시 옮기지 않는다. 움직임 줄이기(`prefers-reduced-motion`)면 애니메이션 없이 바로.
  - 그대로인 것: 지도에서 칸을 직접 누르는 경로(`mapSelect`→`select`)는 지금도 지도를 옮기지 않는다(이번에 바꾸지 않음). 시트 안 관할 해역 이동(`marinePoint`)·연안 위험구역(`hazard`)은 같은 `visiblePadding` 을 쓰며, 열린 시트에서는 종전과 같은 값을 낸다.
  - 검사: 새 `local_server/scripts/test_risk_goto_frame.js` — 실제 `bindApp` 의 `RiskForecast.openAt` 으로 열어 390×844·1280×800 에서 해상 칸·연안 관광지(·칸 id 없는 해상 지점)의 가운데가 시트 위 띠 가운데(±5%)이고 칸 전체가 띠 안인지, 움직임 줄이기면 돌아온 순간 이미 제자리인지. 고치기 전 코드로는 6건 모두 실패(휴대폰 해상 칸 가운데 402px, 띠 0~264px).
