# 위험예측

`index2.html`의 **해양생활 → 해양안전 → 위험예측** 버튼에 연결된 지도 오버레이다. 처음에는 연안만 켜며, 관광지나 해상 칸을 선택하면 시간축과 상세 시트가 열린다. 해상·연안 스위치는 기존 범례 칸에 쌓인다. 선택한 층을 끄거나 Escape를 누르면 시트와 선택 위험구역을 지운다.

지도 범례에는 예비특보·주의보·경보·특보급 날씨 가능성(3일째) 네 줄을 두지 않는다(과제13). 남기는 범례는 해상의 「종합 관심단계/공식 사고예보」 등 색상 범례 한 개뿐이다(2026-10-15 정정: 종합 관심단계 폐지 — 해상 기본 범례는 현재도 「공식 사고예보」). 특보 구역도 지도에 그리지 않는다(2026-10-15, 아래 「특보 영역 미표시」 절). 특보 내용은 상세 시트에 표시한다.

점수·시간축·특보 판정은 `/api/risk-forecast/*` 서버 응답을 사용한다. 연안 관광객 분석은 기존 계산을 유지한다. 해상은 GR4 크기의 공통 표출 격자 하나에서 현재 종합 관심단계·미래 공식 사고예보를 연속 면색으로 표시하고(2026-10-15 합의 변경: 현재도 공식 사고예보 그대로, 혼잡·현재 척수는 상세의 「충돌·접촉 주의」 안내로만 — [marine_fusion.design.md](marine_fusion.design.md) 「충돌·접촉 주의」), 원본 사고·혼잡·현재 교통을 상세에서 비교한다. 클릭 위치에 포함되는 두 격자를 공간으로 연결하며 사고지수에 혼잡 가중치를 추가하지 않는다. 파고·풍속·파주기·파향은 같은 3시간대의 기상청 해구 예보를 별도 출처로 표시한다. 자료가 없거나 수집이 실패하면 정상값을 만들지 않는다.

- `risk_forecast.js`: 버튼·층·선택·60초 자료 갱신 조율
- `risk_api.js`: 요청당15초 제한·최대3회 일시 장애 재시도, 경로별 TTL과 동시 요청 중복 방지
- `risk_map_layer.js`: 육지로 잘린 연안 분할 원·모든 관광지의 선택 중심점, 부드러운 단일 해상 면색·확대 척수·공식 원본 위치 연결, 21개 섬(특보 구역은 그리지 않음)
- `risk_slider.js`, `risk_sheet.js`: 서버 시간축·자료 신선도와 상세 문장·연안 합계 배수 설명·동일 좌표 관광지 선택 목록(해상 시트 시각 막대는 시각별 공식 사고 위험 색)
- `risk_marine.js`: 해상 지점 시트 본문(위 카드·과거 2주간 선박교통량 그래프·과거 선박사고 도넛·날씨·출처)과 지도 면색 보간(위험·혼잡 두 팔레트)
- `risk_format.js`: DMS 정수 초, 16방위, HTML·출처 URL 보호, 색과 숫자 명암
- `risk_basis.js`, `risk_basis_content.js`: 기준 상세 및 서버 PDF 다운로드

## 해상 화면 후속 수정 — 2026-10-13

위험예측 버튼은 페이지마다 비활성 모습으로 시작한다. 첫9회는 기능과 다른 오버레이에 영향을 주지 않고,10회째에 해제하면서 연다. 이후 같은 페이지에서는 보통 토글로 동작한다. HTML disabled는 클릭을 받지 못하므로 aria-disabled와 캡처 처리로 구현한다. 서버 인증이나 자동수집 중지 기능은 아니다.

연안·해상 스위치는 위험지형과 동일한 banzone/bzl 스타일을 사용한다. 해상ON은 기본 통합색, 하위 아코디언의 사고위험 예보·실시간 교통·혼잡도 예측은 한 항목만 선택된다. 선택 후 접고 뱃지로 알리며, 선택한 항목을 다시 끄면 기본 통합으로 돌아간다. 실시간 교통 선택은 현재로 복귀하고, 미래 버튼을 누르면 기본 미래 공식 사고예보로 전환한다. **(2026-10-15 대체: 하위 아코디언·뱃지는 없앴다 — 아래 「해상 시트·지도 조작부 화면」 절.)**

메인 해상 슬라이더 대신46px 전폭 하단 바의 고정 날짜·시각 output과 현재/+3H/+6H/+12H 버튼을 제공한다.11시+3H는12시, 다음+3H는15시다. 바는 메인 탭 바로 위이며 출처·축척·색상범례는 그 위로 올린다. 상세 시트의 시간축은 유지하고 메인 시각과 독립적이다. 예보 범위 밖 버튼은 비활성화한다.

**과제2 — 연안·해상 공통 메인 시각**: 이 하단 바는 해상 전용이 아니라 연안·해상 공통 하나다(연안만 켠 기본 화면에서도 보인다). 연안 ON이면 서버 `meta.timeline.coast`의 3시간 칸(지금~내일 21시 — 아래 「가」)을 그대로, 해상만 ON이면 지금~내일 21시를 고른다. 두 층의 끝이 같으므로 내일 21시에서 앞으로 버튼이 모두 비활성이 된다(종전의 「해상 예보 범위 밖 (내일까지)」 안내는 연안만 남는 모레 구간이 없어져 삭제). 둘 다 끄면 바가 숨는다. 시트 시각은 계속 독립이다.

결측은 면색·클릭 대상에서 제외한다. 확대 시 화면 주변 격자만 만들고 전국 보기에서는 같은 색상의 폴리곤을 최대256개 도형으로 묶는다. 숫자는 확대된 실시간 교통에만 표시하며, 공간 클릭은 원래 격자와 수치로 연결한다. 완성된 면색에 흐림을 한 번 적용한다. 부가 경계/연안 실패가 정상 해상 프레임 표시를 막지 않는다.

## 특보 영역 미표시 — 과제14 폐지 (2026-10-15)

> 사용자 원문(2026-10-15): *「이미지를 보면 지도에 특보 영역을 표시하지 말자고 했는데 나오고 있는데 없애주고. 범례를 없앴으니 다시 없애야지.」*

위험예측 지도(연안·해상)에는 **특보 구역을 칠하지도, 테두리로 그리지도 않는다.** 과제13에서 특보 범례를 없앤 데 맞춰, 과제14로 넣었던 「특보 있는 해상 구역 배경 면」을 통째로 걷어냈다.

- 화면: `risk_forecast.js`의 `refreshWarnings`(특보 구역 요청·그리기)를 지웠다. `risk_map_layer.js`에서 특보 층 `borders`(`rf-borders-canvas`), `drawWarnings`·`zonesLoaded`, 구역 이름 맞춤(`zoneKey`·`zoneGeometry`)을 지웠고 `boundaries()`는 더 이상 `/api/warn-zones`·`/api/warn-zones-sub`를 내려받지 않는다(육지·섬 외곽선만).
- 서버: 이 화면 전용이던 `GET /api/risk-forecast/warning-zones`와 `risk_store.warningZones`, 연안·해상 frame 응답의 `borders` 필드와 그 계산 함수 `borders()`를 지웠다. 화면이 그리지 않는 자료를 매 시각 계산·캐시하지 않는다.
- 그대로 둔 것(다른 화면과 공용): `/api/warn-zones`·`/api/warn-zones-sub` 경로와 정적 도형 파일(해양지도 탭 `ocean_warn_*`, 위치 알림, 온보딩이 사용), 특보 수집·푸시, 해구 예보. 상세 시트의 특보 행·특보 안내 문구와 해상 점수의 특보 반영은 지도 표시가 아니므로 유지한다.
- 지난 결정 「다」(예비특보 구역은 칠하지 않음, 2026-10-15)는 이 결정으로 흡수됐다 — 이제 어떤 특보 구역도 칠하지 않는다.

## 원천 오류 표시 정책 — 과제16

특보·해구 기상·행사 등의 실패/낡음/결측 공통 배너와 상세 시트의 공통 경고 목록은 공개 지도에서 숨긴다. 수집 상태를 정상으로 바꾸지는 않는다. 개별 값의 자료 없음, 선택한 상세를 읽지 못했을 때의 재시도는 유지한다. 오류 내역은 통합 관리자 센터 **AI → AI 사고예측 → 오류현황**에서만 확인한다. 운영 감시는 `risk_history_sources`의 작은 메타데이터와 기존 `risk_store.sources`의 신선도 규칙을 사용하며 화면용 예보 캐시를 강제 로드하지 않는다. 상세는 [오류 이력 운영 문서](../../../../00_docs/operations/risk-forecast-error-history.md)를 참고한다.

## 자료 없음 문구 판정 — 과제4

행사·특보·강풍이 **없는 날(원천은 정상 수신, 목록만 빔)** 은 서버 `missing`·프레임 `degraded` 에 들지 않아 화면에 자료 없음 문구가 나오지 않는다. **받지 못한 경우(파일 없음·손상·오류·낡음)** 만 `missing` 에 들고, 연안 시트에서는 행사 행의 「자료 없음」과 「확인된 요소 기준」 안내로 정상 없음과 구분된다. 전역 경고 목록은 과제16대로 숨기고 관리자 오류현황에 기록한다. 이안류 **비수기(`offseason`)** 는 정상 상태라 `rip` 결측으로 세지 않는다. 검사: `test_risk_missing_notice`.

## 상세 시트 고정 머리·하단 탭 위 배치 — 과제5·7

시트(`#risk-forecast-sheet`)는 지도 박스가 아니라 화면(viewport) 기준 `position:fixed`로 `bottom:var(--ls-bottom-chrome)`(메인탭+열린 서브탭 높이) 위에 놓는다. `--main-tab-height`가 탭 offsetHeight 실측값이라 아이폰 아래 여백(safe-area)이 이미 들어 있어 `env()`를 더하지 않는다. 서브탭이 열리면 변수가 서브탭만큼 커져 이중 여백이 생기지 않는다.

시트 안은 `.rf-sheet-head`(손잡이·닫기·제목·부제·시각 조작, 고정)와 `.rf-body`(내용, 이 안에서만 스크롤)로 나뉜다. 연안·해상·공식 사고 상세, 해상 종합·관할 브리핑 렌더, 같은 위치 관광지 선택 목록이 같은 머리를 쓴다. 닫기 버튼, PopupStack 등록, 휴대폰 뒤로가기는 그대로다. 미리보기(`risk_forecast_preview.html`)는 프레임 안 absolute 배치를 유지한다.

## 시트 고정 일시 표시 — 과제8

슬라이더 말풍선(`.ocean-sheet-tooltip`)을 없애고 슬라이더 위 빈칸에 `<output class="rf-time-label">`로 「'26.10.14(수) 15:00」(KST)를 고정 표시한다. 값은 시트의 `selected.at`(손잡이를 움직이면 그 값)이며 `RiskFormat.stamp`로 만든다. 메인 지도 시각(`t`)은 읽지 않는다 — 메인 15시, 시트 18시로 옮기고 닫으면 메인은 15시, 다른 지점의 새 시트도 15시로 시작한다. 해상 메인 하단 바의 현재/+3H/+6H/+12H와 고정 일시는 그대로다.

## 즉시 열기와 로딩 스켈레톤 — 과제6

지점을 누르면 응답을 기다리지 않고 시트를 열어 회색 틀(`.rf-skeleton`)을 보인다. 제목은 이 지점의 이름을 아는 연안만 쓰고(해상은 「불러오는 중…」) 이전 지점의 제목·내용은 남기지 않는다. 시트 시각 조작을 바꿔도 같은 지점의 제목은 두고 본문만 회색 틀로 바꾼다. 60초 자동 갱신은 열린 상세를 회색 틀로 바꾸지 않는다. 열린 시트는 응답 전부터 휴대폰 뒤로가기(PopupStack) 대상이다.

늦게 온 응답은 기존 검사(요청 세대·선택 객체·요청 시각 일치)로 버린다: 먼저 누른 다른 지점, 이전 시트 시각, 이미 닫은 시트의 응답은 화면에 나오지 않는다. 요청이 실패하면 회색 틀 대신 오류와 「다시 시도」를 보이며 결측을 정상처럼 꾸미지 않는다.

## 위험구역 현황 아코디언과 지도 중앙 이동 — 과제10

연안 「위험구역(3km 안)」 줄의 「위험구역 N곳 현황」은 버튼 모양(높이 40px 이상, ▾ 표시)의 접힘 아코디언이다. 구역을 누르면 지도가 그 구역을 **시트에 가려지지 않은 남은 지도 영역의 가운데**로 이동·확대하고, 목록에서 그 구역이 눌린 상태(`aria-pressed`)로 표시된다. 다른 구역을 누르면 이전 표시는 해제되고, 다른 지점을 고르면 구역 표시가 지도에서 사라진다. 해상 관할 해역 이동(`marinePoint`)도 같은 여백 계산(`visiblePadding`)을 쓴다. 설계 결정 U72·U74⑦·U78⑥은 `coastal_safety_forecast.design.md`.

## 해상 시트·지도 조작부 화면 — 2026-10-15 시안 8차 구현

확정 시안: 해상 시트 8차(+추가 확정 5가지)와 지도 조작부 시안. 서버(`marine_fusion`·`sea_traffic_history`)는 고치지 않고 응답만 쓴다.

**지도 조작부** (`risk_forecast.js`) — 「표시 항목」 접이식(사고위험 예보·실시간 교통·혼잡도 예측)과 「~ 표출 중」 뱃지를 없앴다. 해상 토글이 켜지면 바로 아래 두 칸 단일 선택 **[혼잡도][위험 예측]**(기본·다시 켤 때 [위험 예측])이 나오고, 끄면 숨는다. 켜진 칸을 다시 눌러도 그대로다.

| 선택 | 메인 시각 | 서버 `unified-frame` mode | 범례 제목 | 범례 단계·색 |
|---|---|---|---|---|
| 위험 예측 | 지금·미래 | `risk`(공식 사고예보) | 위험 예측 | 낮음·보통·주의·경계(위험 색) |

**시트 머리** — 제목·관할은 그대로. 해상 시각 막대(`RiskSlider.mount(...,{risk:true,now})`)는 칸마다 그 시각이 든 3시간 공식 사고 위험 단계 색(분석 응답 `marine.outlook.accident`, 응답 전·모르는 칸은 회색), 3시간 눈금·자정 날짜·6시간 「HH시」, 막대 위 가운데 4단계 범례, 「지금」 꼬리표, 미래를 고르면 지금 자리에 파란 눈금과 시각 글자 뒤 「 · 예보」. 연안 막대는 바꾸지 않았다.

**시트 본문** (`risk_marine.js` `render`·`attach`) — 순서: 위 카드 → 과거 2주간 선박교통량 → 이 해역 과거 선박사고 → 날씨 → 출처(+[기준 상세]).

- 위 카드: 「위험 예측」 뱃지(공식 사고 단계·색) + 「최근 5년 간 사고사례 및 / 기상정보 기반 예측 결과」. 예보 시간 줄(「15~18시 예보」)은 없다(추가 확정 1). 지금이면 「밀집도」 뱃지(`current.densityLevel`, 혼잡 색) + 「이 해역 선박 N척(밀집도 x.x%)」 + 충돌주의(`collisionNotice.on` → 「충돌·접촉사고 주의」 굵게) + 「HH시 혼잡예보 [단계]」. 미래면 「혼잡도」 뱃지 + 「혼잡 지수 x.x」 + 충돌주의. 「매우높음」은 뱃지 글자만 줄인다.
- 값이 없을 때(지어내지 않는다): 서버 상태가 `ok` 가 아닌 사고·혼잡 예보, 낡은(15분 넘은)·없는 현재 교통은 단계 뱃지를 「-」로 둔다 — 지도 면색이 같은 자료를 칠하지 않는 규칙(`unifiedFrame`)과 같다. 낡은 현재값은 「이 해역 선박 정보 없음」 아래 「마지막 자료 HH:MM 기준 N척 · 최신성 확인 필요」로 숫자만 보인다(종전 상세의 「최신성 확인 필요」 원칙).
- 과거 2주간 선박교통량: `GET sea/traffic-history?cell=<current.gridId 또는 congestion.gridId>&days=15`. **days=15 인 까닭**: 서버 `days` 는 오늘 포함 달력일이라, 지금 30분 칸을 끝으로 하는 14일(672칸)과 평균의 최근 14번을 다 덮으려면 15일이 필요하다. 칸이 없으면 요청하지 않고 카드는 「-」.
