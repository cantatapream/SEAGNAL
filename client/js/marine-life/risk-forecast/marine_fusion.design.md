# 해상 교통·공식 예보·사고 이력 통합

현재 전국 GR4 교통량(척수)·밀집도와 공식 혼잡 GAN 예보, 공식 사고 MLP 예보, 기존 선박사고 이력을 위치로 연결한다. 연안 관광객 사고 데이터·기존 연안 배수 모델과 혼합하지 않는다. 현재 척수와 미래 예보의 시각은 별도 표기한다. 공식 사고 원시 지수는 확률이나 상대배수로 변환하지 않는다.

## 수집과 메모리

`sea_realtime_collector`는 Fly 운영에서 5분 구간마다 최신 한 벌을 원자 교체한다. `MTIS_REALTIME_SERVICE_KEY`를 설정하면 해당 키를 우선 사용하고, 미설정이면 기존 MTIS 사고 키를 사용해 공식 v2를 시도한다. 키가 없거나 API가 실패하면 마지막 정상 파일을 그대로 두고 오류 상태만 남긴다(웹으로 대신하지 않는다 — 아래 「MTIS 웹 수집 제거」). 밀집도 누락을 0으로 채우지 않는다. API 모든 페이지의 totalCount·등록시각·ID 중복을 검증한다. 기본 호출 상한 1,200건/일은 앱의 보호 상한이며 공식 허용량이 아니다. 최신 조회만 수행하며 2023년 이후 장기 과거자료를 수집하지 않는다.

최신 파일 `sea_realtime.json.gz`는 `cells` 경계를 한 번, `rows=[i,척수,밀집도]`로 저장한다(2026-10-15 전 저장본은 뒤에 선종7·톤수10 칸이 더 있으나 읽지 않는다). 시각은 API 등록시각(regDt)으로 표기하고 관측시각이라고 부르지 않는다. 15분 이상 낡은 현재값은 지도 숫자·관심 판단에서 제외하고 상세에서 마지막값의 최신성 확인 필요를 표시한다. 누락은 정상·안전·0척으로 치환하지 않는다. 원천 실패는 마지막 정상 파일을 유지한다.

> ⚠**정정 (2026-10-15 밤)** — 「현재 교통 누락」은 이제 두 가지로 가른다. ①**수집 실패·낡음**(파일 없음, 15분 넘음)은 지금처럼 모름(null, 0척으로 치환하지 않음). ②**최신 응답(status ok)에 그 칸이 없음**은 0척이다 — 공단 실시간 API 는 배 없는 칸을 보내지 않는다(운영 응답 3,890칸 중 척수 0 칸 0개·최소 1척, 실행 확인). `analysis` 의 `current` 는 이때 `{count:0,density:0,densityLevel:'낮음',absent:true}` 를 낸다. 지도 [혼잡도](지금)도 최신 응답에 없는 칸을 「낮음」(0척, 숫자 글자 없음)으로 칠한다(사용자 2026-10-15 「혼잡도에서 배가없는 칸을 낮음으로 색칠해줘」). 수집이 낡았으면 아무 칸도 칠하지 않는다.

혼잡 예보는 `marine_congestion_codec`가 격자ID·좌표·생성시각을 공통 표로 분리하고 시각별 `[i,지수,단계,생성시각index]`를 저장한다. 기존 저장본과 상세 API 계약을 계속 지원하며 최대8시각만 기존 행 객체로 해석한다. 관할 분석은 작은 수치 위치표로 개별 격자를 조회한다. 과거 선박사고는 요청마다 전부 다시 읽지 않고 최근5개연도 공간 버킷·요약을 공유한다. 상세/브리핑은 외부 수집이나 Gemini 호출을 실행하지 않는다.

## 공간과 시각

해역명은 기존 `risk_sea_cells.describe`의 주요 지명 좌표·16방위·해리 거리와 `해양종합정보 → 해구기상`의 `marine_zone_area.json` 대해구 및 같은 3×3 소해구 번호를 사용한다. 예: 제주항 북서방 8.2해리 해역(163-6해구). (2026-10-19 덧붙임: 해상 분석 결과에 `nameRef` = 그 이름을 만든 같은 칸의 중심·주요지명·해구도 싣는다 — 연안 안전 브리핑 「지금 밀집」이 해역 카드와 같은 규칙(주요지명이 10km 넘게 멀면 관할 관광지)으로 이름을 다시 짓는 재료, `coastal_safety_forecast.design.md` §11.10.38. 이 시트 제목은 그대로 주요지명만.) 원본 교통 GR4와 약5㎞ 사고 격자를 실제 선택 위치의 공간 포함으로 연결한다. 공유 경계는 ID순 한 칸을 대표로 고른다. 과거 사고 통계는 연결한 사고 예보 격자 전체의 값임을 명시한다.

현재 교통은 최신값으로 계속 별도 표기한다. 혼잡은 선택시각이 속한 정시, 사고는 선택시각이 속한3시간대, 기상은 기존 해구별 예보의 유효범위와 가장 가까운 제공시각을 사용하고 각 실제 예보시각을 표시한다. 통합 시간대별 표는 오늘·내일로 제한한다. 기존 공식 사고 수집기의3일 원본은 유지한다. (2026-10-15 정정: 사용자 「해상 공식 사고예보는 2일까지만」에 따라 수집기도 오늘·내일 16칸만 받고, 통합 조회 시각 `time()`도 지금+72시간 대신 오늘00시+48시간 미만만 받는다 — 설계 결정 U80, [guide.md](guide.md) 「해상 공식 사고예보 2일 제한」.)

시트 시각은 열린 시트 안에서만 유효하다. 메인15시 → 시트18시 → 닫으면 메인15시 유지, 다른 시트도15시 시작. 시트에서 바꾸는 시각은 메인 지도 프레임을 변경하지 않는다. 기존 미완료 메인 슬라이더 작업은 이번 PR에 포함하지 않는다.

## 사고 이력 범위

현재 앱 자료의 가장 최근 연도를 끝으로 최근5개연도를 집계한다(현재 자료는2021~2025). 위치·날짜·사고유형·원인·사망·실종을 사용하고 구조인원은 피해 합계에 더하지 않는다. 충돌·접촉·좌초/좌주·전복·침몰/침수·화재·폭발·표류·행방불명 유형과 기상악화 원인을 포함한다. 해양오염·부유물감김은 원인이 기상악화여도 우선 제외한다. 기타 기관손상·운항저해 등은 기상악화 원인이 명시된 경우에만 포함한다. 기상악화 침몰은 전체 사고1건, 기상 원인 별도1건으로 집계한다. 인명 수치 미기록은0명 확인으로 표현하지 않는다. 공단 MLP는 부유물감김 등을 포함하므로 앱 필터로 공식 지수를 다시 산출하지 않는다.

## 관할 브리핑

기존 파출소 폴리곤에 교통 격자 중심을 배정해 전체 현재 척수를 집계한다(선종별 척수는 2026-10-15 제거). 겹친 관할은 이름순1개로 고정 배정하여 이중 합산하지 않는다. 실제 선박 위치가 없으므로 결과는 '관할 대응 격자 기준'이며 경계 선박의 정확한 관할 척수로 표현하지 않는다. 수신 격자가 없는 관할은 자료 없음이다. 과거 사고는 사고점 위치로 관할에 배정한다.

모든 현재·예보 격자를 검토하고 같은 공식 사고격자를 중복 관심구역으로 집계하지 않는다. 같은 사고격자에 연결된 모든 교통격자를 분석한 뒤 관심단계가 높은 격자를 대표로 선택하고, 단계가 같으면 현재 척수가 많은 격자를 선택한다. 공식 사고 주의/경계, 혼잡 높음/매우높음, 현재 GR4 21척 이상을 근거로 관심 해역을 추출하고(2026-10-15 정정: 여기에 「충돌·접촉 주의」(혼잡 높음 이상 또는 현재 14척 이상)도 '관심 필요' 근거로 더한다 — 맨 아래 「충돌·접촉 주의」 절) 우선순위20개를 표시하되 전체 건수도 보존한다. 기상과 사고 이력은 설명 근거이지 사고확률 가중치가 아니다. '순찰하라' 대신 '관심 필요·운항 시 주의 필요·공식 경계 단계 확인 필요'를 사용한다. 선택한 시각에서 오늘·내일의 주의 시간대를 근거와 함께 표시한다. 문장은 규칙 기반으로 생성하며 같은 결과를 격자 시트와 브리핑이 공유한다.

## 모바일 지도 단순화(2026-10-13 사용자 추가 요구)
GR4 하나로 표출 격자를 통일한다. 사고예보/혼잡예보/현재교통 중 한 항목만 면색으로 표시하며 점·점선·중복5㎞ 격자선을 제거한다. 사고는 원본5㎞ 값을 GR4 중심 위치로 연결한 표출이며 새로운 고해상도 사고예측이 아니다. 격자선은 확대 시에만 가늘게, 현재 척수 숫자는 더 확대할 때만 충돌 방지(declutter)와 함께 표시한다. 범례는 선택 항목의4단계만 한 줄로, 관할 선택은 접힌 항목으로 둔다. 상세에서 세 원천을 함께 비교한다.

현재 기본 지도는 앱의 종합 관심단계(낮음/관심/주의/경계)이다. 공식 낮음·보통이면서 현재 GR4척수14이상이면 관심을1단계 높이고, 공식 주의·경계는 낮추거나 상향 가중하지 않는다. 미래는 공식 사고단계(낮음/보통/주의/경계)로 자동 전환한다. 현재 미수신·낡음은 공식값만 사용한 셀 수를 응답에 표시하고 상세에서 알린다. 밀집도와 척수를 중복 가중하지 않으며, 조합표는 검증된 사고확률이 아닌 사용자가 합의한 관심 규칙이다. 주요 기준은 상세의 접힌 기준보기로 이동한다. **(2026-10-15 합의 변경 — 이 문단의 종합 관심단계·14척 한 단계 올림은 폐지. 현재도 공식 사고단계 그대로이고 혼잡·척수는 「충돌·접촉 주의」 안내로만 쓴다. 맨 아래 절.)**
사고정보 화면의 Heatmap은 점밀도 합산 방식이므로 그대로 복제하지 않는다. 원본 GR4 면색의 경계만6px blur로 부드럽게 하고 육지를 다시 마스킹한다. 숫자는 별도 선명한 텍스트층으로 확대할 때만 표시한다. 색을 부드럽게 해도 원본값·단계·클릭 공간 포함은 변경하지 않는다.

색상은4개 고정색을 칠하지 않고0~1색상위치를 RGB 연속 보간한다. 공식 단계별 원지수 범위의 로그 위치로 같은 등급 안의 색을 구분하고, 현재는 합의한 관심단계를 유지하며 등급 안의 공식 지수 위치와 현재 척수(28척 상한) 위치를 절반씩 반영한다(2026-10-15 정정: 현재 척수 반영 폐지 — 현재도 공식 지수 위치만 쓴다). 이것은 색상 표시규칙이며 사고발생확률이나 별도 공식지수가 아니다. 범례는 좌측하단 한 개이며 제목·연속 그라데이션 막대·4단계 이름을 쓴다. 현재/예보 뱃지가 바뀌고 의미가 바뀔 때에만650ms제목 강조를 주며 reduced-motion에서는 애니메이션을 생략한다.

교통 격자가 없는 사고예보 해역도 빠뜨리지 않도록 원본GR4와 같은0.025도 표출망으로 확장한다. 확장 칸은 내부 display_ ID를 쓰고 공식GR4번호로 표현하지 않는다. 원본5㎞ 사고 값은 칸 중심 공간포함으로 연결하고, 정확한 클릭 위치의 원본 격자는 상세에서 다시 확인한다. 현재 교통 미수신 칸은0척으로 만들지 않는다.

## 최우선 후속 화면 계약 — 2026-10-13

### 서버 — `marine.warnings` (`/sea/analysis`)

```json
"warnings": {
  "status": "ok",
  "updatedAt": "2026-10-16T09:01:00+09:00",
  "zone": { "name": "제주도북부앞바다", "kind": "앞바다" },
  "items": [
    { "zone": "제주도북부앞바다", "kind": "앞바다", "type": "풍랑", "level": "주의보",
      "issued":    { "start": "2026-10-16T04:30:00+09:00", "end": "2026-10-16T04:30:00+09:00", "range": false },
      "effective": { "start": "2026-10-16T06:00:00+09:00", "end": "2026-10-16T06:00:00+09:00", "range": false },
      "release":   { "start": "2026-10-16T21:00:00+09:00", "end": "2026-10-17T00:00:00+09:00", "range": true } }
  ]
}
```

- 원천: `risk_store.marineInputs().warnings`(= `weather_alerts.json`) 의 `current` 트리. 발효 판정은 교통량 그래프 특보 띠와 같은 `sea_warning_history.extract`(부모 `current`·자식 블록의 주의보·경보 — 예비 제외). `extract` 는 이번에 `tmFc`·`tmYn` 을 더 돌려준다(구간 기록 파일에는 쓰지 않는다).
- **구역**: GR4 칸이면 `warn_zone_cells.zonesOfCell`(그래프와 같은 칸 중심), 아니면 그 지점(`zonesAt`). 칸이 **세부구역(연안바다·평수구역)에 들면 그 세부구역의 블록만** 본다 — 부모 앞바다 특보가 「연안바다 제외」로 나오는 일이 실제로 있었고(`client/js/forecast/alerts/child_confirm.design.md` §1.1, 제주도북부앞바다 6/2·6/19), 크롤러는 MMIS 가 준 자식만 트리에 넣는다. 옛 `risk_store.warningsFor` 도 같은 규칙(자식이 있으면 자식, 없으면 부모로 채우지 않음). 세부구역 밖 칸은 본구역 블록.
- **시각 규칙**(t = 선택 시각, 지금·미래 같다):
  - 아직 발효 전이면 뺀다 — 발효시각이 정확한 시각이고 t 보다 뒤, 범위면 범위 시작이 t 보다 뒤.
  - 그 시각 전에 해제될 것으로 알려졌으면 뺀다 — 해제예정이 정확한 시각이고 t 이하, 범위면 범위 **끝**이 t 이하. 범위 안(해제예정 21~24시, t=22시)이면 아직 발효 중일 수 있어 남긴다. 해제예정이 없으면 남긴다(`release:null` → 「정보없음」).
  - 해제예정 = `clrNtcTm`(해제예고) → `tmCc` → `tmYn` — 특보정보 탭과 같은 순서.
  - 옛 `risk_time.warningAt`(해상 점수용)은 범위형 해제예정을 「그날 자정까지」로 넓게 잡는다. 이 상자는 사용자 원문 「해제 예정이 그 전이면 제외」에 맞춰 범위 끝을 쓴다 — 두 규칙은 일부러 다르다.
- **시각 읽기**(`warnTime`): `risk_time.parseMmisTime` 을 쓰되 ①빈 값 `''`·`'0'`·`'000000000000'`·`'일'` 은 null ②날짜 꼴(「N일」 또는 `YYYY.MM.DD`)이 없으면 null — `parseMmisTime('0')` 은 날짜 꼴이 없을 때 `Date.parse` 로 넘겨 **2000-01-01** 을 돌려준다(2026-10-16 실행 확인, 이 함수는 다른 곳도 쓰므로 고치지 않았다) ③12자리 `YYYYMMDDHHMM` 도 읽음 ④시작=끝 범위(예비 6시간 칸 표기 `23시~23시`)는 특보정보 탭처럼 그 6시간 칸(18~24시)으로 넓힌다. 월이 빠진 글자(`16일 …`)는 발표시각 기준 가장 가까운 달로 읽는다(옛 `warningAt` 과 같은 기준). 못 읽은 시각은 null — 지어내지 않는다.
- **여러 개**: 경보 먼저, 같은 단계는 발효 이른 순. 다만 크롤러 트리는 **구역마다 발효 블록이 하나**(MMIS `warn/list` 도 구역마다 가장 우선되는 종류 하나 — `mmis_history.design.md` §2.1.1)이고 한 칸은 한 구역만 보므로, **실제로는 상자가 최대 1개**다. 정렬은 대비용(시험은 인위적 두 블록으로 고정).
- **자료 낡음·실패**: `status` 가 `ok` 가 아니면 `items` 를 비운다(상자 없음). `status` 는 그대로 돌려줘 「특보 없음」과 「특보 자료 확인 불가」를 가를 수 있다 — 화면에 「특보 정보 확인 불가」 글을 띄울지는 정하지 않았다(사용자 판단).

1. 연안바다·평수구역 칸에서 부모 앞바다 이름으로 보일지, 세부구역 이름으로 보일지(지금은 세부구역 블록·이름). 같은 시트의 교통량 그래프 특보 띠는 본구역·세부구역 구간을 **둘 다** 깐다(`sea_traffic_history.createApi`) — 「연안바다 제외」 특보면 그래프에는 띠가 있고 상자는 없을 수 있다.
2. 아코디언이 닫혀 있어도 특보를 알 수 있게 머리에 작은 빨간 「특보」 표시를 둘지(제안만, 만들지 않음).
3. 특보 자료가 낡았을 때 「특보 정보 확인 불가」 같은 글을 띄울지(지금은 아무것도 안 그림).
4. 폭풍해일·강풍은 크롤러 결과에 없어 상자에도 나오지 않는다(크롤러 쪽 변경 필요).
