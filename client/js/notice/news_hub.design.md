## 2. 뉴스 고르는 기준

- **대상자**: 어업인(어선·맨손·해녀·어촌계)·양식인·낚시/레저 = 높음(같은 비중) / 수산물 유통·가공, 섬 주민·여객선, 해양경찰관 = 중간 / 선원(상선·해운) = 낮음
- **6개 영향 묶음**: 돈(정부·지자체 보조금 명시) · 처벌·의무 · 조업·이용 규칙 · 안전 · 바다 여건 · 바다 이용 갈등·제도
- **AI 판정 3단계**: 누구에게 → 무엇이 → 얼마나 확정·급한가(5·4·3점, 2점 이하 탈락)
- 이어지는 사고는 새 소식만, 해외 사고는 우리 연루·국내 규제 영향만, 같은 사건은 1장으로 묶음
- 견본 교훈: 단어 필터로는 확실한 것만 버린다(「수상」이 「수상레저」 법안을 잘못 버린 일)

### 2-1. 판정 AI 고르기
- 관리자 → AI → 「AI 모델 설정」 ⑦ **오늘의 뉴스 판정** 칸에서 고른다(사용자 2026-11-21 「Ai를 통합관리자센터에 있는거처럼 선택할수있도록 해줘. Ai모델선택하는것」).
  다른 기능(①~⑥)과 같은 방식 — 우선순위(▲▼·삭제·다시 추가), 칸별 모델·노력, ChatGPT 실행 위치, 「먼저 Gemma」.
- 기본: 「먼저 Gemma」 켜짐(gemma-4-26b-a4b-it, 무료) → 안 되면 Gemini. 다른 AI(클로드·업스테이지·ChatGPT)는 관리자가 「다시 추가」 해야 쓰인다(몰래 크레딧을 쓰지 않게 — ①③⑤⑥ 과 같은 규칙).
- 서버: `services/bulletin_ai.js` 의 `news` 기능 — 판정 코드(`news_judge.js`)는 `bulletin_ai.call('news', …, { accept })` 로 부른다.

### 어황정보 서버 — 확인한 것
- 실제 게시판에 연결해 돌림(2026-11-21 00:46 KST): 목록 10건 중 최근 7일 안 7건을 받아 PDF·쪽 그림 생성, 두 번째 실행은 다시 받지 않음(0.8초).
- 경로 확인: `GET /api/fishcond`(목록 7건) · `/view`(그림 5장) · `/page/1`(PNG) · `/pdf`(첨부, 한글 이름) · 꼴이 아닌 ID·쪽은 404.
- ⚠ 운영 서버(Fly, 도쿄)에서 국립수산과학원 사이트가 열리는지는 아직 모른다. 막혀 있으면 `state.json` 의 `ok:false` 와 이유로 드러난다(관리자 화면 단계에서 띄움).
- 남동해(남동해수산연구소) 글은 「남해」 꼬리표로 붙인다 — 통영 소재, 남해 동부. 사용자 확인은 받지 않은 판단이다.

### 오늘의 뉴스 서버 — 동작 요약
- 매시 2분(KST): 검색어(기본 46개, 관리자가 바꿀 수 있게 `data/news_config.json`)마다 최신순 100건, 모두 지난 확인 뒤 기사면 다음 쪽(최대 3쪽).
  창 = 지난 정상 확인 15분 전부터(늦게 색인되는 기사), 처음·오래 멈춘 뒤는 26시간.
- 겹침(주소·제목) 제거 → 3일 안에 판정한 기사(`seen.json`) 제외 → 마트 할인만 기계로 버림 → AI 판정 20건씩(⑦ 순서) → 3점 이상 카드.
- 같은 묶음 = 한 장(대표 = 원문 요약이 더 긴 기사), 이미 실은 카드와 같으면 새 사실 있을 때만 새 카드(`followOf`), 아니면 「외 N건」만 늘림.
- 판정이 끝까지 실패한 기사는 `pending.json` → 다음 시간에 다시(26시간 지나면 버림). 검색어 전부 실패·판정 전부 실패는 `state.json` `ok:false` + 이유.
- 새 카드만 대표 기사 페이지에서 og:image·og:site_name(로고로 보이는 주소는 버림). http 사진은 `/api/news/img` 가 우리 카드 사진일 때만 받아 바로 전달.
- 앱 API: `GET /api/news?date=` · `POST /api/news/:date/:id/open`(펼친 횟수, 관리자 하루 1번) · 30일 지난 날짜 파일 삭제.
- 관리자 API(숨기기·살리기·싣기·검색어·지금 갱신·상태)는 관리자 화면 단계에서 만든다.

### 같은 사건 중복 카드 한 번 더 합치기 (2026-11-22, 사용자 「중복내용 제외」)

  판정 AI 가 20건씩 묻는 판정 단계에서 묶음 표시를 빠뜨렸다. 해광호 실종 수색도 같은 날 카드 2~3장으로 나뉘어 있었다.

  지시문: 같은 기관의 같은 발표를 여러 언론이 쓴 것 = 한 묶음 · 같은 사고의 같은 날 보도(후속 포함) = 한 묶음 · **주제가 비슷해도 기관·지역·사건이 다르면 따로**(예: 해수부 원산지 점검과 경남도 원산지 단속은 따로).
- **합치는 법**: 보도가 가장 많은 카드(같으면 원문 요약이 긴 카드)의 id 를 남기고 「외 N건」·언론사·펼친 횟수를 더한다. **카드 머리(제목·요약·사진)는 묶음에서 가장 최근 기사**로 —
  사고 후속(「수색 사흘째」 + 「시신 발견」)이 합쳐질 때 새 소식이 묻히지 않게(판정 단계의 「같은 날 새 소식이면 머리를 최신으로」와 같은 규칙).
- **빠진 카드는 지우지 않고 그날 「AI 가 뺀 기사」로 옮긴다**(까닭: 「같은 사건으로 합침 → 「남은 카드 제목」」). AI 가 잘못 묶어도 관리자가 [싣기]로 되살릴 수 있다.
- **묶기에 넣지 않는 카드**: 숨긴 카드 · 관리자가 직접 실은 카드(관리자가 고른 것 — 되살린 카드가 다음 회차에 다시 합쳐지지 않는 것도 이것 덕분).
- **AI 가 실패하거나 답이 틀리면**(없는 번호·한 카드가 두 묶음) **합치지 않는다.** 처음엔 제목 글자 겹침으로 기계가 대신 묶게 했으나, 검토에서

  실패한 날은 `state.json` `dedupeRetry` 에 남겨 **새 카드가 없어도 다음 회차에 다시 묻고**, 관리자 화면에 「같은 사건 합치기 실패」 줄을 띄운다(조용한 실패 금지). 성공하면 「이번 회차」에 「같은 사건 합침 N장」.
