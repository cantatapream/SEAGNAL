# 파출소 97곳 주소 — 웹 대조 목록 (2026-10-16)

> 「활동지점 안전 브리핑」의 관할 대표 위치는 **파출소 주소를 좌표로 바꿔** 쓴다(§11.6-12, 사용자: *"파출소위치는 웹에서 검색하면 각 주소가 나올거야. 그 주소로 하면될것같은데"*).
> 주소 원천 = 정리판 `local_server/config/coastal_safety/coastguard_stations.geojson` 의 `address`(각 지방해양경찰청 사무분장 규칙 [별표 1] PDF 에서 읽은 것 — 고친 곳은 원문이 `address_raw`, 이유·출처가 `address_fix`).
> 좌표 = 운영 서버가 처음 한 번 카카오 검색(행사 위치 찾기와 같은 `coastal_events_collector.geocode`, 키 `KAKAO_REST_API_KEY`) → `data/station_briefing/locations.json` 에 저장.

### 한 줄 요약

97곳 모두 웹 출처를 하나 이상 찾았다(못 찾음 0). **일치 77 · 다름 20** — 다름 20곳 가운데 **11곳은 같은 장소의 표기만 고쳤고**(정리판 `address` 수정, 원문 `address_raw`), **9곳은 번지나 도로가 달라 어느 쪽이 지금 주소인지 웹으로 가를 수 없어 고치지 않았다**(사용자 판단). 이전·이름 변경·폐지로 보이는 곳: 이름 변경 4곳은 모두 지금 이름이 정리판과 같고(아래), **당진은 2025-09-30 신청사 준공 보도**가 있어 웹 주소(옛 청사일 수 있음)로 바꾸지 않았다.

### 어떻게 찾았나 (실제로 된 것과 안 된 것)

- **해양경찰서 누리집(kcg.go.kr)은 이 작업트리에서 직접 열 수 없었다** — `curl` 은 프록시가 403(CONNECT 거부)으로 막았고, WebFetch 는 `getaddrinfo ENOTFOUND www.kcg.go.kr` 로 실패했다. 위키백과·나무위키·law.go.kr·google·naver·web.archive.org 도 같은 방식으로 막혔다. 그래서 **kcg.go.kr 쪽 주소는 검색엔진(WebSearch)이 그 쪽을 읽고 돌려준 발췌**다 — 표의 「kcg」 링크는 그 발췌가 가리킨 쪽이며, 쪽을 내가 직접 열어 본 것은 아니다.
- **공공데이터포털은 내려받아 직접 대조했다**(`[공공]`):
  - [15105156](https://www.data.go.kr/data/15105156/fileData.do) 「해양경찰청_해경청(파출장소)_경찰청(치안센터)_소방청(119안전센터)_주소_20211231」 — 해경 파출소 94행.
  - [15112633](https://www.data.go.kr/data/15112633/fileData.do) 「…주소_20260701」(수정일 2026-09-02) — **해경 329행이 2021 판과 한 글자도 다르지 않다**(정렬 후 `diff` 로 확인). 옛 이름(봉산·노량·서산·신안파출소)·옛 주소(장항 2020 이전 전 주소, 당진 신청사 전 주소)가 그대로라 **최신 자료가 아니다.**
  - [15013197](https://www.data.go.kr/data/15013197/fileData.do) 「해양경찰청_관서현황_20241231」 — 파출소 수만 있다(2021년 96 → 2022년부터 97). 주소 없음.
  - [15084895](https://www.data.go.kr/data/15084895/openapi.do) 「해양경찰청_파출소 위치」 — 오픈 API(인증키 필요), 수정일 2022-09-16 — 쓰지 않았다.
- 그래서 **판정 원칙**: 정리판(별표)은 사무분장 규칙 개정판이라 웹 자료(2021 공공데이터·작성 시점 모르는 누리집 쪽)보다 새것일 수 있다(당진·장항·암태가 실제 예). 따라서
  - **같은 장소의 표기 차이**(도로명 오기, 도로명 앞에 끼어든 동·리 이름, 빠진 읍·면 이름, 번호 안 띄어쓰기)는 웹 표기로 **고쳤다**.
  - **번지·도로가 다른 곳**은 웹이 옛 주소일 수도, 별표가 틀렸을 수도 있어 **고치지 않고** 아래 「사용자 판단」에 올렸다.
- 「일치」 77곳 가운데 공공데이터만 출처인 곳은 **2021년 기준과 같다**는 뜻이다 — 그 뒤 이전 여부는 확인하지 않았다.

### 좌표 — 「주소가 바뀌면 다시 묻는다」 코드 확인

`local_server/services/station_briefing_inputs.js` `ensureLocations`: `const query = normalizeAddress(st.address); const want = geocoder && (!c || c.address !== st.address || (c.query && c.query !== query) || c.status === 'error');` — 캐시(`locations.json`)에 저장된 `address` 와 정리판 `address`(`loadStations` 가 `p.address` 를 그대로 넘김)가 다르면 다시 묻는다. 이번에 고친 11곳은 운영 다음 생성 때 카카오에 다시 묻는다(그 실행의 위치 찾기 60초 상한 안에서). 웹 검색으로 좌표를 찾아 넣지는 않았다.

- **사용자가 말한 「Google 검색 좌표」**: 장점 — 카카오가 「일치 없음」인 곳도 사람이 지도에서 바로 찍을 수 있다. 단점 — 검색 결과 좌표의 출처·정밀도를 기계로 검증할 수 없고(지금 구조는 카카오 결과의 시군구·도로·번지가 요청과 같아야만 채택), Google 지도 API 는 별도 키·과금·이용약관(지오코딩 결과 저장 제한)이 걸린다.
