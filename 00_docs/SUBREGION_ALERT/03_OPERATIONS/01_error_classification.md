# 자식해역 특보 표출 — 3.1 오류 분류

## 0. 본 파일의 위치

본 파일은 `03_OPERATIONS/` 시리즈의 첫 번째 파일이며, 자식해역 처리 과정에서 발생할 수 있는 모든 오류 유형을 분류하여 정리합니다.

---

## 1. 오류 분류의 목적

### 1.1 분류 의도

오류를 일관된 코드로 분류하면 다음이 가능해집니다.

- 오류 유형별 처리 정책 명시
- 오류 통계 집계
- 운영자에게 일관된 형식의 알림 제공
- 오류 로그 검색 및 필터링

### 1.2 본 작업의 오류 유형

본 작업에서 다음 8가지 주요 오류 유형을 정의합니다.

---

## 2. 오류 유형 (errorType) 전체 목록

| 코드 | 카테고리 | 설명 |
|---|---|---|
| `MAPPING_MISSING` | 데이터 | 매핑 테이블에 없는 해역 등장 |
| `LEVEL_CAP_APPLIED` | 데이터 | 자식 레벨이 부모를 초과하여 캡 적용됨 |
| `TIME_CAP_APPLIED` | 데이터 | 자식 시각이 부모를 초과하여 캡 적용됨 |
| `AFSO_RESPONSE_ERROR` | 외부 | 방재기상 API 응답 오류 |
| `TONGBOMUN_POLLING_ERROR` | 외부 | 통보문 폴링 실패 |
| `PARENT_CHILD_MISMATCH` | 데이터 | 부모 미발효인데 자식 발효 행 등장 |
| `STALE_PARENT` | 운영 | 부모 통보문 24시간 이상 무변화 |
| `RANGE_TIME_PARENT` | 운영 | 부모 통보문 범위형 시각으로 무한 대기 |

---

## 3. 카테고리별 분류

### 3.1 데이터 카테고리

방재기상 또는 통보문에서 받은 데이터 자체의 이상이 발견될 때.

- `MAPPING_MISSING`
- `LEVEL_CAP_APPLIED`
- `TIME_CAP_APPLIED`
- `PARENT_CHILD_MISMATCH`

이 카테고리의 오류는 **시스템은 계속 동작**하며, 처리 과정에서 발생한 데이터 이상을 기록하는 성격입니다.

### 3.2 외부 카테고리

외부 시스템(방재기상 API, 통보문 시스템)의 문제로 우리 앱이 영향을 받을 때.

- `AFSO_RESPONSE_ERROR`
- `TONGBOMUN_POLLING_ERROR`

이 카테고리의 오류는 자식해역 갱신을 일시적으로 보류해야 합니다.

### 3.3 운영 카테고리

장기 운영 중 발견되는 비정상 상태.

- `STALE_PARENT`
- `RANGE_TIME_PARENT`

이 카테고리는 즉각적인 동작 영향은 없으나, 장기적으로 시스템 무결성에 영향을 줄 수 있는 상태입니다.

---

## 4. MAPPING_MISSING 상세

### 4.1 발생 조건

방재기상 API 응답에 등장한 자식해역의 `regId`가 `region_alias_map.json`의 `subregions`에 없음.

### 4.2 처리 정책

- 그 행 무시 (사용자 화면에 표시 안 함)
- `region_alias_map.json`의 `unmapped` 섹션에 추가
- `subregion_error_log.json`에 오류 기록
- 첫 발생 시 관리자 푸시

### 4.3 사용자 영향

해당 자식해역의 정보가 사용자에게 표시되지 않음. 안전 측은 아니지만 큰 영향은 아님 (그 해역만 누락).

---

## 5. LEVEL_CAP_APPLIED 상세

### 5.1 발생 조건

방재기상 자식 행의 `wrnLvl`이 부모 통보문 현재 발효 레벨보다 높음.

### 5.2 처리 정책

- 캡 적용 (자식 레벨 = 부모 레벨)
- 자식해역 상태에 `confidence = WEAKLY_ESTIMATED` 마킹
- `subregion_error_log.json`에 오류 기록 (정보성)
- 신규 발생만 푸시 (반복 발생은 카운트만)

### 5.3 사용자 영향

자식해역 표시는 안전 측으로 처리됨 (부모 레벨로 캡됨). 사용자에게는 추정 마커가 표시될 수 있음.

---

## 6. TIME_CAP_APPLIED 상세

### 6.1 발생 조건

방재기상 자식 행의 `tmEd`가 부모 통보문 `tmCc`보다 늦음.

### 6.2 처리 정책

LEVEL_CAP_APPLIED와 동일.

### 6.3 사용자 영향

자식해역 종료 시각이 부모와 일치하도록 캡됨. 사용자 영향 미미.

---

## 7. AFSO_RESPONSE_ERROR 상세

### 7.1 발생 조건

다음 중 하나:

- HTTP 5xx 또는 타임아웃
- `meta.err == "true"`
- `data.metData == null`
- `data.metData == []`
- 응답 구조 깨짐

### 7.2 처리 정책

- 그 사이클 자식해역 갱신 보류
- 직전 자식 상태 그대로 유지
- 오류 로그 기록
- 첫 발생 시 관리자 푸시 (1회만, 연속 발생은 카운트)

### 7.3 사용자 영향

자식해역 화면 변화 없음 (직전 상태 유지). API 정상 복구 후 다음 사이클부터 갱신.

---

## 8. TONGBOMUN_POLLING_ERROR 상세

### 8.1 발생 조건

기존 통보문 크롤러가 실패하거나 응답을 받지 못한 경우.

### 8.2 처리 정책

- 자식해역 처리에서 신규 해제 처리 보류
- 자세한 처리: `02_error_handling.md` 참조

### 8.3 본 작업의 범위

통보문 폴링 자체는 기존 시스템이며 본 작업이 직접 변경하지 않음. 다만 본 작업의 자식해역 처리는 통보문 폴링 상태를 참조해야 함.

---

## 9. PARENT_CHILD_MISMATCH 상세

### 9.1 발생 조건

방재기상에서 자식해역이 발효 행으로 들어왔으나, 부모 통보문은 미발효 상태.

원칙 5(부모 없으면 자식도 없음) 위반 데이터.

### 9.2 처리 정책

- 자식 행 무시
- 오류 로그 기록
- 비교적 드물게 발생할 케이스이므로 개별 푸시

### 9.3 사용자 영향

해당 자식해역 표시 안 됨. 부모 통보문이 갱신되어 발효 상태가 되면 다음 사이클부터 정상 처리.

---

## 10. STALE_PARENT 상세

### 10.1 발생 조건

부모해역 통보문이 24시간 이상 변화 없이 유지되며, 동시에 자식해역도 변화가 없음.

### 10.2 처리 정책

- 운영 로그에 STALE 경고 기록
- 관리자 푸시 (반복 알림 방지를 위해 1일 1회)
- 시스템은 계속 동작 (자식 표시는 그대로 유지)

### 10.3 사용자 영향

직접적 영향 없음. 다만 통보문 시스템 점검의 신호로 활용.

자세한 안전장치 정책: `07_stale_safeguard.md` 참조.

---

## 11. RANGE_TIME_PARENT 상세

### 11.1 발생 조건

부모해역 통보문의 `tmCc`가 범위형 시각 (예: "오전(06~12시)").

### 11.2 처리 정책

- 자식해역 잠금 상태로 유지 (`tmEd = null`, `tmEdNote` 기록)
- 정보성 오류 로그
- 푸시 알림은 보내지 않음 (정보성)

### 11.3 사용자 영향

자식해역에 강한 추정 마커 표시. 사용자에게 추정 안내 툴팁 노출.

자세한 처리: `01_LOGIC/12_case_range_time.md` 참조.

---

## 12. 오류 신뢰도 분류

### 12.1 푸시 발송 대상 (높음)

다음 오류는 신규 발생 시 즉시 관리자 푸시:

- `MAPPING_MISSING`
- `AFSO_RESPONSE_ERROR`
- `PARENT_CHILD_MISMATCH`
- `STALE_PARENT`

### 12.2 정보성 (중간)

다음 오류는 로그만 기록 (푸시 미발송):

- `LEVEL_CAP_APPLIED`
- `TIME_CAP_APPLIED`
- `RANGE_TIME_PARENT`

### 12.3 외부 위임 (낮음)

다음 오류는 기존 시스템에서 처리:

- `TONGBOMUN_POLLING_ERROR`
