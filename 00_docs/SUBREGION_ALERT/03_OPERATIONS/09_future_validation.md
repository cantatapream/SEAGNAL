# 자식해역 특보 표출 — 3.9 향후 검증 사항

## 0. 본 파일의 위치

본 파일은 `03_OPERATIONS/` 시리즈의 마지막(아홉 번째) 파일이며, 본 작업 도입 후 **시간을 두고 검증해야 할 사항들**을 정리합니다.

본 작업은 일부 가정에 기반한 정책을 채택했습니다. 이 가정들이 운영 데이터로 검증되어야 합니다.

## 2. 검증 방법

### 2.1 데이터 수집

본 작업의 운영 로그(`subregion_error_log.json`)와 자식해역 상태 파일(`subregion_lifecycle.json`)에 모든 이벤트가 기록되므로, 이 데이터를 기반으로 가정 검증.

### 2.2 통계 수집 도구

```javascript
// local_server/scripts/analyze_subregion_data.js
// (선택적 도구)

function analyzeRecentMonth():
  errorLog = loadErrorLog()
  lifecycle = loadLifecycle()

  stats = {
    capApplyRate: countCapApply(errorLog) / totalCycles,
    mappingMissRate: countMappingMiss(errorLog) / totalCycles,
    concurrentDisappearCount: countConcurrentDisappear(errorLog),
    afsoErrorRate: countAfsoErrors(errorLog) / totalCycles,
    rangeTimeOccurrence: countRangeTimeLocks(errorLog),
    ...
  }

  return stats
```

### 2.3 정기 분석

- 일별 집계 → 단기 트렌드 파악
- 월별 집계 → 장기 트렌드 / 정책 조정 근거

## 3. 가정 1 — 방재기상 갱신 주기 (사용자 결정 사항, 검증 불필요)

### 3.1 사용자 결정 — 정책 고정

사용자께서는 "방재기상시스템이 언제 바뀔지는 몰라 지 멋대로라서, 부모해역 스케줄러에 맞춰 1분마다 폴링한다"고 결정하셨습니다.

따라서 본 항목은 **검증 대상이 아니라 고정 정책**입니다.

- 방재기상 갱신 시점 예측 불가
- 사용자에게 가장 빠른 변화 감지 보장을 위해 1분 폴링 무조건 유지
- 갱신 주기 측정 작업은 본 작업의 범위가 아님

### 3.2 향후 의사결정의 기준

만약 향후 1분 폴링이 자원/비용 측면에서 부담이 될 경우에 한해, 갱신 주기 측정 후 폴링 간격 조정을 검토할 수 있습니다. 본 작업의 1차 범위에서는 검토하지 않습니다.

---

## 4. 가정 2 — wrnSeq=99 신호

### 4.1 검증 방법

빈 행이 등장하는 패턴 분석:

- 정상 응답에 빈 행이 항상 있는지 확인
- 빈 행 없이 행 누락만 발생하는 케이스 빈도 측정
- 빈 행 → 발효 행 또는 발효 행 → 빈 행 전환 시점 확인

### 4.2 결과에 따른 정책 조정

- 빈 행이 신뢰할 수 있는 신호로 일관 동작 → 현재 정책 유지
- 빈 행이 등장하지 않는 케이스가 많음 → "행 누락"과 동등 처리 검토

---

## 5. 가정 3 — 동시 사라짐 패턴

### 5.1 검증 방법

- 부모-자식 동시 사라짐 발생 빈도
- 동시 사라짐 후 부모 통보문 해제 시점까지의 평균 시간
- 동시 사라짐 후 부모 통보문이 변경 없이 유지되는 경우 빈도

### 5.2 결과에 따른 정책 조정

- 대부분 부모 해제 시각까지 안정 유지 → 현재 정책 유지
- 동시 사라짐 후 부모 격상 등 의외 패턴 자주 발생 → 정책 재검토

---

## 6. 가정 4 — 격상 시 잠시 빠짐

### 6.1 검증 방법

- 자식 빠짐 후 재등장까지의 평균 시간
- 빠진 후 같은 레벨로 재등장 vs 다른 레벨로 재등장 비율
- "1회 빠짐" 정책으로 격상이 자연스럽게 처리되는지 확인

### 6.2 결과에 따른 정책 조정

- 1~2분 안에 재등장 → 현재 "1회 빠짐 유지" 정책 유효
- 3분 이상 빠지는 경우 빈번 → "2회 연속 빠짐 = 해제" 정책의 재등장 케이스 검토

---

## 7. 가정 5 — 통보문 정상 동작

### 7.1 검증 방법

- 통보문 폴링 성공률
- 통보문 변화 빈도
- stale 안전장치 트리거 빈도

### 7.2 결과에 따른 정책 조정

- 통보문 시스템 정상 → 현재 정책 유지
- 통보문 시스템 문제 빈번 → 보조 안전장치 추가 검토

---

## 8. 가정 6 — 범위형 시각

### 8.1 검증 방법

- 범위형 시각 등장 빈도
- 범위형 → 정확 시각 갱신까지의 평균 시간
- 범위형이 24시간 이상 유지되는 케이스

### 8.2 결과에 따른 정책 조정

- 거의 발생 안 함 → 현재 무한 대기 정책 유지
- 자주 발생하고 갱신 지연 빈번 → "범위 최대값으로 캡" 정책 도입 검토

---

## 9. 가정 7 — 단일 특보 종류

### 9.1 검증 방법

방재기상 응답에서 한 해역에 여러 종류 특보가 동시 발효되는 케이스 발생 여부.

### 9.2 결과에 따른 정책 조정

- 발생 안 함 → 현재 정책 유지
- 발생 → 다중 특보 처리 정책 도입 검토

---

## 10. 가정 8 — 매핑 변경 빈도

### 10.1 검증 방법

- 매핑 누락 발생 빈도 (전수조사 완료 후)
- 운영자가 매핑 추가하는 빈도

### 10.2 결과에 따른 정책 조정

- 매핑 누락 거의 없음 → 운영 부담 적음
- 매핑 누락 자주 발생 → 자동 매칭 도구 또는 정기 재점검 도구 도입

---

## 11. 가정 9 — 자식 ≤ 부모 레벨

### 11.1 검증 방법

- 캡 적용 빈도
- 캡 적용 시 자식 레벨과 부모 레벨의 차이 분석

### 11.2 결과에 따른 정책 조정

- 캡 적용 흔하게 발생 (정상) → 현재 정책 유지
- 캡 적용 거의 안 발생 → 캡 코드의 실효성 점검
