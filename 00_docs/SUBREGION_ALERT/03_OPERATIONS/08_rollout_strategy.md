# 자식해역 특보 표출 — 3.8 롤아웃 전략

## 0. 본 파일의 위치

본 파일은 `03_OPERATIONS/` 시리즈의 여덟 번째 파일이며, 본 작업을 점진적으로 도입하기 위한 롤아웃 전략을 정리합니다.

본 작업의 사용자 결정에 따라 구체적인 롤아웃 방안은 사용자께서 별도로 제시하실 예정입니다. 본 파일은 일반 권장사항을 정리합니다.

---

## 1. 롤아웃의 필요성

### 1.1 변경 규모

본 작업은 다음과 같은 큰 변경입니다.

- 자식해역 정보원이 텍스트 스크래핑 → 방재기상 API로 전환
- 신규 데이터 파일 3개 추가
- 신규 백엔드 로직 (스케줄러 통합, 판정 로직)
- 신규 프론트엔드 표출 로직
- 신규 관리자 UI

### 1.2 위험 분석

큰 변경은 미발견 버그 위험이 큽니다.

- 운영 중인 사용자에게 직접 영향 가능
- 잘못된 자식해역 정보 노출 위험
- 푸시 알림 폭주 위험

### 1.3 점진적 도입의 효과

롤아웃을 단계적으로 진행하면:

- 각 단계별 검증으로 위험 최소화
- 문제 발견 시 빠른 롤백 가능
- 운영자 학습 시간 확보

## 2. 롤아웃 단계 (4단계 권장)

### 2.1 Step A — 사전 준비

```
[기간] 본 작업 코드 작성 전 ~ 코드 작성 중
[활동]
- 매핑 전수조사 (1회성)
- 매핑 테이블 초기화
- 본 문서 시리즈 작성
- 코드 작성
```

### 2.2 Step B — 백그라운드 운영 검증

```
[기간] 코드 배포 직후 ~ 1주
[활동]
- index1과 index2 모두에서 방재기상 폴링 시작
- 결과는 데이터 파일에만 저장 (UI 표시 안 함)
- 매핑 누락, 캡 적용, 응답 오류 등의 빈도 데이터 수집
- 데이터 품질 검증
```

이 단계의 핵심은 **사용자에게 영향 없이 시스템 동작 검증**입니다.

### 2.3 Step C — index1 활성화

```
[기간] Step B 데이터 검증 통과 후 1주
[활동]
- index1_features.json의 방재기상_자식해역 = true
- index1 사용자 (관리자/테스트)에게 자식해역 정보 표시
- 사용자 피드백 수집
- 추가 버그 수정
```

이 단계의 핵심은 **제한된 사용자 그룹에서 실제 UI 검증**입니다.

### 2.4 Step D — index2 활성화 (운영 도입)

```
[기간] Step C 안정 확인 후 (사용자 결정에 따라)
[활동]
- index2_features.json의 방재기상_자식해역 = true
- 일반 사용자에게 자식해역 정보 표시
- 운영 모니터링
```

이 단계의 핵심은 **전체 운영 도입**입니다.

## 3. 환경 변수 / 플래그 기반 즉시 롤백

### 3.1 롤백 메커니즘

문제 발생 시 즉시 롤백 가능하도록 설계:

```
[즉시 롤백 방법]
1. index2_features.json의 방재기상_자식해역 = false 변경
2. 코드 변경 / 재배포 불필요
3. 다음 클라이언트 페이지 로드부터 즉시 비활성화
```

### 3.2 백엔드 정지

방재기상 폴링 자체를 정지하려면:

```
[백엔드 폴링 정지]
- 환경 변수 또는 별도 설정 파일로 폴링 활성화 제어
- 예: AFSO_POLLING_ENABLED=false → 폴링 안 함
- 데이터 파일은 그대로 유지 (마지막 정상 상태)
```

### 3.3 함수 형태

```
function shouldRunAfsoPolling():
  envValue = process.env.AFSO_POLLING_ENABLED
  if envValue == "false":
    return false
  return true

function runScheduler():
  if shouldRunAfsoPolling():
    pollAfsoApi()
    runStep3()
  else:
    log("[AFSO 폴링 비활성화]")
```

## 4. 검증 항목

### 4.1 Step B 검증 항목

| 항목 | 검증 방법 |
|---|---|
| 방재기상 응답 정상 수집 | 로그 / 응답 크기 확인 |
| 매핑 누락 빈도 | `unmapped` 섹션 누적 수 |
| 캡 적용 빈도 | 오류 로그의 `LEVEL_CAP_APPLIED` 수 |
| 동시 사라짐 잠금 빈도 | 오류 로그 |
| 영속화 성공 | 파일 mtime 갱신 확인 |
| 메모리 사용 | 정상 범위 |
| CPU 사용 | 정상 범위 |

### 4.2 Step C 검증 항목

| 항목 | 검증 방법 |
|---|---|
| index1 화면 자식해역 표시 | 수동 테스트 |
| 추정 마커 정확성 | 화면 시각 확인 |
| 매핑 누락 시 누락 표시 | 강제 매핑 누락 발생 후 확인 |
| 관리자 푸시 도착 | 강제 오류 발생 후 푸시 확인 |
| 통합관리자 센터 UI | 수동 테스트 |
| index2 영향 없음 | index2 화면 변화 없음 확인 |

### 4.3 Step D 검증 항목

| 항목 | 검증 방법 |
|---|---|
| 일반 사용자 화면 정상 | 모니터링 |
| 사용자 피드백 | 게시판 / 고객 응대 |
| 데이터 품질 안정 | Step B와 비교하여 빈도 안정 확인 |

## 5. 사용자 알림

### 5.1 사용자 안내

본 작업의 자식해역 정보는 추정을 포함하므로 사용자에게 다음을 안내:

- 추정 마커의 의미
- 정확한 정보는 통보문 또는 기상청 페이지 확인
- 본 정보는 참고 목적

### 5.2 안내 위치

- 통합관리자 센터의 도움말
- 사용자 화면의 추정 마커 클릭 시 설명
- 본 문서 (개발자/운영자용)

### 5.3 본 작업 1차 범위

본 작업의 1차 범위에서는 사용자에게 별도 공지 없이 도입. 자세한 알림 정책은 사용자 결정.

## 9. 롤백 시나리오

### 9.1 가벼운 롤백 (플래그 비활성화)

```
[증상] 일부 자식해역에 잘못된 정보 표시
[조치]
1. index2_features.json의 방재기상_자식해역 = false (해당 페이지)
2. 사용자 화면 즉시 비활성화
3. 백엔드는 계속 운영 (데이터 수집)
4. 문제 분석 후 다시 활성화
```

### 9.2 중간 롤백 (백엔드 정지)

```
[증상] 백엔드에서 비정상 동작 (CPU 폭주, 영속화 실패 등)
[조치]
1. 환경 변수로 AFSO_POLLING_ENABLED=false
2. 백엔드 폴링 정지
3. 프론트엔드는 영향 없음 (직전 데이터 표시)
4. 문제 분석 후 폴링 재개
```

### 9.3 전체 롤백 (코드 되돌리기)

```
[증상] 심각한 버그 (서버 정지, 데이터 손상 등)
[조치]
1. git revert로 본 작업 코드 되돌리기
2. 재배포
3. 데이터 파일 삭제 또는 백업 복원
4. 문제 분석 후 재시도
```
