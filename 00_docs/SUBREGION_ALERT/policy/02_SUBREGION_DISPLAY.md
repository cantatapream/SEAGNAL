## 1. 핵심 원칙 (사용자 결정)

1. **자식해역 시각은 부모와 동일이 기본** — `source: "inherit"` 로 상속
2. **자식 단독 통보문** (P2 패턴) 시에만 자식 고유 시각 저장 — `source: "report"`
3. **부모 없이 자식 단독 발효 불가** — 사용자 원칙 보장
4. **자식해역 변화는 사용자 푸시 알림 발송 X** — 어드민 푸시·아코디언 표시만
5. **자식해역도 부모와 동일한 라이프사이클** — 발표·발효·해제·변경·격상/격하·연장 모두

### 2-2. 단계 건너뛰기 허용

→ 매 통보문이 도착할 때 그 내용대로 장부 갱신. 이전 단계 누락은 신경 쓰지 않음.

## 3. 장부 구조 (`weather_alerts.json` children)

```json
"제주도서부앞바다": {
  "current": { "wrnTp": "풍랑", "wrnLvl": "주의", "tmFc": "...", "tmEf": "...", "tmCc": "..." },
  "upcoming": null,
  "history": [...],
  "children": {
    "북서연안바다": {
      "status": "Y",
      "tmFc": "2026년 05월 16일 14시 00분",
      "tmEf": "2026년 05월 16일 밤(21시~24시)",
      "tmCc": "17일 새벽(03시~06시)",
      "wrnTp": "풍랑",
      "wrnLvl": "주의",
      "source": "inherit",
      "sourceReportId": "met:202605161400:39",
      "lastUpdated": "2026-05-16T14:00:00+09:00"
    },
    "남서연안바다": { ... },
    "가파도연안바다": {
      "status": "EXCLUDED",
      "source": "report",
      "sourceReportId": "met:202605161400:39",
      "lastUpdated": "2026-05-16T14:00:00+09:00"
    }
  }
}
```

### 3-1. status 값 정의

| status | 의미 |
|---|---|
| `"Y"` | 발효 중 |
| `null` | 미발효 |
| `"EXCLUDED"` | 통보문에 "제외" 명시됨 (P1 패턴) |
| `"PENDING"` | upcoming(예비) 상태 |

### 3-2. source 값 정의 및 갱신 정책

| source | 의미 | 부모 시각 변경 시 |
|---|---|---|
| `"inherit"` | 부모 시각 상속 | **자동 동기화** |
| `"report"` | 자식 단독 통보문에서 추출 | **자식 단독 통보문 와야 갱신** |

### 3-3. 부모 해제 시

부모 `current === null` 이 되면 **모든 자식 강제 null** (source 무관). 사용자 원칙 보장.

## 4. 시각 표기 처리

### 4-1. 범위형 / 정확형 둘 다 그대로 보존

| 형식 | 예시 |
|---|---|
| 범위형 | `2026년 05월 16일 밤(21시~24시)` |
| 정확형 | `2026년 05월 16일 22시 00분` |

→ 표시 시점에 적절히 포맷 (변환 없음).

### 4-2. 시각 단조성 검증

정확형 → 범위형으로 뒤로 가는 갱신은 의심:
- 일단 적용 (정정 가능성)
- 어드민 푸시 알림 (case ⑧)

## 5. 자식해역 변화 시나리오 (전 사례)

### 시나리오 A: 부모 + 모든 자식 동시 발효
통보문: `제주도서부앞바다 풍랑주의보 발표` (자식 미명시)
→ children 의 모든 자식 `source: "inherit"` 로 부모 시각 상속

### 시나리오 B: 부모 발효 + 일부 자식 제외 (P1)
통보문: `제주도서부앞바다(가파도연안바다 제외) 풍랑주의보 발표`
→ 가파도연안바다 `status: "EXCLUDED"`, 나머지 inherit

### 시나리오 C: 자식 단독 추가 발효 (P2)
통보문: `제주도서부앞바다(북서연안바다) 풍랑주의보 발표`
→ 북서연안바다 `source: "report"` + 자식 고유 시각

### 시나리오 D: 자식 단독 해제
통보문: `제주도서부앞바다(북서연안바다) 풍랑주의보 해제`
→ 북서연안바다 `status: null`, 다른 자식 영향 X

### 시나리오 E: 부모 해제 → 모든 자식 강제 해제
통보문: `제주도서부앞바다 풍랑주의보 해제`
→ 부모 `current: null` + 모든 자식 `status: null` (source 무관)

### 시나리오 F: 자식 단독 풍랑예비특보 해제 (방식 B)
통보문: `제주도서부앞바다(북서연안바다) 풍랑예비특보 해제`
→ 자식 upcoming 단독 비활성화

### 시나리오 G: 예비특보 자연어 해제 (방식 A — review_needed 라우팅)
[예비] 통보문 참고사항 절: `발표 가능성이 낮아져 해제`
→ 자동 처리 X, `review_needed.json` 추가, 어드민 푸시 (정책 ④ 참조)

## 6. 사용자 화면 (index2)

### 6-1. 부모 카드 펼침 시 자식해역 표시

```
[부모 카드] 제주도서부앞바다  [풍랑주의보] ▼
   ├─ 발표시각: 5/16 14:00
   ├─ 발효시각: 5/16 밤(21~24시)
   └─ 해제예정: 17일 03~06시

   ─── 연안바다/평수구역 ───

   ● 북서연안바다  [풍랑주의보] ▼ (클릭하면 펼침)
       발표시각: 5/16 14:00
       발효시각: 5/16 밤(21~24시)
       해제예정: 17일 03~06시

   ● 남서연안바다  [풍랑주의보] ▼

   ⊘ 가파도연안바다  [제외 처리]   ← 회색, 클릭 X
```

### 6-2. 아코디언 동작

기존 `render_coastal.js` line 563-567 의 클릭 토글 로직 그대로 활용.
- 자식해역 카드에 alertData 있으면 → 클릭 시 detailBox 표시/숨김
- EXCLUDED 자식해역은 회색 처리, 클릭 비활성화

## 7. 푸시 알림 정책

### 7-1. 사용자 푸시 — **부모해역 변화만 발송**

기존 9가지 양식 (`push_helpers.js`) 그대로 유지:
- 📢 발표 / 🚨 발효 / ✅ 해제
- 격상/격하 / 시각 변경

### 7-2. 자식해역 변화 — 사용자 푸시 X

발송 안 함:
- 자식 단독 발효/해제
- 자식 EXCLUDED 전환
- 자식 시각 변경
- 자식 격상/격하

→ 사용자는 부모 카드 펼침 → 자식 아코디언으로 확인.

### 7-3. 자식해역 관련 변화 — 어드민 푸시 발송

정책 ⑥ (`06_ADMIN_PUSH_POLICY.md`) 의 9가지 케이스로 발송.
