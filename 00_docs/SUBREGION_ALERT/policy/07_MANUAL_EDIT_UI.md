# 정책 ⑦ — 자식해역 수동 수정 UI

**작성일**: 2026-05-16
**버전**: 1.0
**기반 코드**: `local_server/js/admin.js` 의 `renderManualInputTab()` (line 813)

---

## 1. 배경

기존 통합관리자센터 → 특보 알림 → 특보 수정 탭은 **부모해역 단위** 로만 수동 CRUD 가능. 자식해역(연안바다·평수구역) 수동 수정 기능이 없음.

본 정책으로 자식해역도 동일하게 CRUD 가능하도록 확장. 추가로 **자식해역 다중 선택 (체크박스)** 으로 한꺼번에 추가/수정 기능 제공.

---

## 2. 핵심 원칙

1. 부모해역과 동일한 CRUD 인터페이스 (추가/수정/삭제)
2. **자식해역에는 푸시 발송 버튼 없음** (자식 변화는 푸시 X 원칙)
3. 사용자 원칙 검증 — 부모 없이 자식 단독 발효 불가
4. **다중 선택 일괄 추가** — 같은 정보를 여러 자식해역에 한꺼번에 적용
5. EXCLUDED 상태 지원 (자식해역 특수 상태)

### 3-2. 다중 선택 — 일괄 추가 모달

체크박스 다중 선택 후 `[+ 선택 자식에 특보 추가]` 클릭:

```
┌──────────────────────────────────────────────────┐
│ ✏️ 자식해역 일괄 특보 추가                          │
├──────────────────────────────────────────────────┤
│ 대상 (3개 자식해역):                                │
│   ✓ 울산앞바다중평수구역                            │
│   ✓ 울산앞바다중연안바다                            │
│   ✓ 경북남부앞바다중평수구역                        │
│                                                    │
│ 부모해역 상태 확인:                                 │
│   ⓘ 울산앞바다 — ✅ 풍랑주의보 발효 중              │
│   ⓘ 경북남부앞바다 — ❌ 미발효 (사용자 원칙 위반)   │
│   → 경북남부앞바다중평수구역은 추가 차단됨         │
│                                                    │
│ ────── 공통 특보 정보 (모든 대상에 적용) ──────    │
│ 특보 종류:  [풍랑 ▼]                                │
│ 등급:      [주의보 ▼]                               │
│ 발표시각:  [2026-05-16 14:00]                       │
│ 발효시각:  [2026-05-16 16:00] (범위형 가능)         │
│ 해제예정:  [17일 03~06시]                           │
│                                                    │
│ source: [⦿ report (수동)] [◯ inherit (부모상속)]   │
│                                                    │
│ ⚠️ 자식해역 수정은 사용자 푸시 발송하지 않습니다.   │
│    어드민 장부에만 반영됩니다.                     │
│                                                    │
│            [취소]   [저장 (적용 가능 2건만)]        │

```

### 3-3. 사용자 원칙 위반 안내

부모해역이 발효 중이 아닐 때 자식에 Y 적용 시도:

```
┌──────────────────────────────────────────────────┐
│ ❌ 사용자 원칙 위반                                 │
├──────────────────────────────────────────────────┤
│ 부모해역(경북남부앞바다)이 발효 중이 아닙니다.       │
│ 자식해역은 부모 없이 단독 활성될 수 없습니다.      │
│                                                    │
│ 해결 방법:                                          │
│  ① 부모해역에 먼저 특보 추가                       │
│  ② 그 후 자식해역 추가                             │
│                                                    │
│ 또는 자식해역만 EXCLUDED 처리하시려면              │
│ [+ 선택 자식 EXCLUDED 처리] 버튼을 사용하세요.     │
│                                                    │
│           [확인]                                    │
└──────────────────────────────────────────────────┘
```

## 5. 신규 API (백엔드)

```javascript
// 단일 자식해역 수정
PUT /api/admin/manual-child-alert
Body: {
  parentZone: '울산앞바다',
  childZone: '울산앞바다중연안바다',
  status: 'Y' | null | 'EXCLUDED',
  alertData: {
    wrnTp, wrnLvl, tmFc, tmEf, tmCc, source
  }
}

// 다중 자식해역 일괄 추가
PUT /api/admin/manual-child-alert/bulk
Body: {
  parentZone: '울산앞바다',
  children: ['울산앞바다중평수구역', '울산앞바다중연안바다'],
  status: 'Y',
  alertData: { ... }  // 공통 적용
}

// 사용자 원칙 사전 검증
GET /api/admin/check-child-principle?parentZone=...&childZones=...

// 자식해역 삭제
DELETE /api/admin/manual-child-alert?parentZone=...&childZone=...

// 다중 자식해역 EXCLUDED 처리
POST /api/admin/manual-child-alert/bulk-exclude
Body: {
  parentZone: '울산앞바다',
  children: ['울산앞바다중평수구역', '울산앞바다중연안바다']
}
```

## 6. 데이터 흐름

```
관리자 [수정] 또는 [+ 선택 자식에 특보 추가] 클릭
   │
   ▼
사용자 원칙 사전 검증 (각 자식에 대해 부모 발효 상태 확인)
   ├─ 부분 위반 → 적용 가능한 항목만 표시 + 위반 항목 안내
   └─ 모두 OK → 모달 표시
   │
   ▼
관리자 값 입력 후 [저장]
   │
   ▼
PUT /api/admin/manual-child-alert(/bulk)
   │
   ▼
weather_alerts.json 의 children 갱신
   ├─ status, tmFc, tmEf, tmCc 등
   ├─ source: 'report' (수동)
   └─ lastUpdated, modifiedBy: 'admin-manual'
   │
   ▼
응답: { success: true, applied: N건, skipped: M건 }
   │
   ▼
UI 재렌더링
   ★ 사용자 푸시 발송 X (자식해역 원칙)
   ★ manual-edit-history 에 기록
```
