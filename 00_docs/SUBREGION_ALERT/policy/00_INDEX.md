## 🎯 합의된 핵심 원칙 (모든 정책 공통)

### 데이터 수집
- **9개 광역 병렬 호출** (충북·전국 제외)
- **1분 사이클**, 평상시 ~1.4초, 격변기 ~22초
- 본문 reportId dedup 후 unique 만 fetch

### 자식해역 처리
- **시각은 부모 상속이 기본** (`source: "inherit"`)
- **자식 단독 통보문** 시에만 별도 시각 (`source: "report"`)
- **부모 없이 자식 단독 발효 불가** (사용자 원칙)
- 자식해역 라이프사이클: 발표·발효·해제·변경·격상/격하·연장 모두 추적
- **단계 건너뛰기 허용** (즉시 발효/해제 등)

### 통보문 파싱
- **AI 파서** (부모 + 자식 카탈로그 25개 주입) +
- **정규식 파서** (P1·P2 패턴) =
- **Dual Validation** (불일치 시 정규식 우선 + 어드민 알림)

### 알림 정책
- **사용자 푸시**: 부모해역 변화만 (기존 9가지 양식)
- **자식해역 변화**: 사용자 푸시 X
- **관리자 푸시**: 자식해역 관련 9가지 케이스 (정책 ⑥)
- **일괄 발송**: 9 광역 수집 후 1회 묶음

### UI
- **사용자 화면(index2)**: 부모 카드 → 자식 아코디언 펼침 활성화
- **어드민(통합관리자센터)**:
  - 특보 수집 테스트: 광역 사이드바 + 3개 탭 통일
  - 특보 수정: 자식해역 CRUD + 체크박스 일괄 처리

### 명칭 매핑
- 앱 `[부모]중[자식]` ↔ 통보문 `[부모]([자식])` 정규화
- `(부모, 자식)` 튜플을 표준 키로 사용
- 자식해역 카탈로그 25개 (영덕연안·가로림만 등 폐지 명칭 제외)
