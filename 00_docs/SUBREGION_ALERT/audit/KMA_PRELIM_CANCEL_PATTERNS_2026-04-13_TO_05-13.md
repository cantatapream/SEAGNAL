## 3. 통보문 본문 형식 패턴 — 2가지

### 패턴 A: 신규 발표 없이 단독 해제

**조건**: `□ 내용` 절이 `o 없음`, **참고사항**에 "해제" 문구

**예시 1** (4-17 전국 [예비] 제04-22호):
```
□ 내용
o 없음

참고사항
o 오늘(17일) 오전으로 예고되었던 제주도산지의 호우 예비특보는 발표 가능성이 낮아져 해제합니다.
```

**예시 2** (4-16 전국 [예비] 제04-20호, 어조 변형):
```
□ 내용
o 없음

참고사항
o 오늘(16일) 오전으로 예고되었던 제주도산지.중산간의 강풍 예비특보는
  발표 가능성이 낮어져 해제하나, 바람이 강하게 부는 곳이 있겠으니,
  시설물 관리와 안전에 각별히 유의하기 바랍니다.
```

> ⚠️ 표기 변형: **"낮어져"** 와 **"낮아져"** 두 가지 모두 발견됨 (기상청 입력 오차 추정). 정규식 작성 시 둘 다 처리 필요.

### 패턴 B: 신규 예비특보 발표와 동시에 일부 해제

**조건**: `□ 내용` 절에 신규 예비특보 발표 내역이 있고, **참고사항**에 별도로 "해제" 문구

**예시** (5-3 전국 [예비] 제05-4호):
```
□ 내용
(1) 강풍 예비특보
  o 05월 03일 오전(06시~12시) : 전라남도(거문도.초도), 제주도(추자도)
  o 05월 03일 밤(18시~24시) : 서해5도, 전라남도(흑산도.홍도)
  …
(2) 풍랑 예비특보
  o 05월 03일 오전(06시~12시) : 남해동부안쪽먼바다, 제주도앞바다(제주도북부앞바다)
  …

참고사항
o 오늘(3일) 새벽으로 예고된 제주도북부와 제주도남부, 제주도남부중산간의
  강풍예비특보는 발표 가능성이 낮아져 해제합니다.
o 제주도남부중산간 : 서귀포시 내 해발고도 200~600m 사이 지역
```

→ 이 사례에서 **새 예비특보를 발표하는 통보문 안에 이전에 발표한 예비특보 중 일부를 함께 해제** 한다. 단일 통보문 안에 발표·해제가 공존.

## 5. 앱 반영을 위한 파싱 규칙

### 5-1. 매칭 정규식

```javascript
// 핵심 패턴 — "발표 가능성이 낮아/낮어 져 해제" 시그니처
const PRELIM_CANCEL_RE = /(?<region>[가-힣.·\s,()0-9~]+?)의?\s*(?<kind>[가-힣]+)\s*예비\s*특보(?:는)?\s*발표\s*가능성이\s*낮[아어]져\s*해제(?:합니다|하나)/g;
```

### 5-2. 추출해야 할 필드

| 필드 | 의미 | 사례 |
|---|---|---|
| `region` | 해당 지역(자식해역 포함) | "제주도산지", "제주도북부", "제주도남부중산간" |
| `kind` | 특보 종류 | "강풍", "호우", "풍랑" |
| `targetTime` | 원래 예고된 발효 시간대 | "오전(06시~12시)", "새벽" 등 |
| `issuedAt` | 본 통보문 발표 시각 | `2026-04-17 11:00` |

### 5-3. 시간대 추출 정규식 (참고사항 앞부분)

```javascript
const TARGET_TIME_RE = /오늘\(\d+일\)\s*(?<period>새벽|오전|오후|아침|낮|저녁|밤)(?:\([0-9~시]+\))?(?:으|로|으로) 예고된/;
```

### 5-4. 처리 흐름 (제안)

1. 새 [예비] 통보문 도착 → `□ 내용` 절과 `참고사항` 절을 분리해 파싱
2. `참고사항` 절에서 `PRELIM_CANCEL_RE` 매칭 시도
3. 매칭되면 해당 (지역, 종류, 시간대) 의 예비특보 표시를 **즉시 제거**
4. 사용자 알림(선택): "○○지역 ○○ 예비특보가 취소되었습니다 (발표 가능성 낮음)"
5. 만약 같은 통보문에 `□ 내용` 절도 채워져 있다면(패턴 B), 신규 예비특보 발표도 함께 처리

### 5-5. 표기 변형 처리 체크리스트

- [x] "낮아져" / "낮어져" 둘 다 매칭
- [x] "예비특보" / "예비 특보" / "호우예비특보" 띄어쓰기 무관
- [x] "해제합니다" / "해제하나" 어미 두 가지
- [x] 자식해역 키워드(중산간·산지·연안 등)도 region 에 포함 가능

## 6. 결론 및 제안

### 결론

1. **31일 윈도우 기준 "예비특보 발표 후 해제" 사례 = 4건** (전국·제주 광역 분할본 포함 7건)
2. **모든 사례가 `참고사항` 절에 자연어로 명시** — `□ 내용`에는 거의 등장하지 않음
3. **"취소" 라는 단어는 통보문 본문에서 사용되지 않음** — 반드시 "발표 가능성이 낮아져 해제" 시그니처로 검색해야 함
4. **표기 오차/변형이 존재** — 정규식 작성 시 띄어쓰기·맞춤법 변형 모두 처리 필요

### 앱 적용 권장

**(가) 단기 (즉시 가능)**
- 통보문 본문 파서에 `PRELIM_CANCEL_RE` 추가
- [예비특보] 처리 로직에 "참고사항 절 별도 파싱" 단계 추가
- 매칭 발생 시 해당 (지역·종류·시간대) 의 예비특보 표시 즉시 제거

**(나) 중기 (과거 데이터 확보 후)**
- 정보공개청구로 작년 8월~ 1년치 데이터를 확보하여 추가 변형 패턴 보강
- 본 31일은 봄철이므로 **겨울철(대설·한파 예비특보 취소)** 사례가 더 풍부할 가능성 ↑

본 조사로 인해 다음이 확실해졌습니다:
- 우리 앱이 현재 **"예비특보 발효 예정 → 발효 직전 갑자기 사라짐"** 상황을 처리 못하는 이유 = 통보문 본문의 `참고사항` 절을 파싱하지 않기 때문
