### 패턴 P4 — 자식해역이 부모해역과 별개로 해제

부모해역은 여전히 효력 중이지만 자식해역만 먼저 해제되는 경우.

대표 사례:

- 184 제04-65호 (04-23 09:30): 제주도남부앞바다(연안바다)·제주도서부앞바다(북서연안바다) 해제.

이 경우 `해당구역` 절에는 부모해역명이 한 번 등장하지만, 괄호 안의 자식해역만 진짜 영향 대상이다.

### 패턴 P5 — `울릉도.독도`는 해역 자식해역이 아니라 육상 특보 구역

`울릉도.독도`는 점(.) 으로 연결된 **단일 육상 특보 구역명**이며, 자식 "연안바다"가 아니다. 통보문에서는 강풍/풍랑 주의보의 발효 구역으로 단독 등장한다.
- 부모해역 표기 형식이 다름: `울릉도.독도` 자체가 leaf-level region.
- 따라서 `STN_DETAIL.json` 류 자식해역 매핑에서는 별도 카테고리 ("도서 특보 구역") 로 분류 필요.

### 패턴 P6 — `(추자도)` 는 *제주도* 의 자식 육상 구역

`제주도(추자도)` 형태로 본문에 등장. 제주도라는 부모 육상 특보 구역의 일부로서 단독 발효/해제 가능.

발견 사례 (8건 모두 제주도 통보문 또는 전국 통보문):
- 04-16 10:00 발표 → 04-17 00:00 해제 (제04-40호 / 42호)
- 05-03 23:00 발표 → 05-04 05:00 해제 (제05-10호 / 12호)

이때도 다른 제주도 자식 (제주도산지, 서부, 동부, 북부중산간) 과 **개별 발효/해제 시각**이 다를 수 있음 (제05-10호: 추자도는 새로 발표, 나머지는 해제예고 연장).

### 패턴 P7 — `해당구역` 절의 구조 (파싱용)

매칭된 48건 모두 `□ 해당구역` 절 안에서 자식해역이 호출된다. 일반 형태:

```
□ 해당구역
 (N) <행위> : <부모구역1>[(자식1, 자식2)][, <부모구역2>[(자식...)]]
 [ o <부모구역>(<자식... 제외>) ]
```

추가 행은 ` o ` 으로 시작하는 보조행으로, **앞 행에 명시된 부모구역의 자식해역 한정**을 설명한다.

### 패턴 X — 본문 미등장 키워드

기간 중 다음 키워드는 한 번도 등장하지 않았다 (해당 시기에 특보 자체가 없었거나, 자식해역이 활동하지 않았기 때문):
- 영덕연안, 안면도, 천수만, 조도부근 (서해/남해 자식해역 — 4월~5월은 활동 비수기)
- 서면, 북면, 울릉읍 — `울릉도.독도`로 일괄 표기되어 행정동 단위로는 표기되지 않음
- 특정관리해역 — 행정 명칭이며, 통보문에는 직접 등장하지 않는다 (자식해역 호칭은 항상 *지명+연안바다* 또는 *지명*).

## 7. 결론 및 시사점

### 7-1. 통보문 텍스트 파싱으로 자식해역 단위 특보 추출 가능성

**가능하다. 단, 다음 규칙·정규식을 모두 적용해야 한다.**

#### 규칙 R1 — 부모 발표 + 자식 제외 (P1)
```regex
(?P<parent>[가-힣]+앞바다)\(\s*(?P<excluded>[가-힣, ]*?(?:연안바다|평수구역)[^)]*)\s*제외\s*\)
```
→ `<parent>` 는 발효, `<excluded>` 의 자식해역은 미발효.

#### 규칙 R2 — 자식해역 단독 발표/해제 (P2, P4)
```regex
(?P<parent>[가-힣]+앞바다)\(\s*(?P<children>[가-힣, ]*?(?:연안바다|평수구역))[^)]*\)
(?!.*제외)   # 같은 괄호 안에 '제외' 없음
```
→ `<children>` 의 자식해역만 발효/해제. 부모 본체는 무관.

#### 규칙 R3 — `o` 보조행은 직전 부모해역의 상세 한정
`□ 해당구역` 절 안에서 ` o ` 으로 시작하는 라인은 같은 항목(N)의 상세이므로 같은 행으로 합쳐서 해석해야 함.

#### 규칙 R4 — 육상 자식 구역
```regex
제주도\(([^)]*추자도[^)]*)\)
울릉도\.독도
경상북도\([^)]*경북북동산지[^)]*\)
```
→ 이들은 *해역 자식*이 아니라 *육상 특보 구역의 자식 또는 단독 leaf*. 별도 매핑 필요.

#### 규칙 R5 — 상태 합성
한 자식해역의 실효 상태(발효/해제)는 단일 통보문이 아니라 **시간순 통보문 시퀀스의 누적**으로 결정. 시뮬레이션:
1. 최초 발표 통보문 (부모 또는 자식)
2. 후속 "발표"/"변경"/"연장"/"해제예고연장" → 상태 업데이트
3. "해제" 통보문 → 상태 종료

P3 사례에서 확인 — 부모 발표 시 제외된 자식이 별도 통보문으로 후행 발효되는 경우가 실제로 존재.

### 7-2. 정확도/완전성에 대한 평가

| 측면 | 평가 |
|---|---|
| **부모해역 발효구역 검출** | 거의 100% — 모든 통보문이 `□ 해당구역` 절을 표준 형식으로 가짐. |
| **자식해역(제외) 검출** | 100% (위 R1 정규식) — 5/5 사례 모두 정확히 매칭됨. |
| **자식해역(단독) 검출** | 100% (R2) — 12/12 사례 매칭. |
| **육상 자식 검출** | R4의 정적 사전이 필요 — `추자도`, `울릉도.독도`, 산지/중산간 명 등. |
| **시퀀스 합성** | 통보문 일련번호(`제MM-N호`)와 발표일시로 정렬 가능. 단, 자식해역에 한정된 발표 통보문과 부모 통보문이 모두 같은 일련번호 시퀀스 안에 섞여 있으므로 reportId 모두 수집해야 함. |
| **누락 사례 가능성** | 사례 4의 평수구역처럼, 자식해역만 별도 발표한 통보문이 본문 키워드 필터에 잡히지 않을 가능성은 거의 없음(자식해역명이 본문에 반드시 등장). 단, 본 스캔의 키워드 외 다른 자식해역(예: 서해 자식)이 활동했다면 추가 키워드 보강 필요. |

### 7-3. 실무적 권고

1. **자식해역 사전(`STN_DETAIL.json` 등)을 완성하라**. 본 스캔에서 등장한 자식해역:
   - 해역: `북서연안바다`, `남서연안바다`, `북동연안바다`, `남동연안바다`, `우도연안바다`, `가파도연안바다`, `연안바다` (제주도남부앞바다 산하), `평수구역` (경북남부앞바다 산하)
   - 육상: `추자도`(제주도 산하), `울릉도.독도`(독립 leaf), `제주도산지`, `제주도서부`, `제주도동부`, `제주도북부중산간`, `제주도남부중산간`, `경북북동산지` 등
2. **파서는 R1 + R2 + R3을 모두 적용**해야 한다. R1만 적용하면 자식해역 단독 발표 12건을 놓친다.
3. **누적 상태 시뮬레이터** 가 필요하다. 단일 시점 스냅샷이 아니라 "이 자식해역이 지금 발효 중인가?" 를 알려면 직전 N건의 통보문을 합성해야 한다.
4. 키워드 기반 1차 필터는 본 보고서의 키워드 목록(연안바다 / 평수구역 / 추자도 / 울릉도 / 우도 / 가파도 + 4방위연안 + 영덕연안 등) + 향후 서해 자식해역(천수만, 안면도, 조도부근 등)을 모두 포함해야 한다. 본 31일 스캔 기간 동안 서해 자식해역은 활동이 없었으므로 다른 기간(겨울/봄 황해 풍랑 비수기 외) 의 추가 검증이 필요.
5. **`특정관리해역` 이라는 행정 명칭 자체는 통보문 본문에 등장하지 않는다** — 코드/사전에서는 *지명+연안바다* 또는 *지명* 패턴을 직접 다뤄야 한다.
