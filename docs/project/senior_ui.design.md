# 어르신 눈높이 UI(쉬운 화면) 설계 검토서

> 작성: 2026-09-07 (KST) · 상태: **구상안 — 코드 변경 없음, 사용자 결정 대기**
> 이 문서는 "어르신·노약자가 SEAGNAL을 쉽게 쓰게 하려면 무엇을 어떻게 만들어야 하는가"를
> 정하기 위한 검토서입니다. 1~3장은 **지금 앱의 실제 상태를 측정한 결과**이고,
> 4장은 **다른 앱들의 사례**, 5장부터가 **설계안**입니다.
>
> 원칙: 이 문서의 모든 숫자는 실제로 세거나 실행해서 얻은 값입니다.
> 확인하지 못한 것은 "확인 못 함"이라고 적었습니다. (CLAUDE.md 「추측 금지」 규칙)

## 0. 어떻게 조사했는가 (재현 방법)

| 방법 | 구체적으로 한 일 |
|---|---|
| 코드 전수 조사 | `client/js` 106개 파일(85,439줄) · `client/index2.html`(6,543줄) · `client/style.css`(12,630줄)을 탭별로 나누어 읽음 |
| 실제 화면 렌더링 | 로컬 서버(`node local_server/server.js`) 기동 + Chromium(Playwright) 390×844 모바일 뷰포트로 접속해 탭별 스크린샷 촬영 |
| 실제 데이터 주입 | 로컬에는 수집 데이터가 없어 화면이 비므로, 브라우저의 `/api/*` 요청을 운영 서버(`seagnal-server.fly.dev`)로 중계해 **실제 특보·낚시지수·공지가 들어간 화면**을 촬영·측정 |
| 화면 실측 | 렌더된 DOM을 순회하며 ①보이는 글자 하나하나의 실제 px ②눌 수 있는 요소의 실제 가로·세로 px 를 집계 |
| 글자 크기 실험 | `FontSizeManager.set('large')` 적용 전후의 같은 텍스트를 1:1로 대조해 "실제로 몇 개가 커졌는지" 셈 |
| 실사용 데이터 | 운영 서버 `GET /api/stats/usage` 를 조회해 기능별 실제 사용 횟수·소속별 사용 패턴 확보 |
| 색 대비 | CSS 변수 값을 WCAG 상대휘도 공식으로 계산해 대비비 산출 |
| 타 앱 사례 | 웹 검색으로 국내 금융권 고령자모드, 해수부 「안전해(海)」, 삼성 간편모드, 시니어 UX 연구, WCAG/Apple/Android 접근성 기준 확인 |

**확인 못 한 것**: 실제 어르신 사용자를 대상으로 한 사용성 테스트는 하지 않았습니다.
앱 사용자의 연령 분포 데이터도 서버에 없습니다(설문 데이터 `surveys.json`은 로컬 기준 비어 있음).
따라서 "어르신이 실제로 어디서 막히는지"는 **측정된 사실이 아니라 설계 가설**입니다.

## 3. 어르신 관점에서 무엇이 문제인가 (실측 근거)

### 3-1. 글자가 작다 — 화면 글자의 64~100%가 14px 미만

390×844 화면에서 실제로 보이는 글자를 세었습니다.

| 화면 | 보이는 글자 수 | 14px 미만 | 비율 | 가장 작은 글자 |
|---|---|---|---|---|
| 특보정보(해역 펼침) | 97 | 64 | **66%** | 9px (기상청 로고 캡션) |
| 해양종합정보(지도) | 30 | 30 | **100%** | **8px** (지도 버튼 라벨 전부) |
| 해양생활(낚시) | 28 | 27 | **96%** | 11.2px (범례) |
| 공지사항 | 80 | 67 | **84%** | 11.2px (카테고리 칩) |
| 설정 모달 | 143 | 81 | **57%** | 9px |

참고: 고령자 대상 설계 권고는 본문 최소 16px 이상, 중요한 글자는 그보다 더 크게입니다.

### 3-2. 「글자 크게」를 눌러도 12.5%밖에 안 커진다

실험(390px 화면, 보통 → 크게):

- 화면 기준 글자 크기 **16px → 18px (+12.5%)**
- 같은 문구 77개를 1:1로 대조한 결과 **11개는 전혀 커지지 않음**(헤더 로고, 방문자 수, 배지 등 px로 고정된 글자)
- 코드 기준으로 px 고정 글자 총 **154곳**(style.css 19 + index2.html 40 + js 95) + 화면폭 기준(vw) 글자 30곳은 확대에서 제외
- 「작게」는 축소가 아니라 "기본 그대로"라, 실질 조절 폭은 **기본 ~ 기본+4px**뿐
- 라디오를 눌러도 즉시 반영되지 않고 **「저장 및 닫기」를 눌러야** 적용됨. 미리보기 없음

비교: iOS·안드로이드의 시스템 글자 크기는 200% 수준까지 확대됩니다. 그런데 이 앱은
`style.css:63-69`에서 `text-size-adjust: none`으로 **시스템 글자 크기 설정 자체를 무시**하도록 강제하고 있어,
어르신이 폰 설정에서 글자를 키워도 이 앱만 그대로입니다.

### 3-3. 누를 곳이 작다 — 44px 기준을 넘는 것이 거의 없다

실측(작은 순):

| 화면 | 보이는 누를 수 있는 요소 | 44px 미만 |
|---|---|---|
| 특보정보 | 40개 | **25개** |
| 해양종합정보 | 31개 | **27개** |
| 해양생활 | 20개 | **16개** |
| 공지사항 | 22개 | **15개** |
| 설정 모달 | 42개 | **29개** |

구체적 실측값: 지도 버튼 **38×40px**, 바텀시트 날짜 ◀▶ **28×28px**, 시트 닫기 **30×30px**,
슬라이더 손잡이 **16~18px**, 서브탭 높이 **18px**(텍스트 영역 기준), 리액션 버튼 높이 약 26px.

기준: Apple 44×44pt, Android 48×48dp, WCAG 2.2 AAA 44×44px, 고령자 특화 권고 48px 이상.

### 3-4. 「글자 크게」로 바꿔도 지도 버튼은 커지지 않는다

실측(보통 → 크게): 지도 버튼 크기 **38×40px → 38×39~41px**. 사실상 그대로입니다.
바뀌는 것은 아이콘이 사라지고 라벨이 2줄 텍스트로 대체되는 것뿐(8px → 약 12.6px)입니다.

### 3-5. 원하는 것 하나를 보려면 3~5번 눌러야 한다

| 알고 싶은 것 | 필요한 조작 |
|---|---|
| 우리 해역에 특보가 언제 풀리나 | 해역 1탭 → 해상구역 1탭 → 카드 1탭 = **3탭** |
| 그 해역 부이의 실제 파고 | **4탭** |
| 통보문 원문 | **4탭** |
| 오늘 여기 낚시 되나 | 메인탭 → 서브탭 → **지도에서 내 지점 찾기(팬·줌)** → 마커 탭 = **3탭 + 지도 조작** |
| 강수확률 지도 특정 시각 | 천기 → 항목 → 슬라이더 드래그 = **2탭 + 드래그** |
| 해구별 기상 | 해구도 ON → 셀 탭 → 같은 셀 재탭 = **3탭** |

특히 해양생활 6개 활동은 **전국 지도에서 자기 지점을 스스로 찾아야** 합니다(초기 배율은 전국 뷰).
지도를 확대하려면 두 손가락 핀치가 필요한데, 이는 고령자에게 가장 어려운 조작으로 알려진 제스처입니다.

### 3-6. 전문용어를 풀어주지 않는다

| 탭 | 화면에 쓰는 전문용어 | 앱 안에 뜻풀이가 있는 것 |
|---|---|---|
| 특보정보 | 발효·발표·예비특보·주의보·경보·격상·격하·유의파고·시정·파주기·돌풍·해구·평수구역·연안바다·앞바다·먼바다·너울·초단기/단기/중기예보 등 30여 개 | **0개** (평균값 산출근거 툴팁 1개와 시정 배지 title 1개는 용어 설명이 아님) |
| 해양종합정보 | 약 30개 | 안내ⓘ 모달 18탭이 **13~14개** 설명. 관제구역·항행경보·유의파고·물때·조위·고조/저조·천기·태풍은 설명 없음 |
| 해양생활 | 유의파고·파주기·물때·유속(kn)·조석·금어기·생활해양예보지수 등 | 글자 설명은 **3개**(이안류/서핑등급/출조항)뿐, 나머지는 PNG 그림 안에만 |

같은 값을 화면마다 다르게 부르기도 합니다 — 서핑에서는 "유의파고", 낚시·해수욕에서는 그냥 "파고".

### 3-7. 색으로만 구분하는 정보가 있다

- **해양생활 지도 마커**: 등급이 오직 색점(파랑/초록/노랑/주황/빨강)으로만 표시되고, 마커 옆 글자는 등급이 아니라 지점 이름입니다. 노랑(보통)과 주황(나쁨)은 14px 점에서 구분이 어렵습니다.
- **지도 버튼 ON/OFF**: 배경색 명암만 다르고 글자·아이콘은 그대로입니다(버튼 22개 공통).
- **진북 버튼**: 3단계 상태 중 2개가 색으로만 구분됩니다.
- **부이 버튼**: 데이터 유무를 글자색(#ccc / #ff6b6b)으로만 표시합니다.
- **아코디언 펼침/접힘**: 화살표 아이콘이 렌더되지 않아, 배경색과 본문 유무로만 열림/닫힘을 알 수 있습니다.

### 3-8. 색 대비 — 두 군데가 기준 미달

WCAG 상대휘도 공식으로 계산한 결과입니다(기준: 본문 4.5:1).

| 조합 | 대비비 | 판정 |
|---|---|---|
| 흰 글자 #ffffff / 카드 #161b2d | 17.09:1 | 통과 |
| 보조 글자 #94a3b8 / 카드 #161b2d | 6.67:1 | 통과 |
| **작은 설명문 #64748b / 카드 #161b2d** | **3.59:1** | **미달** (앱 전체 290곳 사용, 대부분 0.72~0.78rem 작은 글자) |
| **선택된 파란 버튼 위 흰 글자 #ffffff / #448aff** | **3.32:1** | **미달** (「보통」「관심 해역」 등 현재 선택 상태를 알려주는 글자) |

추가로, 이 앱은 **어두운 배경 + 흰 글자 한 가지 테마만** 제공합니다. 밝은 화면(검은 글자/흰 배경) 선택지가 없습니다.
난시가 있는 사람에게는 어두운 배경 위 흰 글자가 번져 보이는 현상(halation)이 생기며,
난시는 성인 3명 중 1명꼴이고 나이가 들수록 늘어납니다.

### 3-9. 화면이 저절로 바뀐다

- 5분마다 전체 데이터를 다시 받아 화면을 다시 그림 → **펼쳐 두었던 카드가 닫힘**
- 파고·풍속·시정 배지는 2초 주기로 테두리가 계속 깜빡임(멈추는 설정 없음, `prefers-reduced-motion` 대응 없음)
- 안내 툴팁은 2초 만에 사라짐 — 천천히 읽는 사람은 다 못 읽습니다
- 앱을 켜면 2초·3초 시점에 팝업이 최대 3종(제보 답변 → 설문 → 공지) 연달아 뜰 수 있습니다
- 설문 팝업은 「나중에」를 눌러도 저장하지 않아 **다음 접속 때 또 뜹니다**

### 3-10. 스크린리더(음성 안내)로 쓸 수 없다

- 지도 버튼 30개 중 `aria-label`이 붙은 것 **0개** (전부 `title` 속성뿐 — 모바일 터치에서는 뜨지 않음)
- 탭3·탭4 영역의 `aria-label` **0개**
- 아코디언 헤더가 전부 `<div onclick=…>` — 버튼이 아니어서 키보드·스크린리더로 조작 불가
- `aria-expanded` / `role="tablist"` / `aria-selected` **0건**

### 3-11. 이미 만들어 둔 좋은 기능이 어르신에게 닿지 않는다

| 기능 | 왜 안 닿는가 |
|---|---|
| **음성 비서**(호출어 + 음성 답변) — 어르신에게 가장 잘 맞는 기능 | 켜는 UI가 **헤더 15회 클릭으로 들어가는 관리자 모달** 안에만 있음 |
| **AI 챗봇(나리야)** | 운영 설정이 `exposure: admin` 이라 일반 사용자에게 안 보임 + 특보 탭에서만 표시 |
| **위치기반 안전경보**(내 위치 해역 특보를 자동으로 알려줌) | 설정 화면에서 **관리자 전용**으로 잠겨 있음 |
| **안전권고 팝업 끄기** 설정 | 체크박스는 있으나 **저장·적용하는 코드가 없음**(`opt-suppress-safety-popup`을 참조하는 JS 0건) — 눌러도 꺼지지 않는 스위치 |
| 특보 예측(beta) | 아코디언 자체가 `display:none` |
| 관심해역 유도 넛지 | 2회차 방문에 **딱 1번**만 뜸. 문구는 "모든 해역(35개)"이라고 하는데 실제 구역은 **44개** |

## 5. 설계안 — 세 가지 방향 비교

| | A안. 지금 화면에 「큰 글씨 모드」 강화 | **B안. 별도 「쉬운 화면」 신설 (권장)** | C안. 별도 앱 분리 |
|---|---|---|---|
| 방식 | 기존 4탭을 그대로 두고 글자·버튼만 키움 | 어르신용 홈 화면을 새로 만들고, 필요할 때 기존 화면으로 넘어감 | 어르신 전용 앱을 따로 배포 |
| 정보량 | 그대로(많음) | **실사용 상위 3축만** 남김 | 그대로 또는 축소 |
| 걸림돌 | JS 안 인라인 스타일 **2,788곳**, `cssText` 107곳, `innerHTML` 711곳 → CSS 한 겹 덧씌우기로는 전체를 키울 수 없음. 실제로 「크게」가 12.5%에서 멈춘 이유가 이것 | 새 화면 1개 + 새 CSS 1개 추가. 기존 화면 코드는 건드리지 않음 | 배포·심사·운영이 2배. 데이터·계정 이원화 |
| 효과 | 제한적(3-2·3-4 참조) | 큼 — 조작 단계 3~4탭 → 0~1탭 | 큼 |
| 위험 | 기존 화면 레이아웃 깨짐(서브탭 `max-height:50px` 고정 등) | 기능이 빠져 불편하다는 반응 → "전체 화면으로 보기" 출구 필요 | 유지보수 부담이 가장 큼 |

> **권장: B안.** 근거 ①금융권 고령자모드·안전해 개편이 모두 "덜어낸 별도 화면" 방식을 택했고
> ②기존 화면을 키우는 방식(A)은 인라인 스타일 2,788곳 때문에 실제로 이미 한계가 드러났으며
> ③C안은 이 저장소 인력 규모에 맞지 않습니다.
> 다만 A안의 일부(px 고정 글자 154곳 정리, 시스템 글자 크기 존중)는 **B안과 별개로 해두면 모두에게 이득**입니다.

## 6. 권장안 상세 — 「쉬운 화면」

### 6-1. 무엇을 남기고 무엇을 뺄 것인가 (실사용 데이터 기준)

**남긴다 (실사용 상위 3축 = 전체의 약 51%, 어업종사자의 약 54%)**

1. **지금 우리 바다 — 나가도 되나** : 내 위치(또는 고른 해역)의 특보 상태 + 바람·파고
2. **물때·조석** : 오늘의 고조/저조 시각과 높이 (어민·갯벌·낚시 공통 축)
3. **위험할 때 알림** : 특보 발효 시 큰 글씨 알림 + 행동요령(이미 있는 `fix_popup_logic` 문구 재사용)

**뺀다(쉬운 화면에서는 안 보임, 「전체 화면으로 보기」로 이동)**
지도 오버레이 21종, 해상일기도, 해양생활 6개 지수 지도, 공지·댓글, 해구도, 태풍 패널, 슬라이더 6종 전부.

### 6-2. 화면 구성 (초안)

```
┌─────────────────────────────┐
│  [ 큰 글씨 ]  우리 바다      │  ← 헤더 1줄, 40px 이상
├─────────────────────────────┤
│                             │
│      🔴  오늘은             │  ← 신호등 아이콘 (색+글자+모양 3중)
│      나가지 마세요           │  ← 32px 이상, 한 문장 판정
│                             │
│   풍랑주의보가 내려졌어요     │  ← 20px, 쉬운 말
│   (오늘 오후 3시부터)        │
│                             │
│   바람   초속 14미터 (셈)    │  ← 숫자 + 쉬운 말 등급
│   물결   2미터 (높음)        │
│                             │
│  ┌───────────────────────┐  │
│  │   🔊  읽어 주세요       │  │  ← 64px 이상 버튼
│  └───────────────────────┘  │
├─────────────────────────────┤
│  ┌──────────┐ ┌──────────┐  │
│  │  🌊 물때  │ │ ☎ 전화   │  │  ← 2개 큰 버튼
│  └──────────┘ └──────────┘  │
├─────────────────────────────┤
│      전체 화면으로 보기 →     │  ← 기존 앱으로 나가는 출구
└─────────────────────────────┘
```

- **한 문장 판정**: "나가지 마세요 / 조심하세요 / 괜찮아요" 3단계. 판정 기준은 특보 등급(경보·태풍=적, 주의보·예비=황, 없음=녹)으로 시작하고, 추후 풍속·파고를 함께 본다.
- **읽어 주세요**: 이미 있는 TTS(`assistant.js`의 Web Speech 경로)를 재사용해 화면 내용을 소리로 읽어 줍니다.
- **전화**: 해양경찰 122 등 — 넣을지 여부는 §8 결정 사항.
- **물때**: 오늘의 고조·저조 시각만 큰 글씨로. 지도 없이 즉시 표시.

### 6-3. 지켜야 할 수치 규칙 (검증 가능한 기준)

| 항목 | 기준 | 지금 값 |
|---|---|---|
| 본문 글자 | **최소 20px** (「크게」에서 26px 이상) | 화면 글자의 64~100%가 14px 미만 |
| 판정 문장 | **최소 32px** | 해당 없음 |
| 누를 수 있는 요소 | **최소 60×60px**, 간격 12px 이상 | 지도 버튼 38×40px |
| 색 대비 | **7:1 이상**(AAA) | 작은 설명문 3.59:1 |
| 한 화면 정보 | **5개 이하** | 지도 화면 첫 진입에 버튼 14개 |
| 조작 단계 | 목표 정보까지 **0~1탭**, 제스처(핀치·회전) **금지** | 3~5탭 + 핀치 필요 |
| 자동 변경 | 화면이 저절로 다시 그려지지 않음. 깜빡임 애니메이션 없음 | 5분마다 재렌더 + 2초 깜빡임 |
| 글자 크기 | 시스템 설정 존중(`text-size-adjust` 해제) + 앱 설정은 **최대 +100%** | 시스템 무시, 앱은 +12.5% |
| 색 외 단서 | 모든 상태를 **색 + 글자 + 모양** 3중으로 | 마커·토글이 색으로만 구분 |
| 스크린리더 | 모든 버튼에 `aria-label`, 상태에 `aria-pressed` | 지도 버튼 0개 |
| 테마 | **밝은 화면 선택지 제공** | 어두운 테마 전용 |

### 6-5. 어떻게 켜고 끄나

1. **첫 실행 때 한 번 물어보기** — "글자를 크게, 화면을 간단하게 보시겠어요?" [예 / 아니요] (큰 버튼 2개)
2. **설정 첫 화면 맨 위에 큰 스위치** — 「쉬운 화면으로 보기」
3. **언제든 되돌리기** — 쉬운 화면 아래 「전체 화면으로 보기」, 전체 화면 헤더에 「쉬운 화면」
4. 선택은 `localStorage`에 저장(기존 `user_font_size`와 같은 방식)

숨김 진입(10회 연타 등)은 쓰지 않습니다 — 어르신이 우연히 발견할 수 없기 때문입니다.

### 6-6. 어떻게 만들 것인가 (기술)

- 새 폴더 `client/js/senior/` + 새 섹션 `#senior-section` + **새 CSS 파일**(기존 `style.css`는 건드리지 않음)
- 데이터는 **이미 있는 API를 그대로 재사용** — 새 서버 API가 필요 없습니다:
  - 특보: 기존 특보 데이터(`fetchAllData` 경로)
  - 내 위치 → 해역 판정: `client/js/location-alert/location_alert_core.js`의 `locateZone`·`classifyTier` (이미 구현·검증됨)
  - 바람·파고·수심 등 한 지점 종합: `GET /api/ocean/all?lat=&lon=`
  - 조석: 기존 조석 카드 경로(`ocean_bottom_sheet3.js`가 쓰는 API)
  - 음성 읽어주기: `assistant.js`의 Web Speech TTS 경로
  - 행동요령 문구: `fix_popup_logic.js`에 이미 있는 특보별 안내문
- 렌더는 처음부터 `rem` 기준, 인라인 px 스타일 금지(§5 A안이 막힌 이유를 반복하지 않기 위해)
- 기존 화면과의 접점은 **탭 전환 함수 한 곳**(`switchMainTab` 래퍼, `index2_patch.js`가 이미 쓰는 방식)만 사용

## 8. 결정이 필요한 사항 (사용자 확인 요청)

1. **대상**: 어르신 일반인가, **고령 어업인**(실사용 데이터상 특보·기상 중심)인가? 화면 구성이 달라집니다.
2. **진입 방식**: 첫 실행 시 물어보기 + 설정 스위치 방식으로 괜찮은가?
3. **밝은 테마**: 쉬운 화면을 지금처럼 어두운 배경으로 할지, **흰 배경+검은 글씨**로 할지(고령자 시각 특성상 후자 권장, 다만 앱 정체성과 다름).
4. **전화 걸기 버튼**: 해경(122)·파출소 연결을 넣을지. 오작동 시 영향이 크므로 확인이 필요합니다.
5. **쉬운 말 표기**: 특보 용어를 쉬운 말로 바꿔 쓰되 **공식 용어를 괄호로 병기**하는 방식으로 괜찮은가?
6. **잠겨 있는 기능 개방**: 음성 비서·위치기반 경보·AI 챗봇을 일반 사용자에게 열지 여부(각각 별도 판단 필요).
7. **범위**: 1단계(화면 1장)만 먼저 만들고 반응을 볼지, 2단계까지 한 번에 갈지.
