# SEAGNAL 특보중계 앱 (kakao_relay_app)

태블릿 전용 안드로이드 앱입니다. 카카오톡 「기상청 해양기상정보포털」 채널에서 특보 알림톡이 오면, 그 대화방을 자동으로 열어 화면의 글자를 읽고 SEAGNAL 서버로 보냅니다.
SEAGNAL 본 앱(`android/`)과는 별개의 프로젝트입니다.

> 사용자 결정 2026-11-02: 「3번으로 진행하자」. 3번은 전용 안드로이드 앱이 접근성 기능으로 대화방을 읽는 방식입니다.
> **현재 단계**: 서버가 받은 글을 **기록만 합니다.** 앱 푸시(MMIS 경로)에는 아직 연결하지 않았습니다.
> 푸시 발사 경로를 바꾸는 일이라, 연결하기 전에 CLAUDE.md 결정로그에 따른 별도 에이전트 적대검증을 거쳐야 합니다.

## 동작
1. **알림 감지**(`KakaoNotiService`): 카톡 알림의 제목에 「해양기상정보포털」이 있거나 본문에 `[해양기상기후정보 알림]`이 있으면 동작합니다.
   - 알림에 담긴 글을 곧바로 서버로 보냅니다(`source=notification`). 이 글은 잘려 있을 수 있습니다.
   - 그다음 대화방 읽기를 `ReaderService`에 맡깁니다.
2. **대화방 읽기**(`ReaderService`, 접근성):
   - 화면을 켜고, 알림의 열기 동작으로 대화방을 엽니다.
   - 화면 변화가 1.2초 동안 멈추면, `[해양기상기후정보 알림]`이 든 글 중 최근 5개를 읽습니다.
   - 「전체보기」가 있으면 한 번 눌러서 전문을 읽은 뒤 뒤로 돌아갑니다.
   - 읽은 글을 서버로 보내고(`source=screen`) 홈 화면으로 나갑니다. 45초 안에 끝나지 않으면 포기합니다.
3. **살아 있음 신호**: 30분마다 `POST /api/kakao-relay/heartbeat`를 보냅니다.
4. 전송에 실패한 글은 태블릿에 쌓아 둡니다(최대 100개). 다음 신호나 전송 때 다시 보냅니다.

★ 특보 표식이 든 글만 서버로 보냅니다. 다른 대화 내용은 서버로 가지 않습니다.

## 파일
| 파일 | 역할 |
|---|---|
| `Config.java` | 설정값, 표식 상수, 화면용 기록 |
| `Sender.java` | 서버 전송, 실패한 글 대기열 |
| `KakaoNotiService.java` | 알림 감지, 30분 신호 |
| `ReaderService.java` | 대화방 열기와 읽기(접근성) |
| `MainActivity.java` | 설정 화면, 권한 바로가기, 시험 전송 |

## 서버 쪽
- `local_server/routes/kakao_relay.js`
  - `POST /api/kakao-relay/messages`: 헤더 `X-Relay-Token` 필요
  - `POST /api/kakao-relay/heartbeat`
  - `GET /api/admin/kakao-relay`: 관리자 토큰 필요
- `local_server/services/kakao_relay.js`
  - 특보 줄로 나누기(구역·종류·시각·발효/해제)
  - 같은 글 한 번만 남기기
  - `data/kakao_relay.json`에 최근 300개 보관
- 서버에 열쇠를 설정해야 창구가 열립니다. 설정하지 않으면 503을 돌려줍니다.

```bash
fly secrets set KAKAO_RELAY_TOKEN=<긴 무작위 문자열>
```

- 검사: `local_server/scripts/test_kakao_relay.js` (verify_all SUITES에 등록됨)

## 빌드
```bash
cd kakao_relay_app && ./gradlew assembleDebug
```
- 빌드하려면 안드로이드 SDK 경로를 적은 `local.properties`가 필요합니다.
- 결과물: `app/build/outputs/apk/debug/app-debug.apk`

## 태블릿 설치·설정
1. APK를 설치합니다. "출처를 알 수 없는 앱" 설치를 허용해야 합니다.
2. 앱 화면에서 서버 주소, 비밀 열쇠, 기기 이름을 넣고 [저장]을 누릅니다.
3. 앱 화면의 버튼으로 세 가지를 켭니다. 앱 화면에 셋 다 ✅가 떠야 합니다.
   - ① 알림 접근 허용
   - ② 접근성(화면 읽기) 켜기
   - ③ 배터리 최적화 제외
4. [서버 연결 시험]과 [시험 글 보내기]를 눌러, 기록에 "전송 성공"이 뜨는지 확인합니다.
5. 운영 조건:
   - **화면 잠금 없음**(잠금 화면이 있으면 대화방을 열 수 없습니다)
   - 충전기와 와이파이 상시 연결
   - 카톡 알림 켜기
   - 카톡의 「해양기상정보포털」 대화방을 열어 둔 채로 두지 않기(열려 있으면 알림이 안 뜰 수 있음)

## 실기기에서 아직 확인하지 않은 것 (이 컨테이너에는 태블릿이 없음)
- 카톡 말풍선 글이 접근성으로 전문 그대로 읽히는지, 화면 밖으로 넘친 부분까지 포함되는지
- 「전체보기」 문구와 버튼 구조가 실제와 같은지
- 안드로이드 14 이상에서 백그라운드 상태에서 알림의 열기 동작이 허용되는지
- 「전체보기」를 누른 경우, 접힌 글과 전문이 서로 다른 글로 둘 다 저장됩니다. 푸시에 연결할 때 특보 줄 단위로 중복을 걸러야 합니다.

## 적대검증 반영 (2026-11-02, 별도 에이전트 검토)
고친 것:
- **알림 걸러내기:** 알림 제목이 채널 이름일 때만 동작합니다. 전에는 본문에 표식만 있어도 통과해서 가짜 특보를 넣을 수 있었습니다.
- **대화방 확인:** 화면에 채널 이름이 보일 때만 읽습니다. 채팅 목록이나 다른 대화방 화면은 읽지 않습니다.
- **읽는 도중 새 특보:** 읽는 중에 새 특보가 오면 버리지 않고, 끝난 뒤 한 번 더 읽습니다.
- **「전체보기」 실패:** 실패하면 "성공"으로 기록하지 않고 따로 기록합니다. 끝낼 때는 BACK으로 전문 화면을 닫고 나갑니다.
- **마지막 읽기 결과:** 30분 신호에 실어 서버로 보냅니다(`note`).
- **알림 감시가 끊기면** 다시 연결을 요청합니다(`requestRebind`).
- **서버 받는 양:** 한 번에 50건까지만 받습니다. 넘으면 일부만 받고 성공이라 하지 않고 413을 돌려줍니다. 앱은 50건씩 나눠 보내고, 보낸 묶음만 대기열에서 지웁니다.
- **분해 결과 표시:**
  - 모르는 동작어는 `unknown` 으로 둡니다.
  - 분해된 줄이 0줄이면 `unparsed` 로 표시하고 경고를 남깁니다.
  - 비교용 `zoneKey`(공백을 모두 뺀 구역 이름)를 함께 저장합니다.
- **저장 파일 손상:** 손상되면 빈 파일로 덮어쓰지 않고 `.bad` 로 보존한 뒤 저장을 거부합니다.
- **열쇠 불일치:** 서버 기록에 남깁니다.

## 멈춤 감시·중복 거르기 (2026-11-02 추가, 사용자 「이어서 만들어봐」)
- **30분 신호:** `BeatReceiver` 가 AlarmManager(`setAndAllowWhileIdle`)로 보냅니다. 절전 중에도 깨어나며, 몇 분 늦을 수는 있습니다.
  - 기기를 다시 켜면 알람을 다시 겁니다(BOOT_COMPLETED).
  - 전송하는 동안은 기기가 다시 잠들지 않게 잡아 둡니다(최대 60초).
- **신호에 담는 상태:** 접근성 꺼짐 · 알림 감시 끊김 · 마지막 대화방 읽기 결과
- **서버 판정:** `services/kakao_relay.judgeHealth`·`checkHealth` 가 판정하고, `scheduler.js` 가 5분마다 부릅니다. 아래 중 하나면 「이상」입니다.
  - 신호가 70분 넘게 없음
  - 접근성 꺼짐
  - 알림 감시 끊김
  - 마지막 대화방 읽기 실패
- **관리자 푸시:** 처음 이상일 때 1통, 정상으로 돌아오면 「복구」 1통을 보냅니다. 기존 `services/collect_fail_alert` 의 항목 `kakaoRelay` 를 그대로 씁니다.
- **판정하지 않는 경우:**
  - 서버에 열쇠(KAKAO_RELAY_TOKEN)가 없을 때
  - 태블릿 신호가 한 번도 온 적이 없을 때(설치 전)
- **관리자 화면:** 관리자 → 점검 → 데이터 수집현황 → 「수집 목록」에 **「카톡 특보중계 신호 (우리 태블릿 앱)」** 카드가 생깁니다. 마지막 신호 시각을 보여 주고, 늦으면 「늦음」으로 표시합니다. 목록표 `config/data_collection_manifest.json` 의 `kakaoRelay` 입니다.
- **특보 줄 단위 중복:**
  - 받은 글마다 `newWarnings` 를 붙입니다. 처음 보는 (구역·종류·시각·동작) 줄 중에서 동작어를 알고, 24시간 안의 것만 들어갑니다.
  - 푸시에 연결할 때는 이것만 쓰면 됩니다.

남은 것:
- **사용자 앱 푸시 연결:** 아직 연결하지 않았습니다. 푸시 발사 경로 변경이므로 설계와 적대검증이 먼저 필요합니다.
- **「MMIS엔 특보가 났는데 카톡 경로 글이 없음」 경고:** 하지 않았습니다. 알림톡은 **알림 신청한 해역만** 오기 때문에, 신청 해역 목록 없이 MMIS 전체와 견주면 잘못 울립니다. 신청 해역 목록을 받으면 만들 수 있습니다.
- **카톡 앱 자체 잠금(암호)** 이 켜져 있으면 대화방을 열 수 없습니다.
