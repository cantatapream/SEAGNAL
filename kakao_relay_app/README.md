# SEAGNAL 특보중계 앱 (kakao_relay_app)

태블릿 전용 안드로이드 앱입니다. 카카오톡 「기상청 해양기상정보포털」 채널에서 특보 알림톡이 오면, 그 대화방을 자동으로 열어 화면의 글자를 읽고 SEAGNAL 서버로 보냅니다.
SEAGNAL 본 앱(`android/`)과는 별개의 프로젝트입니다.

> 사용자 결정 2026-11-02: 「3번으로 진행하자」. 3번은 전용 안드로이드 앱이 접근성 기능으로 대화방을 읽는 방식입니다.
> **현재 단계**: 서버가 받은 글을 **기록만 합니다.** 앱 푸시(MMIS 경로)에는 아직 연결하지 않았습니다.
> 푸시 발사 경로를 바꾸는 일이라, 연결하기 전에 CLAUDE.md 결정로그에 따른 별도 에이전트 적대검증을 거쳐야 합니다.

## 동작
1. **알림 감지**(`KakaoNotiService`): 카톡 알림의 제목에 「해양기상정보포털」이 있거나 본문에 `[해양기상기후정보 알림]`이 있으면 동작합니다.
   - 알림에 담긴 글을 곧바로 서버로 보냅니다(`source=notification`). 이 글은 잘려 있을 수 있습니다.
   - 그다음 대화방 읽기를 `ReaderService`에 맡깁니다.
2. **대화방 읽기**(`ReaderService`, 접근성):
   - 화면을 켜고, 알림의 열기 동작으로 대화방을 엽니다.
   - 화면 변화가 1.2초 동안 멈추면, `[해양기상기후정보 알림]`이 든 글 중 최근 5개를 읽습니다.
   - 「전체보기」가 있으면 한 번 눌러서 전문을 읽은 뒤 뒤로 돌아갑니다.
   - 읽은 글을 서버로 보내고(`source=screen`) 홈 화면으로 나갑니다. 45초 안에 끝나지 않으면 포기합니다.
3. **살아 있음 신호**: 30분마다 `POST /api/kakao-relay/heartbeat`를 보냅니다.
4. 전송에 실패한 글은 태블릿에 쌓아 둡니다(최대 100개). 다음 신호나 전송 때 다시 보냅니다.

★ 특보 표식이 든 글만 서버로 보냅니다. 다른 대화 내용은 서버로 가지 않습니다.

## 파일
| 파일 | 역할 |
|---|---|
| `Config.java` | 설정값, 표식 상수, 화면용 기록 |
| `Sender.java` | 서버 전송, 실패한 글 대기열 |
| `KakaoNotiService.java` | 알림 감지, 30분 신호 |
| `ReaderService.java` | 대화방 열기와 읽기(접근성) |
| `MainActivity.java` | 설정 화면, 권한 바로가기, 시험 전송 |

## 서버 쪽
- `local_server/routes/kakao_relay.js`
  - `POST /api/kakao-relay/messages`: 헤더 `X-Relay-Token` 필요
  - `POST /api/kakao-relay/heartbeat`
  - `GET /api/admin/kakao-relay`: 관리자 토큰 필요
- `local_server/services/kakao_relay.js`
  - 특보 줄로 나누기(구역·종류·시각·발효/해제)
  - 같은 글 한 번만 남기기
  - `data/kakao_relay.json`에 최근 300개 보관
- 서버에 열쇠를 설정해야 창구가 열립니다. 설정하지 않으면 503을 돌려줍니다.

```bash
fly secrets set KAKAO_RELAY_TOKEN=<긴 무작위 문자열>
```

- 검사: `local_server/scripts/test_kakao_relay.js` (verify_all SUITES에 등록됨)

```bash
cd kakao_relay_app && ./gradlew assembleDebug
```
- 빌드하려면 안드로이드 SDK 경로를 적은 `local.properties`가 필요합니다.
- 결과물: `app/build/outputs/apk/debug/app-debug.apk`

## 태블릿 설치·설정
1. APK를 설치합니다. "출처를 알 수 없는 앱" 설치를 허용해야 합니다.
2. 앱 화면에서 서버 주소, 비밀 열쇠, 기기 이름을 넣고 [저장]을 누릅니다.
3. 앱 화면의 버튼으로 세 가지를 켭니다. 앱 화면에 셋 다 ✅가 떠야 합니다.
   - ① 알림 접근 허용
   - ② 접근성(화면 읽기) 켜기
   - ③ 배터리 최적화 제외
4. [서버 연결 시험]과 [시험 글 보내기]를 눌러, 기록에 "전송 성공"이 뜨는지 확인합니다.
5. 운영 조건:
   - **화면 잠금 없음**(잠금 화면이 있으면 대화방을 열 수 없습니다)
   - 충전기와 와이파이 상시 연결
   - 카톡 알림 켜기
   - 카톡의 「해양기상정보포털」 대화방을 열어 둔 채로 두지 않기(열려 있으면 알림이 안 뜰 수 있음)

## 실기기에서 아직 확인하지 않은 것 (이 컨테이너에는 태블릿이 없음)
- 카톡 말풍선 글이 접근성으로 전문 그대로 읽히는지, 화면 밖으로 넘친 부분까지 포함되는지
- 「전체보기」 문구와 버튼 구조가 실제와 같은지
- 안드로이드 14 이상에서 백그라운드 상태에서 알림의 열기 동작이 허용되는지
- 「전체보기」를 누른 경우, 접힌 글과 전문이 서로 다른 글로 둘 다 저장됩니다. 푸시에 연결할 때 특보 줄 단위로 중복을 걸러야 합니다.

## 적대검증 반영 (2026-11-02, 별도 에이전트 검토)
고친 것:
- **알림 걸러내기:** 알림 제목이 채널 이름일 때만 동작합니다. 전에는 본문에 표식만 있어도 통과해서 가짜 특보를 넣을 수 있었습니다.
- **대화방 확인:** 화면에 채널 이름이 보일 때만 읽습니다. 채팅 목록이나 다른 대화방 화면은 읽지 않습니다.
- **읽는 도중 새 특보:** 읽는 중에 새 특보가 오면 버리지 않고, 끝난 뒤 한 번 더 읽습니다.
- **「전체보기」 실패:** 실패하면 "성공"으로 기록하지 않고 따로 기록합니다. 끝낼 때는 BACK으로 전문 화면을 닫고 나갑니다.
- **마지막 읽기 결과:** 30분 신호에 실어 서버로 보냅니다(`note`).
- **알림 감시가 끊기면** 다시 연결을 요청합니다(`requestRebind`).
- **서버 받는 양:** 한 번에 50건까지만 받습니다. 넘으면 일부만 받고 성공이라 하지 않고 413을 돌려줍니다. 앱은 50건씩 나눠 보내고, 보낸 묶음만 대기열에서 지웁니다.
- **분해 결과 표시:**
  - 모르는 동작어는 `unknown` 으로 둡니다.
  - 분해된 줄이 0줄이면 `unparsed` 로 표시하고 경고를 남깁니다.
  - 비교용 `zoneKey`(공백을 모두 뺀 구역 이름)를 함께 저장합니다.
- **저장 파일 손상:** 손상되면 빈 파일로 덮어쓰지 않고 `.bad` 로 보존한 뒤 저장을 거부합니다.
- **열쇠 불일치:** 서버 기록에 남깁니다.

- **카톡 앱 자체 잠금(암호)** 이 켜져 있으면 대화방을 열 수 없습니다.

## [임시] 긁어오기 — 옛 알림톡 분석용 (2026-11-02)
> 사용자: 「임시로만. 그렇게 가져가면 네가 그 데이터를 보고 분석해줄 수 있도록 해줘.」
> 목적: MMIS가 자주 오류를 내서, 카톡 알림톡의 특보 정보를 특보현황에 반영하려 합니다. 그러려면 먼저 지금까지 온 알림톡의 꼴, 용어, 구역 명칭이 우리 앱(MMIS 기반)과 어떻게 다른지 확인해야 합니다.

- **본 휴대폰 설정:**
  - 같은 APK를 설치합니다.
  - **「자동 중계 사용」은 끕니다.** 켜 두면 특보가 올 때마다 쓰는 화면을 가로채 카톡을 엽니다.
  - 권한은 **접근성만** 켭니다. 알림 접근은 필요 없습니다.
  - 자동 중계가 꺼져 있으면 감시 신호를 보내지 않습니다. 그래서 서버 멈춤 감시가 이 기기를 태블릿으로 착각하지 않습니다.
- **쓰는 법:**
  1. [긁어오기 시작]을 누릅니다. 카톡이 열립니다.
  2. 3분 안에 「해양기상정보포털」 대화방을 엽니다.
  3. 앱이 위로 넘기며 특보 글과 그 날짜·시각을 모아 서버로 보냅니다.
  4. 새 글이 4번 연속 없거나 더 넘길 수 없으면 멈춥니다. 대화방을 벗어나거나 [중지]를 눌러도 멈춥니다.
- **서버 보관:** `data/kakao_relay_backfill.json` 에 따로 둡니다(최대 5000개). 실시간 기록이나 특보 줄 중복표와 섞지 않습니다.
  - 받기: `POST /api/kakao-relay/backfill`
  - 꺼내 보기: `GET /api/kakao-relay/backfill`
  - 분석 후 지우기: `DELETE /api/kakao-relay/backfill`
  - 모두 같은 열쇠(`X-Relay-Token`)가 필요합니다.
- **1단계(분석)는 파일로 합니다** (사용자 확정 2026-11-02 「파일로 저장해서 채팅에 첨부」, 운영 서버에는 아직 반영하지 않음).
  - 긁어오기가 끝나면 휴대폰 **다운로드 폴더**에 `kakao_backfill_날짜시각.json` 이 생깁니다.
  - 표식 글만이 아니라 그 채널 대화방 안의 15자 이상 글을 모두 담고, `hasMarker` 로 구분합니다. 표식 없는 다른 꼴 메시지가 있는지 보기 위해서입니다.
  - 서버 주소가 비어 있으면 서버로는 보내지 않습니다.
- 사용자가 정한 이후 단계:
  - ② 분석이 끝나면 휴대폰과 태블릿 둘 다 실시간 중계합니다. 휴대폰은 화면을 건드리지 않는 「알림 글만」 방식으로 할 예정입니다.
  - ③ 관리자 페이지에서 기기별로 끄거나 삭제할 수 있게 합니다. 휴대폰을 빼고 태블릿만 남기는 용도입니다.
- 분석이 끝나면 지우고, 이 기능도 걷어낼 예정입니다.

## 휴대폰 시험 — 「알림 글만 보내기」 (2026-11-02)
> 사용자: 「내일모레 출동을 나가는데, 그 동안 승인이 이루어지지 않으면 휴대폰으로라도 데이터를 받아서 제공하도록 … 일단은 되는지 여부만 내일까지 판단」
> (바다에 나가면 휴대폰 카톡이 안 터진다 — 지금은 실현 가능성 판단용)

- **설정:** 「자동 중계 사용」 켬 + 「알림 글만 보내기」 켬. 권한은 **알림 접근**이 필요합니다.
- **동작:** 알림 글을 서버로 보냅니다. 화면을 켜거나 카톡을 열지 않습니다.
  - 신호 note 는 `ok(알림 글만)` 입니다. 접근성이 꺼져 있어도 이상으로 보지 않습니다.
- **서버:** 운영 서버에 이미 있는 `POST /api/kakao-relay/messages` 로 들어가 **기록만** 됩니다. 특보현황이나 사용자 푸시와는 무관합니다.
- **분석용 읽기:** `GET /api/kakao-relay/messages` 를 같은 열쇠로 추가했습니다. 이건 PR이 합쳐져야 운영 서버에 생깁니다.
- **주의:** 휴대폰이 통신 밖에 있다가 돌아오면 밀린 알림이 한꺼번에 옵니다. 특보현황에 반영할 때는 받은 시각이 아니라 **글 속 시각**으로 순서를 정해야 합니다. 늦게 온 옛 해제가 새 발효를 덮으면 안 됩니다. 2단계 설계에서 다룹니다.

## 해석기 보강·「이미 봤음」·MMIS 대조 (2026-11-03)
사용자 확인 내용과 확정 사항(대화 원문 요지):
- 「남해서부서쪽은 남해서부서쪽먼바다밖에 없어」 → 별칭으로 처리합니다.
- 해제의 미래 시각은 「확정 예고」입니다. 그 시각 전까지는 발효 중으로 봅니다.
- 「변경」은 그 종류·등급으로 바뀌는 것입니다. 격상인지 격하인지는 직전 상태와 비교해야 압니다.
- 「변경해제」는 태풍으로 바뀌면서 풍랑이 끝나는 것입니다.
- 「연장」의 시각은 연장 발효 시각입니다. 해제예고는 카톡에 오지 않습니다.
- 「태풍은 mmis 정보를 사용해야만」 → 태풍 줄은 `mmisOnly` 로 표시하고, 새 특보로 세지 않습니다.

서버(`services/kakao_relay.js`):
- **구역 맞추기:** 표준 해역표는 `marine_warning_crawler.MMIS_CODE_TO_NAME`(93곳, 이번에 export)와 `PARENT_TO_CHILDREN` 입니다. 이름은 공백 제거, 「.」→「·」로 맞추고 별칭을 적용합니다. 부모 해역도 함께 붙입니다. 표에 없는 이름은 `zoneKnown=false` 로 두고 관리자에게 알립니다.
- **예비특보:** `[예비특보]` 의 시간 범위를 `at`(시작)·`until`(끝)으로 읽습니다. 18~00시는 다음 날 00시로 봅니다.
- **이번 알림과 직전 글 구분:** 앱은 방금 뜬 알림과 앞부분이 같은 말풍선에 `trigger=true` 를 붙입니다.
  - `trigger=true` 글에서 나온 처음 보는 줄 → `newWarnings`
  - 함께 읽힌 직전 글(`trigger=false`)에서 나온 처음 보는 줄 → `missedWarnings`. 놓쳤던 글일 수 있고, 이미 지난 특보일 수 있으므로 새 특보로 쓰지 않습니다.
  - 나중에 같은 글이 trigger 로 오면 `newWarnings` 로 올립니다(동시에 2개 온 경우).
- **이미 봤음 미리 채우기:** `POST /api/kakao-relay/seed {texts}` 로 긁어온 옛 글의 id와 특보 줄을 미리 기억시킵니다. 첫 실측에서 전날 특보가 새것으로 잡힌 문제를 막기 위해서입니다.
- **MMIS 대조(`checkMmis`, 매분):**
  - 대상은 「이번 알림」의 풍랑 정식 특보 중 부모 해역입니다.
  - 10분이 지나도 특보현황(`data/weather_alerts.json`)에 반영되지 않으면 관리자에게 알립니다. 알림에는 구역, 카톡 내용, 도착 시각, 지금 특보현황(발효·해제예고·발표), 할 일을 적습니다.
  - 나중에 반영되면 「같아짐」을 한 번 더 알립니다. 몇 분 늦었는지도 적습니다.
  - 6시간이 지나도 다르면 대조를 끝내고 기록만 남깁니다.
  - 보낸 알림은 같은 문장으로 `checks` 에 남깁니다. `GET /api/kakao-relay/messages` 에서 볼 수 있습니다.
  - 판정 기준(`mmisMatches`):
    - 해제: 해제예고나 해제시각이 정확히 같거나, 풍랑이 없음
    - 연장·발효·변경: 같은 등급이 있고 발효/발표 시각이 같거나, 발표가 카톡 도착 90분 전 이후
  - 이 판정은 「옛 발표의 해제예고로 해제되는」 위험을 알아채는 신호이기도 합니다.
- 이 단계는 **기록과 관리자 알림만** 합니다. 특보현황과 사용자 푸시는 바꾸지 않습니다.
