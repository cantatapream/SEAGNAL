## I-1. 왜 재설계했나 — 과대검출의 근본 원인

배포 후 19개 구역이 일제히(균일 80%/63%) 과다검출되었다. 원인을 확정했다:
- 구역을 **중심점 + 원형 반경**(먼바다 99px≈80km)으로 샘플링하고, 그 원 안에서 **최대 밴드**(≥12px)를
  취함 → 사실상 **"구역값"이 아니라 "주변 지역 최대값"**. 이웃의 거친 날씨가 원에 걸치면 연쇄 표출.
- 등급컷(prob≥0.5)과 확률표(25kt→63%)가 결합해, 25kt 픽셀 12개만 스쳐도 "관심 63%"가 떴다.

## I-2. 핵심 수정 (검증된 로직)

- **원형 반경 → 폴리곤 내부 샘플링 + 면적비율**(`zonePolygon.js`): 구역 폴리곤 내부 바다픽셀 중
  위험풍속(≥20kt) 비율 = `areaFraction`. "구역이 충분히 덮였을 때만" 표출 → 이웃 번짐 차단.
- **운영점**: `최대밴드 ≥25kt & 면적 ≥30%`. 전수검증(152,480 표본)에서 동일 재현율 대비 오탐 **18~25%p** 감소.
- **2단계 등급(밴드·면적 2차원)** + **확률 차등(51~70%)**:

  | 게이트 | 재현율 | 현실 정밀도 |
  |---|---|---|
  | ≥25kt & 면적≥30% | 67% | 51% |
  | ≥25kt & 면적≥50% | 59% | 56% |
  | ≥30kt & 면적≥50% | 51% | 64% |
  | ≥35kt & 면적≥50% | — | 70% |

  → **면적이 풍속보다 강한 판별자**. 🔴높음=강풍(≥30kt)&넓은면적(≥50%) / 🟡관심=풍속(≥25&면적≥30) 또는 파고.
- **2사이클 지속성**: 직전 사이클에도 잡힌 구역만 표출(1회성 노이즈 억제). 우리는 ~3일 선행이라 반나절 지연 무해.
- **프레임-외부 스캔**(`onsetScan.js`): 일기도 1장만 메모리 유지(OOM 해소), zone-외부와 동치 증명(5,000 시나리오).

사용자 평가 철학을 반영: **"기상청이 어떤 정보(예비·특보)든 내놓기 전에 우리가 먼저 잡았나"** 가 가치.

### 데이터 확보
- 사용자 제공 **2020-06~2023-06 발효 통보문**(8,167행) + 기존 2023-2026 → **6년 연속**.
- dmdw 예비특보를 **2020까지 확장 수집**(총 2,404 통보문, 천천히·재개가능).
- **잔잔표본 310**(특보·예비 모두 없던 무작위 구역-시각) + **어려운음성 3,973**(이웃은 발효·자기는 미발효 = 옛 과탐 발생 지점) 일기도 수집.

### 결과 — 선행성 (`run_beatkma.js`)
- 사건별 `기상청 첫 신호 = min(예비 발표, 특보 발표)` 보다 먼저 잡았나로 채점(캐시평가 99%).

- 예비 있던 발효: 예비 발표조차 앞지른 비율 71%.

### 결과 — 정밀도 (`calib_abs.js`, 2026 홀드아웃)
- 음성 종류별 오탐: 쉬운(잔잔) **3%** / 어려운(이웃발효) **25%**.
- 현실비중(무경보 구역-일 중 '이웃 발효' = **20.9%**, 기록 산출)으로 가중 → **현실 오탐 8% · 현실 정밀도 51%(면적30) ~ 64%(30kt&면적50)**.
- ⚠️ 함정 정정: 음성표본이 93% 어려운것이라 단순집계는 정밀도를 24%로 **과소평가**했음 → 현실비중 가중으로 정정.

### 결과 — census·기후값
- KMA 예비특보 자체 정밀도 **58%**(6년), 예비→발효 리드 중앙 **24h**, 발효의 **46%는 예비 없이** 발효.

## 2. 분석 방법론

### 2.1 색상 → 물리량 변환
- 유의파고 GIF 색 → 등급(m) (`palette.js`), 해상풍 GIF 색 → 풍속(kt) (`windPalette.js`, 범례 실측 앵커).
- 임계: **유의파고 ≥3m / 풍속 ≥14m/s(주의보)** , ≥5m / ≥21m/s(경보).

### 2.2 색상 오분류 보정 (3종 — 검증으로 발견·제거)
1. **진초록 특보구역 경계선** ↔ 고파고 팔레트 충돌 → 진초록 앵커 제거.
2. **범례·고정마커** → 정적 마스크(`staticMask.js`, 여러 프레임 RGB불변+임계색 = 고정 크롬).
3. **하단 VALID/TIME 빨강 캡션** → 하단 10% 크롭.

### 2.3 per-zone 보정
- 청 차트(고정 템플릿) 프레임박스+축라벨로 **위경도↔픽셀 affine 보정**(`geoCalib.js`, 6청).
- `seaZoneCoordinates.js` 부모 특보구역 위경도를 차트에 투영, 구역 주변만 분석.

## 3. 검증 과정 (단계별 — 실제 수행 순서)

> 아래는 시스템을 만들며 **실제로 거친 검증 순서**다. 각 단계가 다음 단계의 전제를 확인했다.

### [검증 1] 색상분석 — 음성대조군
- **방법**: 잔잔한 날 vs 폭풍날 동일 분석 → 차이 확인.
- **결과**: 보정 전엔 잔잔/폭풍 모두 maxBand 5.5(아티팩트). **보정 후 잔잔 ≤2.5, 폭풍 ≥3.5로 명확 분리.**
- **의의**: 색상 신호가 실제 기상과 연동됨을 입증(아티팩트 제거 검증).

### [검증 2] per-zone 투영 — 공간 정합
- **방법**: 제주 구역들을 차트에 투영해 위치(북/남/동/서) 정합 확인 + 강풍일 공간구조.
- **결과**: 2025-12-21 강풍 시 **제주 남쪽 구역 5.5m·북부 약함** = 실제 공간구조 일치. 잔잔=0.

### [검증 3] 구역 매칭률
- **방법**: CSV 해역명 → 특보구역 매칭(`zones.js`, 정확+집합/region centroid).
- **결과**: **97.4% (6,259/6,425)**. 미매칭은 평수구역 자식·파서부스러기(부차적).

### [검증 4] 리드타임/재현율 — 전 기간 배치
- **방법**: 6청 × 전기간 풍랑 발효 이벤트(2,580건)마다, 발효 L시간 전 일기도가 이미 임계를
  그렸는지 측정(`runLeadtime.js`). 인과성(미래 run 미열람) 보장.
- **결과(파고)**: 청단위 높음(~80%)이나 **per-zone은 약함(~26%)**.

### [검증 5] 풍속 신호 추가 — 약점 규명·보강
- **발견**: per-zone 파고가 약한 이유 = **풍랑주의보 다수가 풍속(앞바다) 기반**.
- **방법**: 해상풍 차트 색상분석 추가(별도 조사 에이전트로 "풍속 색상분석 가능" 확인).
- **결과**: per-zone 재현율 **파고 26% → 풍속 71%**. 대전청 전기간 100건: 파고 7% vs 풍속 84%.

### [검증 6] 로직 개선 — 무손실 정밀화
- **방법**: 풍속 컷 25→20kt + 구역 샘플 반경 1.8배. **per-zone 거짓경보율 동시 측정**.
- **결과(대전청)**: 재현율 85%→**92%**, per-zone 거짓경보 **3.3% 유지(무손실)**.
- 전국 결합(파고 OR 풍속) per-zone 재현율: 62% → **73%(@12h)**.

### [검증 7] 면적 마진
- **방법**: "구역 면적의 몇 %가 임계 초과 시 발효되나" τ 스윕(`marginSweep.js`).
- **결과**: 풍속 마진 τ≈2~5%에서 재현/오탐 최적. 특보가 작은 강풍 패치에도 선제 발효되는 경향 확인.

### [검증 8] 미검출 분석 (놓친 사례 분해)
- **방법**: 결합 미검출 사례를 (A)일기도 신호 없음 vs (B)있었는데 미검출로 자동 분류(`missAnalysis.js`).
- **결과**: 놓친 것의 상당수가 (B, 반경/양자화) → 개선 여지 정량화 → [검증6]·5일확장으로 회수.

### [검증 9] **홀드아웃 검증 (과적합 배제) — 핵심**
- **방법**: 학습기간(<2026-01-01)으로 "풍속 강도→발효확률" 보정표 생성, **학습에 안 쓴 2026년**으로 검증(`probCalib.js`). 음성표본은 전 기간 잔잔 시점에서 별도 수집(2026 포함).
- **결과 (발효 24h 전, 2026 미사용기간)**:
  - **재현율 89%** (실제 발효 408건 중 362건 예측)
  - **정밀도 78%** (발효예측 464건 중 362건 적중)
  - **확률 보정도**: 예측 80%↑ → 실제 99% 발효 / 60~80% → 73% / <20% → 5% (**잘 보정됨**)
- **의의**: 과거에 기준을 맞춘 게 아니라, **안 본 미래 데이터에서도 동일 성능** → 일반화 입증.

### [검증 10] 발표·예비특보 대비 선행성 (+정정 이력)
- **발표(주의보) 대비**(`leadVsAnnounce.js`): 검출 시 **100%가 더 빠름**, 중앙값 ~70h. (기상청 주의보 발표는 발효 ~2h 전)
- **예비특보 대비** — **검증 중 오류 발견·정정**:
  - 1차(해역만 매칭): 예비특보 선행 101h, 우리 41% → **부정확**(무관한 이전 예비특보에 매칭됨).
  - **정정(예상시점 매칭, `preCompare3.js`)**: 예비특보 실제 선행 **26시간(≈1일)**, 우리가 **98% 더 빠름**(중앙값 +66h).
  - 정정 근거 데이터: 예비특보 상세 크롤 **해역×예상시점 12,675건**.
- **의의**: 자체 검증으로 **자기 오류를 발견·정정**한 이력 = 신뢰성의 증거.

### [검증 11] 5일(96h) 확장
- **방법**: 리드타임을 12/24/48/72 → **+96/120h** 확장 재배치.
- **결과**: 실질 최대 **96h(4일)** 까지 재현율 유지(96h ~65%). 120h는 예보지평 초과로 빈값.

### [검증 12] **통보문 AI 추출 — 3회 반복 검증**
교차참조(기상청 해설 "풍랑특보 가능성")용 AI 추출 프롬프트를, **서로 다른 기간의 통보문에 3회 반복**하며 갭을 찾아 보강:

| 라운드 | 대상 통보문 | 발견·보강 규칙 |
|---|---|---|
| 1차 | **8건** (2025-12, 2026-01, 2026-04) | ① 발효중↔발표가능성 ② 제외 ③ 비표준명 ④ 광역 |
| 2차 | **5건** (2024-02 등) | ⑥ 한정(괄호=only) |
| 3차 | **5건** (2024-11 등) | ⑦ 경보변경 ⑧ 해제시각괄호 ⑨ 확실성 |
| **합계** | **통보문 18건, 3라운드** | **규칙 9종 + 괄호 3종 + 상태 4종** |

- **핵심 검증 결과**: 우리 교차참조에 필요한 **"발효중 vs 발표가능성 + 해역 + 풍속/파고"** 핵심
  필드는 **3개 배치 모두에서 정확 추출**됨. 나머지(경보변경·해제시각)는 롱테일 정제 대상.
- 18건은 **회귀테스트 골든셋**으로 고정 → 프롬프트 수정 시 자동 검증.

## 5. 제품 설계 (요구사항 반영)

### 5.1 "특보 예측" 아코디언 (인덱스 페이지)
- 위치: **해역별 특보현황 바로 위**, **항상 존재**(예측 0건이어도 헤더 표시, 열면 "예측 없음").
- 헤더: `🔮 특보 예측 [예측 N] · {기준시각} ⓘ` (ⓘ=방법론·신뢰성 팝업).
- 표시 단위: **개별 부모 특보구역**(앱 특보구역도 44개). 묶음(먼바다/앞바다)은 시각 헤더로만.
- 관심구역 필터: 전체 설정자=전 구역 / 관심 설정자=해당 구역.

### 5.2 등급 (확률 기반)
- 🔴 **높음 ≥80%** (정밀도 ~99%) / 🟡 **관심 50~80%** / <50% 미표시.
- 임계는 조정 가능한 다이얼(헛알람↓ vs 포착↓ 트레이드오프).

### 5.3 표시 내용 (서술형 + 근거)
- 서술 문구: "○○구역 일기도 분석 결과 {시간대} 풍속 ~{X}, 파고 ~{Y} 예상, 발효 가능성 {P}%".
- 일기도 근거: 풍속(kt)·파고(m) 실측값.
- **교차참조(단계적)**: 이벤트 임박 시 ① 기상청 단기 해상예보 숫자 ② 해설 "풍랑특보 가능성" AI 추출 → "✅ 기상청 예보 일치" 보강.

### 5.4 상태 전이 (예측중 / 최근 해소 / 억제)
```
신호 발생 → [예측 중]
  ├ 예보 호전·예상시각 경과 → [최근 해소] (사유+풍속/파고 전→후, 1일 유지 후 제거)
  └ 공식 특보/예비특보 발표 → 완전 제거(특보현황 핸드오프, 해소목록 X)
```
- "최근 해소" = **우리 판단 해제만**(공식 발표로 빠진 것과 구분). 사유에 풍속·파고 변화 명시.

### 5.5 억제 연계 (공식 정보 매칭)
- 공식 특보(`weather_alerts_crawler`/`dmdw_warn_crawler`) + 예비특보(rpt=7 크롤) 실시간 조회.
- 통보문 묶음명은 **앱 기존 `ZONE_GROUP_MAP`** 으로 구성 구역 펼침(예: 제주도먼바다→3구역) 후 억제.
- 구역 ID 통일: `seaZoneCoordinates`(예측) = `zoneOverlayConfig`(앱표시 44개, 이름 100% 일치) = 공식 해역명(`resolveZone`).

1. **3년 전수 데이터** 기반 (임의 표본 아님).
2. **다단계 검증 12단계** — 색상정확도→공간정합→매칭→재현율→홀드아웃까지.

7. **재현 가능**: 모든 도구·데이터·리포트가 저장소에 커밋되어 재실행·재검증 가능.
