# 사람 점수의 「30일 평균」 — 앞으로 30일 vs 지난 30일 비교 (2026-10-15)

모든 숫자는 `local_server/tools/coastal_accident_analysis/u81/window_compare.py` 의 출력(이 폴더 CSV)에서 옮겼다.

## 왜 했나
앱의 사람 점수는 「오늘 붐빔 ÷ 그 관광지의 30일 평균」이고, 그 30일은 **오늘부터 앞으로 30일**(관광공사 예측값)이다.
사용자 질문: *"30일 평균이라는 거는 앞으로 30일이잖아. 근데 과거 평균이 근데 이게 과거 데이터도 중요한 거 아니야? 해수욕장에서 1월달 30일 평균과 여름 30일 평균은 다르니까 말이야."*
→ 같은 사고 자료로 「30일」을 네 가지로 바꿔 보고, 어느 쪽이 실제 사고를 더 잘 설명하는지 쟀다.

| 이름 | 30일 창 |
|---|---|
| **F30** (현행) | 그날부터 앞으로 30일 |
| P30 | 지난 30일, 오늘 포함 |
| P30x | 지난 30일, 오늘 제외 |
| C30 | 오늘을 가운데 둔 30일(앞 15일·뒤 14일) |

틀은 달 점수를 잰 `month_relative.py` 주 모형과 완전히 같다(같은 사고, 같은 날짜 비교 방식, 달·요일·공휴일 보정). 창만 바꿨다.
**재현 확인**: F30 을 다시 돌리니 기존 결과(`month_relative.csv`)와 사람 항·달 점수 12개월이 소수점 끝까지 같았다(`repro_check.csv`, 차이 1e-16 이하).

## 한 줄 결론
**전체 사고는 현행(앞으로 30일)이 가장 잘 설명한다 — 차이도 크다(AIC 19~28).** 사망·실종 사고만 지난 30일이 조금 앞서지만
차이가 2.5 로 겨우 경계를 넘는 수준이고, 사망·실종에서는 사람 항 자체의 설명력이 약하다. **창을 바꿀 근거는 나오지 않았다.**

## 1. 공통 표본 비교 — 네 창을 같은 날·같은 사고로 (비교는 이 표로 한다)
창이 자료 범위(2020-01-01~2024-12-31)를 벗어나는 날은 그 창에서 평균을 못 낸다(지난 30일은 2020년 1월 초, 앞으로 30일은 2024년 12월 하순).
그래서 네 창이 모두 계산되는 날만 남겨 같은 표본에서 비교했다. AIC 는 작을수록 사고를 잘 설명한다는 뜻이고, **차이 2 미만은 「구별 안 됨」**으로 읽는다.

| 결과 | 창 | 사람 2배당 사고 배수 (95% 구간) | AIC 차이(가장 좋은 것 = 0) | 판정 |
|---|---|---|---|---|
| 전체 사고 (2,978건) | **F30 현행** | **2.04 (1.70–2.46)** | **0** | 가장 좋음 |
| | C30 가운데 | 2.04 (1.66–2.50) | 19.65 | 확실히 못함 |
| | P30 지난(오늘 포함) | 1.84 (1.52–2.22) | 27.38 | 확실히 못함 |
| | P30x 지난(오늘 제외) | 1.80 (1.50–2.15) | 28.12 | 확실히 못함 |
| | 사람 항 없음(달만) | — | 134.48 | 훨씬 못함 |
| 사망·실종 사고 (459건) | P30 지난(오늘 포함) | 1.52 (1.09–2.12) | 0 | 가장 좋음 |
| | P30x 지난(오늘 제외) | 1.48 (1.07–2.04) | 0.36 | P30 과 구별 안 됨 |
| | **F30 현행** | **1.44 (1.01–2.06)** | **2.52** | 조금 못함(경계 수준) |
| | C30 가운데 | 1.38 (0.94–2.04) | 4.21 | 못함 |
| | 사람 항 없음(달만) | — | 5.90 | 못함 |

- 모형마다 추정하는 값의 개수가 같다(사람 항 있는 모형 19개, 달만 18개). 그래서 같은 표본에서 AIC 차이 = 로그우도 차이 × 2 로 바로 비교된다.
- 사망·실종에서 사람 항을 아예 빼도 AIC 가 5.90(현행 대비 3.38)만 나빠진다 — 사망·실종은 사람 붐빔으로 설명되는 몫이 원래 작다. 그 안에서 2.5 차이는 크게 읽지 않는다.
- ⚠AIC 는 「각 사고가 서로 독립」이라는 가정의 우도로 계산했다(구간은 같은 날 사고끼리 묶은 강건 오차). 같은 날 사고가 여러 건이면 AIC 차이가 실제보다 조금 커 보일 수 있다. 네 창 모두에 똑같이 걸리는 한계다.
- ⚠창을 네 개 시험해 가장 좋은 것을 고르면 우연히 앞서는 것이 나올 수 있다. 사망·실종의 2.5 차이는 그 정도 크기다.

## 2. 창마다 자기 표본으로 (참고 — AIC 는 서로 비교하지 않는다)
각 창이 계산되는 날을 모두 쓴 결과. 표본(날짜 행)이 창마다 달라서 AIC 를 서로 견주면 안 된다(자기 표본 AIC 는 CSV 에만 둠).

## 3. 달 점수가 얼마나 달라지나 (공통 표본, 전체 사고, 1년 평균 날 = 0)
사람 점수와 달 점수는 한 묶음이다 — 창을 바꾸면 사람 점수가 담는 몫이 달라지므로 달 점수도 다시 재야 한다.

| 창 | 1월 | 2월 | 3월 | 4월 | 5월 | 6월 | 7월 | 8월 | 9월 | 10월 | 11월 | 12월 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| F30 현행 | −0.92 | −0.60 | −0.22 | −0.14 | +0.19 | +0.30 | +0.71 | +0.74 | +0.73 | +0.07 | −0.28 | −0.61 |
| P30 | −0.96 | −0.61 | −0.30 | −0.28 | +0.20 | +0.32 | +0.50 | +0.91 | +0.63 | +0.18 | −0.07 | −0.56 |
| C30 | −0.96 | −0.60 | −0.28 | −0.21 | +0.20 | +0.31 | +0.58 | +0.88 | +0.66 | +0.15 | −0.16 | −0.60 |
| 달만(사람 항 없음) | −1.00 | −0.62 | −0.28 | −0.21 | +0.21 | +0.33 | +0.58 | +0.89 | +0.64 | +0.15 | −0.13 | −0.60 |

- F30 ↔ P30 차이가 가장 큰 달은 7월(0.71 → 0.50, 0.21점)·11월(−0.28 → −0.07)·8월(0.74 → 0.91).
  (자기 표본 F30 은 1월 −0.95 · 12월 −0.60 으로 앱 값과 같다. 공통 표본에서 1·12월이 조금 다른 것은 2020년 1월 초·2024년 12월 하순 날이 빠졌기 때문이다.)
- 사망·실종 사고는 F30 ↔ P30 차이가 최대 0.13점(7월). 전체 표는 `window_months.csv`.
- 뜻: 지난 30일 기준이면 7월(성수기 오르막)에 사람 점수가 더 올라가 그만큼 7월 달 점수가 내려가고, 8월(내리막 직전)은 반대다. 두 점수를 합친 설명력은 F30 쪽이 높았다(1절).

## 4. 철이 바뀌는 시기 — log2(오늘 ÷ 30일 평균) 분포
「0」이 평균만큼 붐빈 날, 「+1」이 평균의 2배. 앱 사람 점수 = 0.97 × max(0, 이 값). 자료: 해안 시군구 78곳 × 2020~2024년(두 창 모두 계산되는 날).

| 시기 | 대상 | 날 수 | F30 평균 / 중앙값 | P30 평균 / 중앙값 | 0 넘는 날 비율 F30 / P30 | 앱 사람 점수 평균 F30 / P30 |
|---|---|---|---|---|---|---|
| 6월 하순(6/16~30) | 시군구×날 전체 | 5,850 | +0.063 / +0.002 | +0.027 / −0.017 | 50% / 47% | 0.149 / 0.131 |
| | 사고 당일 | 158 | +0.248 / +0.107 | +0.221 / +0.135 | 62% / 58% | 0.307 / 0.296 |
| 8월 하순(8/16~31) | 시군구×날 전체 | 6,240 | +0.033 / −0.026 | −0.143 / −0.133 | 46% / 33% | 0.147 / 0.072 |
| | 사고 당일 | 206 | +0.256 / +0.226 | −0.053 / −0.063 | 68% / 44% | 0.313 / 0.129 |
| 7월 전체(참고) | 시군구×날 전체 | 12,090 | −0.122 / −0.126 | +0.054 / +0.009 | 37% / 51% | 0.089 / 0.158 |
| | 사고 당일 | 353 | −0.016 / −0.061 | +0.222 / +0.186 | 45% / 69% | 0.146 / 0.275 |
| 1월 전체(참고) | 시군구×날 전체 | 9,828 | −0.047 / −0.118 | +0.002 / −0.048 | 34% / 43% | 0.113 / 0.133 |
| 1년 전체(참고) | 시군구×날 전체 | 137,982 | −0.002 / −0.058 | +0.000 / −0.049 | 42% / 44% | 0.138 / 0.139 |

- **8월 하순이 가장 크게 갈린다.** 지난 30일(성수기 한복판)과 견주면 8월 하순은 「평소보다 한산」(평균 −0.14)으로 보이고,
  앞으로 30일(9월)과 견주면 「평소만큼~조금 붐빔」(+0.03)이다. 사고 당일만 보면 F30 은 +0.26 인데 P30 은 −0.05 — 즉
  **8월 하순 사고는 「앞으로보다 붐빈 날」이었지 「지난달보다 붐빈 날」은 아니었다.** 앱 사람 점수로는 사고 당일 평균 0.31점(F30) vs 0.13점(P30).
- 7월은 거꾸로다(오르막): 지난 30일(6월)과 견주면 더 붐벼 보여 P30 점수가 높다.
- 6월 하순은 두 창 차이가 작다(평균 차이 −0.04).
- 1년 전체로 보면 두 창의 평균은 거의 같다(차이 0.002) — 차이는 철 경계에서만 난다.

## 5. 결론
1. **현행(앞으로 30일)을 유지하는 것이 자료와 맞다.** 전체 사고에서 F30 이 다른 세 창보다 AIC 로 19.65~28.12 낫다(2 미만이 「구별 안 됨」이니 큰 차이).
2. 사망·실종 사고만 지난 30일이 2.52 앞서지만, ①경계 수준 ②창 네 개 중 골라낸 결과 ③사망·실종은 사람 항을 빼도 AIC 가 3.38(현행 대비)만 나빠질 만큼 사람 몫이 작다 — 창을 바꿀 근거로 쓰기 어렵다.
3. 사용자 걱정(「1월 30일 평균과 여름 30일 평균은 다르다」)은 **달 점수가 맡고 있다** — 1월 −0.95 … 8월 +0.74 가 계절 차이를 담고, 사람 점수는 「그 철 안에서 평소보다 붐비는가」만 본다.
   지난 30일로 바꾸면 그 철 경계(7월·8월 하순·11월)에서 사람 점수와 달 점수가 서로 몫을 주고받을 뿐, 합쳐서 더 잘 맞지는 않았다.

## 한계 (확인 못 한 것)
- 이 분석의 30일 평균은 **실제로 온 방문자**(데이터랩 외지인, 2020~2024)로 계산했다. 앱은 관광공사 **예측값**을 쓴다. 예측 오차가 창 방향에 따라 다르게 작용하는지는 재지 않았다(과거 예측값 자료 없음).
- 앱에서 「지난 30일」을 쓰려면 매일 값을 모아 둬야 한다(과제 설명에 따르면 관광공사 API 는 과거 조회가 안 된다 — 이 분석에서 직접 확인하지는 않았다).
- 사람 항 한 가지(log2(오늘÷평균), 자르지 않음)로만 비교했다. 앱처럼 0 아래를 자른 형태(max(0,·))로 창을 비교하지는 않았다.

## 파일
| 파일 | 내용 |
|---|---|
| `window_models.csv` | 창 × 표본(own 자기 / common 공통) × 결과 — 사람 2배당 배수·구간·로그우도·AIC·공통 표본 ΔAIC·사고 수·행 수 |
| `window_months.csv` | 같은 모형들의 달 점수 12개월(점수·배수·95% 구간·달별 사고 수) |
| `window_boundary.csv` | 4절 표의 원자료(평균·중앙값·0 넘는 비율·앱 점수 평균·두 창 상관) |
| `repro_check.csv` | F30(자기 표본) ↔ 기존 `month_relative.csv` 주 모형 대조 |

재현: `OMP_NUM_THREADS=1 python3 -I local_server/tools/coastal_accident_analysis/u81/window_compare.py` (저장소 자료만 사용, 약 4분).
입력 주의: 저장소의 사고 특징표(`accident_features_person_2020_2024.csv.gz`)는 변사를 포함한 v1 판이다. 스크립트가 변사를 빼서 v2 분석과 같은 3,075건으로 맞춘다(행 단위 대조로 일치 확인).
