# 위험구역 종류별 효과 — 관광지 단위 재분석

작성 2026-10-15 · 대상 질문(사용자 원문): *「위험구역은 실질적으로 위험구역, 사망사고발생구역, 연안사고 다발구역? 인가 이렇게 3개로 나뉘고 있는데 구역의 종류와 관계없이 동일한 점수를 매기는건 아닌지 궁금하고」 → 「위험구역의 종류별 효과 다시 분석 필요.」*

이 문서의 모든 표·숫자는 `src/` 스크립트가 찍은 값이다(본문 숫자도 이 조립 스크립트가 결과 파일에서 읽어 넣음). 저장소 파일은 읽기만 했다.

## 요약

1. **지금 앱은 종류를 가리지 않는다(코드로 확인).** 3km 안 위험구역을 종류 구분 없이 모두 세어 0 / 1~2 / 3~5 / 6곳 이상으로 점수를 주고, 사망사고 발생구역이 1곳이라도 있으면 0.37점만 더한다. 연안사고 다발구역은 따로 대우받지 않는다.
2. **지정 이후(2023~24) 사고로 세 종류를 서로 보정해 재면** 다발구역 1.64배 · 사망구역 1.55배 · 위험구역 1.19배(그 종류가 3km 안에 있을 때; 위험구역은 신뢰구간이 1을 포함)로 순서는 있지만, **"세 종류의 효과가 같다"를 통계로 물리치지 못한다(p=0.23, 시군구 군집 표준오차로는 p=0.54) — 「구분 안 됨」.** 2020~24 전체로는 차이가 있지만(p=0.037, 시군구 군집으로는 p=0.12) 다발·사망 구역은 법정 기준상 "최근 3년 사고"로 지정돼 지정 전 사고와 순환하므로 부풀었을 수 있다.
3. **더 분명한 것은 "세는 방법"이다.** 지정 이후 사고에 대한 맞음(AIC, 낮을수록 좋음, 차이 10 이상이면 큰 차이)이 지금 표 → **후보 A(종류마다 따로 세어 3곳에서 멈추고 더함)** 로 22.5 좋아진다. 그 가운데 17.3 만큼은 "4단계 구간 + 사망 가산"을 **종류 구분 없이 개수를 매끄럽게(log) 세는 것**으로만 바꿔도 얻고, 종류마다 따로 세는 몫은 5.2 이다. 지금 표는 구역 6곳 이상인데 사망구역은 없는 관광지 73곳(그 구역 467개 중 위험구역 365개)의 사고를 과대 예상한다(관측÷기대 0.85).
4. 종류별 무게를 따로 주는 것(다발 > 사망 > 위험)은 **지정 전(2020~22)에 정한 모양이 지정 후(2023~24)에도 같은 무게보다 조금 더 잘 맞아(AIC 차이 6.5) 약한~중간 근거가 있다.** 사망·실종 사고만 보면 2020~24 에서는 사망구역이 두드러지지만(1.89배, 다발 1.01배) 지정 이후 사망·실종 123건으로는 구분 안 됨(p=0.91).
5. 그래서 자료가 지지하는 점수표 후보는 둘이다 — **후보 A: 종류마다 1곳 0.44 · 2곳 0.70 · 3곳 이상 0.88점(세 종류 같은 무게, 합산, 사망 가산 없음)**, **후보 B: 종류별 무게(위험 0.26/0.41/0.51 · 사망 0.47/0.74/0.94 · 다발 0.61/0.97/1.22)**. 둘 다 지금 표보다 평균이 낮아지고(관광지 평균 1.12 → 0.92 / 0.80점) 위험구역만 많은 곳은 크게 내려가며, 세 종류가 다 몰린 곳은 올라간다.

- "왜 종류별로 따로 세는 것이 잘 맞나": 전체 개수가 같아도 여러 종류가 섞인 곳이 사고가 더 많은가를 L1(전체 log2 + 있는 종류 수)로 보면, 2023~24 에서 종류 하나 더 있을 때 1.19 (0.94–1.50)(뚜렷하지 않음), 2020~24 1.21 (1.02–1.43). 위험구역이 많이 몰린 곳을 지금 표가 과대 예상하는 것(§13.3)과 함께 보면, **같은 종류(특히 위험구역)가 여러 곳인 것은 한 곳보다 크게 더 위험하지 않다**는 쪽이 자료에 맞는다.

### 13.1 지금 표의 두 가지 문제

1. **섞어 쓴 값**: 구간 점수는 사망 항이 없는 모형(A0: 1.62 / 2.36 / 3.34)에서, 사망 가산은 구간과 사망을 함께 넣은 모형(A1)에서 왔다. A1 안에서는 구간 배수가 1.43 / 1.94 / 2.66 로 작아진다 — 사망구역이 있는 곳의 몫이 구간 배수에 이미 들어 있었기 때문이다. 6곳 이상+사망구역의 배수: 지금 앱 2^(1.74+0.37) = 4.32, A1 = 2.66 × 1.29 = 3.43.
   다만 자료 적합에 주는 손해는 작다(§13.3: 지금 앱 고정 대 A1 ΔAIC 2.1).
2. **종류를 모르는 개수**: 전체 개수는 거의 「연안사고 위험구역」 개수(순위상관 0.82)이고, 위험구역은 다른 두 종류를 보정하면 효과가 가장 작다(§6). 실제로 구역 6곳 이상인데 사망구역은 없는 관광지 73곳(그 구역 467개 중 위험구역 365개)의 사고를 지금 표는 과대 예상한다(관측÷기대 0.85, §13.3). 후보 A·B 에서는 0.97·0.99.

### 13.5 정리 — 「종류별로 다르게 줘야 하나」

- **지금 표를 바꿀 근거는 자료가 뚜렷하게 준다**: 지금 표 → 후보 A·B 로 지정 이후 사고 적합이 크게 좋아진다(ΔAIC 22.5 / 25.8, ΔQAIC 15.5 / 15.6). 다만 그 이득의 대부분(ΔAIC 17.3)은 **종류와 무관하게** 4단계 구간을 매끄러운 개수 함수로 바꾸는 데서 나온다(§10).
- **종류마다 따로 세는 것(같은 무게)** 은 추가로 ΔAIC 5.2(과산포 감안 ΔQAIC 3.0) 좋아진다 — 구간→log 의 이득보다 작다. 같은 종류(특히 위험구역)가 여러 곳 몰린 것을 덜 쳐 주는 효과다.
- **종류마다 무게를 다르게(다발 > 사망 > 위험) 주는 것은 근거가 약하다**: 같은 자료 안에서는 구분 안 됨, 지정 전→지정 후 표본 밖 확인에서는 조금 더 맞음. 단순함을 우선하면 후보 A, 점추정 순서를 반영하려면 후보 B.
- **사망 가산(+0.37)을 따로 두는 지금 방식**은 사망·실종 사고 쪽으로 2020~24 근거가 있으나(사망구역 1.89 (1.43–2.49)) 지정 이후 사망·실종으로는 확인되지 않는다(구간 함께 넣은 가산 1.30 (0.82–2.06), 123건). 후보 A·B 에서는 사망구역이 자기 줄로 들어가므로 별도 가산이 필요 없다.
- 이 문서는 분석 결과다. 점수표를 바꿀지는 사용자 결정 사항이다(보고서 §8.7 과 같은 성격).
