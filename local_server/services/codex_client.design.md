# 나리야 답변 AI를 ChatGPT 정액제(Codex)로 돌리는 개발자 전용 모드 — 설계안

> 상태: **설계안(미구현)** · 작성 2026-09-27 · 대상 코드: `services/gemini_client.js`, `routes/legal.js`
> 이 문서는 구현 전에 사용자 확인을 받기 위한 것이다. 확인 전에는 코드를 바꾸지 않는다.

## 0. 사용자 확정 사항 (대화 원문 병기)

> *"챗봇의 목적은 공공으로 사용할 목적이지만, 현재는 내 개인 개발용으로 사용 중이고, 개발이 완료되면
> 고사양 vm이 들어왔을 때 전환할 예정인데, 현재 open ai 정액제 요금으로 사용해서 반영할 수 있지 않니 ?
> 개인 사용 목적이므로, 현재 사용자들에게 노출도 시키지 않고 있으니 말이야."*

> *"좋아. 그렇게 한번 해보자. 설계부터 해볼래 ?"*

같은 대화에서 합의한 조건:
1. **관리자(본인) 요청에만** ChatGPT 정액제를 쓴다. 그 밖의 요청은 지금처럼 Gemini.
2. **기본값은 Gemini.** ChatGPT는 스위치로 켜는 개발용 모드.
3. **공공 서비스 전환 전에 반드시 떼어낸다.** (고사양 VM 자체 모델 또는 정식 API 로 교체)
4. 먼저 **5문항 정도**로 시험한다.

## 1. 왜 조건이 필요한가 (확인한 사실)

| 사실 | 근거 |
|---|---|
| OpenAI 이용약관: 계정을 다른 사람이 쓰게 하면 안 됨, 자동·프로그램 방식 추출 금지 | 검색엔진 요약으로 확인(원문은 이 환경 망에서 openai.com 차단으로 직접 못 엶) |
| 자동화·서버용은 API 키를 권장 | 검색엔진 요약(OpenAI Codex 인증 문서) |
| 챗봇 버튼 노출은 기본 `off` | `routes/legal.js:228~262` |
| **그러나 `/api/legal/ask` 자체엔 관리자 확인이 없다** — 주소를 알면 누구나 질문 가능 | `routes/legal.js:1541` (직접 읽음) |

→ 버튼을 숨긴 것만으로 ChatGPT를 붙이면 **남이 내 정액제를 쓸 수 있는 구조**가 된다(= 약관상 계정 공유).
그래서 아래 §3 의 **삼중 잠금**이 이 설계의 핵심이다.

## 2. 구조 한눈에

```
[질문] → routes/legal.js /api/legal/ask
            │  삼중 잠금 통과? (§3)
            ├─ 아니오 → 지금과 100% 동일 (Gemini)
            └─ 예    → "이 요청은 codex" 표시를 요청 범위에 심는다 (AsyncLocalStorage)
                         │
          legal_retriever.js (수정 없음 — 22곳의 gemini.callGemini* 호출 그대로)
                         │
          gemini_client.js 입구 두 곳(callGeminiRaw·callGeminiStream)에서 표시 확인
                         ├─ 표시 없음 → 기존 Gemini 경로
                         └─ 표시 있음 → codex_client.js → `codex exec` (VM에 설치된 CLI, ChatGPT 로그인)
```

**왜 이 자리인가**: AI 호출 지점이 `legal_retriever.js` 18곳 + `routes/legal.js` 4곳 = 22곳이다(grep 으로 셈).
22곳을 다 고치면 빠뜨리기 쉽고, 떼어낼 때도 22곳을 되돌려야 한다. `gemini_client.js` 입구 두 곳에서만
갈라지면 **추가도 제거도 파일 한두 개**로 끝난다(§8).
특보분석·해상전망 등 다른 기능도 `gemini_client.js` 를 쓰지만, 표시는 `/api/legal/ask` 요청 안에서만
심기므로 그쪽은 영향이 없다.

## 3. 삼중 잠금 — 셋 다 맞아야 ChatGPT 로 간다

| 잠금 | 내용 | 어디서 |
|---|---|---|
| ① 서버 스위치 | 환경변수 `NRYA_CODEX=1` 이 **켜진 서버에서만**. Fly.io 운영 서버에는 넣지 않는다 | 서버 시작 시 1회 읽음 |
| ② 관리자 인증 | 요청 헤더 `X-Admin-Token` 이 유효 (`admin_auth.verifyToken`) | 요청마다 |
| ③ 명시 선택 | 요청 본문 `llm: "codex"` | 요청마다 |

하나라도 빠지면 **조용히 Gemini** 로 간다(오류로 막지 않음 — 일반 사용 흐름을 깨지 않기 위해).
답변 완료(`done`) 이벤트에 **`llm: "gemini" | "codex"`** 를 실어 어떤 AI 가 답했는지 항상 보이게 한다.

## 4. 실행 위치 — VM

- Codex CLI(`@openai/codex`, 확인 시점 0.157.1)를 **VM에만** 설치하고 `codex login --device-auth` 로 본인 계정 로그인.
  (기기 인증: 화면에 뜬 코드를 휴대폰·PC 브라우저에 넣어 로그인하는 방식 — GUI 없는 VM 용)
- VM 에서 서버를 **개발용으로 따로 띄운다**(`NRYA_CODEX=1`). Fly.io 운영 서버에는 Codex 도 로그인 정보도 두지 않는다.
  - 이유: 운영 서버 메모리 1GB(`fly.toml`), 그리고 **개인 로그인 정보를 공개 서버에 두지 않기 위해**.
- 시험은 두 가지 입구로:
  - ⓐ **스크립트**: VM 에서 `node … --llm codex "질문"` — 가장 단순, 1차 시험은 이것만으로 충분.
  - ⓑ **앱 화면**: VM 서버 주소로 접속한 관리자 화면에서 스위치 — ⓐ 가 잘 되면 그때 결정(§9 질문 2).

## 5. `codex_client.js` — 무엇을 어떻게 부르나

`gemini_client.js` 와 **같은 약속**(반환 모양)을 지킨다:
`callCodex({contents, config, caller}) → { success, text, error, isRateLimited, keyLabel:'codex' }`

실행 명령(이 환경에서 `codex exec --help` 로 옵션 존재 확인함):
```
codex exec --json --ephemeral --skip-git-repo-check -s read-only -C <빈 임시폴더> [-m <모델>] -
```
| 옵션 | 왜 |
|---|---|
| `-` (질문을 stdin 으로) | 근거자료가 최대 약 9만 자 — 명령줄 길이 한도를 피한다 |
| `--json` | 진행 이벤트를 한 줄씩 JSON 으로 받아 최종 답만 골라낸다 |
| `--ephemeral` | 대화 기록 파일을 디스크에 남기지 않는다 |
| `-s read-only` + `-C <빈 폴더>` | Codex 는 코딩 비서라 명령을 실행하려 할 수 있다 — 읽기 전용, 빈 폴더로 가둔다 |
| 프롬프트 앞머리 | "도구·명령을 쓰지 말고 아래 자료만으로 답하라" 한 줄 추가 |

- `config` 중 Gemini 전용 값(`thinkingConfig`, `temperature`)은 **무시**한다. `responseMimeType:'application/json'` 인
  호출은 프롬프트에 이미 "JSON만 출력" 지시가 있어 그대로 두고, 응답 앞뒤의 ```` ``` ```` 만 벗겨 낸다.
- **동시 실행 1개**(순서 대기). 한 사람이 쓰는 모드이고 정액제 한도를 아끼기 위해.
- 스트리밍: `--json` 이벤트 중 최종 답변 이벤트를 받으면 한 번에 넘긴다. 글자 단위 스트리밍이 되는지는 **미확인**(§7).
- 한도 초과·로그인 만료 시: **Gemini 로 몰래 대체하지 않는다** — 어느 AI 답인지 섞이면 비교 시험이 무의미해진다.
  실패로 표시하고 이유(한도/로그인/시간초과)를 로그에 남긴다.

## 6. 대기 중 상태 변화 (CLAUDE.md 결정로그: 대기를 도입하면 전수 열거)

| 대기(순서 대기·실행) 중 일어난 일 | 동작 |
|---|---|
| 질문한 화면이 닫힘(연결 끊김) | 대기 중이면 취소, 실행 중이면 프로세스 종료 |
| 실행이 N초 넘음 | 프로세스 종료, "시간초과"로 실패 (N 은 1차 시험 소요시간을 보고 정한다) |
| 서버 재시작 | 대기열 유실 — 재질문 필요(개발용이라 저장하지 않음) |
| 로그인 만료 | 실패 "로그인 필요" — VM 에서 `codex login` 다시 |
| 한도 도달 | 실패 "한도" — 그동안 이 모드는 쓰지 않음 |

## 7. 아직 모르는 것 (추측 금지 — 1차 시험에서 잰다)

이 개발 환경은 OpenAI 서버 접속이 막혀(`api.openai.com` 403, 직접 실행해 확인) **실제 호출을 못 해봤다.**
1. 질문 1개 소요시간 (Codex 는 한 질문에 AI 를 최대 여러 번 부른다 — 호출 지점 9종)
2. 5문항에 정액제 한도를 얼마나 쓰는지 (`/status` 로 전후 비교)
3. JSON 형식 지시를 지키는 비율 (되묻기·검색어 확장 단계가 JSON 에 의존)
4. "도구 쓰지 말라"를 지키는지 (`--json` 이벤트에 명령 실행 이벤트가 있는지로 확인)
5. 정액제에서 고를 수 있는 모델 이름

## 8. 1차 시험 계획과 성공 기준

5문항(골든 문제집에서 뽑음)을 **같은 질문으로 Gemini·Codex 각각** 돌려 비교:

| 항목 | 성공 기준 |
|---|---|
| 완주 | 5문항 모두 답변까지 도달 (JSON 파싱 실패로 멈추지 않음) |
| 정확성 | 답의 조문번호·금액·기관명이 근거자료 원문에 있음 (환각 0 — 기존 원칙) |
| 도구 사용 | 명령 실행 이벤트 0건 |
| 잠금 | 관리자 토큰 없이 `llm:"codex"` 보냈을 때 Gemini 로 감 (테스트로 고정) |
| 기록 | 소요시간·한도 사용량을 표로 남김 |

**떼어내는 법**: `codex_client.js` 삭제 + `gemini_client.js` 입구 분기 두 줄 + `routes/legal.js` 잠금 부분 삭제.
공공 전환 체크리스트(HANDOFF)에 "Codex 모드 제거"를 한 줄 넣는다.

## 9. 사용자 결정이 필요한 것

1. **VM 에 서버를 개발용으로 띄워도 되는가** (Node 설치·저장소 복제·`.env` 에 Gemini 키 포함). 아니면 다른 방식 선호?
2. **1차 시험은 스크립트(§4ⓐ)만으로** 할지, 처음부터 앱 화면 스위치(§4ⓑ)까지 만들지. → 권장: 스크립트만.
3. ChatGPT 요금제 종류(Plus/Pro 등) — 한도 추정에 필요.

## 10. 별건 (이번 범위 밖, 기록만)

`/api/legal/ask` 가 인증 없이 열려 있다. 지금은 버튼만 숨긴 상태라, 주소를 아는 누구나 Gemini 요금을 쓰게 할 수 있다.
Codex 모드와 무관하게 공공 공개 전에 따로 다룰 사항.
