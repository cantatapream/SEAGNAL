## 3. 작동 방식
- **사서 3연산**: ①넣기(ingest: raw→개념카드) ②찾기(query: 질문→검색→답) ③정합(lint: 카드끼리 링크·색인·구멍점검)
- **검증 루프**(3층): 감사(질문 던져 구멍 판정 full/thin/missing/collection_hole/awkward) → 수정(없는 페이지 생성·얇은 것 심화·별표/고시 반영) → 재감사(전문가+일반인 150문항, 회귀 확인) → 구멍이 5% 미만/개선 정체/3라운드면 종료.
- **자율 오케스트레이터**: 15분마다 자동 전진(트리거). 세션 한도 걸리면 리셋 후 resumeFromRunId 자동 재개, 매 단계 커밋(손실 0), **승인 요청 없음**.
- **모델**: 대량 감사·수정 = Sonnet 5(effort high, 10에이전트 병렬), 조율·판단 = Opus 4.8.

## 4. 확정된 설계 결정 = 사용자 요구사항 (누락 없이)
**A. 챗봇 답변 방식**
1. **음성 비서 폐기 → 텍스트 챗봇**(음성으로 법률 쏟으면 혼란).
2. **대화형 온디바이스 프로필** — 배 톤수·용도·면허·구역을 챗봇이 물어 얻고 **기기에만** 저장(서버 저장 금지), 질의 필터로 재사용.
3. **점진적 공개** — 1/2/3/4차 처벌은 "통상 1차 + 상황에 따라 다름" 먼저 → 되물음 → 원하면 전체.
4. **모르는 구어 해소** — DB에 없으면 웹으로 뜻 확인 → 사용자에게 되물음 → `_candidates`에 학습후보 적재. 웹은 뜻확인용, 근거는 항상 위키 원문.
5. **하이브리드 검색** — 직접매칭(정식 명칭)·glossary 구어사전(사람 말)·임베딩(뜻)을 **동시에 점수 매겨 최고점 카드 선택**(구어사전이 무조건 첫 관문 아님. "구명조끼"처럼 법에 적힌 정식 명칭은 직접매칭으로 직행, glossary는 "조개껍데기→폐기물"처럼 정식 명칭 아닌 말의 안전망) + 그래프 홉, 그 뒤 프로필 필터.
6. **인용 규율(환각 0)** — 위키 원문만, 없으면 "확인 안 됨", 처벌은 조·항·호·금액 그대로, 답에 출처 concept ID 부착(따봉↓ 연결).
7. **처벌값 검수 최소화** — 원문 그대로 인용은 자동검증, 벌칙 포괄표현("이 법에 따른 명령…") 매핑만 사람 REVIEW.
   - **(관련) 기존 직군 분류 시스템(`knowledge/jikgun`·`graph`) 재사용 안 함** — 직군·소속·취미는 챗봇이 대화로 획득(위 2번). 음성비서용 두뇌(runBrain)에 얹지 않고 별도 컴포넌트.

**B. 위키 구축 방식**
8. **다수 에이전트(10) 동일 지침**으로 법당 풀깊이 분해(전 규제주제 개념화) + 교차 링킹(거미줄).
9. **처벌 3축 정밀**: 벌칙·과태료·행정처분(1~4차 별표) 조·항·호·금액.
10. **교차 테마 허브 + graph 신경망 + 백본**(공통 인용법). lint로 에이전트끼리 못 본 교집합 재검토.
11. **고시·조례 먼저 수집** → 위임 구멍 없이 채움.

**C. 운영·인프라**
12. **자율 진행** — 승인 요청 금지, 진행현황 자동 점검, 취침 중에도 자동.
13. **작업 전 모델 권고** + Opus(고집중)/Sonnet(나머지), Haiku 미검증 제외.
14. **관리자 UI** — 통합관리자센터 AI탭 하위 "AI 챗봇": 따봉↑↓·AI 신지식 후보·처벌값 REVIEW, **상세 AI 분석 리포트**(원답변 근거→사용자 의문→AI 재분석→권고), **앱 기존 디자인 준수**. (목업 완료)
15. **모든 세션 공통 규칙**(main 반영): 카파시 가이드라인(#1045)·Superpowers 도입보류(#1046)·세션기억 MEMORY.md(#1047)·시각 KST 표기(#1049).
16. **모델 검증 심화** — 작업 전 어떤 모델을 왜 쓰는지 권고 + **모델별 리스크 점검**("A모델은 실수 안 하는데 B모델은 구멍날 가능성"). Sonnet은 **파일럿으로 처벌금액·정의사슬이 Opus 수준·환각0**임을 검증한 뒤 채택. Haiku는 미검증이라 제외.
17. **병렬 진행 원칙** — 수집·위키빌드·감사·링킹은 **백그라운드**, 앱 UI·설계 논의는 **포그라운드**로 동시 진행. 가능한 것은 10에이전트까지 병렬로 시간 단축.
18. **산출물(참고, 아티팩트)** — 전체 구조도 HTML · 방(폴더) 중심 좌우 팬/줌 트리 HTML(방별 역할·상태·모델·진행·💬요구) · 관리자 검토 목업 HTML.
19. **앱 코드 착수 시** — Superpowers 통설치는 안 하되 **2개만 가볍게**: ⓐ작업별 리뷰 게이트(에이전트가 짠 걸 다른 에이전트가 검수) ⓑ체계적 디버깅 (→ `CLAUDE.md` 도구·방법론 결정로그).
