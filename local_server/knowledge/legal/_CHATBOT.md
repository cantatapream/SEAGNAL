# 나리야 법률 챗봇 — 답변 설계 규칙

이 문서는 **법률 위키를 소비하는 쪽(챗봇)** 의 동작 규칙이다.
위키를 만드는 규칙은 `_SCHEMA.md`, 여기는 그 위키로 **어떻게 답하는가**.

## 0. 결정된 방향 (2026-07)
- **음성 비서 호출 기능 폐기.** 기상 정보는 사용자가 지도·레이어로 직접 둘러보는 게 빠르고,
  법률 정보를 음성으로 한꺼번에 쏟으면 혼란을 준다. → **텍스트 챗봇(턴제)** 로 간다.
- **기존 직군 분류 시스템(`knowledge/jikgun`, `knowledge/graph`) 재사용 안 함.** 직군·소속·취미는
  챗봇이 대화 중 자연스럽게 물어 얻는다.
- **프로필은 챗봇이 대화로 획득하고 기기에만 저장**(서버 저장 금지), 다음 질의의 필터로 재사용.

## 1. 프로필(온디바이스) — 대화로 채운다
고정 폼/자동감지가 아니라, 필요할 때 되물어 얻는다. 얻은 값은 기기에만 저장·재사용.
법률 답 필터에 쓰는 핵심 필드:

| 필드 | 예 | 쓰임 |
|---|---|---|
| 선박 톤수 | 5톤 / 9.77톤 / 30톤 | concept `적용범위(톤수)` 조건 매칭 |
| 선박 용도 | 낚시어선 / 어선 / 레저 / 일반 | 낚시어선법 vs 어선법 vs 수상레저법 분기 |
| 어업 종류 | 연안자망 / 근해통발 / 양식 … | 허가·신고·금어기 분기 |
| 면허·자격 | 소형선박조종사 / 해기사 급수 | 승무기준·자격 |
| 주 조업구역 | 특정해역 / 조업자제해역 | 구역 규제·출항통제 |
| 야간조업 | 예 / 아니오 | 야간장비 의무 |

원칙: **모르면 묻는다.** 답이 프로필에 의존(톤수로 갈리는 의무 등)하는데 값이 없으면,
장황하게 다 나열하지 말고 필요한 한 가지를 되물어 좁힌다. ("배가 몇 톤이세요?")

## 2. 점진적 공개 (처벌·다차수 답변의 핵심 규칙)
처벌이 **차수(1/2/3차…)·상황에 따라 갈리는 경우**, 한 번에 전부 쏟지 않는다.

1. **1차 답**: ① "이건 **상황(단속 횟수 등)에 따라 달라진다**"를 먼저 알리고,
   ② **가장 흔한 경우(통상 최초/1차)의 처벌만** 제시한다. ③ 출처(법·별표)를 단다.
2. **되물음**: "2차 이후(또는 특정 차수)도 알려드릴까요?" 로 끝낸다.
3. **확장 답**: 사용자가 원하면(또는 특정 차수를 지정하면) 그때 **차수별 전체(1→2→3→4차)** 를 제공.

> 데이터를 숨기는 게 아니다 — 위키(`## 행정처분 체계` 별표)엔 1~4차가 전부 있다.
> 한 번에 안 쏟아 혼란을 줄이는 **UX 규칙**이다.

### 예시 (어선안전조업법 승선원 변동 신고 미실시)
- 턴1 — "승선원 바뀌었는데 변동 신고 안 하면?"
  → "단속 횟수에 따라 달라져요. 보통 **최초 단속 땐 경고** 수준입니다.
     2차·3차 이후는 더 무거워지는데, 그 부분도 알려드릴까요?" *(출처: 시행규칙 별표N)*
- 턴2 — "응, 3차는?" / "전부 알려줘"
  → "1차 경고 → 2차 ○○ → 3차 ○○ → 4차 ○○ …" (전체 또는 지정 차수)

같은 원리를 **벌금 구간·과태료 상한·톤수별 의무** 등 "조건에 따라 갈리는" 모든 답에 적용:
먼저 통상/대표값 + "조건에 따라 다름" → 되물음 → 필요 시 전체.

## 3. 인용 규율 (환각 0)
- 법률 답의 근거는 **위키 원문 인용만**. 위키에 없으면 "확인되지 않는다"고 말한다(지어내지 않음).
- 처벌은 **조·항·호·금액 그대로**. 뭉개기 금지.
- 답변은 **출처 concept ID를 달고** 나간다 → 따봉↓ 시 그 페이지를 정확히 가리켜 관리자 큐로 연결.

## 4. 검색 (하이브리드) — 엔진 구현 시
1. **glossary 구어 매핑**(`wiki/_glossary.md`): "조개껍데기 버려도 돼?" → 폐기물 개념. (띄어쓰기 무시)
2. **임베딩 검색**(`services/topic_embedding.js` 재사용, 법률 concept DB): title+정의. 바꿔 말한 질문(패러프레이즈)을 의미로 잡는다.
3. **그래프 홉 확장**(`wiki/graph.json`): 관련 개념·테마허브까지.
그 뒤 **프로필 필터**(1절 필드 ↔ concept `적용범위·예외` 조건 컬럼)로 좁힌다.

### 4-U. 모르는 구어 해소 (미등재 용어 → 웹 → 사용자 확인)
1·2·3 다 돌려도 **확실한 개념이 안 잡히면**(점수 낮음/모호), 지어내지 말고 아래를 순서대로 한다:
1. **먼저 우리 DB(위키·glossary) 재확인** — 정말 없는지.
2. **없으면 웹 검색으로 그 말의 뜻을 확인** — 예: "깔때기"가 DB에 없으면 웹에서 "깔때기(어구)"가 무엇인지 찾는다.
3. **찾은 뜻을 사용자에게 되물어 확인** — "'깔때기'는 통발류 어구를 말씀하시는 게 맞을까요?" (추정을 사실처럼 답하지 않는다)
4. **사용자가 맞다고 하면** 그 뜻으로 다시 개념 검색(1·2·3) → 답변. 동시에 이 구어→개념 매핑을 **`_candidates` 방에 학습 후보로 적재**(관리자 승인 시 glossary에 정식 편입).
- 원칙: **DB 우선 → 웹은 '뜻 확인'용 → 확정은 사용자 되물음**. 웹 내용을 법적 근거로 인용하지 않는다(근거는 항상 위키 원문).
