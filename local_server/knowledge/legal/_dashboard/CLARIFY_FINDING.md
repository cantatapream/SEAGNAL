# 되묻기가 왜 이렇게 자주 나오나 — 라이브 실측 (2026-08-28)

## 0. 한 줄
실제 서비스에 32문항을 던져 보니 **29건(91%)이 되묻기로 갔다.** 그 29건을 성격별로 갈랐더니
**절반은 사용자에게서 새로 얻는 것이 없는 되묻기**였다.

## 1. 어떻게 쟀나
`_dashboard/loop/ask_live.js` 로 실제 서비스(`/api/legal/ask`)에 문항을 한 번씩만 던지고
(요청 1회/문항) 첫 응답의 `clarify` 를 모았다.
- 대상 20문항: 오프라인 채점판에서 근거를 못 찾던 것들
- 대조군 12문항: 오프라인에서 **잘 되는** 것들(고정 간격으로 뽑음 — 무작위 시드 대신 재현 가능하게)

**되묻기 비율은 두 집단이 사실상 같았다** — 대상 20건 중 18건(90%), 대조군 12건 중 11건(92%).
**즉 검색 난이도와 무관한 보편 현상이다.**

## 2. 29건을 갈라 보면

| 성격 | 건수 | 뜻 |
|---|---:|---|
| ① **이해확인** — 질문을 되읽어 주고 "맞나요?" | 14 (48%) | `understandConfirmStep` 단계 |
| ③ 진짜 조건 되묻기 | 11 (38%) | 답이 실제로 갈리는 구분을 물음 — **정상** |
| ② **어느 법인지 고르라고 함** | 4 (14%) | 검색이 끌어온 법 목록이 그대로 질문이 됨 |

## 3. ①이해확인 — **절반은 새로 푼 것이 없다**

이 단계의 설계 원칙은 문서에 이렇게 적혀 있다: *"정보 이득이 없으면 개입하지 않는다.
실제로 풀어쓴 재진술을 낼 때만 카드를 낸다."* 그런데 실측은 그렇지 않았다.

재진술이 **원 질문에 없던 낱말을 몇 개나 새로 넣었는지** 셌다
(형태소 분석기가 아니라 조사·어미를 거칠게 떼어 센 **근사치**임을 밝힌다):

**새 낱말 0개 = 7건 / 15건 (47%)** — 질문을 평서문으로 바꿔 놓았을 뿐이다.

```
질문: 하천·저수지에도 이 법이 적용되나요?
재진술: 하천·저수지에 이 법이 적용되는지 알고 싶다        ← 새로 푼 것 없음
질문: "이사 가면(사업장 소재지 변경) 신고해야 하나요?"
재진술: 사업장 소재지 변경 시 신고해야 하는지 알고 싶다    ← 질문이 이미 괄호로 풀어 줬다
질문: 공단 직원이 업무상 알게 된 정보를 함부로 말해도 돼?
재진술: 공단 직원이 업무상 알게 된 정보를 말해도 되는지 알고 싶다
```

⚠**처음 세운 잣대는 틀렸다.** "글자 조각(2-gram)이 80% 이상 겹치면 되읽기"로 재니 **0건**이었다 —
재진술이 "…알고 싶다"를 붙이고 어순을 바꾸므로 글자 겹침으로는 안 잡힌다.
겹침이 아니라 **새 낱말이 있나**로 재야 뜻이 맞았다. 첫 잣대를 그대로 보고했으면 틀린 말이 나갔다.

### ~~★그리고 한 건은 재진술이 아니라 법 이름이었다~~ — **철회(2026-08-29 독립 검산)**

> **이 사고는 일어나지 않았다.** 아래 서술은 틀렸으므로 취소선으로 남긴다.
> 문제의 문항(`준보전무인도서에서 조리·야영…`, 실행기록 `lv_pass_2.json`)은
> `restate` 가 **빈 값**이고 `note` 가 `"추가 정보가 필요해요"` 인 **정상 조건 되묻기**였다.
> 법 이름은 재진술 자리가 아니라 **되묻기 질문 문장 안**에 있었고, 거기서는 정상이다
> (`"해당 무인도서가 「독도 등 도서지역의 생태계보전에 관한 특별법」에 따른 특정도서에 해당하나요?"`).
> 그날 실행기록 전체의 `restate` 값 **106개 중 법 이름 꼴은 0개**다(전수 확인).
> §8 에서 이 서술을 근거로 적용한 `RESTATE_LAWNAME` 은 **되돌리지 않는다** — 다만 그 근거는
> "관측된 사고"가 아니라 **"규칙의 빈칸"**(RESTATE_BAN 이 낫표 없는 맨 법 이름은 못 막는다)으로
> 바꿔 적는다.

### ~~(원 서술)~~
```
질문: 준보전무인도서에서 조리·야영 허가 안 받고 하면 처벌이 뭔가요?
재진술: 독도 등 도서지역의 생태계보전에 관한 특별법          ← 뜻풀이가 아니라 법 이름
```
설계는 이것을 금지하고 있고(`RESTATE_BAN`) 걸러내는 정규식도 있다. 그런데 **안 걸렸다** —
`RESTATE_BAN = /제\s*\d+\s*조|법률|법령|벌금|과태료|징역|「|」|만원/` 는 `법률`·`법령`은 잡지만
**`…특별법`처럼 `법`으로 끝나는 이름은 못 잡는다**(코드로 확인).

## 4. ②"어느 법인지 고르라고 함" — 검색 오류가 질문으로 나온다

```
질문: "1년 내 4번째 같은 위반 적발이다. 별표4 상한(500만원)을 넘겨 부과할 수 있나?"
되묻기: 어떤 법률 위반으로 적발되셨나요?
선택지: 폐기물관리법 / 해운법 / 독도의 지속가능한 이용에 관한 법률 /
        유류오염손해배상 보장법 / 양식산업발전법 / 어선안전조업법 / 잘 모르겠어요
```
사용자는 자기가 무슨 법 위반인지 몰라서 물은 것인데, **우리가 되물어 버린다.**
게다가 저 목록은 검색이 끌어온 것이라 **정답이 목록에 없을 수도 있다**
(그런 사고가 실제로 있었고, 그래서 `ensureTopLawOption`·`dropForeignLawOptions` 같은
보정이 이미 코드에 들어 있다 — 이번 4건은 그 보정을 통과한 뒤의 모습이다).

## 5. 이미 있는 안전장치 (확인함)
- `CLARIFY_MAX_ROUNDS = 5` — 되묻기 무한루프를 결정론적으로 끊는다. 실제로 5라운드째에
  멈추고 답이 나오는 것을 확인했다(그때 인용이 기대 조문과 일치했다).
  ⚠나는 이걸 모르고 *"영영 답으로 못 간다"* 고 보고했다가 정정했다(L-201).
- `이해확인`은 3회 백스톱(`UNDERSTAND_MAX_ROUNDS`)이 따로 있고 되묻기 라운드를 쓰지 않는다.

## 6. 고칠 만한 것 (제안 — **아직 안 고쳤다**)
답변 경로는 모든 사용자가 지나가는 자리라, 재는 것과 고치는 것을 나눈다.
아래는 제안이고 **적용 전 독립 검토를 붙일 자리**다(CLAUDE.md 결정로그).

1. **이해확인에 결정론적 백스톱을 단다.** LLM 이 `clear:false` 라 해도, 재진술이 원 질문에
   없던 낱말을 하나도 안 넣었으면 **카드를 내지 않고 통과**시킨다. 지금은 판정이 전적으로
   LLM 몫이고 백스톱이 없다 — 다른 되묻기에는 이미 그런 백스톱이 있다(`CLARIFY_MAX_ROUNDS`).
   실측 기준 **이해확인 14건 중 7건이 이 백스톱에 걸려 사라진다**(되묻기 29 → 22, 91% → 69%).
2. **`RESTATE_BAN` 에 "…법으로 끝나는 이름"을 더한다.** 한 줄이고, 위 3절 사고를 막는다.
3. ②유형은 되묻기 문제가 아니라 **검색 문제**다. 되묻기 쪽에서 더 손대면 증상만 가린다.

## 7. 재현
```
node _dashboard/loop/ask_live.js --state /tmp/x.json start "<질문>"
```
첫 응답의 `되묻기`·`선택지` 를 보면 된다. 요청 1회라 비용이 작다
(되묻기까지만 가는 문항 하나가 입력 8.5k 토큰 안팎).

## 8. 처리 결과 (2026-08-29)

| 제안 | 상태 |
|---|---|
| 2. `RESTATE_BAN` 에 법 이름 추가 | **적용함** |
| 1. 이해확인 결정론적 백스톱 | **안 함 — 독립 검토가 먼저다** |
| 3. ②유형은 검색 문제 | 손대지 않음(제안대로) |

### 2번 — 적용

`RESTATE_BAN` 에 낱말을 더하는 것으로는 안 됐다. 처음에 `[가-힣]{2,}(?:특별법|기본법)$` 을
더했는데 **사고 사례가 그대로 통과했다** — `독도 등 도서지역의 생태계보전에 관한 특별법` 은
`특별법` 앞이 **공백**이라 `[가-힣]{2,}` 가 안 붙었다.

그래서 잣대를 바꿨다: **재진술 문장 전체가 법 이름인가**를 본다.

```js
const RESTATE_LAWNAME    = /^[가-힣0-9ㆍ·()\s]{4,}법(?:률)?\s*$/;
const RESTATE_LAWNAME_OK = /(?:방법|용법|수법|어법|화법|기법)\s*$/;
```

정상 재진述은 `…알고 싶다` 로 끝나 `법` 으로 끝나지 않으므로 걸리지 않는다.
`방법` 으로 끝나는 정상 문장만 따로 뺐다. 8가지로 양방향 확인함:

| 넣은 값 | 결과 |
|---|---|
| 독도 등 도서지역의 생태계보전에 관한 특별법 | 막힘 ✅ |
| 해사안전기본법 · 수산업협동조합법 | 막힘 ✅ |
| 하천·저수지에 이 법이 적용되는지 알고 싶다 | 통과 ✅ |
| 사업장 소재지 변경 시 신고해야 하는지 알고 싶다 | 통과 ✅ |
| 공단 직원이 업무상 알게 된 정보를 말해도 되는지 알고 싶다 | 통과 ✅ |
| 신고를 접수하는 방법 | 통과 ✅ |
| 제32조 위반이면 과태료다 | 막힘 ✅(기존 규칙) |

### 1번 — 안 했다. 왜인지 적어 둔다

이 백스톱은 **모든 사용자가 지나가는 답변 경로의 동작을 바꾼다**(되묻기 29 → 22 추정).
위 6절이 스스로 *"적용 전 독립 검토를 붙일 자리"* 라고 적어 뒀고, 저장소 결정로그도
사용자에게 즉시 드러나는 경로는 **다른 에이전트의 독립 검토**를 기본 절차로 둔다.
이번 세션은 그 검토를 붙일 수 없어(에이전트 투입은 사용자 지시 사항) **재는 것까지만 하고
고치지 않았다.** 2번은 설계가 이미 금지한 것을 정규식이 못 잡던 **명백한 결함**이라
같은 잣대를 대지 않았다.

검토를 붙일 때 프롬프트에 넣을 것(결정로그 4요건): ①이 문서와 `_CHATBOT.md` 를 먼저 읽게 할 것
②"추측 금지 — 코드나 실행 결과로 확인한 것만" ③"이 제안이 안 다룬 경우를 지적하는 것을 환영"
④"못 찾았으면 못 찾았다고".

## 9. 독립 검토 3건 결과 (2026-08-29) — 이 문서의 숫자 절반이 무너졌다

서로 다른 세 각도(설계 빈칸 / 숫자 검산 / 사용자 영향)로 독립 검토를 붙였다. 결과를 그대로 남긴다.

### 살아남은 것 — 기초 집계는 전부 재현됐다
검산 검토가 이 세션 임시폴더에 남아 있던 실행기록 32건(`lv_probe_0~19`·`lv_pass_0~11`)을
찾아 다시 셌고, **되묻기 29/32(91%) · 이해확인 14 · 진짜 조건 11 · 어느 법이냐 4 가 전부 일치**했다.
대조군 12건은 뽑는 규칙까지 재현됐다.

### 무너진 것 넷

| 이 문서의 주장 | 검산 결과 |
|---|---|
| 새 낱말 0개 = **7건** | **어떤 잣대로도 7이 안 나온다** — 네 가지로 세니 2·4·4·10건. 사람이 읽어 센 값은 10건 |
| 분모 **15**건 | **14가 맞다.** §2 표·§6-1 은 14인데 §3만 15 — 오기다 |
| ★재진술이 **법 이름**이었다 | **그런 사고는 없었다.** 위 §3★ 참조. 실행기록 restate 106개 중 법 이름 0개 |
| 백스톱 넣으면 **29 → 22** | **28 안팎이다.** 이해확인 카드는 검색보다 앞에서 끊으므로(`routes/legal.js:1324`), 막으면 답변이 아니라 **뒷단 되묻기로 간다.** 이 표본에서 뒷단까지 간 18건 중 15건(83%)이 되묻기였다 → 29 − 7 + 7×0.83 ≈ 27.8 |

### 세 검토자가 **독립적으로 같은 결함**을 지목했다
> **"새 낱말 0개" 잣대는 이 기능의 대표 사례를 정확히 죽인다.**

지시어("그거·이거")를 푼 재진술은 원 질문에 이미 그 말이 있어 **새 낱말이 0**이다. 이해확인
프롬프트가 정답 예시로 박아 둔 예1·예3·예4가 전부 0으로 계산된다. 반대로 살아남는 것은
`받지`·`않으면` 같은 **활용형이 붙은** 카드다. **잣대가 정보 이득과 방향이 반대로 걸린다.**

### 표본 자체의 한계도 드러났다
32문항 중 **30건이 질문 안에 법 이름을 안 쓴다.** 골든 문항집은 법별로 쓰여 각 행에 `law` 칸이
붙는데, `ask_live.js` 는 **질문 문장만** 보낸다 — 측정 도구가 "어느 법 이야기인지"를 떼어 버린 것이다.
대조군도 같은 결함을 공유하므로(12건 중 11건이 법 이름 없음) *"난이도와 무관한 보편 현상"* 이라는
§1 결론은 **성립하지 않는다**(Fisher 정확검정 p=1.0 — 차이를 못 찾았을 뿐 무관함을 입증한 게 아니다).

### 결론
**§6-1 백스톱은 지금 형태로 넣지 않는다.** 넣으려면 최소한 ①지시어 예외(`RESTATE_DEICTIC`
문자열 대조, AI 불필요) ②계수 규칙을 코드 상수로 못박고 회귀 테스트로 고정 ③`assumed` 고지
붙일지 결정 ④효과는 켜기 전 추정이 아니라 **켠 뒤 같은 32문항으로 재측정** — 네 가지가 함께 가야 한다.

⚠**이 문서를 근거로 무언가를 결정하려는 다음 사람에게**: 원자료(32문항 실행기록)는
**저장소에 없다.** 이 세션 임시폴더에만 있었고 컨테이너가 사라지면 함께 사라진다.
숫자를 다시 쓰려면 `ask_live.js` 로 다시 재야 한다.
