# 되묻기가 왜 이렇게 자주 나오나 — 라이브 실측 (2026-08-28)

## 0. 한 줄
실제 서비스에 32문항을 던져 보니 **29건(91%)이 되묻기로 갔다.** 그 29건을 성격별로 갈랐더니
**절반은 사용자에게서 새로 얻는 것이 없는 되묻기**였다.

## 1. 어떻게 쟀나
`_dashboard/loop/ask_live.js` 로 실제 서비스(`/api/legal/ask`)에 문항을 한 번씩만 던지고
(요청 1회/문항) 첫 응답의 `clarify` 를 모았다.
- 대상 20문항: 오프라인 채점판에서 근거를 못 찾던 것들
- 대조군 12문항: 오프라인에서 **잘 되는** 것들(고정 간격으로 뽑음 — 무작위 시드 대신 재현 가능하게)

**되묻기 비율은 두 집단이 사실상 같았다** — 대상 20건 중 18건(90%), 대조군 12건 중 11건(92%).
**즉 검색 난이도와 무관한 보편 현상이다.**

## 2. 29건을 갈라 보면

| 성격 | 건수 | 뜻 |
|---|---:|---|
| ① **이해확인** — 질문을 되읽어 주고 "맞나요?" | 14 (48%) | `understandConfirmStep` 단계 |
| ③ 진짜 조건 되묻기 | 11 (38%) | 답이 실제로 갈리는 구분을 물음 — **정상** |
| ② **어느 법인지 고르라고 함** | 4 (14%) | 검색이 끌어온 법 목록이 그대로 질문이 됨 |

## 3. ①이해확인 — **절반은 새로 푼 것이 없다**

이 단계의 설계 원칙은 문서에 이렇게 적혀 있다: *"정보 이득이 없으면 개입하지 않는다.
실제로 풀어쓴 재진술을 낼 때만 카드를 낸다."* 그런데 실측은 그렇지 않았다.

재진술이 **원 질문에 없던 낱말을 몇 개나 새로 넣었는지** 셌다
(형태소 분석기가 아니라 조사·어미를 거칠게 떼어 센 **근사치**임을 밝힌다):

**새 낱말 0개 = 7건 / 15건 (47%)** — 질문을 평서문으로 바꿔 놓았을 뿐이다.

```
질문: 하천·저수지에도 이 법이 적용되나요?
재진술: 하천·저수지에 이 법이 적용되는지 알고 싶다        ← 새로 푼 것 없음
질문: "이사 가면(사업장 소재지 변경) 신고해야 하나요?"
재진술: 사업장 소재지 변경 시 신고해야 하는지 알고 싶다    ← 질문이 이미 괄호로 풀어 줬다
질문: 공단 직원이 업무상 알게 된 정보를 함부로 말해도 돼?
재진술: 공단 직원이 업무상 알게 된 정보를 말해도 되는지 알고 싶다
```

⚠**처음 세운 잣대는 틀렸다.** "글자 조각(2-gram)이 80% 이상 겹치면 되읽기"로 재니 **0건**이었다 —
재진술이 "…알고 싶다"를 붙이고 어순을 바꾸므로 글자 겹침으로는 안 잡힌다.
겹침이 아니라 **새 낱말이 있나**로 재야 뜻이 맞았다. 첫 잣대를 그대로 보고했으면 틀린 말이 나갔다.

### ★그리고 한 건은 재진술이 아니라 **법 이름**이었다
```
질문: 준보전무인도서에서 조리·야영 허가 안 받고 하면 처벌이 뭔가요?
재진술: 독도 등 도서지역의 생태계보전에 관한 특별법          ← 뜻풀이가 아니라 법 이름
```
설계는 이것을 금지하고 있고(`RESTATE_BAN`) 걸러내는 정규식도 있다. 그런데 **안 걸렸다** —
`RESTATE_BAN = /제\s*\d+\s*조|법률|법령|벌금|과태료|징역|「|」|만원/` 는 `법률`·`법령`은 잡지만
**`…특별법`처럼 `법`으로 끝나는 이름은 못 잡는다**(코드로 확인).

## 4. ②"어느 법인지 고르라고 함" — 검색 오류가 질문으로 나온다

```
질문: "1년 내 4번째 같은 위반 적발이다. 별표4 상한(500만원)을 넘겨 부과할 수 있나?"
되묻기: 어떤 법률 위반으로 적발되셨나요?
선택지: 폐기물관리법 / 해운법 / 독도의 지속가능한 이용에 관한 법률 /
        유류오염손해배상 보장법 / 양식산업발전법 / 어선안전조업법 / 잘 모르겠어요
```
사용자는 자기가 무슨 법 위반인지 몰라서 물은 것인데, **우리가 되물어 버린다.**
게다가 저 목록은 검색이 끌어온 것이라 **정답이 목록에 없을 수도 있다**
(그런 사고가 실제로 있었고, 그래서 `ensureTopLawOption`·`dropForeignLawOptions` 같은
보정이 이미 코드에 들어 있다 — 이번 4건은 그 보정을 통과한 뒤의 모습이다).

## 5. 이미 있는 안전장치 (확인함)
- `CLARIFY_MAX_ROUNDS = 5` — 되묻기 무한루프를 결정론적으로 끊는다. 실제로 5라운드째에
  멈추고 답이 나오는 것을 확인했다(그때 인용이 기대 조문과 일치했다).
  ⚠나는 이걸 모르고 *"영영 답으로 못 간다"* 고 보고했다가 정정했다(L-201).
- `이해확인`은 3회 백스톱(`UNDERSTAND_MAX_ROUNDS`)이 따로 있고 되묻기 라운드를 쓰지 않는다.

## 6. 고칠 만한 것 (제안 — **아직 안 고쳤다**)
답변 경로는 모든 사용자가 지나가는 자리라, 재는 것과 고치는 것을 나눈다.
아래는 제안이고 **적용 전 독립 검토를 붙일 자리**다(CLAUDE.md 결정로그).

1. **이해확인에 결정론적 백스톱을 단다.** LLM 이 `clear:false` 라 해도, 재진술이 원 질문에
   없던 낱말을 하나도 안 넣었으면 **카드를 내지 않고 통과**시킨다. 지금은 판정이 전적으로
   LLM 몫이고 백스톱이 없다 — 다른 되묻기에는 이미 그런 백스톱이 있다(`CLARIFY_MAX_ROUNDS`).
   실측 기준 **이해확인 14건 중 7건이 이 백스톱에 걸려 사라진다**(되묻기 29 → 22, 91% → 69%).
2. **`RESTATE_BAN` 에 "…법으로 끝나는 이름"을 더한다.** 한 줄이고, 위 3절 사고를 막는다.
3. ②유형은 되묻기 문제가 아니라 **검색 문제**다. 되묻기 쪽에서 더 손대면 증상만 가린다.

## 7. 재현
```
node _dashboard/loop/ask_live.js --state /tmp/x.json start "<질문>"
```
첫 응답의 `되묻기`·`선택지` 를 보면 된다. 요청 1회라 비용이 작다
(되묻기까지만 가는 문항 하나가 입력 8.5k 토큰 안팎).
