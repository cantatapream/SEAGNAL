## B. 단계별 계획 — 과거 → 현재 → 미래

### 과거 (완료)
1. **방향 확정**: 음성비서 → 텍스트 챗봇 "나리야". Karpathy LLM-Wiki 패턴 채택.
2. **설계 확정**: 점진공개·온디바이스 프로필·하이브리드 검색·인용 환각0·처벌 3축·다에이전트 병렬 등 요구사항 확정(README 4절).
3. **원문 1차 수집**: 법 70계열·별표·고시.
4. **위키 1차 구축**: statutes 73·concepts(→904)·comparisons·graph.
5. **검증 루프 5라운드**: 감사→수정→재감사. 5차 70/70 완결. full 18%(적대적 재질문값)의 gap 분류 A12%/B20%/C1%/**D67%(위키로 불가)**.
6. **DoD 재정의**: full률 ≥90%를 **스코프 내**로(판례·법리·다툼·입법공백 제외).
7. **수집 3단계로 전환**(D단계): ①범위확정 ②수집 ③대조검증.
8. **스코프 규칙 확정**: 기준법 전량 / 타법 거쳐가는 조문+부속 / 지자체 조례·고시 안내대체 / 소관부서 전화 마무리 / 판례·법리 스코프밖.

### 현재 (진행중) — phase②
9. ✅ **phase① 범위확정 70/70**: 각 법 가지 전체 매니페스트. 집계 = **가지 9,566개, 수집률 90.4%(8,648), 남은 918, 수집곤란 78**.
   - 공용 타법 최다: 전자정부법 제36조(38법). 마스터 워크리스트로 dedup.
10. 🔄 **phase② 수집**: ①공용 타법 부트스트랩(20종 ✅) → ②법별 collect(매니페스트 체크리스트대로 하나씩, 항목별 collected/failed 검증) → 기준법 시행령·시행규칙 전문 재확인(0.5단계).
11. 🔄 **기술기준=기준법-급 정책**(신규): 어선구조·설비·기관·복원성/선박설비·구명·소방·전기·구조 기준 등을 ①전문 전량 수집(첨부 스텁 전문화 포함) ②기준법 수준 위키 구축. (`_SCHEMA.md` 0-A 반영)

### 미래 (예정)
12. **phase② 완료**(70/70 collect) + **기술기준 전문화·위키**(설비/구조 기준 ~50종).
13. **phase③ 대조검증**: 매니페스트 체크리스트 완결 확인(항목별 실수집 대조).
14. **6차 감사**: 스코프-내 full률 재측정 → **DoD 90% 판정**.
15. **Phase E — 챗봇 엔진**(방 8): 하이브리드 검색 → 답변(명확조문 필수·소관부서 전화 마무리) → 온디바이스 프로필.
16. **Phase F — 앱 UI**: 챗봇 화면 + 관리자 검토 실배선 + `_feedback`/`_candidates` 배선.
17. **Phase G — 운영**: 개정 diff 재인제스트 스케줄러 + 피드백 학습 루프.
18. **머지 후**: `gen_architecture.js` 스코프에 `knowledge/legal` 추가 → ARCHITECTURE.md에 챗봇 영역 자동 반영.
