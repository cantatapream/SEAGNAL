# 위키 방식 vs 법제처 API 직접 방식 — 비교 실험 (2026-10-06 착수)

## 이 폴더가 무엇인가

나리야(법률 챗봇)는 지금 **미리 정리해 둔 위키**를 근거로 답한다. 사용자가 어느 발표에서
*"위키 없이 국가법령정보센터 API 를 그때그때 불러 답하는 방식"* 을 보고, 그 방식이

- 형법처럼 큰 법을 다 읽어야 하지 않는지(양·시간),
- 답이 맞는지 확인할 수 있는지,
- 법률 → 시행령 → 시행규칙 → 별표 → 고시로 **위임 흐름을 따라가 답을 꺼낼 수 있는지**

를 물었다. 추측이 아니라 **같은 질문을 실제로 세 방식에 던져** 비교하려고 만든 실험 장치다.

> 사용자 원문(2026-10-06): *"단순히 그냥 이럴 것이다 라는 가정 말고, 일단 코드가 어떻게 되어 있고
> 어떤 식으로 답변을 도출하는지 확인하고 그 방식 대비해서 … API만을 이용해서 … 실제로 호출해서
> 어떻게 답변이 적절하게 되는지 여부를 확인해서 그 둘을 비교하고 싶거든"*
> *"나는 그것에 영향없이 별도로 검증해보고자하는데"* → **(가) 실험 전용 키를 넣고 전체 비교** 로 확정.

## 세 방식

| | 근거를 어디서 | 실제 코드 |
|---|---|---|
| **A** 지금 챗봇 | 위키 검색 → 상위 페이지 발췌 → AI 답변. 위키에서 근거가 안 남으면 2차(원문 직독)로 넘어간다. 되묻기 포함 | `routes/legal.js` POST `/api/legal/ask` 를 **그대로** 띄워 부른다 |
| **B** 원문 직독 | AI 가 법 1~2개 고름 → 우리가 모아 둔 `법률.txt`(파일당 5만 자에서 자름) + 폴더 목록 → AI 가 시행령·시행규칙·별표·고시 파일 최대 4개 고름 → 답변 | `legal_retriever.searchRawFallback()` 를 강제로 부른다(앱에서는 위키가 빈손일 때만 켜진다) |
| **C** 법제처 API 만 | AI 가 도구로 법제처를 직접 부른다: 법령 검색 → 목차 → 조문 → 위임 정보 → 시행령·시행규칙·별표·행정규칙 | `lawapi.js`(도구 7개) + `run_arms.js` 의 도구 호출 루프(최대 15회) |

**공정성**: 세 방식 모두 같은 AI(`legal_retriever.ANSWER_MODEL` = gemini-2.5-flash), 같은 답변 규칙
(`ANSWER_RULES_BODY`), 같은 생성 설정(온도 0)을 쓴다. 다른 것은 **근거를 어디서 가져오느냐**뿐이다.

## ★운영에 영향이 없게 — 어떻게 지키나

- **운영 서버(fly.dev)를 부르지 않는다.** A 도 이 컴퓨터 안에 챗봇 라우터를 띄워 부른다.
- **임시 작업 사본에서 돈다.** A 는 돌면서 파일을 쓴다(지식 후보 큐 `_candidates/queue.jsonl`,
  보관 답변 `data/pending_answers.json`, 설정 `data/nariya_config.json`). `run.sh` 가 지금 커밋 그대로의
  사본(git worktree)을 따로 만들어 그 안에서만 돌리고, 끝나면 **사본째 지운다**. 결과만 `results/` 로 나온다.
  (2026-10-06 배선 시험 후 `git status` 로 확인: 작업본에 남은 변경 없음, 사본 목록도 비어 있음.)
- **앱 코드는 한 줄도 고치지 않는다.**
- **AI 키는 실험 전용으로 새로 받는다.** 운영 키(`GEMINI_API_KEY_26_8`, Fly.io)와 같은 키를 쓰면
  사용 한도·요금을 나눠 써서 실험 중 사용자가 「한도 소진」을 겪을 수 있다.
- 커밋 전 검사(`verify_all.sh`)는 키를 일부러 비우고 돈다(47~48행) — 키를 넣어도 검사 중 AI 호출은 없다.

## 키 넣기

1. Google AI Studio 에서 **실험 전용** Gemini API 키를 새로 받는다.
2. 클라우드 작업 환경 설정(세션 제목 줄의 환경 메뉴 → Edit)에 환경변수 **`GEMINI_API_KEY_26_8`** 로 넣는다
   (앱 코드가 이 이름만 읽는다 — `services/gemini_client.js` 50행). 키를 대화창에 붙여 넣지 않는다.
3. **새 세션**부터 적용된다.

## 돌리는 법

```bash
cd local_server/knowledge/legal/_dashboard/api_vs_wiki
bash run.sh pilot      # 시험 10문항 × A·B·C  → results/pilot_<KST시각>/
bash run.sh main       # 본실험 40문항 × A·B·C
ARMS="c" bash run.sh pilot   # 한 방식만
```

**GitHub 에서 돌리기 (2026-10-06 사용자 확정 — 운영 키 `GEMINI_API_KEY_26_8` 시크릿 사용)**:
작업 세션에 키가 없을 때는 `run_request.json` 의 `set`(pilot|main)·`arms` 를 고쳐 `claude/**` 갈래에 push 한다.
`.github/workflows/api-vs-wiki-run.yml` 이 그 push 에서만 돌아 `run.sh` 를 실행하고 결과 폴더를 같은 갈래에 커밋한다.
⚠운영 키와 한도를 나눠 쓴다. ⚠GitHub 서버는 해외라 법제처 접속이 막힐 수 있다 — 실행 기록의 「법제처 연결 확인」 줄을 먼저 본다.

결과 폴더에 `a.jsonl`·`b.jsonl`·`c.jsonl`(문항별 답변 전문·시간·토큰·API 호출 기록)과 `score.txt`(채점표)가 남는다.
같은 결과 파일로 다시 돌리면 이미 한 문항은 건너뛴다.

## 질문지 (`questions.json`, `select_questions.py` 가 만든다)

골든 문항(원문으로 정답 조문을 확인해 둔 것, `_dashboard/loop/pinned/golden_questions.json`) 중에서
**답이 있는 층별로** 골랐다: 법률 12 · 시행령 7 · 시행규칙 6 · **별표 10** · **행정규칙 5** = 40.
그대로 뽑으면 법률 층이 64% 라 위임 사슬을 거의 못 보므로, 위임을 따라가야 하는 질문을 일부러 늘렸다.
시험 10문항은 층마다 2개. 씨앗 고정이라 다시 만들어도 같다.
감사 메모가 섞였거나(★재질문·라운드·회귀) 「이 법」처럼 앞 대화를 전제한 문항은 뺐다(251문항에서 고름).
⚠그래도 법 이름 없이 짧은 문항이 일부 남아 있다(예: 「이물질 몇 % 이하로 제거해야 하나?」) —
세 방식 모두에 똑같이 불리하지만, 결과를 읽을 때 감안한다.

## 채점 (`score.py`) — AI 를 쓰지 않는다

글자 대조만 한다(L-133). B·C 에는 근거 목록이 없어서 **세 방식 모두 답변 글**로 잰다.
`hit`(기대 법령 + 기대 조문·별표 전부) · `partial` · `miss_art` · `miss` · `clarify` · `no_answer` ·
`skipped`(한도·키 오류 — 감점하지 않고 분모에서 뺀다, L-263). 시간·토큰·문항당 비용·(C)법제처 호출 수도 낸다.

**이 채점이 못 재는 것**
- **답의 사실 정확성**(숫자·요건이 원문과 맞나)은 안 잰다. 「조문을 댔다」 ≠ 「답이 맞다」.
  결과 파일의 답변 전문을 원문과 따로 대조해야 한다(시험 결과부터 사람이 본다).
- 조문 번호가 **어느 법의 것으로** 쓰였는지까지는 안 본다(법 이름과 조문 번호가 답 어딘가에 있으면 맞힌 것으로 센다).
- 비용 단가는 2026-07-30 코드 주석에 적힌 값이다.

## 지금까지 확인한 것 (2026-10-06, 키 없이)

- 법제처 API 로 **조문 하나만**, **목차만**, **위임 정보만** 받을 수 있다 — 법 전체를 읽지 않아도 된다.
  예: 마리나항만법 제24조의2 → (위임 정보) 시행령 제26조의2 → 시행령 별표1(안전점검 시기 표 글 본문)까지
  도구로 따라가는 것을 실제 호출로 확인했다.
- ⚠위임 정보의 조문 번호는 가지번호(「의2」)가 **따로 오는 필드**에 있다 — 안 붙이면 엉뚱한 조문(제26조)을 읽는다. 도구에 반영했다.
- ⚠행정규칙 중에는 법제처 API 가 **글 본문을 주지 않는 것**이 있다(예: 「어선구조기준」 고시 — `조문내용` 이 빈 값,
  첨부파일로만 있음). C 방식은 이런 고시에 닿지 못한다. 몇 건이나 그런지는 실험 결과로 센다.
- ⚠이 작업 환경에서 법제처 연결이 **중간에 끊기는 일이 잦았다**(5번 연속 끊긴 적도 있음). 도구는 6번까지 다시 시도하고, 그 횟수를 센다.
- 배선 시험(가짜 키): 세 방식 모두 끝까지 돌고 결과·채점이 나오는 것, 구글 AI 서버까지 연결되는 것(키 오류 응답)을 확인했다.

## A 방식이 운영과 다를 수 있는 점

- 설정 스위치는 운영값을 그대로 쓴다(`prod_config.json`, 2026-10-06 조회).
- 운영에 있는 네이버 사전 키(모르는 낱말 풀이 단계)가 이 환경엔 없다 → 그 단계는 조용히 빠진다.
- 운영에 배포된 버전과 이 저장소 최신본이 같은지는 확인하지 않았다.
- 2차 조회의 원문을 GitHub 대신 사본 디스크에서 읽는다(내용은 같은 커밋).
