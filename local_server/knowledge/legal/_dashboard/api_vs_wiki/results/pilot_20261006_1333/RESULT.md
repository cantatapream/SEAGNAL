## 3. 읽어낸 것

1. **API 방식의 가장 큰 약점은 「어느 법인지 찾기」다.** 법 이름이 없는 생활어 질문(「지도사」「검수사」「경비원 위험성평가」)에서
   C 는 검색어를 바꿔 가며 헤매다 **엉뚱한 법을 골랐고, 그 법으로 자신 있게 답했다**(✗✗ 2건). 위키는 구어 사전·주제 색인으로 이 단계를 미리 풀어 둬서 맞혔다.
2. **법을 맞게 찾은 뒤의 위임 사슬 추적은 API 가 잘했다.** 별표-02 에서 C 는 법 → 위임정보 → 시행령 → 별표까지 스스로 따라가 시기표 값을 답했고,
   A 는 같은 질문에서 별표 내용이 발췌에 안 들어와 「언제」를 못 답했다(위키 발췌 예산·연결의 구멍으로 보인다 — 원인은 아직 안 캤다).
3. **"형법 전체를 읽어야 하는" 문제는 실제로는 안 생겼다.** C 는 목차·조문 단위로만 읽어 문항당 입력 토큰이 평균 4.2만으로 셋 중 가장 적었다.
   다만 시간은 A 와 비슷했다(도구를 평균 6번, 최대 10번 부름).
4. **B(원문 직독)는 C 와 같은 약점(법 고르기)을 가졌고, 고른 법이 맞으면 답도 맞았다.** 1건은 법 고르기 자체가 실패해 빈 답이었다.
5. **위키(A)에도 빗나감이 있다** — 법률-02·시행령-01 은 위키 검색이 다른 주제 페이지를 물어와 엉뚱한 답이 됐다.
