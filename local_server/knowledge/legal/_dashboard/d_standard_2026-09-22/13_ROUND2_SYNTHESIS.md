## 0. 이 라운드가 답한 물음

1라운드는 **「열리나」**(도달성)를 쟀다 — 링크가 열리는가, 조가 있는가, 게이트가 초록인가.

**결론 한 줄**: 도달성은 99.9%로 거의 완벽하다. 충실도는 **잴 때마다 값이 다르고, 재는 코드가 아예 없다.**

## 2. ★내가 직접 열어 확정한 것 — 5건 전부 원문 대조

### ⓓ-1 수산업협동조합법 제89조 (**canonical**) — 법보다 엄하게 적었다
```
위키 53행: "청산인은 조합의 채무를 다 갚은 후가 아니면 그 재산을 분배하지 못한다."
raw  715행: 청산인은 지구별수협의 채무를 변제하거나 변제에 필요한 금액을 공탁(供託)한
            후가 아니면 그 재산을 분배할 수 없다.
```
**「공탁하면 된다」는 길이 통째로 사라졌다.** 같은 쪽 39행 표도 *"채무를 완제한 후"* 로 같은 축약을 되풀이한다. 주체도 `지구별수협`→`조합`으로 넓어졌다.

### ⓓ-2 선박안전법 제19조의2③ (draft) — 재량을 의무로
```
위키 50행: "…그 사실을 공표하여야 한다."
raw  177행: …그 사실을 해양수산부 인터넷 홈페이지 등에 공표할 수 있다.
```
★ 같은 쪽 **284행 「변경 이력」이 이 조를 두고 *"(raw 원문 EXACT)"* 라고 적어 두었다.** 기록이 사실과 반대다.

### ⓓ-3 선박안전법 제26조 (**canonical**) — 위임 형식이 틀렸고 영어가 박혀 있다
```
위키 23행: 법 제26조("선박시설은 해양수산부령으로 정하는 basic 기준에 따라야 한다" 취지)
raw       : 선박시설은 해양수산부장관이 정하여 고시하는 선박시설기준에 적합하여야 한다.
```
**부령이 아니라 장관 고시다.** `basic` 이라는 영어 낱말은 **전 위키에서 이 한 곳뿐**이다(직접 grep).

### ⓓ-4 마리나항만법 제28조의4 (draft) — 없는 낱말을 넣었다
```
위키 76행: "…해양수산부령으로 정하는 바에 따라 미리 시·도지사에게 신고하여야 한다."
raw       : 등록사업자가 그 영업의 전부 또는 일부를 휴업ㆍ재개업 또는 폐업하려는 경우에는
            해양수산부령으로 정하는 바에 따라 시ㆍ도지사에게 신고하여야 한다.
```
`미리` 는 그 조에 **0건**(직접 확인). 뜻은 맞다(3일 전 기한은 시행규칙 제26조) — 위키도 바로 뒤에 그렇게 적는다. 그러나 **큰따옴표 안에 법에 없는 낱말이 들어갔다.**

### ★-5 「위험물 선박운송 기준」 별표21 (**canonical**) — 구판이 굳어 있다
```
위키 머리말: lawService.do?target=admrul&ID=2100000059129  (2026-08-17)
             "AI 승급 근거: 정부 공식 HWP 원문 표 구조 기계적 전사(EXACT)"
raw  2행   : ID=2100000280940 (수집 2026-08-31)
```
| 낱말 | 현행 raw | 위키 |
|---|---:|---:|
| 자기반응물질 | **0** | 1 |
| 인화성고압가스 | **0** | 1 |
| 0.4 W | **0** | 1 |
| 최고허용운송온도 | **0** | 1 |
| SADT | 8 | **0** |

**서로 낱말이 하나도 안 겹친다.** 위키는 `status: canonical`, 색인 등재, `concepts/선박안전법__산적화물위험물운송` 이 링크 → **챗봇이 꺼낼 수 있다.**
`_SCHEMA §6-G`(*"완료 기록은 근거가 아니다"*)와 `L-250`(*"정확히 읽은 구판이 가장 위험하다"*)이 **한 쪽에서 동시에 재현**됐다.

## 3. ★대기 큐 — 같은 파일을 세 도구가 세 값으로 센다

| 누가·무엇 | 대기 |
|---|---:|
| 내 첫 집계(승인 `[ ]` 만) | **89** |
| E | **39** |
| **서버 `routes/legal.js parseReviewQueue()`** (관리자 화면에 뜨는 값) | **3** |
| `_dashboard/loop/human_workload.py` | **0** |

E 와 내 값은 **`쪼갬`·`해당 없음` 3상태를 안 적용한 것** — 우리 둘이 틀렸다.
남은 **3 대 0** 은 두 운영 도구가 실제로 어긋난 것이다:
- 서버 133행 `if (ap) { cur.approved = ... }` → **마지막 승인줄이 이긴다**
- `human_workload.py` 33행 `if re.search(r'^-\s*승인:\s*\[[xX]\]', b, re.M): continue` → **하나라도 `[x]` 면 승인**

### 그 3건 중 2건은 파서 결함이다 — 내가 줄 번호로 확정
```
9424행  ### REVIEW-해양생태계…-907          ← 카드 열림
9431행  - 승인: [x] 범위 밖 종결 — 2026-09-19 사용자 확정
9433행  ### 〔기록〕 REVIEW-수산업ㆍ어촌…-803  ← ### 인데 「REVIEW-…:」 꼴이 아니라 새 카드가 안 열린다
9435행  - 승인: [ ] 대기                     ← ★앞 카드로 샌다 → 승인이 대기로 뒤집힘
```
전수로 세니 **이렇게 새는 줄이 정확히 3개**(9435·9468·9515), 뒤집히는 카드 **2장**(해양생태계-907·선박법-907).
남은 1장(선박평형수-806)은 카드가 **일부러** `[x]` 뒤에 `[ ] 대기` 를 더 단 것이다 — 결함이 아니라 서식의 한계.

> 검토 F 는 같은 3건을 찾았으나 *"세 장 모두 카드 안에 승인줄이 둘"* 이라고 원인을 잘못 짚었다. **고쳐야 할 자리가 다르다**(카드 본문이 아니라 `### 〔기록〕` 을 카드 경계로 인정하는 것).

## 7. 뿌리 사슬이 한 마디 더 늘었다

```
①규칙은 있었다              → 코드가 안 읽는다
②코드가 안 읽는 규칙은 죽는다 → 그래서 게이트를 만들었다
③게이트가 안 재는 자리도 죽는다 → 그런데 게이트를 부르는 것이 없다
④게이트를 부르는 것이 없으면 게이트도 죽는다   ← 1라운드
⑤게이트가 묻지 않는 물음은 영영 답이 없다     ← 12번 문서
★⑥세는 법을 안 정하면 같은 것을 재도 답이 다르다 ← 이번 라운드
```

⑥의 증거: 같은 날 같은 저장소에서 **인용 정확도 61.5~91.1%, catch 39~133, 재발률 23.5~42%**.
`_SCHEMA §0-E 규칙 3`이 *"정규화 없이 비교하지 마라"* 고만 하고 **씻을 목록을 안 줬기 때문**이고, `_SCHEMA §8-A`가 *"근거 조문 행"* 을 정의하지 않아 운영 도구 셋이 **19,161 / 17,903 / 14,218** 로 갈리는 것과 같은 병이다.
