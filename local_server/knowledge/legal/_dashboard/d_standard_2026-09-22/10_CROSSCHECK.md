# ⑩독립 3벌 병렬 검토 + 내 검증 — 교차 대조 (2026-09-22)

> 사용자 지시: *"다른 에이전트도 병렬로 동일한 것을 독립적으로 동일한 지침 하에 검토하게 하고,
> 그 결과를 종합해서 알려줘."*
>
> 감사관 **A · B · C** 에게 **같은 지침**을 주고 서로의 결과를 못 보게 했다.
> 나도 같은 범위를 직접 쟀다. **A · C 도착, B 진행 중.**
> 아래 판정은 전부 **내가 다시 실행해 확인한 것**이다.

## §1 ★가장 큰 것 — 별표가 "있는데 안 열린다"

세 사람이 **같은 결함을 찾았는데 숫자가 갈렸다.** 그래서 내가 다시 쟀다.

### 1-1. 먼저 자를 맞춰야 했다

별표 파일은 **여는 길이 세 갈래**다. 갈래마다 코드가 다르다.

| 갈래 | 파일 이름 꼴 | 수 | 여는 코드 |
|---|---|---:|---|
| ③계층접두 | `시행령_별표1.txt` | 2,774 | 파일명으로 바로 |
| ③무접두 | `별표1.txt` | **2,037** | 파일명 + **선언줄 검증**(`BYL_DECL_RE`) |
| ⑤고시형 | `<고시명>_별표1.txt` | 2,648 | `parseBylFile` |

★**내가 처음에 ⑤고시형까지 ③의 자로 재서 2,969 라는 값을 냈다.** 갈래를 갈라야 한다.

### 1-2. 갈래를 맞춘 뒤의 숫자 — ③무접두 2,037개

```
✅ 선언줄 일치 → 열린다      1,549
✅ 삭제(정상)                   77
★ 선언줄을 코드가 못 읽음      259
★ 파일명 번호 ≠ 선언 번호      152
───────────────────────────────
★★못 여는 것                  411  (20%)
```

### 1-3. 네 사람의 값

| | A | C | 나 | 코드 주석 |
|---|---:|---:|---:|---:|
| 파일명 번호 ≠ 선언 번호 | **152** | 146 | **152** | *"실측 41개"* |
| 선언줄 못 읽음 | 116* | 328 | 259 | — |
| **못 여는 것 합계** | 203 | **474** | **411** | — |

\* A 는 "번호 없는 `[별표]`"라는 **다른 정의**로 셌다.

> ★**"파일명≠선언 번호"는 셋이 146~152 로 수렴했다.** 그런데 **코드 주석은 41개**라고 적혀 있다.
> `article_text.js:1547` 의 *"실측 41개"* 는 **3.5배 과소**다. 아무도 다시 재지 않았다.

**A 의 203 은 과소**다. C 의 474 와 내 411 의 차이는 `삭제` 판정 범위 차이로 보이며,
**둘 다 "400~470개"라는 같은 결론**을 가리킨다.

## §2 ★가장 구체적인 것 — 법 하나가 통째로 안 열린다 (내가 직접 확인)

C 가 찾았고 **내가 코드로 재현했다.**

`raw/15_관련타부처/선박에서의오염방지에관한규칙/별표/` — **90개 파일**

```
✅ 열린다      0
   삭제       10
★ 못 읽음     80
```

**원인은 낱말 하나다.** 운영 정규식(`article_text.js:1041`)은 이렇게 생겼다 —

```js
const BYL_DECL_RE = /■[^\n[〔【]*?(시행규칙|시행령)\s*[[〔【]\s*…/
```

**`시행규칙` 또는 `시행령`** 만 받는다. 그런데 이 법의 선언줄은 —

```
■ 선박에서의 오염방지에 관한 규칙 [별표 2]
                        └── "규칙" 이다. "시행규칙"이 아니다.
```

이 법은 **`tier: 1`(기준법급)** 이고, `_meta.json` 에 이렇게 적혀 있다 —

```json
"tier": 1, "소관부처": "해양수산부",
"note": "2026-07-19 기술기준=기준법급 재분류(H-15 #4, 해양환경관리법 하위 기술기준)",
"별표_수집현황": { "공식_별표_수": 51, "수집된_별표_파일": 51, "확인일": "2026-09-02" }
```

> ★**별표 51개를 공식 수와 맞춰 전부 받아 놓고, 한 개도 안 열린다.**
> 그리고 위키는 그 별표를 근거로 짚는다 — *"「선박에서의 오염방지에 관한 규칙」 제8·9조·**별표2·3**"*.

같은 꼴이 더 있다 — `■ 「국가기술자격법 시행규칙」 [별지…]`(낫표 때문에 실패, 21개) ·
`■ 선박톤수의 측정에 관한 규칙 [별표 N]`(6개) · `■[별지 제N호서식]`(공백 없음, 6개) ·
**`■` 선언줄이 아예 없는 것 122개**.

### 내가 A 의 오류 1개를 잡았다

**사실은 맞다.** 그러나 커밋 이력을 파니 —

> 2026-08-05 `feat(legal): 답변엔진 문장 단위 REVIEW 필터 구현`
> *"`_SCHEMA.md`에 예정으로만 적혀 있던 인라인 REVIEW 마커 필터를 **사용자 지시로 실장.**
> 지금까지 draft 페이지는 **통째로** 제외됐다 — REVIEW 마커 없는 나머지까지 함께 막혔다."*
> *검증: draft 310개 전수 스캔 — 스트립 후 빈 페이지 0건, 295개는 마커 있음, 15개는 원래 없음*

**A 의 "사용자 피해 1순위" → "문서만 낡음"으로 재분류.**
남는 진짜 결함은 `_CHATBOT §3` 과 코드 30행 머리말이 옛말이라는 것, 그리고
**당시 REVIEW 마커가 없던 draft 15쪽**의 잔여 위험.

### C 가 A 의 오류 1개를 잡았다

`index.md` — A 는 *"깨진 링크 2개"*, C 는 *"링크 1,022개가 전부 깨짐"*.
