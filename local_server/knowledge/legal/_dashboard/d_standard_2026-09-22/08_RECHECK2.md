## §1 새로 찾은 것 검증 — **맞았지만, 밑에 더 큰 것이 있었다**

### 1-1. "§0-A tier 규칙을 돌리면 80개가 1군" → ✅맞다. 그런데…

타법 430개에 규칙을 그대로 돌리면 1군 80개(단독 63 · 공동 17). **이 숫자는 맞다.**

**그런데 그 63개를 하나씩 열어 보니 전혀 다른 문제가 나왔다.**

### 1-2. ★**같은 법이 기준법 폴더와 타법 폴더에 이중으로 있다 — 25개**

| 법 | 기준법 폴더 | 타법 폴더 |
|---|---|---|
| 해양환경관리법 | 07_해양환경생태 · **534,427자** | 15_관련타부처 · **3,062자** |
| 양식산업발전법 | 05_수산어업 · 463,552자 | 15_관련타부처 · 1,167자 |
| 수산업법 | 05_수산어업 · 433,778자 | 15_관련타부처 · 14,016자 |
| 선박안전법 | 04_선박해운 · 394,412자 | 15_관련타부처 · 2,813자 |

**25개 전부 내용이 다르다** — 기준법 쪽은 전문, 타법 쪽은 발췌.

### 1-3. ★그래서 **사용자 피해가 있나?** — 없다 (운영 함수로 확인)

`article_text.js` 의 `resolveBase()` 를 직접 불러 10개를 시험했다.

> **10개 전부 기준법(전문) 폴더를 골랐다. 타법 발췌본을 고른 것 0개.**

**챗봇은 안전하다.**

### 1-4. ★그런데 **검사기는 속는다** — 그리고 이미 속고 있었다

V5-16 이 지금 남긴 **14곳 중 7곳**이 이 이중 폴더 탓이다 —

```
5곳  raw/15_관련타부처/수산업협동조합법/시행규칙.txt   ← 05_수산어업에 전문이 있다
2곳  raw/15_관련타부처/항만법/법률_발췌.txt           ← 10_항만물류에 전문이 있다
```

★**내가 어제 "8곳은 고칠 것이 없다"고 보고한 것 중 7곳이 정확히 이것이었다.**
결론(고칠 것 없음)은 맞았지만 **원인(이중 폴더)을 못 알아봤다.**

### 1-5. 그래서 앞 보고를 정정한다

| 앞서 한 말 | 바로잡은 말 |
|---|---|
| *"단독 소관 63개는 타법 폴더에 있으면 자리가 틀린 것"* | **25개는 자리가 틀린 게 아니라 복사본이다.** 기준법 폴더에 원본이 이미 있다 |
| — | 나머지 **38개는 아직 안 열어 봤다.** 진짜 자리가 틀린 것일 수 있다 |

## §2 아직 안 본 곳 훑기 — 새로 나온 것 3가지

### 2-1. ✅`_legacy/` 686파일·11MB — **안전하다**

폐지·구법 조문 보관소. 위험은 *"챗봇이 이걸 읽어 폐지된 법을 답하나"* 였다.

- `services/`·`routes/` 어느 코드도 `_legacy` 를 **참조하지 않는다** (grep 0건)
- 경로 지도 `law_raw_paths.json` 에도 **없다** (0건)

**→ 읽기 경로에 못 들어온다. 문제없다.**

### 2-2. ★`log.md` — 규약 §7 형식을 지킨 줄이 **10%**

`_SCHEMA.md §7` 이 정한 형식:
```
## [YYYY-MM-DD] ingest | <법령명 제N조> | <한줄 요약>
```

| | |
|---|---|
| `## [날짜]` 로 시작하는 줄 | **493** |
| **그중 규약 형식(`ingest \|`)을 지킨 줄** | **49 (10%)** |
| 파일 크기 | 1,086줄 · **1,392 KB** |
| **가장 긴 줄** | **5,842자** |

★**"한 줄 요약"이라는 규약이 무너져, 한 줄이 5,842자가 됐다.**
`_meta.json`·위키 절 제목과 **똑같은 유형**이다 — 규약은 있고, 읽는 코드가 없다.

### 2-3. ★`_feedback/` · `_candidates/` — 규약이 그린 구간이 **비어 있다**

`_SCHEMA.md §0-B` 는 전체를 5구간으로 그려 뒀다 —
> ① `raw/`(원문) → ② `wiki/`(정리) → ③ 답변 → ④ `_feedback/`(불만족 수집→AI 재검토) →
> ⑤ `_candidates/`(새 지식 후보→검증→위키 편입). **④⑤가 이번에 추가된 피드백 영역.**

**실측:**

| 폴더 | 파일 수 | 내용 |
|---|---|---|
| `_feedback/` | **1** | `README.md` 뿐 |
| `_candidates/` | **1** | `README.md` 뿐 |
| `_amendments/` | 2 | README + `queue.jsonl` |
| `draft/` | 14 | 실제 초안 |

서버에는 `/api/legal/feedback`·`/api/legal/candidates` 엔드포인트가 있고
관리자 AI 탭에 대기함도 있다. 그런데 **데이터가 쌓인 흔적이 없다.**

**→ 규약이 그린 ④⑤ 구간은 "설계는 됐고 아직 안 돌고 있다."**
이걸 모르고 보면 *"피드백 파이프라인이 있다"* 고 착각한다.

### 2-4. ✅DB는 없다 — 전부 JSON 파일

sqlite·mongo·postgres·mysql·redis **어느 것도 안 쓴다.**
데이터는 `local_server/data/*.json` 이다(볼륨). 법률 쪽 관련 파일 —
`legal_amendments_queue.jsonl`(361KB) · `review_approvals.json`(3KB).

## §4 이번 회차의 교훈

**"다시 보라"고 할 때마다 새것이 나오는 이유**는 내가 대충 봐서가 아니라 —

> **한 번에 한 겹씩만 벗겨지기 때문이다.**
> ①발췌본이 이상하다 → ②아니다, 설계대로다 → ③그런데 tier 가 9%뿐이다 →
> ④tier 를 돌려 보니 80개가 1군이다 → ⑤그 63개를 열어 보니 **25개가 복사본이다** →
> ⑥복사본이 검사기를 속이고 있었다(V5-16 의 7곳)

**각 단계는 앞 단계를 해야만 보인다.** 그래서 "끝"을 선언하려면
**안 본 곳 목록(§3)을 다 훑어야** 한다. 지금은 **못 훑었다.**

**그리고 지금까지 여섯 겹 중 다섯 겹에서, 내려가 보니 결론이 바뀌었다.**
남은 §3 의 8가지도 같을 것으로 본다.
