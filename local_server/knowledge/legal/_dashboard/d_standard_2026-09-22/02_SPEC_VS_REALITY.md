# ②기준은 "없는" 것이 아니었다 — **적혀 있는데 한 건도 안 지켜졌다** (2026-09-22 실측)

> 01 문서는 *"기준을 적어 둔 곳이 없어서 도구마다 자기 기준을 만들었다"* 로 끝냈다.
> **그 결론이 틀렸다.** `_SCHEMA.md` 를 열어 실제 데이터와 대조하니 —
> 기준은 **2026-07-14 부터 적혀 있었고**, 지켜지지 않았다.
> 이 정정이 다음 단계의 성격을 바꾼다: **새로 쓰기가 아니라 지키게 만들기**다.

## §2 ★대조 1 — `§1 입력: raw 문서의 frontmatter`

`_SCHEMA.md` 는 raw 메타를 이렇게 **못 박아 뒀다**.

```yaml
---
법령ID: "003598"
법령일련번호: "268127"          # MST
법령명: 수산업법
법령구분: 법률
공포일자: 2025-01-03
시행일자: 2025-07-03
현행연혁코드: 현행
위임관계:
  - 조문: 제12조
    위임대상: 시행규칙 제8조
---
```

**실제는 이렇다.**

| 규정 | 실제 |
|---|---|
| YAML frontmatter, 원문 파일 안에 | **`_meta.json`** — 별도 JSON 파일, 폴더마다 하나 |
| 키 **8종** | 키 **125종** |
| — | YAML frontmatter 를 쓴 raw 파일 **0개** |

규정된 8개 키의 실제 준수율 (`_meta.json` 516개):

| 키 | 있는 파일 | |
|---|---|---|
| `법령명` | 490 (94%) | ✅ |
| `법령ID` | 69 (13%) | ❌ |
| `법령일련번호` | 17 (3%) | ❌ — 대신 이름이 **7가지**로 갈렸다 |
| `시행일자` | 18 (3%) | ❌ — 대신 `시행일` 417 |
| `법령구분` | 13 (2%) | ❌ |
| `공포일자` | 9 (1%) | ❌ |
| **`현행연혁코드`** | **0 (0%)** | ❌ 한 건도 없다 |
| **`위임관계`** | **0 (0%)** | ❌ 한 건도 없다 |

> ### ★**8개를 다 갖춘 `_meta.json` : 0개 / 516**

**이것이 이번 조사의 가장 큰 발견이다.** 부분적으로 어긋난 것이 아니라
**형식(YAML↔JSON)부터 다르다.** 스키마가 쓰이고 나서 **한 번도 구현된 적이 없다.**

그리고 이것이 우리가 겪은 사고를 그대로 설명한다 —

- `현행연혁코드` 가 0건이다 → **"이게 현행 판인가"를 메타로 알 수 없다** →
  매번 law.go.kr 에 다시 물어야 하고, 안 물으면 옛 판을 쓴다(L-296 · 미시행 31조문)
- `법령일련번호` 가 3% 다 → **MST 를 못 믿는다** →
  `lawService?target=law&MST=` 이 엉뚱한 판을 준 사고(L-297)
- `위임관계` 가 0건이다 → 위임 사슬을 **매번 API 로 다시 캔다**

## §3 ★대조 2 — `§0-B 폴더 규약: raw/ 는 "불변, 절대 수정 안 함"`

| 폴더 | 용도 | 쓰기 주체 |
|---|---|---|
| `raw/` | 국가법령정보센터 API로 받은 원문. **불변, 절대 수정 안 함** | **수집 단계만** |

**실측 (이력 전체 8,101 커밋)**

| | |
|---|---|
| 이력 중 추가된 raw `.txt` | **11,341** |
| 그중 **나중에 수정된** 것 | **1,508 (13%)** |
| 수정 횟수 합계 | **3,573회** |
| 가장 많이 고쳐진 파일 | 개인정보보호법 `법률.txt` **18회** · 행정절차법 `법률.txt` 15회 · 전자정부법 `법률_발췌.txt` 14회 |

그리고 `_dashboard/loop/` 도구 **191개 중 94개가 파일을 쓴다** — "수집 단계만"이 아니다.

⚠**공정하게 말한다.** 수정의 상당수는 **정당한 재수집**(개정 반영)이고, 어제 내가 한
부칙 병합·`--refresh` 도 여기 들어간다. 문제는 그 일이 나쁘다는 것이 아니라,
**문서가 그 일을 한 번도 인정한 적이 없다**는 것이다. 규약이 현실을 못 따라가면
규약은 죽고, 죽은 규약 아래에서는 **아무도 무엇이 옳은지 모른다.**

## §4 지켜진 것도 있다 — 공정하게

| 규약 | 상태 |
|---|---|
| `§0-B` 폴더 배치 (`draft/` · `_legacy/` · `_feedback/` · `_candidates/` · `_dashboard/`) | ✅ 전부 존재 |
| `§5` 위키 `status` 값 | ✅ **3가지뿐** — `canonical` 1,112 · `draft` 170 · `review-pending` 4 |

★**차이가 뭔가.** 지켜진 둘은 **코드가 강제한다** — 폴더는 경로가 틀리면 파일을 못 찾고,
`status` 는 `legal_retriever.js` 가 값으로 거른다. 안 지켜진 것들은 **아무도 안 본다.**

> **결론: 규약은 문서에 적혀서 지켜지는 것이 아니라, 코드가 읽어야 지켜진다.**

## §5 ★`§0-E` 는 기준이 아니라 **목록**이다

어제(2026-09-21) 내가 신설한 `§0-E. raw 파일의 표기 관례` 는 이렇게 시작한다 —

> *"관례가 **여러 벌 공존**하는데 그것이 어디에도 한꺼번에 적혀 있지 않은 것이 원인이다.
> 여기에 모은다."*
> *"⚠**새 형식을 발견하면 이 표에 더한다.**"*

그리고 표의 칸 이름이 **"쓰이는 형식(전부)"** 이다.

★**이것은 처방(prescription)이 아니라 기술(description)이다.** "이렇게 적어라"가 아니라
"이런 것들이 있으니 도구가 전부 받아 줘라"다. 급한 불로는 옳았지만 —

- **여러 벌 공존을 공식화한다.** 새 형식이 생기면 표에 한 줄이 늘 뿐, 데이터는 안 고친다.
- 그래서 **모든 도구가 모든 형식을 알아야 한다.** 도구가 94개다.
- 하나라도 빠뜨리면 그 도구가 조용히 틀린다 — 어제 L-305 가 정확히 그랬다
  (`--refresh` 가 평문 머리를 몰라 머리줄 21줄을 지웠다).

## §6 그래서 원인을 다시 쓴다 (01 문서 §3 정정)

01 문서는 이렇게 적었다 — *"기준을 적어 둔 곳이 없어서 도구마다 자기 기준을 만들었다."*
**절반만 맞다.** 정확히는 —

```
①기준은 2026-07-14 부터 적혀 있었다 (_SCHEMA.md §1 · §0-B)
      ↓
②그런데 **코드가 그것을 읽지 않는다.** 스키마를 강제하는 검증이 없다
      ↓
③그래서 수집 도구가 자기 형식으로 썼고(_meta.json 125키), 아무도 안 막았다
      ↓
④문서는 현실을 뒤쫓아 절을 덧붙였다 (53절 중 22절에 날짜가 박혀 있다)
      ↓
⑤어제는 아예 **공존을 목록화**했다 (§0-E "쓰이는 형식(전부)")
      ↓
⑥이제 도구 94개가 형식 여러 벌을 전부 알아야 한다 → 하나 빠뜨리면 조용히 틀린다
      ↓
⑦"라운드마다 문제가 터진다"
```

**핵심 한 줄** —
> 문제는 기준이 없는 것이 아니라, **기준을 강제하는 코드가 없다**는 것이다.
> 지켜진 규약 둘(폴더·status)은 **코드가 읽기 때문에** 지켜졌다.

## §7 다음 단계의 성격이 정해졌다

이 대조 전에는 ②단계가 *"기준을 새로 쓴다"* 인 줄 알았다. **아니다.**

| 해야 할 것 | 아닌 것 |
|---|---|
| 적힌 기준 중 **살릴 것 / 버릴 것 / 고칠 것**을 가른다 | 백지에서 새로 쓴다 |
| 기준마다 **그것을 읽는 코드**를 하나씩 붙인다 (없으면 그 기준은 죽는다) | 문서에 절을 더 붙인다 |
| `§0-E` 를 **목록 → 처방**으로 바꾼다 — 정본 형식 하나를 정하고 나머지는 **변환**한다 | 새 형식을 발견할 때마다 표에 한 줄 더한다 |
| `_meta.json` 을 **단일 기록자**로 모은다 (지금 94개가 쓴다) | 도구마다 키 이름을 맞추라고 당부한다 |
| 기준을 바꾸면 **과거 숫자 환산표**를 같이 낸다 | 새 자로 잰 값을 그냥 새 기준선으로 박는다 |

**남은 확인 두 가지**

1. 마디⑤⑥(챗봇 답변 표현 · 관리자 AI 탭)을 같은 깊이로 아직 못 쟀다.
2. `_CHATBOT.md`(93KB) 도 같은 대조를 해야 한다 — 이 문서는 `_SCHEMA.md` 만 봤다.
