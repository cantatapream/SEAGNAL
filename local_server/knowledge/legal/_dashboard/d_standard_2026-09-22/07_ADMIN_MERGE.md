## §2 그래서 "합친다"는 무슨 뜻인가

**처음부터 만드는 것이 아니다. 이미 있는 것을 쓰게 하고, 뼈대만 새로 만든다.**

```
지금                               합친 뒤
─────────────────────            ─────────────────────
draftCardHTML      (13줄)         ┌─ cardShell()  ← 새로 만드는 유일한 것
feedbackCardHTML   (18줄)         │    머리(제목·배지·날짜)
candidateCardHTML  (16줄)         │    본문  ← 종류마다 다른 부분만 넣는다
mokCardHTML        (32줄)         │    꼬리(승인/반려 버튼)
reviewCardHTML     (54줄)         └────────────────────
freshnessCardHTML  (63줄)              ↑
amendmentCardHTML  (90줄)         7개 생성기는 **본문만** 만든다
                                  (13~90줄 → 5~40줄로 줄어든다)
bindDecideCard  ← 2개만 씀         bindDecideCard ← 7개가 다 쓴다
```

### 3단계로 한다 — 한 번에 하나씩, 눈으로 확인하며

| 단계 | 하는 일 | 위험 |
|---|---|---|
| **1** | `cardShell(머리, 본문, 버튼)` 을 만들고 **가장 단순한 `draftCardHTML`(13줄) 하나만** 옮긴다 | 낮음 — 틀려도 초안승인 탭 하나 |
| **2** | 판정 길을 하나로 — **5개를 `bindDecideCard` 로 옮긴다.** 탭 하나 옮길 때마다 눈으로 확인 | 중간 — 승인 버튼이 실제로 도는지 봐야 한다 |
| **3** | 나머지 6개 생성기를 `cardShell` 로 옮긴다. **큰 것(`amendmentCardHTML` 90줄)은 맨 마지막** | 중간 |

**★어느 단계에서 멈춰도 화면은 돈다.** 옮긴 것과 안 옮긴 것이 섞여 있어도 동작에 문제가 없다.

### 합치고 나면 무엇이 달라지나

| | 지금 | 합친 뒤 |
|---|---|---|
| "승인 버튼 옆에 근거 조문 링크를 달자" | **7군데** 고친다 | **1군데** |
| 새 대기함(8번째)을 붙인다 | 카드 HTML 을 처음부터 쓴다 | **본문만** 쓴다 |
| 화면 모양이 탭마다 다르다 | 그렇다 (공유 클래스 1/29) | 머리·버튼이 같아진다 |

### 덤으로 고칠 것

- 코드 주석이 **"5개 서브탭"** 이라 적혀 있다 — 실제 7개
- `_SCHEMA.md §6-D` 가 이 화면을 **"미구축"** 이라 적고 있다 — 2026-08-01 이후 갱신 없음
