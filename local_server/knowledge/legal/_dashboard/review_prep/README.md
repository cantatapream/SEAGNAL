# review_prep — 검수 큐 314건 예습 원자료

## 이게 뭔가

관리자 화면의 승인 대기열(`_dashboard/review_queue.md`)에 쌓인 314줄을, 사람이 하나씩
누르기 전에 **미리 읽어 둔 결과**다. 읽기 전용 에이전트 8개가 각각 40건(마지막 34건)을 맡아
큐 항목마다 대상 위키 페이지와 근거 원문(`raw/`)을 직접 열어 확인했다.
이 단계에서는 저장소 파일을 하나도 고치지 않았고, 승인·반려도 하지 않았다.

## 파일

| 파일 | 내용 |
|---|---|
| `prep0.json` ~ `prep7.json` | 에이전트 8개의 출력. 큐 항목 1건 = JSON 1개. |
| `prep5_extra.json` | 4건(원산지표시법-803 · 음주운항_측정거부-901 · 해양레저관광진흥법-4 · 해양수산생명자원의확보…-907)을 오케스트레이터가 에이전트와 별개로 직접 확인한 것. 나중에 도착한 에이전트 결과와 대조해 결론이 같음을 확인했고, `해양레저관광진흥법-4`만 갈래 판정이 갈렸다(에이전트: 사실확인 / 오케스트레이터: 방침결정). |
| `assemble.py` | 위 JSON을 사람이 읽는 문서 하나로 묶는 스크립트. |

## 항목 하나의 구조

| 키 | 뜻 |
|---|---|
| `id` | 큐 항목 ID |
| `kind` | `사실확인형`(원문이 답을 정함) / `방침결정형`(사람이 골라야 함) / `수집공백형`(자료 자체가 없음) |
| `checked` | 원문을 실제로 열어 확인했나 |
| `still_live` | `false` 면 이미 해소됐는데 큐에만 "대기"로 남은 것 |
| `plain` | 비개발자용 한 줄 설명 |
| `answer` | 사실확인형에서 원문 대조로 나온 답 |
| `options`·`recommend` | 방침결정형의 선택지와 추천 |
| `evidence` | 직접 확인한 파일·행 위치 |
| `note` | 확인 못 한 것·한계를 정직하게 적은 자리 |

## 다시 만들려면

```
python3 local_server/knowledge/legal/_dashboard/review_prep/assemble.py \
  > local_server/knowledge/legal/_dashboard/REVIEW_DECISION_DOC.md
```

## 한계

- `answer`·`still_live` 는 대부분 **에이전트 보고**다. 오케스트레이터가 직접 다시 확인한 것은
  결과 문서 「가장 먼저 볼 것」 5건과 표본 몇 건뿐이며, 어디까지 확인했는지는 그 문서에 적어 뒀다.
- 에이전트가 스스로 "확인 못 했다"고 밝힌 것은 지우지 않고 `note` 에 그대로 뒀다.
