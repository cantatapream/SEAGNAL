# 27차 라운드 — 실제 챗봇에 물어본 검증 (2026-09-07, 미완)

## 이 폴더가 무엇인가

지금까지의 "감사"는 **위키 문서를 법 원문과 대조**하는 일이었다. 이 라운드는 다르다 —
**운영 중인 챗봇(`https://seagnal-server.fly.dev/api/legal/ask`)에 골든 질문을 실제로 던져,
사용자가 받는 답에 기대한 근거 조문이 실제로 실리는지** 잰다.

왜 필요한가는 `_LESSONS.md` L-112 에 있다. 2026-08-18 실측에서 감사관이 "답변 가능(full)"으로
채점한 논점을 실제 챗봇에 물었더니 **검증된 58법 중 30법(52%)이 근거를 못 댔다.** 감사관은
위키 파일 전체를 읽지만 챗봇은 개념 페이지의 `## 근거 조문` 표에서만 근거를 만들기 때문이다.
그 격차를 다시 재는 것이 이 라운드다.

## 채점 방법

AI 를 채점자로 쓰지 않는다(L-133: 채점자가 AI 면 라운드 간 42% 가 뒤집힌다). **문자열 대조만** 한다.

| 판정 | 뜻 |
|---|---|
| `confirmed` | 기대한 근거(조문·별표·별지·부칙)를 **전부** 댔다 |
| `partial` | 기대한 근거 여러 개 중 **일부만** 댔다 — 답이 불완전할 수 있는 자리 |
| `wrong_article` | 법은 맞는데 기대한 조문·별표를 하나도 안 댔다 |
| `no_evidence` | 기대한 법이 근거줄에 아예 없다 |
| `clarify` | 되묻기만 하고 답을 주지 않았다(최대 5회 왕복 뒤에도) |
| `skipped` | **잴 수 없었다** — 서버가 "AI 사용 한도 소진"이라고 알려 온 것. 감점하지 않는다 |

⚠**층(법률/시행령/시행규칙)으로는 채점하지 않는다.** 한때 "법 제37조 vs 시행규칙 제37조는
다른 조문"이라며 층을 따로 셌는데, 확인해 보니 골든 문항의 `expect_law` 칸은 대개
**부모 법 이름(묶음 열쇠)** 이지 층 정보가 아니었다. 예를 들어 「농수산물품질관리법 | 별표4」는
그 **법률 자체에 별표가 0개**이고(직접 셈) 별표4 는 시행규칙에 있으며 내용도 질문과 맞는다
("가. 거짓이나 그 밖의 부정한 방법 → 지정 취소"). 즉 챗봇이 옳고 라벨이 부정확했다.
층으로 감점하면 **챗봇이 맞은 것을 틀렸다고 세게 된다.**

`skipped` 를 따로 둔 이유는 L-263 에 있다. 처음엔 이걸 `no_evidence` 로 감점해 통과율을
26% 로 잘못 계산했다.

## 이 자가 재지 못하는 것

- **답변 문장의 사실 정확성은 안 잰다.** "근거가 닿는가"만 본다.
- 되묻기는 최대 5회까지만 자동으로 이어간다.
- 골든 문항의 기대 근거는 **사람이 미리 적어 둔 라벨**이다. 챗봇이 다른 조문을 댔다고 해서
  자동으로 챗봇이 틀린 것은 아니다 — 라벨 쪽이 틀렸을 수도 있다(표본에서 실제로 그런 사례가 있었다).
  판정이 갈린 문항은 사람이 원문을 봐야 결론이 난다.

## 결과 (미완 — 291문항 중 133문항만 잼)

| 판정 | 건수 | 비율 |
|---|---|---|
| confirmed | 70 | 52.6% |
| partial | 9 | 6.8% |
| wrong_article | 5 | 3.8% |
| no_evidence | 39 | 29.3% |
| clarify | 10 | 7.5% |

`confirmed + partial` = **59.4%** 가 기대한 근거를 적어도 일부는 댔다.

`no_evidence` 39건의 갈래:
- **A. 엉뚱한 법으로 자신 있게 답함 — 13건.** 사용자가 틀린 법의 절차를 안내받는다.
  예: "허가증을 잃어버리면 어떻게 재발급받나요?"(해적피해예방법 제10조를 기대) →
  챗봇이 **수산업법 시행규칙 제59조**의 어업허가증 재발급 절차를 안내했다.
  ⚠다만 질문 자체가 법을 특정하지 않아 생긴 경우가 섞여 있다. 어느 쪽이 옳은지는 문항별 확인이 필요하다.
- **B. "모르겠다"고 멈춤 — 23건.** *"말씀하신 표현이 무엇을 뜻하는지 끝내 확인하지 못해,
  지어내지 않고 여기서 멈춥니다."* 답은 못 줬지만 지어내지 않은 안전한 실패다.
- C. 그 밖 — 3건.

`partial` 9건은 **법 조문은 맞게 댔는데 하위 법령이 빠진** 경우가 많다. 예: "시정명령을 안 지키면
얼마?"에 법 제90조제2항제1호는 댔으나 **과태료 금액이 적힌 시행령 별표2**를 못 댔다 —
근거는 맞는데 사용자가 알고 싶은 숫자가 빠진다.

## 왜 미완인가

서버의 Gemini API 키가 **1개뿐**이고(코드 확인: `GEMINI_API_KEY_26_8` 하나), 그 한도를 다 썼다.
1갈래로 천천히 돌려도 다시 막혀, **일일 한도**로 보인다. 남은 **158문항은 한도가 회복된 뒤**
1갈래로 이어서 재면 된다 — `run.py` 는 이미 잰 문항을 건너뛴다.

```
python3 _dashboard/live27/run.py 0 291 <결과파일.jsonl>
python3 _dashboard/live27/rescore.py <결과파일.jsonl>
```

`run.py` 는 한도 표시가 3연속 나오면 스스로 멈춘다(L-263).

## 오늘 이 라운드에서 배운 것

두 가지 실수를 했고 둘 다 **재는 도구가 재는 대상을 망가뜨린** 경우다.
- `L-262` 호출 **방식**이 앱과 달라 "챗봇 무한 되묻기"로 오인했다(실제로는 내 잘못).
- `L-263` 호출 **속도**가 과해 서버의 AI 한도를 소진하고, 그 실패를 챗봇의 실력으로 채점했다.

## 파일

- `results.json` — 문항별 결과(질문·기대근거·챗봇이 낸 근거줄·답변 앞부분·판정)
- `run.py` — 질문을 던지고 응답을 모으는 도구
- `rescore.py` — 서버를 다시 부르지 않고 채점 규칙만 고쳐 다시 매기는 도구
