## 6. 방법론 메모 (다음 라운드 참고)

1. **이 그룹에서 (c)uncollected는 34건 중 1건(2.9%)뿐이었다.** 나머지 33건은 재수집으로 해결되지 않는 (a)/(b)이거나 이미 해소된 것 — collection_hole 백로그를 "재수집 대기열"로 보면 실제 작업량을 크게 과대추정하게 된다.
2. **"소실됐다(=재수집하면 나온다)"와 "원본에 애초부터 없다"는 정반대 결론인데 표기가 비슷해 오래 방치된다.** 연안사고 좌표 건이 18R에서 원인 자체가 뒤집혔는데도 허브 페이지는 4라운드째 옛 문장을 유지 중 — **hole의 원인 재분류가 일어나면 그 hole을 언급하는 모든 페이지를 함께 갱신해야 한다**(§2 wiki_sync).
3. **감사가 (c)로 적어둔 항목이라도 "law.go.kr에 실제로 있다"는 실측 근거가 붙어 있는지 확인해야 한다** — 항만운송 부산항 세칙은 6라운드 연속 (c)로 기록됐지만 근거는 `ls`로 raw에 없음을 확인한 것뿐이었다. "우리한테 없다"는 "저쪽에 있다"를 뜻하지 않는다.
4. **API 차단 상황에서도 raw 폴더 자기기록이 상당히 유용했다** — 선박법 `선박톤수측정요령.txt` 151행처럼 수집 당시 flSeq·공란 여부를 raw 파일 안에 남겨둔 관행 덕분에 API 없이도 (c) 판정을 확증할 수 있었다. 이 관행은 유지할 가치가 있다.
