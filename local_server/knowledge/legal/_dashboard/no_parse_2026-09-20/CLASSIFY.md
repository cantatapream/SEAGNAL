# "칸을 못 읽음"(no_parse) 125건 전수 분류 — 2026-09-20

> HANDOFF §6 "0. 지금 이 순서대로" **E-3** 항목. 지시는 *"표본 20건 먼저 진짜 결함/오탐 분류"* 였으나,
> 판정을 코드로 돌릴 수 있어 **125건 전수**를 분류하고 그중 8건을 손으로 검산했다.
> 원자료: `no_parse_classified.json` (줄마다 쪽·법령칸·조문칸·tier·baseLaw 전문 수록, 잘리지 않음).

## 판정 기준은 어디서 왔나
이 숫자를 내는 것은 `_dashboard/loop/link_ready.js`(게이트 V5-8)이고, 조건은 한 줄이다 —
`A.parseArticleRef(row.article, tier, law)` 가 falsy이면 `no_parse`.
분류도 **그 생산 함수와 `R.articleEnumTokens` 를 그대로 불러서** 했다(판정을 재구현하지 않는다 — L-136).

측정 명령(상시 검사가 부르는 방식 그대로 — L-293):
```
node local_server/knowledge/legal/_dashboard/loop/link_ready.js \
  --base local_server/knowledge/legal/_dashboard/loop/pinned/link_ready_base.json
```

## 손 검산 8건에서 드러난 것 (이 분류 자체의 결함)
처음엔 A 를 71건 한 덩어리로 세었다. 표본을 열어 보니 **갯벌생태해설사 쪽은 tier 가 `notice`(고시)인데
조문 칸이 `시행령 제18조제2항 위임`** 이었다 — 고시에서 제18조를 열면 **엉뚱한 문서의 조**가 열린다.
즉 파서가 거절하는 것이 옳다. 그래서 A 를 A1(58)·A2(13)로 갈랐다.
**표본을 안 열었으면 "진짜 결함 71건"이라고 13건 부풀려 보고했을 것이다.**

## 고치는 방향 (제안 — 착수 전 사용자 확인 대상)
- **A1 58건** — 한 칸에 몰아 적은 것을 **의무 1개 = 조 1개**로 행을 쪼갠다(L-168 ①). ⚠행을 쪼개면
  **남는 쪽도 새 행**이므로 시행일 칸을 다시 뽑아야 한다(L-268).
- **D 28건** — raw 의 별표 목록과 대조해 번호를 채운다. 그 법에 별표가 하나뿐이면 `별표1` 로,
  여럿이면 위키 본문이 실제로 인용한 별표를 찾아 특정한다.
- **A2 13건** — 조문 칸에서 위임 근거를 빼고 **그 문서 자신의 조**를 적는다(또는 조가 없으면 비운다).
- **E 4건** — 부칙은 파서 소관 밖이다. 고칠 것은 위키가 아니라 **도구**(L-193 이 이미 지적).
- **C·F 19건** — 손대지 않는다. 조가 아닌 것을 조처럼 적게 만들면 더 나빠진다.

## 이 분류가 못 보는 것
- "챗봇이 이 줄로 원문을 못 연다"까지만 본다. **그 줄의 내용이 맞는지는 안 본다.**
- A1 을 고치면 V5-8 의 `no_parse` 는 줄지만 `no_article`(그 파일에 그 조 없음, 현재 10)이
  늘 수 있다 — 쪼갠 조가 실제로 그 파일에 있는지는 별개 축이다.
