## method_notes (감사 방법론 관련 소견)

1. **총 문항 150개(회귀 108 + 신규 42)**, 사용자가 요청한 "총 300문항" 목표에는 여전히 못 미친다 — 3R(131문항) 대비는 증가했으나, 이번 라운드도 회귀 확인(3R 비-full 108문항 전수)을 최우선으로 삼고 신규 질문은 "원문은 확보됐는데 위키 미반영"이라는 이번에 새로 발견한 문제 유형 위주로 압축했다. 300문항 규모로 채우려면 조문 단위(법률 20개조·시행령 6개조·시행규칙 3개조·행정규칙 3건)를 더 잘게 쪼개 T1~T7 유형을 기계적으로 적용하는 후속 작업이 여전히 필요하다.
2. **"3R 리포트 커밋 이후 실제 수정 커밋을 diff로 확인"하는 방법이 이번 라운드에서 매우 유효했다** — 3R 리포트가 지적한 구멍 리스트를 그대로 재질문하는 대신, `git diff <3R커밋> HEAD`로 실제 변경분을 먼저 확인하고 그 변경이 질문에 실제로 답이 되는지를 검증하는 방식이 훨씬 정확하고 효율적이었다. 다음 라운드에도 이 방법(리포트 커밋 해시 → diff → 검증)을 권고한다.
3. **"원문 확보됐으나 특정 페이지 미반영" 유형이 처음으로 체계적으로 드러났다** — 이전 라운드들은 "원문 자체가 없다/있다"만 구분했는데, 이번에 보조금관리법·정보공개법·국가배상법 사례에서 "원문은 이미 raw에 있는데 관련 페이지 중 일부만 반영했다"는 제3의 상태를 발견했다. 이는 `_SCHEMA.md` 9절이 정의한 "교차 연결 정합화(lint)" 패스가 필요한 정확한 사례이며, 향후 감사는 판정 기호에 이 상태를 구분하는 것을 고려할 만하다(예: 🔗 lint_pending).
4. **전문가 해석론(T그룹 다수)의 위키 스코프 문제는 4라운드 연속 반복 확인**됐다 — 3R의 권고(위키 운영자가 `_SCHEMA.md`나 `_CHATBOT.md`에 "이 위키는 원문 인용 + 정의사슬까지만 다루고, 법률 해석론은 다루지 않는다"는 스코프를 명문화)를 다시 강조한다. 명문화되면 다음 라운드부터 이 계열을 missing이 아니라 "설계상 범위 밖(na)"으로 판정할 수 있다.
