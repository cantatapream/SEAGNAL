### method_notes (이번 라운드 신규)

1. **git diff가 mtime보다 신뢰도 높은 회귀 검증 근거임을 확인했다.** 이번 라운드는 `git log --oneline -- <파일>`로 7회차 저장 이후 각 concept 페이지의 실제 커밋 이력을 확인해, "손대지 않은 5개 페이지"를 mtime 대조보다 명확하게 확정했다(파일시스템 mtime은 lint 등 무관한 프로세스로도 갱신될 수 있어 부정확할 위험이 있음 — 실제로 `__독도의용수비대지원.md`는 mtime이 07-19 23:51로 갱신됐으나 git diff 결과 실질 내용은 "(편입예정)" 태그 추가뿐이었다. mtime만 봤다면 "내용 변경"으로 오판할 뻔했다). **다음 라운드부터 회귀 검증 시 git log/git diff를 표준 절차로 채택할 것을 권고.**
2. **★준용·인용 조문 배선 시 "인용대상 법의 raw 존재"를 짝지어 확인해야 한다**(E86 발견, 4절 참조). 이번 라운드에서 처음 드러난 방법론적 교훈.
3. **완전 배선 vs 부분 배선을 구분해야 한다.** 이번 자연유산법 벌칙 배선은 "대표 위반유형"만 위반시처벌표에 매핑했고, 조문 자체(제66~70조 전문)는 다 인용했으나 모든 개별 호를 "위반시처벌" 표에 매핑하진 않았다(E68). 벌칙체계표(조문 원문 인용)와 위반시처벌표(사용자 시나리오 매핑)는 별개 완성도로 추적해야 정확하다.
4. **다음 라운드 우선순위 제안**: ① 제22조(행정명령 원문)·제61조(손실보상)·제62조(권한위임 원문)·제64조(청문) 4개 조문 배선(W88·E101·E90·E89 해소) ② 문화유산법 제90·90의2·91~98조 개별 내용 확보(양벌 REVIEW 정밀화, E104) ③ 매장유산법 raw 자체 수집 시도(E86, 수집가능/곤란 판정부터) ④ E68 완전 매핑표(제67·68조 잔여 호) 보강 ⑤ 서식 다운로드 원본 확보(E93, SCHEMA 0-A 서식규칙 완결).

## 7. 결론

이번 라운드(재감사 7라운드, 통산 8회차)는 **4라운드에 걸쳐 최우선으로 지정됐던 과제(자연유산법 벌칙 배선, L49 정정)가 마침내 이행됐음을 확인**했다. git diff로 확정한 실제 변경분(concept 페이지 2개 중 1개가 대규모 개정)을 근거로 직접 연동된 40개 항목을 재검증한 결과 18개가 완전 해소(missing/thin→full), 5개가 부분개선, 1개는 재조사로 더 정확한 판정(collection_hole)으로 재분류됐다.

동시에 이번 라운드는 **배선의 "완전성"에 관한 새로운 발견**을 했다: ①대표 사례만 매핑된 부분배선(E68)과 ②준용조문은 배선했으나 피인용 법 자체가 raw에 없는 경우(E86, 매장유산법)를 구분해 다음 우선순위로 남겼다. 이는 "raw 있음·wiki 미배선"이라는 이전 라운드들의 문제의식이 이제 "배선의 완전성(부분 vs 전체)"이라는 더 세밀한 단계로 넘어갔음을 보여준다.

**다음 라운드 우선순위**: ① 제22·61·62·64조 4개 조문 배선 ② 문화유산법 양벌 REVIEW 정밀화(제90~98조 개별 내용) ③ 매장유산법 raw 수집 가능성 판정 ④ E68 완전 매핑표 보강 ⑤ 서식 다운로드 원본 확보 ⑥ 회귀검증 표준절차로 git diff 채택(method_notes #1).
