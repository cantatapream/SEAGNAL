# 항만운송사업법 — 위키 품질감사 9라운드 (2026-07-26, 약점집중+3페르소나)

## 0. 방법론 — 9R가 실제로 한 일

지시대로 8R 리포트(직전 감사, 2026-07-20/21 작성)를 정독하고, **8R의 thin/missing/hole 전부를 재질문**하되
**8R full은 재질문하지 않는다.** 다만 이번 라운드는 8R 저장 이후 **`git log`로 확인되는 대규모 사후
remediation 커밋(2026-07-21, "8R gap remediation"·"Stage C 재빌드")**이 존재해, 8R이 스스로 "다음 라운드
최우선"으로 미룬 항목 대부분이 **8R 리포트 저장 직후 곧바로 반영**돼 있었다(7R→8R 때와 같은 패턴이
반복됨 — 리포트 권고→즉시 반영→다음 라운드 검증). 그래서 9R은:

1. **git log + grep(`still_missing`·`📛`·`REVIEW`·`처리기간`·`유효기간`·`연해구역` 등)로 현재 wiki 7페이지
   전체의 "진짜 아직 열려있는 gap" 목록을 원문 재대조로 재수집**했다(마커 기반 전수조사 — 267건의 개별
   ID를 일일이 재입력하는 대신, 현재 wiki에 실제로 남아있는 마커를 전수 검사해 "지금 시점 진짜 미해결"을
   확정하는 방식으로 전환. 이유: 8R 자신도 "7R 회귀분은 git diff로 무변경만 확인하고 재기술 생략"이라고
   밝혔듯, 오래된 개별 ID 재타이핑보다 **현재 wiki 원문의 마커 전수조사가 더 정확**하다).
2. 그 목록에 대해 **3페르소나 재질문**(회귀 확인)을 수행했다.
3. **새로 발견된 raw 자료**(「항만운송업무 처리지침」 제3~15조 세부, 「부두운영회사 성과평가 업무지침」
   세부, 9개 항만세칙의 비공개 OCR 이미지 5건, 나머지 서식)를 기반으로 **신규 질문**을 추가했다.

## 7. method_notes (답변방식 미흡 근거)

1. **프로필조건 weak 소지**: 하역업·검수업·항만운송관련사업·항만종합서비스업 4개 사업유형의 "급지"
   목록이 서로 다른데(§3-F 참조), 각 페이지에 경고 문구만 반복 서술되고 `wiki/comparisons/` 통합
   허브가 없다. 사용자가 "OO항이 몇 급지?"를 물으면 먼저 "어느 사업이세요?"를 되물어야 하는데, 이
   되물음 로직 자체는 챗봇 엔진(Phase E) 몫이라 지금 단계 결함은 아니나, 위키 구조상 비교표 허브를
   만들어두면 프로필 필터가 더 빠르게 답할 수 있다(제언).
2. **부두운영회사 OCR 수치의 draft-노출 리스크**: `answerCanonicalOnly` 스위치가 켜지기 전까지는
   draft 페이지의 미검증 OCR 수치(TOC 성과평가 배점·인센티브 금액)도 검색 결과에 노출될 수 있다.
   이는 위키 구조 문제가 아니라 **운영설정(스위치 ON 시점) 문제**이므로 method_notes로만 기록.
3. **검수사등·사업등록 두 페이지의 "재발급 절차 없음"(G4·G21)**: 완전히 동일한 법령 공백(등록증·
   자격증·수첩 모두 재발급 조문 없음)이 3개 문서 유형에 걸쳐 반복된다. 이는 위키 오류가 아니라
   원문 자체의 공백이지만, 실무상 매우 자주 나올 질문(분실 신고)이라 "관할 지방해양수산청·시·도
   민원실에 문의(일반 행정절차상 재발급이 실무상 이뤄지는 것으로 추정되나 근거조문 없음)"라는
   안내문이라도 표준화해 3페이지에 공통 추가하면 사용자 경험이 개선될 것(제언, 결함은 아님).
