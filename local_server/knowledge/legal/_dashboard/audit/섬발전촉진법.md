### 1-2. 스키마 대조 판정

`_SCHEMA.md` §5(이원화 정제 — grounding 기준)의 문언: "AI 승급 가능(grounding OK) = 처벌 조문·수치가 있어도 그 값이 raw 원문과 grep로 EXACT 일치하는 인용이면 기계검증 가능 → AI가 draft→canonical 승급" / "사람 승인 필수 = ①별표 스캔 이미지·OCR 박스표에서 읽은 수치 ②AI가 원문에 없는 것을 추론한 처벌 매핑·법리 판단·유권해석·판례·입법연혁."

3건 모두 이 기준을 **통과하지 못한다**:
- ①·②는 문언 그대로 "AI가 원문에 없는 것을 추론한 법리 판단"(②는 페이지 스스로 이를 인정).
- ③은 애초에 원문에 해당 값 자체가 없어 "EXACT 일치 검증"이 성립할 수 없다(검증 불가능한 값 = grounding 실패).

또한 §5 상단 H-12② 원칙("처벌·안전값·⚠REVIEW를 **포함하는** 페이지는 반드시 관리자 검증 UI 승인 후에만 canonical. AI가 임의 승격 금지")과도 정면으로 충돌한다 — 이 페이지는 REVIEW를 3건이나 포함한 채 `status: canonical`이다.

**결론: 이것은 스키마 위반이다.** `promote_섬발전촉진법.done`(13:38) 마커가 찍힌 시점에 이 3개 REVIEW를 사람이 승인했다는 기록(승인 로그·관리자 승인 UI 흔적)이 어디에도 없다 — 변경이력에도 "AI 재검증 승급(원문 grounding)"이라며 **법률.txt·시행령.txt의 무관한 다른 두 문장**(제2조① 정의 원문, 시행령 제2조 "10년" 문언)만 EXACT 대조하고, 정작 문제의 3개 REVIEW는 언급조차 하지 않은 채 canonical로 승급됐다. 즉 자동화 파이프라인이 "일부 문장의 grounding 성공"을 "페이지 전체의 grounding 성공"으로 오인해 승급시킨 것으로 판단된다.

**권고(직접 되돌리지 않음, 관리자 확인 요망)**: `wiki/concepts/섬발전촉진법__개발대상섬지정.md`의 `status`를 `canonical`에서 `draft`로 환원 필요. 대안으로, 위 3건 REVIEW를 관리자가 실제로 검토·승인하거나(①②는 법리 해석이므로 "관리자가 그렇게 해석하기로 확정"하는 결정이 필요, ③은 raw에 없는 값이므로 **삭제하거나** 실제 출처(law.go.kr 소관부서 검색 등)를 찾아 재기입) 해소한 뒤에만 canonical 유지가 정당하다. `_CHATBOT.md` §3의 "canonical 필터"가 켜지면(`answerCanonicalOnly=ON`) 이 페이지의 부속섬·무인도 해석과 미검증 전화번호가 **그대로 사용자에게 인용**되는 구조이므로 실사용 리스크가 실재한다.

## 11. 결론

r8의 핵심은 두 가지다.

**(1) fix_r8이 이 법의 절차적 잔여 공백(위원회·실무위·진흥원·사업시행자·사업계획)을 대량으로 메웠다** — r5부터 3라운드 연속 "wiki_gap"으로 지적된 6개 항목 중 사실상 5개가 이번에 해소 수준까지 도달했다(재질문 132문항 중 43문항이 새로 full로 격상, 3-D 추정 포함 시 최대 53문항). 이는 이 시리즈 감사 중 가장 큰 개선폭이다.

**(2) 그러나 이 법의 canonical 페이지 2개가 스키마를 위반한 상태로 방치돼 있다** — `섬발전촉진법__개발대상섬지정.md`·`__교통편의증진지원.md`가 "AI가 원문에 없는 것을 추론한 법리 판단"(제주 부속섬 반대해석, 무인도 0명 해석, 선박안전법 적용여부)과 "원문에 근거가 아예 없는 미검증 값"(전화번호)을 포함한 채 사람 승인 없이 `canonical`로 승급됐다. 이는 `_SCHEMA.md` §5(H-12②)를 정면으로 위반하며, `_CHATBOT.md`의 canonical 필터가 켜질 경우 미검증·미확정 내용이 그대로 사용자에게 인용될 실사용 리스크가 있다. **draft 환원 및 관리자 검토를 최우선 권고한다.**
