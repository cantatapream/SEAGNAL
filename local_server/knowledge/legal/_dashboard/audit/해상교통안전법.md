### method_notes (10R 신규 발견/확인 사례)

1. **위키 자체 진화로 회귀 논점 3건이 감사 전 이미 해소됨을 확인**했다 — RG10(아포스티유 발급기관, wiki_lag 완전해소)·RG36(정부대행기관 실제 지정목록, H-26 collection_hole(b) 정식 재분류+graceful 안내)·해상항법충돌예방의 「선박설비기준」 신규 반영(2026-07-27자, 기적·등화·형상물 규격). 이는 이번 감사가 발견한 신규 결함이 아니라 감사 시점 사이 사서 작업의 정상적 결과이므로, "10R이 새로 고쳤다"고 오기하지 않고 "확인만 했다"로 정직하게 구분했다(카파시 원칙).
2. **H-26 collection_hole 3분류(a/b/c) 태깅을 이번 라운드에 전량 완료**했다 — RG7(우수사업자 위임고시)=genuine(a), RG11(스쿠버강습업체 종목목록)=uncollected(c), RG36(정부대행기관 지정목록)=structural(b). 이전 라운드까지는 이 구분이 일부만 태깅돼 있었다.
3. **scope_out_answered_gracefully 3건 확정**(RG3·RG59·RG60) — 9R까지 단순 "scope_out"으로만 표기됐던 항목들이 실제로 위키 본문에 명시적 소관부서·연락처 안내 문구를 갖추고 있음을 확인했다(H-26 §6-B 기준 적용).
4. **`선박설비기준` OCR 수치 신규 반영분은 review_pending 성격**으로 별도 관리 필요 — 기적 주파수·음압, 마스트등 간격, 형상물 치수 등은 처벌·안전 직결 수치이면서 원문 이미지 OCR 기반이라, `_SCHEMA.md` §5 이원화 기준상 사람 검증 없이는 canonical 인용 근거로 쓸 수 없다. 페이지 자체는 canonical 상태이나 이 절만 실질적으로 draft 성격이 혼재돼 있어 — **다음 라운드 권고: 이 절만 별도 REVIEW 마커로 분리**해 canonical 필터가 페이지 전체가 아니라 이 문단만 걸러내도록 정비할 필요(H-26 인라인 마커 원칙 적용 대상).
5. **draft 상태 페이지 리스크는 9R과 동일하게 유지**: 23개 페이지 중 `정의및적용범위`·`벌칙과태료체계`·`해사안전우수사업자지정`·`해상교통장애수중레저`·`항행장애물처리` 5개가 여전히 `status: draft`(L-15 REVIEW 잔존). canonical 필터 가동 시 이 5개 페이지는 답변 근거에서 제외될 수 있음 — 콘텐츠 정확성과 별개로 서비스 노출 리스크가 계속 남아 있다.
