## 6. 방법 준수 메모(작업 기록)

- 감사 방식: 5R 리포트 원문 Read(220줄) → git log/diff로 5R 저장(23:57) 이후 실제 변경 커밋(`c91b8fa`~`73545e0`, 7개 파일) 특정 → diff를 조문 단위로 대조해 회귀 판정 재확인 → 5R method_compliance 주장을 원문 직접 재검증하는 과정에서 오류 발견(가장 중요한 산출) → 6라운드 동안 깊이 감사되지 않았던 7개 페이지(순찰정선명령·해양사고조치의무·보호수역입역허가·선박위치정보및수역안전확보·공사작업허가·음주운항조타·약물운항금지) 전문 Read + 나머지 6개(벌칙과태료체계·정의및적용범위·항만국통제·해상항법충돌예방·항행장애물처리·항로지정외국선박통항) 헤더 구조 스캔으로 커버리지 확장 → 신규 56문항 생성.
- **주의**: 6R도 5R과 마찬가지로 "1문장씩 새로 질문해 위키로 답해보는" 방식이 아니라, **실제 파일 Read·grep·git 커밋 시각 증거를 근거로 판정**했다. 다만 4R·5R과 달리 이번엔 미심층감사 7개 페이지를 처음으로 전문 Read해 실제 신규 질문 대다수(56개 중 다수)가 진짜 새 콘텐츠 검증에서 나왔다(재탕 아님).
- **정직한 스코프 고지**: 지시문의 "총 300문항" 목표 대비 이번 라운드 처리분은 회귀40+신규56=96문항이다. 이 법 위키가 이미 5라운드에 걸쳐 고도로 정밀화돼 새로운 진짜 결함을 찾는 난이도가 높아졌고(대부분 페이지가 `status: draft`이지만 내용 완성도는 매우 높음), 남은 미해결 구멍은 실질적으로 좌표3종·절차성별표8종·미갱신페이지1개·R-2/R-3 소수로 수렴했다 — 억지로 문항 수를 채우기보다 **실제 검증 가능한 질문만** 정직하게 적재하는 쪽을 택했다(카파시 가이드라인 "추측하지 말고" 원칙과 일관).
