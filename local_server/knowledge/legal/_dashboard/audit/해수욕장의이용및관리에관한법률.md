## 2. 신규 컴플라이언스 발견 (감사관 직권 확인)

### 2-A. review_reason 잔존 메타 모순 — 8R이 놓친 2건

8R §2-B/§6은 `유해생물관리.md`의 `review_reason` frontmatter(처벌·안전값 포함 — 사람 승인 대기)를 `status: canonical`과의 모순으로 지적·삭제했다. 그러나 **동일한 문제가 두 페이지에 더 남아 있다**(`grep -n review_reason` 재확인):

| 페이지 | 남은 필드 | 실제 본문 | 문제 |
|---|---|---|---|
| `평가위원회및정보시스템.md` | `review_reason: 처벌·안전값 포함 — 사람 승인 대기(H-12② 소급, 2026-07-19)` | "이 조문군(제39~43조)은 행정 절차 규정으로, 벌칙·과태료가 없다" | 본문이 스스로 처벌값 없다고 명시하는데 frontmatter는 "처벌·안전값 포함"이라 모순 |
| `해수욕장기본계획및관리계획.md` | 동일 문구 | "이 조문군(제9~16조)은 ... 벌칙·과태료가 없다" | 동일 모순 |

경미하나 자동화 스크립트가 `review_reason` 필드 존재만으로 draft 취급하는 로직이 있다면 이 2개 canonical 페이지가 부당하게 답변 근거에서 배제될 위험 — 즉시 필드 삭제 권고(내용 변경 불요, `유해생물관리.md`와 동일 조치).

### 2-B. 페이지 단위 draft가 조각 단위 REVIEW를 과잉 차단 (구조적 재확인)

8개 draft 페이지(물놀이구역·이용준수사항·안전관리요원·수질백사장·관리운영위탁·시설사업·이용제한사유·지정해제기준) 전부에서, **원문과 EXACT 일치가 이미 확인된 처벌 조·항·호·금액 표**(변경이력 "AI 재검증 승급(원문 grounding)" 각주로 매 페이지마다 명시됨)까지 페이지 전체가 draft라는 이유로 인용이 막힌다. 예: 물놀이구역 과태료(60/80/100만원), 시설사업 형벌(2년/2천만원, 1년/1천만원) — 스키마 §5 "AI 승급 가능(grounding OK)" 기준을 명백히 충족하는데도, 같은 페이지 안의 별개 문장(예: "협의회는 자문기구로 읽힌다")이 REVIEW라는 이유로 페이지 전체가 draft로 묶여 있다. **결과적으로 나리야가 `answerCanonicalOnly`를 켜면, 이 법에서 실사용 빈도가 가장 높은 질문(물놀이구역 과태료·준수사항 과태료 등)에 답을 못 하게 된다.** 8R도 동일 문제를 지적했으나(§2-B) 이번 라운드는 **영향받는 구체 처벌표를 특정**했다는 점이 다름. 조각(fragment) 단위 승급(예: 처벌표만 별도 canonical 블록으로 분리)을 스키마 개선안으로 건의(직접 구현하지 않음, `_SCHEMA.md` 관리자 결정 사항).

### 2-C. review_pending 재정의 — 라운드 간 용어 불일치 정리

8R은 draft 페이지의 AI-법리추론형 REVIEW를 `review_pending`으로 분류했으나, 이번 라운드 지침의 `review_pending`은 **별표 이미지 OCR 판독값 등 사람이 검증 못 한 수치**만을 가리킨다(2단계 지침 원문). 이 법은 raw 별표 4종이 전부 텍스트 전사이고(`시행령_별표1~4.txt`), 위키 14개 페이지 `grep "⚠REVIEW\|REVIEW —"` 결과 OCR 관련 언급 0건 — **이 법의 review_pending은 구조적으로 0건**이다. 8R의 W8류 항목은 위 §0에서 thin으로 재분류했다(용어 정의 차이일 뿐 실질 문제는 동일하게 §2-B에 남아 있음).
