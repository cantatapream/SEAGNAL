## R22 횡단 감사

> 담당 범위(§6-H): `wiki/_glossary.md` · `wiki/_backbone.md` · `wiki/comparisons/` · `wiki/activities/`. 링크 존재 여부(xref_check.py)는 이미 게이트 통과(0건) — 이 감사는 **내용**(엉뚱한 목적지·구조적 미도달)만 본다.

### 🔴 최우선 발견 — glossary 행 16%가 코드 파서에서 통째로 유실(런타임 결함, 마크다운 문제 아님)

**증상**: `wiki/_glossary.md`는 마크다운으로는 멀쩡하고 `xref_check.py`도 0건(링크 자체는 유효)이지만, 실제 챗봇이 구어를 개념으로 번역하는 코드 `services/legal_retriever.js`의 `loadGlossary()`가 **행을 셀 3개(구어|링크|법령)로 쪼개는 정규식**을 쓴다:

```
line.match(/^\|\s*([^|]+?)\s*\|\s*([^|]+?)\s*\|\s*[^|]*\|\s*$/)
```

이 정규식은 `|`가 정확히 4개(칸 3개)일 때만 매칭된다. 그런데 glossary 표는 위키 관례대로 링크에 표시 라벨을 붙일 때 `[[대상페이지|화면표시라벨]]` 문법(파이프 포함)을 쓴다 — 이 파이프가 행을 3칸이 아니라 5~6칸으로 쪼개버려 **정규식이 통째로 매칭 실패**하고, `loadGlossary()`가 해당 행을 **캐시에서 조용히 빠뜨린다**(에러도 안 남, `try/catch`가 삼킴). 즉 문서엔 있는데 챗봇 코드는 그 존재 자체를 모른다.

**규모**: 데이터 행 397개 중 **63개(15.9%)** 가 `[[대상|라벨]]` 문법을 쓰고, **이 63개 전부**가 파싱 실패로 유실됨(원인이 100% 이것 하나로 수렴 — 라벨 없는 `[[대상]]`행 334개는 전부 정상 로드됨, 직접 재현 확인).

**직접 재현(node로 실제 코드 로직 재실행)**:
```
loadGlossary() 결과: 397행 중 333행만 캐시에 로드됨
"금어기가 뭐예요"      → glossaryExpand 매칭 없음 (glossary 행: "금어기, 금지체장" 유실)
"TAC 얼마나 되나요"    → glossaryExpand 매칭 없음 (glossary 행: "TAC" 유실)
"영해가 몇 해리인가요" → glossaryExpand 매칭 없음 (glossary 행: "12해리, 영해선, 영해 경계" 유실)
"나룻배 타려면"        → glossaryExpand 매칭 없음 (glossary 행: "나룻배" 유실)
"무인도 상륙해도 되나요" → "해도"(엉뚱한 행, 항해용간행물)만 걸림, 정작 "무인도 상륙, 입도" 행은 유실
```

**유실된 63개 구어 표현 예시(실사용 빈도 높은 것 위주)**: 금어기·금지체장, TAC(총허용어획량), 12해리·영해선·영해 경계, 직선기선·저조선·썰물선, 24해리, 200해리 수역, 우리 바다 경계, 무인도, 무인도 상륙·입도, 섬에서 야영·캠핑, 영해기점섬, 나룻배, 유람선(소규모), 바다목, 마리나, 요트장·보트 계류장, 요트 대여·보트 렌트, 보트 정비소, 요트 검사, 국가어항·지방어항, 선착장 자리세, 방파제 낚시 자리 차지, 어항에 폐그물 버림, 뺑소니 배(사고 낸 배 도주), 수상구조법·조난신고 118, 버려진 배·폐선 방치, 바다에 폐타이어·스티로폼 버림, 바닷가(공유수면)·간척, 해도, 조석표·등대표·항로지·항행통보, 관측 부이, 수로측량업체, 항내 어로 금지·항구 낚시, 우선피항선, 뱃사람 임금·보합·비율급, 선장 배 안 지키면, 외국인 선원·선원 상륙증, 밀입국 배 대줌, 외국인 어선원 계절근로, 도서개발 촉진법·지정섬, 섬의 날, KOMSA, 해양심판, 아차사고, 면허정지(해기), 블랙박스·항해기록, 항만재개발, 원형지, 항운노조 생계지원금, 바다 오염시키면 누가 책임지나, 기름유출 배상·유조선, 해사안전법(기본법·교통안전법 구분) 등.

**실제 사용자 영향 완화 요인(과장 방지 차원에서 확인함)**: 검색 ①단계(직접매칭, 본문 grep)가 별도로 있어, "TAC"·"영해"·"무인도"·"나룻배"처럼 그 낱말이 목적지 페이지 본문에도 그대로 실려 있는 경우는 직접매칭으로 우회 구제될 가능성이 있다(예: `수산자원관리법__총허용어획량.md`에 "TAC" 29회 등장 확인). 하지만 glossary가 애초에 존재하는 이유(`_CHATBOT.md` 4절)는 "**정식 명칭이 아닌 말**"을 위한 안전망이라, 완전히 다른 낱말(예: "밀입국 배 대줌"→"선박등의 제공금지", "선장 배 안 지키면"→"재선의무")로 매핑된 행은 본문 직접매칭으로도 우회되지 않을 가능성이 높다 — 이런 행일수록 glossary가 유일한 경로인데 그게 지금 끊겨 있다.

**근본 원인**: `loadGlossary()`가 마크다운 파이프 테이블을 파싱할 때 `[[...]]` 대괄호 내부의 파이프를 "칸 구분자가 아닌 것"으로 인식하지 못한다(정규식이 대괄호 문맥을 모름). `xref_check.py`(링크 검증기)는 이 문제가 없는 걸로 보아 별도의(대괄호를 인식하는) 파서를 쓰는 것으로 추정 — 즉 "링크 유효성 검사 통과"와 "런타임 glossary 로드 성공"이 서로 다른 파서를 거치기 때문에, 21라운드 내내 xref_check만으로는 이 문제가 전혀 드러나지 않았다.

**고치는 법(택1, 코드 소유자 판단 필요 — 이 감사는 진단만, 수정은 범위 밖)**:
  - ⓐ `services/legal_retriever.js`의 `loadGlossary()` 정규식을 `[[...]]` 내부 파이프를 무시하도록 교체(예: 먼저 `[[...]]` 구간을 임시 치환해 파이프를 숨긴 뒤 3칸으로 split, 다시 복원).
  - ⓑ glossary 63행에서 `[[대상|라벨]]` 대신 `[[대상]]`(라벨 없이)으로 통일 — 다만 이러면 화면 표시가 어색해지는 행이 많고(예: "금어기·금지체장·금지체중"처럼 사용자에게 보여줄 자연스러운 이름을 라벨로 쓴 것), 원 설계의도(사람이 읽기 좋은 라벨)를 포기하는 셈이라 ⓐ가 더 낫다.
  - 우선순위: 코드 수정 1줄~수 줄로 63개 행이 한 번에 살아나는 **가성비가 매우 높은 수정**이라, 다음 라운드 착수 항목 1순위로 제안.

### 🟡 발견 2 — "definition-hub" 개념 페이지 2건이 `## 근거 조문` 표 자체가 없어 §6-E 기준 unreachable

`_SCHEMA.md` §6-E는 "근거가 개념 페이지에 있어도 그 페이지의 `## 근거 조문` 표에 행이 없으면 unreachable"이라 규정한다. `kind: definition-hub`로 태그된 개념 페이지 4개 중 2개가 `## 정의 표`만 있고 `## 근거 조문`이 아예 없다:

| 페이지 | status | 문제 |
|---|---|---|
| `concepts/영해및접속수역법__기선영해접속수역정의.md` | draft | glossary 3행("12해리·영해선·영해 경계"/"직선기선·저조선·썰물선"/"24해리")이 직접 가리키는 목적지인데, `## 정의 표`(6-필드, 매우 상세)만 있고 `## 근거 조문`이 없음. 21라운드 동안 REVIEW 3건 해소 등 공들여 관리된 페이지인데 정작 챗봇 인용추출기(`extractCitationChain`, `## 근거 조문` 헤딩만 인식)는 이 페이지에서 빈 배열을 반환. 다만 `statutes/영해및접속수역법.md`에는 같은 내용(12해리·24해리·기선)이 `## 근거 조문 (전체 사슬)` 표로 이미 존재해, 검색이 그 statute 페이지를 함께 잡아주면 우회될 수 있음(§6-E 1번 유형과 정확히 일치하는 패턴 — "개념페이지엔 없고 statutes에만 있음"). |
| `concepts/수산업법__어업정의허브.md` | **canonical** | 「수산업법」은 28개 이상 법이 인용하는 최상위 백본(`_CHATBOT.md`가 "첫 구축 대상"으로 명시한 근간 허브법)인데, 이 정의허브 페이지에 `## 근거 조문` 섹션이 없음(`## 정의 표`만 존재). "어업이 뭔가요"·"어업권이 뭔가요"·"마을어업이 뭔가요" 같은 가장 기초적인 질문의 근거가 이 페이지에서 인용목록으로 추출되지 않음. **canonical 상태라 더 심각** — 검증 완료로 분류돼 있어 다음 라운드 감사가 "이미 끝난 페이지"로 건너뛰기 쉽다. |
