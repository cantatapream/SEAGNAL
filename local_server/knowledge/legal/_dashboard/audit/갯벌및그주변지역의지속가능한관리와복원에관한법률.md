### method_notes (6라운드 신규 지적사항)

1. **5R의 "다음 라운드 최우선 과제"가 5R 당일 저녁에 이미 해소돼 있었음**: 습지보호지역 좌표 wiki_gap이 5R 리포트 작성(07-18 00:08) 이후 같은 날 저녁(07-18 08:16 계열 커밋) 반영됐다. 이는 감사 라운드와 실제 수정 작업의 **타이밍이 어긋나면 직전 라운드가 "아직 안 됐다"고 적은 항목이 다음 감사 시점엔 이미 해결돼 있을 수 있다**는 뜻 — 매 라운드 시작 시 git log로 "직전 감사 이후 변경분"을 먼저 확인하는 절차(이번에 실제로 수행)가 앞으로도 필수임을 재확인.
2. **"raw는 있는데 wiki가 안 가져온" 유형의 wiki_gap이 이 법에서 반복 발견됨(3번째)**: L7/V5(습지보호지역 좌표, 5R에서 첫 발견해 6R에 해소 확인) → 연안관리법(AA1, 6R 신규) → 청정갯벌 공개조항(AA14·AA15, 6R 신규). 공통점: **셋 다 raw 수집은 이미 끝났고, 위키 반영(사서 작업)만 안 된 상태**다. 이는 이 법의 raw 수집률이 이미 매우 높다는 뜻이기도 하다 — 다음 라운드는 collection_hole(raw 자체 미수집, 8건 확정)보다 이런 **"raw 존재·wiki 미반영" 유형을 찾는 것**이 더 생산적인 감사 방향일 수 있다(예: 각 페이지가 인용하는 시행령·시행규칙 조문 번호를 raw 원문과 항목별로 diff하는 기계적 점검).
3. **글로서리 "간석지" dead link — 3라운드 방치 끝에 구체적 수정법을 특정함(AA3)**: 종전엔 "존재하지 않는 페이지"라고만 지적했으나, 이번에 실제로 `wiki/statutes/공유수면관리및매립에관한법률.md`에 간석지 정의가 이미 있음을 확인했다 — **다음 사서 작업은 glossary 254행의 링크 타겟만 `[[공유수면관리및매립에관한법률]]`로 교체**하면 즉시 해소되는 1줄 수정이다(신규 콘텐츠 작성 불필요).
4. **connector 계열 disclosure의 확산 여지(Z9→AA1)**: Z9가 잘못된 용어("연안특별관리해역")로 질문됐음에도, 재검증 과정에서 실제 인접 개념(연안침식관리구역)과 더 중요한 사실(연안관리법 raw 전량 보유)을 찾아냈다 — 질문의 정확성보다 **질문이 가리키는 "검토되지 않은 인접 영역"을 찾는 태도**가 감사의 핵심 가치임을 보여주는 사례.
