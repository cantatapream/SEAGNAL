# 별표(부속 표·기준표) 위키 반영 전수 조사 — "원문엔 있는데 답변엔 안 나오는 수치"는 얼마나 되나

- 작성일: 2026-08-17 (KST)
- 성격: **읽기 전용 조사.** 이 조사에서 위키·raw 파일은 **하나도 수정하지 않았다.** git 명령도 실행하지 않았다. 산출물은 이 파일 하나뿐이다.
- 조사 대상(모집단): `raw/<분류>/<법>/별표/*별표*.txt` **전체 1,179개 파일**. 그중 **기준법(1군, `raw/01_*~14_*`) 690개**가 이 조사의 주 대상이고, 타법(`raw/15_관련타부처`) 489개는 `_SCHEMA.md` 0-B에 따라 "별표 완비 대상"이 아니므로 집계에서 분리했다.
  - 같은 `별표/` 폴더에 있는 **서식(별지 제N호서식) 3,534개는 제외**했다 — 신고서·신청서 양식이라 "수치가 든 기준표"가 아니고, `_CHATBOT.md` 5-5의 다운로드 규칙이 따로 적용되는 별개 트랙이다.
- 위키 쪽 대상: `wiki/annexes` 178 · `concepts` 945 · `statutes` 74 · `comparisons` 44 · `activities` 1.
- 파일명 해석 규칙은 `local_server/services/article_text.js` 머리 주석(실측 근거 포함)을 그대로 따랐다. 그 주석이 말한 "계층 없는 `별표N.txt`는 파일명 번호와 내용 번호가 어긋난 게 41개"는 이 조사에서 **44개**로 재현됐다(집계 방식 차이 범위 — 판정 방법이 원문과 어긋나지 않음을 확인한 것).

## 0. 다섯 줄 요약 (비개발자용)

1. 별표는 "법에 딸린 표"다. 풍속·파고·금액·크기 같은 **사용자가 진짜 알고 싶어 하는 숫자**가 대부분 여기 들어 있다. 기준법 690개 별표 중 위키에 **전용 페이지(annexes/)가 있는 것은 133개(19.3%)뿐**이다.
2. 그렇다고 나머지 557개가 다 빠진 건 아니다. **대부분은 개념 페이지 본문 안으로 옮겨져 있다** — 자동 판정이 가능한 389개 중 350개(90%)에서 원문의 수치가 위키 어딘가에서 확인됐다. 즉 **"전면적 누락"은 아니다.**
3. 문제는 나머지다. 자동 판정으로 **"이름만 인용하고 수치는 안 옮긴" 후보 43개**, 수동 표본 조사로 추정한 것까지 합치면 **기준법 별표의 약 11~12%(대략 75~80개)** 가 미반영 또는 반쪽 반영이다. 절대수는 크지 않지만, 하필 **"몇 ㎧부터 못 나가나" 같은 실전 질문의 답**이 여기 몰려 있다.
4. **이번 유선·도선 사고는 조사 결과 "위키에 없어서"가 아니었다.** 톤수별 풍속·파고표는 `statutes/유선및도선사업법.md`와 `comparisons/출항통제_기상특보.md`에 **정확히 옮겨져 있었다.** 다만 ①별표 전용 페이지가 없고 ②질문에 가장 잘 걸리는 개념 페이지에는 **별표 이름만** 적혀 있으며 ③수치를 가진 두 페이지는 모두 `## 근거 조문` 표가 없는 종류(statute·comparison)라 근거 목록에 한 줄도 못 싣는다 — 세 조건이 겹쳤다. (자세한 것은 §4)
5. **반대 방향(위키는 인용하는데 raw 원문이 없는 수집 구멍)은 사실상 없다** — 41건이 걸렸으나 손으로 확인하니 거의 전부 "다른 법의 별표를 인용한 것"이었고, 진짜 수집 구멍은 **1건**(해양이용영향평가법 시행령 별표1·2·3)뿐이다.

> **그래서 얼마나 심각한가**: "위키에 데이터가 없다"는 종류의 사고가 아니다. **"데이터는 있는데 사용자 질문이 닿는 자리에 없다"**는 배치 문제다. 고치는 비용은 새로 조사하는 것보다 훨씬 싸고(원문이 이미 raw에 있고 대부분 다른 페이지에 이미 옮겨져 있다), 효과는 즉시 나타난다.

## 1. 판정에 쓴 규칙 (전제 — 이 규칙의 한계는 §7에 따로 적었다)

| 단계 | 무엇을 | 어떻게 |
|---|---|---|
| ① raw 별표 식별 | (법, 계층, 별표번호) | 파일명 `시행령_별표3.txt`·`시행규칙_별표2의2.txt`처럼 계층이 붙은 것은 파일명으로. 계층이 없는 `별표N.txt`는 **파일 안 선언줄**(`■ 항만법 시행령 [별표 6]`)을 읽어 계층·번호를 정함(`article_text.js` 규칙과 동일). 번호가 없는 별표는 `별표0.txt`로 저장돼 있어 "무번호"로 따로 처리 |
| ② 위키 전용 페이지 | `wiki/annexes/*.md` | 파일명·frontmatter `id`·본문의 `raw 원문:` 경로 3가지를 다 써서 (법, 계층, 번호)로 연결. `별표3_11`처럼 **범위를 밑줄로 적은 페이지**는 본문에 3~11이 다 있는지 확인해 구간으로 인정(수산자원관리법 조업금지구역 9개 별표가 여기 해당) |
| ③ 개념 페이지 인용 | 그 법의 위키 페이지 전체 | `별표N` 표기를 찾고, 앞 60자 안에 `시행령`·`시행규칙` 같은 계층어가 있으면 "계층까지 맞는 인용"으로 봄 |
| ④ 수치가 실제 옮겨졌나 | **단위가 붙은 숫자**의 일치율 | raw에서 `10㎧`·`1.5m`·`2.5톤`·`500만원`처럼 **숫자+단위**를 뽑아 집합으로 만들고, 위키 페이지에서 같은 집합을 뽑아 겹치는 비율을 계산. **60% 이상 겹치면 "옮겨졌다"**로 판정 |
| ⑤ 자동 판정 불가 | 단위 없는 표 | `(단위: 만원)`을 표 머리에만 적고 칸에는 `600`·`1,000`만 쓴 금액표, 좌표(도·분·초), 색상·도형·목록형 별표는 ④로 판정할 수 없다 → **`ⓔ`로 따로 빼고 수동 표본으로 추정** |

| 항목 | 값 |
|---|---:|
| 자동 판정으로 걸린 "raw 미보유 인용" | **41건** (29개 법) |
| 그중 손으로 확인해 **다른 법의 별표를 인용한 것**으로 판명 | 대다수 |
| 그중 **표기 차이**(무번호 별표를 "별표1"로 적은 것 등) | 4건 이상 |
| **진짜 수집 구멍으로 확인된 것** | **1건** |

- **유일한 진짜 구멍**: 「해양이용영향평가법」의 **시행령 별표1·2·3**. raw 폴더에는 시행규칙 별표1~7만 있고 시행령 별표가 하나도 없다(`_meta.json`의 `별표수: 26`과 실제 수집분이 어긋난다). 그런데 `concepts/해양이용영향평가법__정의및협의평가구분.md` L31은 **"매립이 협의대상인지 평가대상인지는 시행령 별표2에 달려 있다"**고 명시한다 — 즉 **판정의 갈림길이 되는 표가 없다.** 이 법은 `raw/15_관련타부처`(타법)라 별표 완비 대상은 아니지만, 위키가 그 별표를 "결정적"이라고 적고 있으므로 **재수집 대상**이다.
- 오탐 예: 선원법 페이지의 "시행령 별표3"은 **선박직원법** 시행령 별표3, "시행규칙 별표7"은 **수산업법** 시행규칙 별표7 인용이다. 표기 차이 예: 한국해양교통안전공단법·선박법·연안사고예방법은 raw에 **무번호 별표**(`시행령_별표0.txt`)가 있는데 위키가 "시행령 별표1"로 적는다(내용은 맞다).

### 6-2. 병렬 처리 그룹 제안 (6그룹 + 선행 1건)

## 7. 판정 규칙의 한계 (반드시 감안 — 오탐·누락 방향을 명시한다)

### 7-1. 오탐(있다고 했는데 실제로는 없을 수 있는 것)

- **ⓑ 판정의 "수치 일치율 60%"는 법 단위·페이지 단위 집합 비교다.** 같은 법 안에서 우연히 같은 숫자+단위가 다른 맥락으로 쓰이면 "옮겨졌다"로 잘못 셀 수 있다(예: 별표의 `5년`과 다른 조문의 `5년`). 특히 **단위 종류가 적고 토큰이 3~4개뿐인 별표**에서 위험하다.
- **행정규칙(고시) 별표의 전용 페이지 매칭은 고시 이름을 무시하고 (법, 행정규칙, 번호)로만 맞췄다** — 한 법에 고시가 여럿이면 다른 고시의 같은 번호 별표를 "커버됐다"로 오인할 수 있다.
- **무번호 별표(13건)는 `별표N` 대신 `별표`(숫자 없음)로 검색**했다. 이 검색은 지나치게 넓어 거의 항상 "인용됨"으로 잡힌다.

### 7-2. 누락(없다고 했는데 실제로는 있을 수 있는 것) — **이쪽이 더 크다**

- **ⓒ1(이름만 인용) 38건은 오탐률이 높다.** 손으로 10건을 확인한 결과 **약 40%는 실제로는 잘 반영돼 있었다**(예: 농수산물품질관리법 시행규칙 별표19·별표33·34, 선박안전법 시행규칙 별표31, 선박평형수 시행규칙 별표14의2 — 모두 전용 절이 있는데도 단위 표기 차이로 걸렸다). 나머지 중 약 35%는 부분반영, 약 25%가 진짜 미반영이었다. **따라서 43건을 그대로 "빠진 것"으로 읽으면 안 되고, 착수 전 건별 확인이 필요하다.**
- **좌표(도·분·초), 색상, 도형, 비율식, 한자·기호 표기 수치는 단위 추출기가 못 본다.** 그래서 이런 별표는 ⓔ로 밀려나 자동 판정에서 빠졌다(256건, 전체의 37%).
- **다른 법의 위키 페이지에 옮겨진 경우를 못 본다.** 이 조사는 "그 법 이름으로 시작하는 위키 파일"만 뒤졌다. 타법 페이지나 `comparisons/` 허브에 수치가 옮겨져 있으면 놓친다.
- **`행정규칙/*.txt` 본문 안에 인라인으로 들어 있는 고시 별표는 모집단에 없다.** 과제가 정한 모집단(`별표/*.txt`)을 그대로 따랐기 때문이다. 고시 별표 전체 규모는 이 조사로 알 수 없다.
- **ⓔ 256건의 판정은 표본 20건(7.8%)에 근거한 추정이다.** 전수가 아니다.

### 7-3. 확인하지 못한 것 (모르는 것은 모른다고 적는다)

1. **③ 가설(statutes 페이지가 4,000자 컷에서 밀렸는지)** — 실제 검색을 실행해 보지 않았다.
2. **타법(15_관련타부처) 489개 별표의 반영 상태** — `_SCHEMA.md`상 완비 대상이 아니라 집계에서 뺐다. "인용된 조문 관련 별표만" 기준으로 다시 세면 결과가 달라진다.
3. **`별표0`(무번호) 13건이 정말 무번호인지, 수집기가 번호를 못 읽어 0으로 저장한 것인지** — 파일 안 선언줄이 `[별표]`(번호 없음)인 것은 확인했으나, 원문에 원래 번호가 있었을 가능성은 배제하지 못했다.
4. **㉯ 53건 각각이 실제로 미반영인지** — 자동 판정이 불가능해 성격만 추정했다. 표본 판정도 하지 않았다.
5. **위키에 옮겨진 수치가 원문과 "정확히" 같은지** — 이 조사는 "있는가/없는가"만 봤고, 값이 맞는지(전사 오류)는 보지 않았다. 그건 별도의 원문 대조 작업이다.
