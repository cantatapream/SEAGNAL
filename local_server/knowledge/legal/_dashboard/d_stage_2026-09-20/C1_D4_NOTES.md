## 그러면 C-1 이 진짜로 겨냥한 구멍은 어디인가

`collect_eval` 이 보는 것은 **"가져야 할 파일이 손에 있나"** 까지다. 보지 않는 것이 둘이다 —
**"가진 파일이 최신판인가"** 와 **"그 파일에 조문이 다 있나"**. 그 둘을 보는 도구는 있는데
**상시 검사가 하나도 안 부른다**(`grep -c` 로 셌다, 전부 **0회**):

| 도구 | 무엇을 보나 | `verify_all.sh` 언급 |
|---|---|---:|
| `admrul_fresh.py` | 행정규칙 824건의 판번호가 현행인가 | **0회** |
| `law_fresh.py` | 법률·시행령·시행규칙 200건의 판번호가 현행인가 | **0회** |
| `mok_audit.py` | 원문의 목(가·나·다)이 빠지지 않았나 | **0회** |
| `admrul_annex_survey.py` | 행정규칙 별표가 빠지지 않았나 | **0회** |

⚠**넷 다 law.go.kr API 를 부른다.** `verify_all.sh` 의 V5-7 주석이 admrul_fresh 를 두고
*"매 실행이 653회 API 호출이라 무겁다"* 며 상시 게이트에서 뺀 이유를 이미 적어 두었다.
즉 **몰라서 안 넣은 게 아니라 무거워서 뺀 것**이다. 그러니 C-1·C-2 는 "게이트를 새로 만든다"가
아니라 **"무거운 검사를 어떤 주기로, 무엇이 실패하면 무엇을 막을 것인가"** 를 정하는 일이다.
이미 있는 것 — 서버 cron 주간 실행(일요일 03:00 KST, A-3 참조). 없는 것 — **그 결과가
나빠졌을 때 무엇이 멈추는가.**

→ **C-1 을 다시 쓸 것을 제안한다.** 다만 이것은 계획 문구를 바꾸는 일이라
  **사용자 확인 대상**으로 남긴다. 여기서는 측정만 적는다.

### 곁가지로 확인한 것 — 결함 아님
`verify_all.sh` 의 `--base` 표기가 두 갈래다. V5-7·V5-8·별표는 저장소 루트 기준 전체 경로를,
V5-9·V5-10 은 `pinned/…` 짧은 경로를 준다. **둘 다 제대로 읽힌다** — 뒤 두 도구는
`path.resolve(HERE, bp)` 로 **스크립트 폴더 기준**으로 풀기 때문이다(`collect_eval.js:238`,
`link_sym.js:76`). 실제로 저장소 루트에서 돌려도 "기준선(2) 이하" 가 나오고, 없는 경로를 주면
"기준선이 없어 게이트를 건너뜁니다" 가 나온다(둘 다 실행해 확인). **조용히 틀린 값을 내지 않는다.**

## D-4 대상 확정 — 본문이 안 딸려온 행정규칙 2건

`collect_eval.js --examples` 가 이름까지 찍어 준다:

```
[  2] 물환경보전법 — 행정규칙빔 금강수계수변구역변경.txt(0자) · 물환경측정망운영계획.txt(0자)
```

| # | 법 | 파일 | 크기 |
|---|---|---|---|
| 1 | 물환경보전법 | `금강수계수변구역변경.txt` | **0자** |
| 2 | 물환경보전법 | `물환경측정망운영계획.txt` | **0자** |

- 둘 다 **물환경보전법** 한 법에 몰려 있다.
- ⚠**이 둘은 기준선이기도 하다**(게이트 기준선 2 = 이 2건). 고치면 기준선을 2 → 0 으로
  **더 엄격하게** 내려야 한다. 안 내리면 다음에 새 결손이 생겨도 2건까지는 통과한다.
- ⚠**왜 비었는지는 아직 모른다.** 채우려면 law.go.kr 을 불러야 하므로 **A-1 종료 후**에 한다.
  HANDOFF 가 "A-1 에 흡수될 수 있다"고 적어 둔 것도 같은 이유로 보인다 —
  다만 A-1(`admrul_fresh.py`)은 **판번호만** 보지 본문을 받아오지 않으므로,
  **자동으로 흡수되지는 않을 것이다.** 재수집은 별도다.
- 참고: `collect_eval` 은 30자 미만만 결손으로 센다. 30~300자인 **짧은 행정규칙 43건**은
  지정고시류라 원래 짧으므로 결손이 아니라고 스스로 밝히고 게이트에서 뺀다.
