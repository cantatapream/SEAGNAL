## 무엇을 놓쳤나 — **HTTP 200 을 성공으로 착각했다**

사용자가 *"1번 다시 해봐바"* 해서 다시 부르니 **1.1초에 1455바이트**가 왔다. 터널 실패였다면 나올 수 없는 응답이다.
본문을 열어 보니 —

```
HTTP 200 · text/html;charset=UTF-8 · 1455 바이트
<h2>미신청된 목록/본문에 대한 접근입니다.</h2>
```

**HTTP 200 인데 내용은 권한 오류쪽이었다.** `api()` 는 *"JSON 이 아니면 실패"* 로만 보고 조용히 세 번
재시도한 뒤 `None` 을 줬고, 그 `None` 이 `⚠원본을 못 받아 판정 못 한 계열` 로 집계됐다.
**화면에 뜬 말은 "모른다"였지만 실제로는 "권한이 없다"였다.**

터널 흔들림(`ws_closed_mid_exchange`)은 **정말로 있었다.** 그래서 두 원인이 겹쳐 보였고,
눈에 띄는 쪽(터널)을 원인으로 집었다. **재시도를 늘려 터널 실패를 걷어내자 진짜 원인이 드러났다.**

## 고친 것

**① `eflaw` → `law`** (`mok_audit.py` 82행)
**MST 가 판(version)을 고정하므로 target 이 달라도 같은 문서다.** 확인했다 —
폐기물관리법 시행규칙 `MST=289271` 을 `target=law` 로 부르니 `시행일자=20260918` 이 왔고,
우리 raw 머리말의 *"target=eflaw, MST=289271, 시행 20260918"* 과 **같다.**
응답 구조(조문→항→호→목)도 같아 `api_mok_count()` 를 한 글자도 안 고쳤다.

**② `api()` 가 "권한 없음"과 "네트워크 흔들림"을 갈라서 알린다**
JSON 이 아니면 `<h2>` 의 사유를 **한 번 크게 찍고 그 자리에서 물러난다**(권한 문제는 재시도로 안 풀린다).
```
⛔law.go.kr 이 본문 대신 오류쪽을 줬다: "미신청된 목록/본문에 대한 접근입니다."
   → 재시도로 풀리는 문제가 아니다. OC 계정의 target 신청 상태를 확인할 것.
```

**결과**: 표본(선박안전법 3계열) **판정 불가 3 → 0**. 전수 573계열 실행 시작.

## 남기는 교훈

1. **HTTP 200 은 성공이 아니다.** 본문을 봐야 한다. 이 도구는 7시간을 "모른다"로 보냈다.
2. **"모른다"를 세는 칸이 있으면, 왜 모르는지도 세야 한다.** `판정 불가 573건` 은 정직했지만 쓸모가 없었다.
3. **눈에 띄는 원인이 진짜 원인이 아닐 수 있다.** 터널 실패는 진짜였지만 A-2 를 막은 것은 아니었다.
   증상이 둘 이상일 때는 **하나를 제거하고 다시 봐야** 한다(재시도를 늘려 터널을 걷어내니 권한이 드러났다).
4. **틀린 진단은 틀린 자동화를 낳는다.** 발사대가 83번 실패한 것은 고장이 아니라 **전제가 틀린 것**이었다.
