# ★고장난 호출로 만든 산출물 전수 훑기 (2026-09-21, L-297 이행)

L-297 이 이렇게 끝난다 — *"도구를 고쳤으면 그 도구가 낸 **과거 숫자를 전부 의심**해야 한다."*
그래서 `lawService.do?target=law&MST=`(어느 시행일 판이 올지 못 고르는 호출)을 쓰던 도구들이
남긴 산출물을 **하나씩 열어 봤다.** 이 문서가 그 결과다.

## 결론 한 표

| 산출물 | 만든 도구 | 판정 | 근거 |
|---|---|---|---|
| `mok_audit.json` · `A2_REPORT_2026-09-21.json` | `mok_audit.py` | **⛔무효 — 재실행** | 도선법 시행령이 2년 전 판과 견줘졌다(A2_RESULT.md 상단) |
| `law_change_baseline.json` | `backfill_lawid.py` → `build_change_baseline.py` | **⛔오염 11건 — 재생성** | 아래 §2 |
| `law_fresh_report.json` | `law_fresh.py` | **✅건전** | 아래 §1 |
| `budchik_check.json` · `budchik_recollect_log.json` | `check_budchik.py` · `recollect_budchik.py` | **⚠판정 보류** | 아래 §3 |
| `recollect_tier_report.json` | `recollect_tier.py` | **✅건전** | `eflaw`+`efYd` 로 판을 명시해 받는다 |

## 1. `law_fresh.py` 는 처음부터 옳았다 — 그리고 그게 뼈아프다

이 도구는 `lawSearch.do?target=eflaw&LID=<법령ID>` 로 **그 법의 판 목록 전부**를 받아
①시행일자가 오늘 이전인 것 중 최신을 고르고 ②**우리 파일 머리글의 `(시행 …)`** 까지 맞춰 본다.
머리말에 이렇게까지 적혀 있다 —

> ★**번호가 같아도 판이 다를 수 있다**(2026-09-10 실측). 한 MST 가 시행일 여럿으로 등재되는
> 단계시행이 있다 — 「해양환경관리법 시행령」 MST 287499 는 시행일 20260630·20260701·20260828 로
> 세 번 나온다. **MST 숫자만 비교하면 287499 == 287499 이라 '현행'으로 통과한다.**

★**내가 오늘 만든 `law_api_guard.current_efyd` 는 이 방식의 재발명이다.**
`recollect_tier.py` 머리말에 이미 반례가 적혀 있었던 것과 같다(L-295 교훈 3).
**우리 저장소는 이미 답을 알고 있었고, 그 앎이 도구 하나에만 갇혀 있었다.**
→ 그래서 이번에는 **공용 모듈**로 빼고 11곳에 물렸다. 지식을 한 파일에 가두지 않는 것이 요점이다.

## 2. `law_change_baseline.json` — 오염 11건, 그중 4건은 미래

baseline 스냅샷은 **2026-09-10**, `law_fresh_report` 는 **2026-09-20** 이라 차이 대부분은
**그 열흘 사이의 진짜 개정**이다(MST 자체가 바뀐 8건). 결함의 지문은 따로 있다 —
**MST 는 같은데 시행일이 다른 것.**

| 법·계층 | MST | baseline 시행 | 현행 시행 | |
|---|---|---|---|---|
| 농수산물품질관리법 시행령 | 288973 | **20270101** | 20260825 | ← 미래 |
| 해운법 법률 | 286933 | **20270101** | 20260616 | ← 미래 |
| 선박의입항및출항등에관한법률 법률 | 285971 | **20261113** | 20260512 | ← 미래 |
| 도선법 시행령 | 243569 | 20230101 | 20250101 | 2년 전 |
| 해사안전기본법 법률·시행령·시행규칙 | 252901·258873·260153 | 20240126 | 20250726 | |
| 해상교통안전법 법률 | 252871 | 20240126 | 20240726 | |
| 해양환경관리법 시행령·시행규칙 | 287499·287955 | 20260701 | 20260828 | |

(별도로 `물환경보전법 법률 MST=283441 시행=20270220` 도 스냅샷일보다 뒤다 — 위 표와 합쳐 미래 4건.)

**왜 중요한가**: `detect_law_changes.py:385` 가 baseline 의 이 값들을 그대로
`before = {MST, 법령명, 공포번호, 공포일자, 시행일자, 소관부처명}` 로 만들어 **검수 카드에 싣는다.**
즉 사람이 보는 "바뀌기 전" 칸이 틀린 판을 가리킬 수 있다. 살아 있는 크론이 쓰는 값이라
**A-2 다음으로 급하다.**

**고치는 법**: `backfill_lawid.py`(오늘 `fetch_law_body` 로 고침) → `build_change_baseline.py`
를 **단독·직렬**로 다시 돌린다. ⚠`backfill_lawid` 는 74법 공유 `_meta.json` 에 쓴다 — 병렬 금지.

## 3. `budchik_check.json` — 판정 보류(아직 안 쟀다)

`check_budchik.py` 는 `target=law&MST=` 를 **재시도 없이 한 번** 부르던 도구였고(오늘 고쳤다),
**부칙은 판마다 다르다**(해양환경관리법 시행규칙 287955 는 20260701 판이 부칙 52개,
20260828 판이 53개). 이 파일은 73법 중 **mismatch 144건**을 담고 있고 그것이
`recollect_budchik.py` 의 작업 지시서가 됐다.

⚠**아직 재지 않았다.** "144건이 틀렸다"고 말할 근거도, "맞다"고 말할 근거도 지금은 없다.
2026-07 의 H-26 일회성 감사였고 그 결과는 이미 raw 에 반영됐으므로, 다시 세는 것보다
**지금 raw 에 부칙이 제대로 있는지**를 직접 재는 편이 싸다. 그건 별건으로 남긴다.

## 4. 이 훑기에서 배운 것

- **한 결함은 ①코드 ②자료 ③그 자료로 만든 판단** 세 겹으로 퍼진다. ③을 찾으려면
  *"이 도구가 무슨 파일을 남겼나"* 를 코드에서 기계로 뽑아 하나씩 열어 보는 수밖에 없다.
- **"재실행하면 된다"와 "재실행할 수 있다"는 다르다.** A-2 와 baseline 재생성은 둘 다
  **단독 실행**이 필요해서 A-1 재검증이 끝날 때까지 못 돌린다. 순서를 적어 두지 않으면
  다음 세션이 동시에 돌려 또 망가뜨린다 → 아래 순서를 지킨다.

### 실행 순서 (반드시 하나씩)
1. **A-1 재검증**(진행 중) 완주
2. **A-2 재실행** — `python3 _dashboard/loop/mok_audit.py --out <새 산출물>`
3. **baseline 재생성** — `backfill_lawid.py` → `build_change_baseline.py`
4. 2의 결과로 **B-2 대상 목록**을 새로 만든다
