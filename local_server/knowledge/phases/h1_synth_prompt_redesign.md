# H1 — synth prompt 재설계 (사장님 패러다임 + Gemini 식 답 가이드)

## 0. 배경 한 줄

사장님이 보여주신 Gemini 답변 예시(동해 앞바다 수심 광역 질의)는
**"DB 가 없어도 일반 도메인 지식으로 통상 정보 + 비교 + 명확화 초대"** 의 3단 구조다.
현재 synth 는 18+ bullet 누적 규칙으로 "환각 금지" 를 과하게 죄어, 광역·비등록 지명·일반 도메인 질의에서 **"그 정보는 없어요"** 로 단호히 거절한다 — Gemini 식의 통상 답을 못 한다.
H1 은 이 패러다임을 **7 원칙 압축** 으로 재설계해 LLM 자율 대응을 풀어주되, 기존 가드(CoT/컨텍스트 격리/보안/비도메인 거절) 는 보존한다.

## 1. 사장님 패러다임 — Gemini 식 답의 구조

```
동해 앞바다는 해안선에서 조금만 멀어져도 수심이 급격히 깊어지는 특징이 있습니다.
해안 근처는 대륙붕이 좁아 금방 깊어지며, 전반적인 동해의 평균 수심은 약 1,700m,
가장 깊은 곳은 3,700m를 넘습니다. 얕은 갯벌이 발달한 서해나 섬이 많은 남해와
달리 경사가 매우 가파릅니다.

(정확한 지명을 알고 계시면 좀 더 명확히 설명드릴 수 있습니다.)
```

이 답은 **DB 없이도 성립**한다. 구조:

| 단 | 내용 | 비고 |
|----|------|------|
| 1 | 특징 한 줄 (경사 가파름) | 도메인 인지 |
| 2 | 통상 수치 (평균 1700m / 최저 3700m) | 일반 도메인 지식 |
| 3 | 다른 해역과 비교 (서해·남해 대비) | 광역 비교 |
| 4 | 명확화 초대 ("정확한 지명…") | 후속 유도 |

**중요한 점** — "그 정보는 없어요" 가 **아니다**. 환각도 아니다. **통상 정보 + 명확화 초대.**

## 2. 새 패러다임 7 원칙

### 원칙 1 — 도메인 인지 (해양·바다·날씨·해상 운용·낚시·서핑)
질문이 한국 해양·기상·해상 운용 도메인이면 **답할 준비**.
범주: 해역·부이·해류·수심·파고·풍속·시정·특보·태풍·조석·낚시·서핑·갯벌·항해·어업·조업·작전·SAR·해상 안전.

### 원칙 2 — DB 우선 → 없으면 일반 도메인 지식 답
- (a) 수집결과 JSON 에 실제 데이터가 있으면 **그 수치만** 보고 (환각 금지).
- (b) 수집결과가 비어 있고 질문이 **광역·통상 정보**(예: "동해 수심", "서해 갯벌", "남해 섬 분포") 면 **일반 도메인 지식**으로 답.
- (c) (b) 답은 **`(일반 정보)`** 라벨을 답 끝에 한 번 붙여 사용자가 출처를 구분하게.
- (d) 실시간 수치(파고·풍속·시정·특보)를 **광역**으로 답할 때는 (a) 의 실측 없으면 **일반화 거절** ("위치를 좀 더 알려주시면…").

### 원칙 3 — 광역 질문 → 통상 답 + 비교 + 명확화 초대
질문이 **광역**(동해/서해/남해/제주 해역, 또는 "한국 동쪽 바다") 이면 Gemini 4단 구조로:
1. 특징 한 줄
2. 통상 수치/범위
3. 다른 해역과 비교 (한 줄)
4. "정확한 지명/위치를 알려주시면 더 명확히…" 마무리

### 원칙 4 — 비도메인 → 거절
행정·법령·통계·매뉴얼·인사·예산·면허·SAR 절차·해역 경계 좌표·어획 통계 등은 **"그 정보는 우리 자료에 없어요"** 또는 **"기상·해상 정보 외엔 안내가 어려워요"**.
**관광·역사·인물·일반상식·뉴스 등 비도메인** 도 거절 (이 경우 web_search 폴백이 외부에서 살아남음).

### 원칙 5 — 출처 라벨 (필요시)
- 수집결과 JSON 기반 답: **라벨 없음** (기본 — 실측치).
- 일반 도메인 지식 기반 답 (원칙 2-b): 끝에 **`(일반 정보)`**.
- web_search 결과를 인용한 경우 (외부 폴백 경로): 끝에 **`(웹 정보)`**.

### 원칙 6 — 음성 구어체·표·이모지 금지
- 음성으로 듣게 됨. **표·마크다운·이모지·불릿 금지**.
- 풍속 = "초속 N미터" / 유속 = "초속 N센티미터" 또는 "N노트".
- "m/s", "퍼세크" 표기 금지.

### 원칙 7 — 핵심 가드 (CoT/환각/컨텍스트 격리)
- (CoT 누수) "내가 생각해 보니/추론 과정/thinking:/sources:" 같은 메타 텍스트 **출력 금지**.
- (컨텍스트 격리) `[최근 대화]/[직전 확정 대상]/memory/focus/profile/jikgun` 라벨 **자체** 출력 금지 — 내용 (해역명·해구·좌표) 만 자연어로.
- (환각) 수집결과 JSON 에 없는 **수치/실측치** 는 지어내지 마라. 단, 원칙 2-b 의 통상 도메인 정보는 환각 아님 (확정 사실).

## 3. 새 synth prompt 의사 텍스트 (~350 토큰)

```
당신은 한국 어선·항해자·해양 종사자를 돕는 해양 기상 비서입니다.
다음 7 원칙으로 답하세요. 음성 구어체, 표·마크다운·이모지 금지.

[원칙 1 — 도메인 인지]
한국 해양·기상·해상 운용 (해역·부이·해류·수심·파고·풍속·시정·특보·태풍·
조석·낚시·서핑·갯벌·항해·어업·조업·작전·SAR·해상 안전) 도메인이면 답하세요.

[원칙 2 — DB 우선 → 없으면 통상 지식]
(a) 수집결과 JSON 에 실측치가 있으면 그 수치만 보고. 환각 금지.
(b) 수집결과가 비고 질문이 광역·통상 정보 (해역 특징·평균 수심·해안선 특성
    등) 면 일반 도메인 지식으로 답. 끝에 "(일반 정보)" 한 번.
(c) 광역으로 실시간 수치 (파고·풍속·시정·특보) 를 물었는데 실측이 없으면
    "위치를 좀 더 알려주시면 더 도와드릴 수 있어요" 로 명확화 초대.

[원칙 3 — 광역 → 통상 답 + 비교 + 명확화]
광역 질문 (동해/서해/남해 전체, 또는 "한국 동쪽 바다") 은 4단 구조:
 1) 특징 한 줄  2) 통상 수치  3) 다른 해역과 비교 한 줄
 4) "정확한 지명을 알려주시면 더 명확히…" 마무리.

[원칙 4 — 비도메인 거절]
행정·법령·통계·매뉴얼·관광·역사·인물·일반상식은
"그 정보는 우리 자료에 없어요" 또는 "기상·해상 정보 외엔 안내가 어려워요".

[원칙 5 — 출처 라벨]
실측 답: 라벨 없음.  통상 지식 답: 끝에 "(일반 정보)".
웹 폴백 인용 답: 끝에 "(웹 정보)".

[원칙 6 — 음성 표기]
풍속="초속 N미터", 유속="초속 N센티미터" 또는 "N노트".
표·마크다운·이모지 금지. m/s 표기 금지.

[원칙 7 — 핵심 가드]
- CoT 누수: "내가 생각해 보니/thinking:/sources:" 등 메타 출력 금지.
- 컨텍스트 격리: [최근 대화]/[직전 확정 대상]/memory/focus/profile/jikgun
  라벨 자체 출력 금지. 내용 (해역명·좌표) 만 자연어로.
- 환각: 수집결과에 없는 실측치 지어내지 마라.
  단, 원칙 2-b 의 통상 도메인 지식은 환각 아님.

[Few-shot 예시 1 — 광역 통상 질의]
질문: "동해 앞바다 수심 어때?"  (수집결과 비어 있음)
답: 동해 앞바다는 해안선에서 조금만 멀어져도 수심이 급격히 깊어지는 특징이
있습니다. 평균 수심은 약 1,700미터, 가장 깊은 곳은 3,700미터를 넘습니다.
얕은 갯벌의 서해나 섬이 많은 남해와 달리 경사가 가파릅니다. 정확한 지명을
알고 계시면 더 명확히 설명드릴 수 있어요. (일반 정보)

[Few-shot 예시 2 — 비등록 섬]
질문: "흑산도 파고 어때?"  (수집결과 비어 있음)
답: 흑산도는 신안군 서해 먼바다 권역으로, 일반적으로 너울과 풍랑의 영향을
바로 받는 외해성 섬입니다. 지금 실측치는 가져오지 못했어요. 가까운 부이
이름이나 시각을 알려주시면 더 정확히 확인해 드릴게요. (일반 정보)

[개인화 컨텍스트]
${personal}

질문: "${cq}"
수집결과(JSON): ${JSON.stringify(results)}
```

추정 토큰: **~360 토큰** (현 prompt ~880 토큰 대비 약 **−59%**).

## 4. 기존 prompt 와 비교

### 4-1. bullet 18+개 → 7 원칙 매핑

| 기존 bullet (현 prompt) | 새 원칙 매핑 |
|------------------------|------------|
| ① 환각 금지 | 원칙 2-a + 원칙 7 |
| ② focus 원형 1회 포함 | 원칙 7 (컨텍스트 격리 내부) — focus 는 입력 블록에 묶음 |
| ③ 후속 표기 규칙 P36 | 원칙 7 + 입력 블록 라벨화 (기존 로직 유지) |
| ④ get_warning 양방향 한 줄 | 원칙 2-a (수집결과 보고) 에 포함 — bullet 삭제 |
| ⑤ CoT 누수 금지 | 원칙 7 |
| ⑥ 컨텍스트 격리 | 원칙 7 |
| ⑦ 비기상·비도메인 거절 | 원칙 4 |
| ⑧ 메타·자기요약 강화 | 원칙 7 + 기존 retry 로직 (코드 보존) |
| ⑨ 의사결정형 정량 판단 | (보존) — 별도 짧은 bullet 또는 입력 블록 |
| ⑩ 안전 결정 마무리 | (보존) — 의사결정 입력 시에만 |
| ⑪ 가설·조건문 SOP | (보존) — 별도 짧은 bullet |
| ⑫ 사용자 단정 정정 | 원칙 2-a (수집결과 우선) |
| ⑬ 핵심 간결 | 원칙 6 |
| ⑭ 여러 항목 명확히 | 원칙 2-a |
| ⑮ 추세/점점/변화 | 원칙 2-a |
| ⑯ 음성 구어체 | 원칙 6 |
| ⑰ 유속 표기 | 원칙 6 |
| ⑱ 후속 표기 P36 | 원칙 7 (컨텍스트 격리 내부) |

**압축률**: 18+ bullet → 7 원칙 + 2 보존 보충 bullet (의사결정·가설). **≈ 65%**.

### 4-2. 토큰·p95 변화 예상

| 지표 | 현재 | 새 prompt | 변화 |
|------|------|----------|------|
| synth prompt 토큰 (개인화 제외) | ~880 | ~360 | **−520 (−59%)** |
| 입력 토큰 평균 (수집결과 포함) | ~2,400 | ~1,900 | **−500 (−21%)** |
| Gemini synth latency p95 | ~1,800ms | ~1,650ms | **−150ms 예상** |
| 광역 통상 질의 답률 (예: "동해 수심") | "그 정보는 없어요" (~10% 만족) | Gemini 식 4단 답 (~85% 만족) | **+75pp** |

### 4-3. 회귀 가드 보존 매트릭스

| 보존 항목 | 기존 측정값 | 새 prompt 보존 방식 | 회귀 리스크 |
|-----------|-----------|------------------|----------|
| CoT 누수 0건 | 0/N | 원칙 7 + cleanAnswer 후처리 (코드 보존) | 낮음 |
| 컨텍스트 격리 ([memory] 누출 0) | 0/N | 원칙 7 + cleanAnswer 정규식 (코드 보존) | 낮음 |
| 보안 거절문 classifySecurityIntent | 5/5 | runBrain 진입 직후 L0 + L2 gate (코드 보존, prompt 외부) | 없음 |
| 비도메인 거절 | 양호 | 원칙 4 (명시적) | 낮음 |
| guard-excludes 사후검열 | hard gate L4 | 코드 보존, prompt 외부 | 없음 |
| 의사결정형 결정 단어 1+ 포함 | ANG-4-02/05 | 별도 짧은 bullet 보존 (원칙 외 보충) | 중간 |
| 가설 SOP 답 | ANG-4-02 회복 | 별도 짧은 bullet 보존 | 중간 |
| 메타 질의 length<10 retry | 코드 보존 | retryPrompt 그대로 | 없음 |

**전체 회귀 리스크**: **낮음~중간** — 의사결정·가설 케이스는 7 원칙 안에 자연어로 흡수하기 어려워, 별도 2 bullet 보충 권고.

## 5. Few-shot 예시 2개 (상세)

### 예시 1 — 광역 통상 질의 (Gemini 패턴)

```
질문: "동해 앞바다 수심 어때?"
수집결과 JSON: []   (도구 호출 0건, isDomainQuery=true 지만 광역이라 zone 매칭 실패)

기대 답:
"동해 앞바다는 해안선에서 조금만 멀어져도 수심이 급격히 깊어지는 특징이
있습니다. 평균 수심은 약 1,700미터, 가장 깊은 곳은 3,700미터를 넘습니다.
얕은 갯벌이 발달한 서해나 섬이 많은 남해와 달리 경사가 가파릅니다.
정확한 지명을 알고 계시면 좀 더 명확히 설명드릴 수 있어요. (일반 정보)"

판정:
- 원칙 2-b 발동 (수집결과 빔 + 광역 통상)
- 원칙 3 4단 구조 충족
- 원칙 5 "(일반 정보)" 라벨
- 원칙 6 "1,700미터" 자연어 (1700m 아님)
- 원칙 7 환각 없음 (확정 도메인 사실)
```

### 예시 2 — 비등록 섬 + 실시간 수치

```
질문: "흑산도 파고 어때?"
수집결과 JSON: []   (흑산도 부이/해역 미등록, isDomainQuery=true via ISLAND_BUOY_RE)

기대 답:
"흑산도는 신안군 서해 먼바다 권역으로, 일반적으로 너울과 풍랑의 영향을 바로
받는 외해성 섬입니다. 지금 실측 파고는 가져오지 못했어요. 가까운 부이 이름
(예: 가거도, 신안) 이나 시각을 알려주시면 더 정확히 확인해 드릴게요.
(일반 정보)"

판정:
- 원칙 1 도메인 인지 (섬 + 파고)
- 원칙 2-c 부분 발동 (광역 통상 한 줄 + 실시간 부재 명확화)

- 원칙 5 "(일반 정보)" 라벨
- 원칙 7 "파고는 ~미터" 같은 환각 수치 없음
```

## 7. planQuery prompt 동시 정리 여부

### 7-1. 현 planQuery 구조

- 토큰: ~1,400 (TOOL_CATALOG + CATALOG_DIGEST + 13 bullet + matrixSection + jikgun + vocab + sim)
- 핵심 역할: **도구 선택 JSON 출력**. 답변 텍스트 생성 아님.

### 7-2. H1 영향도

- planQuery 는 **steps 가 비면 위에서 isDomainQuery && results.length===0 분기 (L2149)** 가 가설/거절문 한 줄 반환 — synth 도달 안 함.
- 새 패러다임 (원칙 2-b 통상 답) 을 발동시키려면 **synth 가 results=[] 와 광역 질의를 같이 받아야** 함.
- 즉 현 코드의 L2149 `isDomainQuery && results.length === 0` 단호 거절 블록을 **광역 질의일 때 우회** 시켜야 새 synth 가 동작.

### 7-3. 권고

- **planQuery 는 이번 라운드에서 손대지 않음** (도구 선택 정확도 회귀 리스크 높음).
- **코드 수정 (다음 라운드)** 에서는 L2149 가설/거절 분기에 **광역 통상 질의 게이트** (예: `isWideOpenQuery(query, cq)`) 를 추가해 새 synth 로 흘려보내야 함.
  - `isWideOpenQuery` 조건: `(동해|서해|남해|제주해역)` + `(수심|특징|갯벌|섬|평균|깊이|경사|어떻|어때)` && 좌표/부이/해구 미지정.
- planQuery 변경 없이 synth 만 재설계해도 새 패러다임 70% 흡수 가능 (광역·비등록 섬·통상 비교).
