## 1. 신규 카테고리 정의 + expect 매핑 규칙

### Cat 9. 시계열·추세 (label="시계열추세")
- **정의**: "어제→오늘→내일", "오전 대비 오후", "주말 동안 변화" 등 시간축 변화·추세를 묻는 질의.
- **기존과 차이**: Cat1(현재 스냅샷)·Cat3(다중도구 종합)과 달리 **시간 비교축**이 핵심.
- **expect 매핑**: `expect_tools_any=tools_basic` (+중기예보 보유 직군은 `get_midterm_forecast` 포함),
  `expect_decision=True`.
  ⚠️ **주의**: runner의 `DECISION_RE = 가능|적합|주의|무리|안전|위험|불가|곤란|어렵|좋습|괜찮|조심` 에는
  "악화/개선/유지/상승/하락" 같은 추세어가 **포함되지 않는다**(검증함). 따라서 추세어만 답하면 `expect_decision` 실패.
  → 예시 query를 "…좋아질까/위험해질까/출조 가능?"처럼 **결론어를 강제로 끌어내는 형태**로 작성해야 채점된다(아래 §2 예시 반영).

### Cat 10. 복합조건 (label="복합조건")
- **정의**: 두 개 이상 제약을 AND/OR/제외로 묶는 질의. 예 "파고 1.5m 이하 **그리고** 풍속 10m 미만인 해역만".
- **기존과 차이**: Cat4(단일 임계 판단)와 달리 **다중 제약 결합 + 필터링**.
- **expect 매핑**: `expect_tools_all=tools_basic[:2]`, `expect_decision=True`.

### Cat 11. 오염질의 (label="오염질의")
- **정의**: 오타("거뭄도"), 한영혼합("오늘 wave 어때"), 띄어쓰기붕괴, 구어 축약("ㅈㅁ도 출조됨?")을 의도적으로 주입.
- **기존과 차이**: Cat8(변칙=의미모호/행정구역)과 달리 **표기 노이즈 강건성**이 핵심.
- **expect 매핑**: `expect_tools_any=tools_basic`(정상 지명 정규화 성공 시 도구 호출), `expect_no_cot=True`.
  단, 복원 불가 노이즈는 `expect_no_halluc=True`(추측 금지)로만 채점.

### Cat 12. 멀티턴 3단 (label="멀티턴3단")
- **정의**: 기존 후속(2턴)을 **3턴**으로 확장. T1 질의 → T2 focus 전환 → T3 종합/판단.
  예) T1"거문도 파고" → T2"거기 풍속은?" → T3"그럼 출조 되겠어?"
- **기존과 차이**: Cat2는 2턴 연속성만. 여기는 **누적 컨텍스트 위 결론**.
- **expect 매핑**: T1 `expect_tools_any`; T2 `prev_id=T1, expect_zone_match`; T3 `prev_id=T2, expect_zone_match + expect_decision`.

### Cat 13. 거짓전제 정정 (label="거짓전제")
- **정의**: 틀린 사실을 전제로 깔고 질문. 예 "오늘 거문도 풍랑특보 떴잖아, 출조 위험하지?"(실제 미발효 가정).
- **기존과 차이**: Cat7(환각=없는 통계 요구)과 달리 **사용자가 심은 거짓전제를 검증·정정**해야 함.
- **expect 매핑**: `expect_tools_any=["get_warning", ...]`(전제 검증을 위한 도구 호출). 1차적으로 **A축(도구 호출)** 로 채점.
- ⚠️ **한계(정정 여부는 현 플래그로 직접 채점 불가)**: runner의 `expect_no_halluc` 은 `HALLUC_RE`(약 \d+km·통계는·법령 제\d조 등)
  패턴만 본다(검증함). 모델이 거짓전제를 **그대로 추종**해 "네, 특보 발효 중이라 위험합니다"라고 답해도 HALLUC_RE에 안 걸려 **`expect_no_halluc`을 통과**한다.
  즉 `expect_no_halluc`은 거짓전제 추종을 **탐지하지 못한다**. 따라서 본 카테고리는
  **(1) `expect_tools_any`로 "검증 도구를 부르는지"만 자동 채점**하고, **(2) 정정문 여부는 runner 무수정 범위에서 자동 채점 불가 → 결함 신호 샘플(수동 리뷰) 대상**으로 둔다.
  `expect_no_halluc`은 보조(엉뚱한 통계 단정 방지)로만 부가한다. (정정 자동 채점을 원하면 runner에 거짓전제 추종 패턴 룰 추가가 필요 → 이는 "runner 무수정" 제약 밖.)

### Cat 14. 단위·지표 혼동 (label="단위혼동")
- **정의**: 단위를 뒤섞거나 비현실 값 제시. 예 "풍속 50노트인데"(m/s 혼동), "파고 200cm 위험?"(cm/m), "수온 18도면 시정 좋아?"(지표 혼동).
- **기존과 차이**: Cat4(정상 임계)와 달리 **단위 환산/지표 구분**을 요구.
- **expect 매핑**: `expect_decision=True`(환산 후 판단), `expect_no_halluc=True`(엉뚱한 단위로 단정 금지).

### Cat 15. 우선순위·비교랭킹 (label="비교랭킹")
- **정의**: 후보 다수 중 상대 비교·순위. 예 "거문도, 추자도, 홍도 중 오늘 제일 나은 곳".
- **기존과 차이**: Cat3(단일 해역 종합)과 달리 **N개 비교·랭킹**.
- **expect 매핑**: `expect_tools_any=tools_basic`(+가능 직군 `get_zones_ranked`), `expect_decision=True`.
  ⚠️ Cat9와 동일하게 "최적/1순위" 등 랭킹어는 DECISION_RE에 **없다**(검증함). "…제일 나은 곳/안전한 곳" 처럼
  안전·적합 계열 결론어가 답에 나오도록 query를 유도해야 `expect_decision`이 채점된다.

## 2. 직군별 예시 초안 (각 카테고리 5개씩)

> 표기: 케이스는 `query`만 적되 멀티턴은 `T1/T2/T3`. 지명은 각 직군 `zones` 슬롯에서 차용.
> **결론어 규칙(Cat9·15 필수)**: `expect_decision` 채점을 위해 query 끝을 "…출조/작업/운영 가능?", "…안전해?", "…위험해질까?"
> 처럼 DECISION_RE(`가능|적합|주의|무리|안전|위험|…`) 단어를 끌어내는 형태로 닫는다. 순수 추세·랭킹 표현("추세", "오르는 중?", "비교")만으로는 채점 실패하므로 시드 확장 시 결론절을 덧붙일 것.

## 3. expect 매핑 규칙 요약표 (runner 무수정 채점)

| Cat | label | expect 플래그 | 채점축(runner) |
|---|---|---|---|
| 9 시계열추세 | 시계열추세 | `expect_tools_any`(+중기), `expect_decision` | A |
| 10 복합조건 | 복합조건 | `expect_tools_all=tools_basic[:2]`, `expect_decision` | A,D |
| 11 오염질의 | 오염질의 | `expect_tools_any` 또는 `expect_no_halluc`, `expect_no_cot` | A/B |
| 12 멀티턴3단 | 멀티턴3단 | T1 `expect_tools_any` / T2 `prev_id,expect_zone_match` / T3 `prev_id,expect_zone_match,expect_decision` | A,C |
| 13 거짓전제 | 거짓전제 | `expect_tools_any=["get_warning",…]` (자동) + `expect_no_halluc`(보조) | A (정정 여부는 수동 리뷰) |
| 14 단위혼동 | 단위혼동 | `expect_decision`, `expect_no_halluc` | A,B |
| 15 비교랭킹 | 비교랭킹 | `expect_tools_any`(+`get_zones_ranked`), `expect_decision` | A |

> 신규 플래그 0개(검증함). 모든 신규 케이스는 기존 runner의 A/B/C/D/E 축으로 채점됨 → **runner·jsonl 무수정 유지**.
>
> ⚠️ **runner 무수정 시 2가지 자동 채점 한계(설계상 인지·수용)**:
> 1. **거짓전제(Cat13) 정정 여부**: `expect_no_halluc`은 거짓전제 추종을 못 잡음(HALLUC_RE 패턴만 봄). → 정정문 판정은 수동 리뷰.
> 2. **카테고리 9~15가 요약 *표*에 안 뜸**: runner의 직군×카테고리 표(`evaluate` 아닌 출력부)는 `[1..8]`로 하드코딩(line 217-226). PASS/total 총합 카운트(by_jg)는 category 값을 일반적으로 받으므로 **9~15도 정상 합산되어 채점은 정확**하나, **카테고리별 세부 표에는 9~15가 표시되지 않는다**. 세부 표 확인이 필요하면 출력부(채점 로직 아님) 한 줄 수정 필요 — 채점 정확도와 무관.

| 15 비교랭킹 | 3 다중도구 | 단일해역 종합 vs N개 비교·순위 |
→ **7종 모두 변별점 확보. 중복 없음.**

### 5.2 expect_* 매핑 가능성
- 신규 플래그 **0개** 도입(`evaluate()` 코드 대조 검증함). 모든 케이스가 runner의 `evaluate()` 분기(A/B/C/D/E축)로 채점됨. ✔
- 주의점(2차 검토 반영):
  - Cat9/15의 `expect_decision`은 DECISION_RE(`가능|적합|주의|무리|안전|위험|불가|곤란|어렵|좋습|괜찮|조심`) 의존.
    **추세어(악화/개선/유지)·랭킹어(최적/1순위)는 DECISION_RE에 없음(검증함)** → 그런 단어만 답하면 채점 실패.
    → 예시 query를 "좋아질까/위험?", "제일 나은(안전한) 곳"처럼 **결론·안전 계열 단어가 답에 강제로 나오도록** 작성해야 함(§2 반영). ⚠️→설계 보강
  - Cat11 복원불가 노이즈는 도구호출 강제 시 false-negative 위험 → `expect_no_halluc`로만 채점(완화). 단 §4.2의 prefix 분기(`startswith(("거뭄","ㅎ",…))`)는 휴리스틱이라 누락 가능 → 시드별로 `expect_*`를 직접 지정하는 편이 안전. ✔(보완)
  - Cat12 T2/T3는 `prev_id` 체인 필요 → runner가 prev_id로 멀티턴 컨텍스트 주입함을 확인(기존 Cat2와 동일 메커니즘). ✔
  - **Cat13(거짓전제)**: `expect_no_halluc`은 거짓전제 *추종*을 탐지 못함(HALLUC_RE 패턴만 검사 — 검증함). 정정 여부는 runner 무수정 범위에서 자동 채점 불가 → **A축(검증 도구 호출)만 자동, 정정문은 수동 리뷰**로 강등. ✗→정정(이전 "통과 ✔" 주장 오류)

### 5.3 직군 편향 점검
- 7카테고리 × 8직군 **대칭 적용**. 특정 직군 전용 카테고리 없음. ✔
- zones·tools_basic은 직군 슬롯에서 차용 → 직군별 난이도 균형. 단:
  - §4.2 Cat9는 `get_midterm_forecast`를 `expect_tools_any`에 OR로 추가. 미보유 직군은 이 도구를 못 불러도
    tools_basic 중 하나만 호출하면 통과(OR조건) → 형평성 페널티 없음. ✔ (보유 직군엔 가점 효과)
  - `get_zones_ranked` 미지원 직군은 Cat15에서 OR조건이라 tools_basic만으로도 통과. ✔
  - local_gov는 zones가 추상("관내")이라 Cat11 노이즈/Cat15 비교 시 변별 약함 → 예시를 "관내/관할/시연안" 다지명 비교로 구성해 보완. ✔
- 잔여 리스크: Cat12 3턴은 모델 컨텍스트 길이에 민감 → 직군 무관 공통이므로 편향 아님(난이도 상향은 의도).
