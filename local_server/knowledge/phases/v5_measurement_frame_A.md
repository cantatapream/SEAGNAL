## 1. 측정 시작 전 체크리스트

> 모두 PASS 해야 v5 측정을 가동한다. 한 줄이라도 실패면 측정 보류 — 결함이 *우리* 패치인지 *환경* 인지 구분 못함(2026-05-30 marine.kma 403 사례 참고).

### 1.1 서버 사전 점검 (5 단계)

| # | 항목 | 확인 명령(요지) | 합격 기준 |
|---|------|-----------------|-----------|
| C1 | 로컬 서버 살아있음 | `curl -s http://127.0.0.1:3001/api/health` | HTTP 200 + `ok:true` |
| C2 | marine.kma 데이터 적재 | `ls -la data/marine_buoys.json data/marine_vs.json data/marine_wh_buoys.json` | 3 파일 ≥ 1KB, mtime ≤ 24h |
| C3 | 임베딩 캐시 hit | `ls -la data/topic_embeddings.json data/tool_embeddings.json` | 두 파일 존재, 169 topic / 19~20 tool |
| C4 | 직군 임계표 로드 | `cat knowledge/jikgun/_thresholds.json | head -3` | 9 직군 키 모두 존재 |
| C5 | 평가셋 무회귀 | `python3 knowledge/phases/phase2b_eval_runner.py --n=3` | PASS 10/10 (사전 베이스라인) |

> C2 실패 시: marine.kma 적재 잡(별도)을 먼저 돌린다. 측정 자체는 의미가 있지만 *판정 권한*은 사라진다. C5 실패 시: 골든이 깨졌으므로 자유변칙 의미 없음 — 즉시 차단.

### 1.2 입력 자산 점검

## 2. 측정 실행 SOP

### 2.1 표준 가동(권장)

```bash
# 작업 디렉터리는 항상 local_server
cd /home/user/SEAGNAL/local_server

# 이전 로그 보존(타임스탬프 부착) 후 새 로그 가동
mv -f /tmp/freevar.log /tmp/freevar_prev_$(date +%Y%m%d_%H%M%S).log 2>/dev/null

# 백그라운드 가동 — nohup + & + disown 으로 셸 종료 내성
nohup python3 -u knowledge/phases/phase2b_eval_freevar_runner.py \
  > /tmp/freevar.log 2>&1 &
echo $! > /tmp/freevar.pid
disown
```

> `-u`(unbuffered) 필수 — 안 그러면 진행 라인이 1KB 단위로 묶여 폴링이 늦어진다.
> PID 파일은 §3.4 강제종료/§3.5 재시작 절차에서 사용한다.

### 2.2 부분 측정(스팟 디버그용 — v5 본측정은 *전체*)

- 1 직군만: `--jikgun=local_gov` (v3 에서 -8% 회귀한 직군 재현용)
- 상위 N건: `--limit=20`
- 본측정에는 사용 금지. *부분 PASS율로 전체를 추정하지 않는다.*

### 2.3 측정 메타 캡처(가동 직후 1회)

```bash
{
  echo "=== v5 measurement meta ==="
  date -u +"start_utc=%Y-%m-%dT%H:%M:%SZ"
  git -C /home/user/SEAGNAL rev-parse HEAD
  git -C /home/user/SEAGNAL status --porcelain | head -20
  cat /tmp/freevar.pid
} > /tmp/freevar_meta.txt
```

→ 비교 표(§4)의 "측정 컨텍스트" 행으로 사용.

## 3. 진행 모니터링

### 3.1 실시간 tail

```bash
tail -f /tmp/freevar.log
```

기대 패턴(러너 코드 LOG_EVERY=10 기준):
- 가동 직후 1줄: `=== Phase 2b 자유 변칙 평가 — 440 케이스 직렬 실행 ===`
- 매 10건마다: `  [10/440] 경과 35s …` … `  [440/440] 경과 2230s …`
- 마지막: `======= 직군별 종합 =======` 블록 + `==== 종합 PASS … ====`

### 3.2 폴링 주기(추천)

| 진행 단계 | 폴링 간격 | 확인 포인트 |
|-----------|-----------|-------------|
| 0~30s | 1회만 | "=== Phase 2b" 헤더 출력됐는지(가동 실패 즉시 검출) |
| 30s~5분 | 60s | [10/440], [20/440] 라인 누락 없이 진행 |
| 5분~30분 | 5분 | 경과 시간/케이스 비례 적정(440 × ~5s ≒ 37분) |
| 30분~ | 1분 | 끝물 — 종합 블록 등장 감지 |

> 폴링은 `tail -n 30 /tmp/freevar.log` 면 충분. `cat` 으로 전체 읽지 말 것(로그가 수십 MB 가능).

### 3.3 비정상 신호(즉시 대응)

| 신호 | 해석 | 대응 |
|------|------|------|
| 30s 안에 헤더 없음 | 서버 미가동 또는 EVAL 파일 경로 오류 | §3.4 종료 → §1 재점검 |
| `HTTP 429(exhausted)` 다발(>5건/100케이스) | Gemini quota 한도 | 측정 중단, 키 교체 후 §3.5 재시작 |
| `HTTP 5xx` 다발 | 로컬 서버 죽음 | 중단, 서버 재가동 후 처음부터 |
| `fetch failed` 다발 | 외부 KMA 장애 | 중단(§1 C2 재점검) — 결과는 *환경 결함* 으로 라벨링 |
| 케이스당 평균 시간 > 8s | LLM 응답 지연 또는 다중도구 폭주 | 종료 안 함, p95 악화 신호로 기록만 |
| 진행 라인 5분간 없음(stall) | 서버 hang 또는 timeout=60 미작동 | 즉시 종료, 서버 로그 점검 후 재시작 |

### 3.4 강제 종료 절차

```bash
PID=$(cat /tmp/freevar.pid)
kill -TERM $PID                           # 정중히
sleep 5
ps -p $PID > /dev/null && kill -KILL $PID # 죽지 않으면 강제
tail -n 50 /tmp/freevar.log | grep -E '^\s*\[' | tail -1   # 마지막 진행
```

### 3.5 재시작 절차(중단된 측정 복구)

> 러너는 **체크포인트 없음**. 부분 결과 신뢰 금지. 재시작은 *처음부터* 가 원칙.

1. `/tmp/freevar.log` 를 `/tmp/freevar_aborted_<ts>.log` 로 이름 변경(증거 보존).
2. §1.1 체크리스트 재실행(특히 C2/C3 — 중단 원인이 외부 의존성일 가능성).
3. §2.1 표준 가동 다시.
4. v5 결과는 **재시작 후 깨끗하게 완주한 것** 한 회만 정본으로 채택. 중복 실행 시 *마지막* 회 채택(이전 회는 메타에 "discarded: <사유>" 표기).

### 3.6 중간 폴링용 한 줄 헬퍼

```bash
# 진행률 + 마지막 케이스 + 추정 잔여
awk '/^  \[[0-9]+\/440\]/ {n=$1; t=$3} END {gsub(/[\[\]\/440]/,"",n); gsub(/s/,"",t); if(n>0) printf "done=%s/440 elapsed=%ss eta=%.0fs\n", n, t, (440-n)*t/n}' /tmp/freevar.log
```

## 5. 측정 후 산출물 — 다음 패치 우선순위 결정 규칙

> 측정만으로는 가치 없음. v5 결과를 *어디를 파야 가장 ROI 가 큰가* 의 신호로 변환한다.

### 5.1 v5 결과 요약 템플릿(3~5줄)

```
v5: PASS __/440 (__%). v3 대비 Δ=__pp.
직군 floor: __(__%) — DoD 70% __합/미달.
카테고리 우선순위 잔여: 연속 __% / 다중 __% / 정량 __%.
신규 결함 후보: <케이스 ID 또는 패턴 키워드>.
지연 p95 __ms — DoD __합/미달.
```

### 5.2 승률 갭 분류

| 분류 | 정의 | 의미 |
|------|------|------|
| 전체 상승(≥+3pp) | v5 종합 PASS > v3 + 3pp | 패치 효과 명확 — 다음 트랙으로 |
| 전체 동률(±2pp) | v3 와 사실상 같음 | 부분 회복+회귀 상쇄(v3 가 그 사례) — 카테고리/직군 표 정밀 분석 필수 |
| 전체 하락(≤−3pp) | 회귀 — 직전 패치 롤백 후보 | 즉시 §5.5 롤백 의사결정 |

### 5.3 신규 결함 후보 추출 알고리즘

1. 러너 출력 `[실패 샘플 — 처음 10건]` 블록을 v3 의 동일 블록과 diff.
2. v5 에만 새로 등장한 케이스 ID(전체 fails 에서) → "**신규 결함 후보**".
3. v3 에 있었고 v5 에서 사라진 케이스 ID → "**회복 케이스**"(패치 ROI 증거).
4. 양쪽에 있는 케이스 ID → "**잔존 결함**"(우선순위 하단).
5. CoT/환각 샘플 블록의 신규 케이스 ID는 결함 후보 *최상단* — 가드 회귀는 다른 어떤 PASS% 보다 우선한다(불변식).

> 위에서 아래로 평가. 첫 번째 조건이 참인 항목을 다음 라운드 *주* 패치 대상으로 채택.

### 5.5 롤백 결정 규칙

- 직전 라운드 패치 N건 중 *어느 것* 이 회귀를 일으켰는지 알 수 없으면 → **N건 전체 롤백 + 1건씩 재적용** 하며 v5 부분 측정(`--jikgun=<해당직군>` 단일)으로 가설 검증.
- 부분 측정은 의사결정용 *증거* 가 아니라 *방향성* — 최종 채택은 다시 전체 440 측정으로.
